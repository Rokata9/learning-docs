Chapter 4 · Shapes, corners, paths, and masks

Lesson 4.8 — Masks

Lesson 4.7 kept drawing inside one closed Path. A mask lets a separate shape or value field decide which parts of a larger drawing remain visible. The drawing may move behind a fixed mask, or the mask itself may move to reveal different parts of the drawing.

Practical question

How can Android cut oversized content to a chosen shape, keep an animation visible only inside that shape, or reveal content by moving the shape that controls visibility?

The main idea

A mask is a spatial visibility map: separate data that says how much content survives at every drawing position.

The per-position multiplication explains how the map is applied. It is not the complete purpose of a mask. This correction begins with the visible shape-cutting and reveal uses.

1 · WHAT YOU WILL SEE

Three common uses of the same mask idea

The arithmetic stays per position, but the visible result is spatial.

Cut content to a shape

Start with content larger than the final silhouette. A hard capsule mask keeps only the content positions inside the capsule.

Move content behind a fixed mask

The capsule stays still. Stripes, artwork, or an animation move underneath it. Only the portion currently under the capsule reaches the output.

Move the mask to reveal content

The content stays still. Moving or resizing the mask changes which content positions are visible. This produces a reveal or wipe.

Hard-mask shape rule: at positions where both the content and a binary 0-or-1 mask exist, the visible result is their overlap. A simple hard clip can produce the same visible silhouette away from the edge. Masks become more general when they use partial values, textures, gradients, images, or shader-calculated fields.
2 · TERMS

Define every new object before the first formula

Mask

A spatial visibility map: separate data aligned with the content that controls how much content survives at each position.

Mask value

One number from 0 through 1 stored for one position or enlarged teaching zone.

Mask field

The complete collection of mask values arranged across the drawing area. A shape can create a field with 1 inside and 0 outside.

Effective source alpha

The candidate alpha after the mask value has reduced it. Source-over consumes this alpha.

Grayscale preview: mask value m is shown as opaque preview RGB(m, m, m). This lets black represent 0 and white represent 1. The preview RGB is not added to the orange candidate.

6 · WHICH VALUES ARE MULTIPLIED?

The mask controls alpha; the stored RGB answer depends on representation

This resolves the difference between straight and premultiplied RGBA from Lesson 3.5.

The candidate carries its own alpha. The mask supplies a second visibility restriction. The general visibility calculation is:

Straight RGBA view

Straight RGB stores the color independently from alpha. Applying mask value 0.60 to the opaque candidate changes alpha, not its straight RGB fields.

candidate straight RGBA = (0.8400, 0.3600, 0.1800, 1.0000) masked straight RGBA = (0.8400, 0.3600, 0.1800, 0.6000)

Premultiplied RGBA view

Premultiplied RGB already contains the alpha weighting. The same mask therefore multiplies the stored RGB contributions and alpha.

candidate premultiplied RGBA = (0.8400, 0.3600, 0.1800, 1.0000) × mask 0.6000 masked premultiplied RGBA = (0.5040, 0.2160, 0.1080, 0.6000)
Precise answer to “is it multiplying color channels?” At the straight-RGBA API level, a pure opacity mask preserves straight RGB and multiplies alpha. In a premultiplied buffer, the stored RGB contributions are also multiplied because those values already include alpha. After the masked result is composited over an opaque background, the final displayed RGB also includes the background contribution.
Special-case warning: the main candidate alpha is 1.00, so effective source alpha equals the mask value. If candidate alpha is 0.50 and mask value is 0.60, effective source alpha is 0.50 × 0.60 = 0.30.

The gray preview does not tint the candidate

This is the most likely misconception.

Incorrect mental model

“Mask value 0.60 paints gray RGB(0.60, 0.60, 0.60) over the orange candidate.”

That would be a color-compositing or tint operation. It is not the mask contract taught here.

Correct mental model

The mask preview displays the number 0.60 as gray so the value is visible to the learner.

12 · ANDROID CONNECTION

Group the content, then apply the mask to that group

The complete file remains in Android Studio and the incremental Android ZIP.

1 · Parent background

The navy Surface exists outside the masked content group.

2 · Offscreen group

CompositingStrategy.Offscreen gives the Canvas content an isolated temporary drawing target.

3 · Candidate content

Draw the full multi-color pattern first. It becomes the destination inside the isolated group.

4 · Mask shape

Draw the capsule second with BlendMode.DstIn. Its alpha is the mask value.

5 · Masked group

Only candidate content under the capsule remains. Outside positions become transparent inside the group.

6 · Final composition

The isolated masked group is then composited over the parent navy background.

// MasksExplorer.kt — SpatialMaskUseCard
Canvas(
    modifier = Modifier.graphicsLayer {
        compositingStrategy = CompositingStrategy.Offscreen
    },
) {
    drawTeachingPattern(contentOffsetPx)
    drawRoundRect(
        color = Color.Black,
        topLeft = maskTopLeft,
        size = maskSize,
        cornerRadius = maskCornerRadius,
        blendMode = BlendMode.DstIn,
    )
}
Why offscreen isolation matters: the DstIn operation must affect the grouped candidate content, not previously drawn siblings or the parent background. The parent background therefore remains outside the isolated Canvas.
Controlled microscope remains valid: the four-zone experiment still uses alpha = maskValue for one solid candidate and non-overlapping zones. That is exact for its narrow contract. It is not the general architecture for arbitrary multi-draw content.

Exercise 1 · Fixed mask, moving content

A striped image moves left while a capsule mask stays fixed. What moves in the final output: the capsule boundary, the stripes visible inside it, or both?

Show answer

The capsule boundary stays fixed. Different stripe positions pass underneath it, so the visible stripes move inside the unchanged capsule silhouette.

Exercise 3 · Diagnostic: are straight RGB channels multiplied?

Apply mask value 0.60 to straight RGBA(0.84, 0.36, 0.18, 1.00) before compositing. What is the masked straight RGBA? What is its premultiplied RGBA?

Show answer
masked straight RGBA = (0.84, 0.36, 0.18, 0.60) masked premultiplied RGBA = (0.84×0.60, 0.36×0.60, 0.18×0.60, 0.60) = (0.504, 0.216, 0.108, 0.60)

Straight RGB remains the candidate color. Premultiplied RGB stores the alpha-weighted contributions.

Exercise 4 · Clip or mask?

You need a fixed hard capsule boundary around moving content, with no soft visibility texture. Which is the simpler tool: a clip or a general offscreen mask?

Show answer

A clip is the simpler tool for that hard geometric boundary. Use a mask when you need variable 0-to-1 visibility, an image or texture, a soft reveal, or another field that is not just one hard geometry decision.

18 · SOURCES AND EVIDENCE

What the Android contracts support

  • Compose DrawScope.drawRect accepts an alpha value from 0 through 1 and a blend mode.
  • Compose BlendMode.DstIn treats its source as a mask: source RGB is ignored and source opacity controls how much destination content remains.
  • CompositingStrategy.Offscreen isolates the candidate content in a temporary drawing target before DstIn is applied, preventing the mask operation from affecting previously drawn siblings or the parent background.
  • The Android explorer keeps the direct per-zone alpha model only as a small arithmetic microscope. It does not present that path as the general implementation for arbitrary captured or filtered content.
