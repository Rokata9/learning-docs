Chapter 4 · Shapes, corners, paths, and masks

Lesson 4.8 — Masks

Lesson 4.7 kept drawing inside one closed Path. A mask lets a separate shape or value field decide which parts of a larger drawing remain visible. The drawing may move behind a fixed mask, or the mask itself may move to reveal different parts of the drawing.

Practical question

How can Android cut oversized content to a chosen shape, keep an animation visible only inside that shape, or reveal content by moving the shape that controls visibility?

The main idea

A mask is a spatial visibility map: separate data that says how much of another drawing survives at every position.

This revision keeps three scene objects separate from the start: the content being masked, the mask data, and the background behind the masked group. The one-position multiplication appears only after those objects are visible.

1 · WHAT YOU WILL SEE

Three common uses of the same mask idea

The arithmetic stays per position, but the visible result is spatial.

Cut content to a shape

Start with content larger than the final silhouette. A hard capsule mask keeps only the content positions inside the capsule.

Move content behind a fixed mask

The capsule stays still. Stripes, artwork, or an animation move underneath it. Only the portion currently under the capsule reaches the output.

Move the mask to reveal content

The content stays still. Moving or resizing the mask changes which content positions are visible. This produces a reveal or wipe.

Hard-mask shape rule: at positions where both the content and a binary 0-or-1 mask exist, the visible result is their overlap. A simple hard clip can produce the same visible silhouette away from the edge. Masks become more general when they use partial values, textures, gradients, images, or shader-calculated fields.
2 · TERMS AND SCENE OBJECTS

Name the three scene objects before naming blend operands

Source and destination are temporary roles inside one blend operation.

Content being masked

The multi-color pattern in the spatial demo, or the opaque orange color in the one-position microscope. This is the drawing whose visibility will be restricted.

Mask data

One alpha value at every relevant position. The capsule creates one mask field: alpha 0 outside and a selected alpha inside.

Background

The opaque navy drawing behind the masked group. It is not the mask. It becomes visible where the masked group is translucent or transparent.

Blend operand

One input to a blend operation. Source means the input supplied now. Destination means the input already present in that blend target. Draw order decides these roles.

Mask shape versus mask data: the capsule is geometry used to write mask alpha. The complete mask is the resulting alpha field across the whole content-group bounds. The geometry and the stored values are related, but they are not the same object.

4 · DSTIN VERSUS SRCIN

Both keep an overlap, but they keep different operands

Start from draw order, not from the words mask and content.

DstIn · keep the destination

draw first into the group: content = destination draw second as the mask layer: mask = source output premultiplied RGB = destination premultiplied RGB × source alpha output alpha = destination alpha × source alpha

The mask source RGB is ignored. Its alpha controls how much of the earlier content destination remains.

SrcIn · keep the source

prepare first: mask = destination draw second: content = source output premultiplied RGB = source premultiplied RGB × destination alpha output alpha = source alpha × destination alpha

The mask destination RGB is ignored. Its alpha controls where the later content source remains.

Why both can look like “show only the overlap”: with the same hard capsule alpha field and the matching reversed draw order, both produce transparent output outside and content-colored output inside. That visible overlap is a useful summary. The full definition still says which operand's color survives: destination for DstIn, source for SrcIn.
5 · ALPHA MASK VERSUS GRAYSCALE PREVIEW

DstIn reads alpha, not how black or white the mask looks

This is the missing bridge between the capsule code and the four gray teaching swatches.

The actual Compose mask input

inside at full strength: Color.Black = straight RGBA(0, 0, 0, 1) inside at 60%: Color.Black.copy(alpha = 0.60) = straight RGBA(0, 0, 0, 0.60) outside: transparent mask-layer position = straight RGBA(0, 0, 0, 0)

DstIn ignores the three black RGB fields. Alpha 1 keeps all content. Alpha 0.60 keeps 60% of the content contribution. Alpha 0 removes it.

The grayscale row in the microscope

The gray swatches are a chart that makes numbers visible to you.

preview of value 0.60: opaque straight RGB(0.60, 0.60, 0.60) preview alpha = 1.00

That opaque gray would behave as mask alpha 1 under DstIn, not 0.60. To create mask value 0.60, the actual mask alpha must be 0.60. The mask RGB may be black, white, red, or another color without changing DstIn.

A luminance mask is a different contract: another operation first converts mask RGB brightness into a visibility value. Compose DstIn does not perform that conversion automatically. This lesson teaches an alpha mask.

8 · STRAIGHT AND PREMULTIPLIED VALUES

The mask scales alpha; stored RGB depends on the representation

Reuse the two RGBA representations from Lesson 3.5.

The content carries its own alpha. The mask supplies another independent alpha restriction. The first operation calculates:

Straight RGBA view

Straight RGB stores the orange color independently from alpha.

content straight RGBA = (0.8400, 0.3600, 0.1800, 1.0000) masked straight RGBA = (0.8400, 0.3600, 0.1800, 0.6000)

Premultiplied RGBA view

Premultiplied RGB stores the alpha-weighted color contributions.

content premultiplied RGBA = (0.8400, 0.3600, 0.1800, 1.0000) × mask alpha 0.6000 masked premultiplied RGBA = (0.5040, 0.2160, 0.1080, 0.6000)
Precise answer to “are color channels multiplied?” A pure opacity mask preserves the straight RGB color and multiplies alpha. In a premultiplied buffer, the stored RGB contributions are also multiplied because those fields already contain alpha weighting.

10 · CLIPPING VERSUS ALPHA MASKING

A binary alpha field can match a hard clip away from the edge

The visible similarity does not make the underlying operations identical.

Hard clip

clearly outside → current draw rejected clearly inside → current draw allowed

The renderer restricts drawing by geometry. For one fixed hard capsule, this is the simpler production tool.

Alpha mask

outside mask alpha = 0 inside mask alpha = 1 partial region may use 0.25, 0.60, 0.85...

The renderer keeps a fraction of a grouped drawing at every position. The mask may come from geometry, an image, a texture, or a shader.

11 · WHY THE DIRECT-ALPHA MICROSCOPE IS A SHORTCUT

Applying alpha to every draw is not the same as masking a completed group

A concrete overlap exposes the difference.

Correct grouped mask

draw two opaque shapes into one group → overlap is still opaque apply mask alpha 0.60 once to the group → non-overlap alpha = 0.60 → overlap alpha = 0.60

Incorrect per-draw shortcut

draw shape 1 with alpha 0.60 draw shape 2 with alpha 0.60 over it overlap alpha = 0.60 + 0.60 × (1 − 0.60) = 0.84
Why the four-zone microscope is still exact: each zone contains one solid orange draw, and the zones do not overlap. Under that narrow contract, drawing the orange color with alpha = maskValue collapses Stage A and Stage B without changing the answer. It is not a general masking architecture for multi-draw content.

14 · ANDROID CONNECTION

Use one documented content-isolation boundary and one full-bounds mask layer

The complete file remains in Android Studio and the incremental Android ZIP.

1 · Navy parent

The opaque navy Surface is outside the masked content group.

2 · Offscreen content target

CompositingStrategy.Offscreen guarantees a Canvas-sized target that receives only this composable's pattern drawing.

3 · Draw grouped content

The complete multi-color pattern is drawn into that target and becomes the DstIn destination.

4 · Full-bounds mask layer

Canvas.saveLayer creates a transparent source mask across the complete Canvas bounds.

5 · Apply DstIn

The capsule writes selected alpha inside. Restore multiplies the isolated destination by source-mask alpha, including alpha 0 outside.

6 · Draw over navy

Compose composites the finished offscreen Canvas over the navy parent.

// MasksExplorer.kt — SpatialMaskUseCard + applyFullBoundsCapsuleAlphaMask
Canvas(
    modifier = Modifier
        .fillMaxWidth()
        .height(SpatialDrawingHeightDp.dp)
        .graphicsLayer {
            compositingStrategy = CompositingStrategy.Offscreen
        },
) {
    drawSpatialTeachingPattern(contentOffsetPx)

    val canvas = drawContext.canvas
    val fullBounds = Rect(0f, 0f, size.width, size.height)

    canvas.saveLayer(fullBounds, dstInMaskLayerPaint)
    try {
        drawRoundRect(
            color = Color.Black.copy(alpha = maskAlpha),
            topLeft = maskTopLeft,
            size = maskSize,
            cornerRadius = maskCornerRadius,
        )
    } finally {
        canvas.restore() // apply the complete source mask with DstIn
    }
}

Why your device can look correct without Offscreen

The visible result proves one narrow fact: during that run, the destination reached by DstIn did not visibly include the navy parent. The final image does not reveal which Compose or renderer-owned target supplied that isolation.

Possible internal boundaries cannot be selected from appearance alone. Proving the exact reason would require a renderer/layer trace or inspection of the exact Compose, Android renderer, and Skia source path used by your build.

Why the lesson keeps Offscreen

The modifier turns the required containment into an explicit, documented contract: blend modes inside this Canvas operate on this composable's offscreen content before the result is placed over the parent.

Removing it would convert one successful measurement into an undocumented correctness assumption. An explicit outer Canvas.saveLayer could replace it, but using both outer mechanisms without another need would add redundant offscreen work.

Cost boundary: Offscreen creates a texture the size of the drawing area and clips drawing to that region. Canvas.saveLayer also redirects drawing into an offscreen target and is expensive. Keep bounds tight, avoid redundant outer layers, and profile the real component count and size.
Production choice: use clipPath for this exact hard capsule when the inside value is always 1 and the outside value is 0. Use a real alpha mask when partial, image-based, textured, or shader-generated visibility is required.

18 · EXERCISES

Answer before opening the hidden solutions

Each exercise targets one likely ambiguity from this revision.

Exercise 1 · DstIn versus SrcIn

The content is drawn first and the mask layer is supplied second. Which mode keeps the content color: DstIn or SrcIn?

Show answer

DstIn. The earlier content is the destination. DstIn keeps destination color and multiplies it by source-mask alpha. SrcIn would keep the later source color.

Exercise 2 · Why does black keep content?

The mask capsule is Color.Black. Why does that not hide the content under DstIn?

Show answer

Color.Black is straight RGBA(0, 0, 0, 1). DstIn ignores mask RGB and reads mask alpha. Alpha 1 keeps the complete destination content. Black is irrelevant here; opacity is what matters.

Exercise 3 · Two-stage zone-C trace

Content straight RGBA is (0.84, 0.36, 0.18, 1.00), mask alpha is 0.60, and navy is (0.10, 0.18, 0.30, 1.00). Calculate masked content alpha and final red.

Show answer
Stage A: masked content alpha = 1.00 × 0.60 = 0.60 Stage B: background opening = 1 − 0.60 = 0.40 final red = 0.84 × 0.60 + 0.10 × 0.40 = 0.504 + 0.040 = 0.544
Exercise 4 · Diagnostic: why not set every draw to alpha 0.60?

Two opaque shapes overlap. Compare masking the completed group once at 0.60 with drawing each shape separately at alpha 0.60.

Show answer
grouped mask overlap alpha = 0.60 separate draw overlap alpha = 0.60 + 0.60 × (1 − 0.60) = 0.84

The per-draw shortcut applies opacity twice in the overlap. It is not a general grouped mask.

20 · SOURCES AND EVIDENCE

What the Android contracts support

  • Compose BlendMode.DstIn keeps the destination image where source and destination overlap. Source RGB is ignored; source opacity acts as the mask.
  • Compose BlendMode.SrcIn keeps the source image where source and destination overlap. Destination RGB is ignored; destination opacity acts as the mask.
  • CompositingStrategy.Offscreen forces a composable's content into an offscreen texture so alpha blend modes apply to that content rather than previously drawn background content.
  • Canvas.saveLayer redirects the full-bounds mask drawing into a transparent offscreen target. On restore(), the layer paint applies DstIn to the already isolated content group.
  • The browser's grayscale row is a teaching visualization. The Android DstIn code reads mask alpha; it does not convert gray RGB brightness into alpha.
  • The four-zone direct-alpha path is validated only for one non-overlapping solid draw per zone. The overlapping-shape counterexample shows why it is not the general grouped-mask implementation.
