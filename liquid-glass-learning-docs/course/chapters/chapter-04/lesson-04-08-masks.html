Lesson 4.8 — Masks

Lesson 4.7 used one closed Path to answer a yes-or-no question at positions that were clearly inside or outside. This lesson keeps the same kind of candidate drawing and opaque background, but gives each enlarged interior zone a separate visibility value from 0 through 1.

Practical question

How can one effect be fully hidden in one region, partly visible in another, and fully visible elsewhere without changing the effect's RGB color?

One new idea

A mask is separate data that controls how much of another drawing is allowed to contribute at each position.

This lesson uses four enlarged zones rather than physical display pixels. Lesson 4.9 will explain the renderer-created transition around a mathematical edge.

2 · TERMS

Define every new object before the first formula

Mask

Separate data that controls how much another drawing contributes at each position.

Mask value

One number from 0 through 1 stored for one position or enlarged teaching zone.

Mask field

A collection of mask values arranged over many drawing positions.

Effective source alpha

The candidate alpha after the mask value has reduced it. Source-over consumes this alpha.

Grayscale preview: mask value m is shown as opaque preview RGB(m, m, m). This lets black represent 0 and white represent 1. The preview RGB is not added to the orange candidate.

8 · DIAGNOSTIC

The gray preview does not tint the candidate

This is the most likely misconception.

Incorrect mental model

“Mask value 0.60 paints gray RGB(0.60, 0.60, 0.60) over the orange candidate.”

That would be a color-compositing or tint operation. It is not the mask contract taught here.

Correct mental model

The mask preview displays the number 0.60 as gray so the value is visible to the learner.

candidate straight RGB stays (0.84, 0.36, 0.18) mask changes effective source alpha background then contributes through source-over

6 · Source-over

The Canvas combines the masked source with the opaque background.

// MasksExplorer.kt — controlled non-overlapping zones
clipPath(badgePath) {
    maskValues.forEachIndexed { index, maskValue ->
        drawRect(
            color = CandidateColor,
            topLeft = zoneTopLeft(index),
            size = zoneSize,
            alpha = maskValue,
        )
    }
}
Production boundary: this direct path is exact because the candidate is one solid fill and the four zones do not overlap. Arbitrary content with several overlapping draw calls normally needs the candidate grouped before a separate mask is applied, or a shader that reads one mask value per position. Compose BlendMode.DstIn is one general compositing tool: Android's documentation states that it keeps the destination only where the source mask overlaps, ignores source RGB, and uses source opacity.

13 · EXPLAIN THE RESULT

Larger mask value leaves less room for the background

at mask 0.60: background opening = 1 − 0.60 = 0.40 at mask 0.80: background opening = 1 − 0.80 = 0.20

The background contribution becomes smaller. The output moves numerically toward the unchanged candidate RGB. At mask 0.80, the output is straight sRGB RGB(0.6920, 0.3240, 0.2040).

What final RGB appears when candidate alpha is 1 and mask value is 0?

Show answer

Effective source alpha is 1 × 0 = 0. The candidate contributes nothing. The final output is the unchanged background straight sRGB RGB(0.10, 0.18, 0.30).

Exercise 3 · Diagnostic: does mask gray tint orange?

The preview for mask value 0.60 is RGB(0.60, 0.60, 0.60). Does that gray RGB become part of the final output calculation?

Show answer

No. The grayscale preview makes the mask number visible. The mask value controls effective source alpha. Candidate RGB and background RGB supply the source-over color inputs.

Exercise 4 · Candidate alpha 0.40 and mask 0.50

Calculate effective source alpha.

Show answer
0.40 × 0.50 = 0.20

Do not add the values. The mask further restricts the candidate's existing opacity.

17 · SOURCES AND EVIDENCE

What the Android contracts support

  • Compose DrawScope.drawRect accepts an alpha value from 0 through 1 and a blend mode.
  • Compose BlendMode.DstIn treats its source as a mask: source RGB is ignored and source opacity controls how much destination remains.
  • The Android explorer deliberately uses direct per-zone alpha for one single solid candidate. It does not claim that this is the general implementation for arbitrary captured or filtered content.
