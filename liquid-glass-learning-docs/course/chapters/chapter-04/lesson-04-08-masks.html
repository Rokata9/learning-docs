Lesson 4.8 — Masks

A mask is a second image that controls how much of another image survives at the same position. This rewrite shows every image before and after every operation. It does not ask you to imagine invisible layers from prose.

Practical question

How do the pattern, the capsule-shaped mask, and the navy background become one final image—and what exact pixel values are read at one selected position?

Representation used by the code

SwiftUI Color values are supplied as straight RGBA. The destinationIn blend calculation is easiest to show with premultiplied RGBA contributions. Section 4 calculates the same case both ways and proves that both descriptions represent the same result.

1 · TERMS

Name the concrete images before naming blend operands

source and destination are assigned later, for one exact blend operation.

Pattern image

One temporary image containing every colored band, the white ring, and the white diagonal line.

Mask image

One temporary image covering the same Canvas bounds. Its alpha is 0 outside the capsule and the selected value inside.

Drawing target

The image that receives the next draw command. Calling drawLayer changes the current drawing target until the closure returns and the layer is composited.

Intermediate result

The complete image that exists after one step and becomes the input to the next step.

Where the temporary images are created: the first context.drawLayer { patternLayer in ... } creates the pattern target. The nested patternLayer.drawLayer { maskLayer in ... } creates the mask target, composited with patternLayer.blendMode = .destinationIn. Both are normal RGBA drawing targets. GraphicsContext.BlendMode.copy is used while constructing the mask target. .destinationIn is used later, when that completed mask target is restored into the pattern target. These are two separate operations at two separate times.






  
3 · PER-POSITION MICROSCOPE
Why one pixel-sized position explains the complete layer operation
The same rule runs independently at every matching position inside the layer bounds.

  
Two separate per-position algorithms: first, destinationIn reads the pattern pixel and mask alpha at the same coordinate (x, y). Its multiplication creates the masked-pattern intermediate pixel. Second, ordinary source-over reads that masked-pattern pixel and the navy parent pixel at the same coordinate. A neighboring coordinate does not enter either calculation.

Transparent mask pixels are not “missing.” The mask image contains a valid pixel with alpha 0. The destinationIn multiplication uses that zero and produces a transparent masked-pattern pixel. Any checkerboard shown behind that pixel is only a teaching visualization of transparency; it is not stored pixel content. A renderer may optimize the physical work internally, but the required output must match this per-position result.

Straight RGBA path
SwiftUI Color(red:green:blue:opacity:) receives these straight component values.

    
Premultiplied RGBA path
destinationIn scales the stored premultiplied RGB contributions and alpha by the mask alpha. Dividing the non-zero output contributions by output alpha recovers the straight RGB.

Why bounds matter
A temporary target stores one value per pixel position in its bounds. Doubling width and height creates four times as many positions.
positions = width × height

2× width and 2× height
→ 2 × 2 = 4× positions
The simple estimate uses 4 bytes per pixel for an RGBA8 target. Real GPU formats, alignment, tiling, and reuse can differ.

// MasksExplorer.swift — drawPatternThroughCapsuleMask
let fullBounds = CGRect(origin: .zero, size: size)

// Step 2: create the pattern target.
context.drawLayer { patternLayer in
    // Step 3: draw every pattern object into that target.
    drawSpatialTeachingPattern(
        context: &patternLayer,
        size: size,
        horizontalOffset: offset
    )

    // Step 4: create the full-size mask target.
    // destinationIn is applied when this nested layer restores.
    patternLayer.blendMode = .destinationIn
    patternLayer.drawLayer { maskLayer in
        // Step 4A: construct the mask target.
        // copy replaces every mask-target pixel with transparent RGBA,
        // so mask alpha is explicitly 0 across the complete bounds.
        maskLayer.blendMode = .copy
        maskLayer.fill(Path(fullBounds), with: .color(.clear))

        // Step 5: write the selected alpha inside the capsule.
        maskLayer.blendMode = .normal
        maskLayer.fill(
            capsulePath,
            with: .color(.black.opacity(maskAlpha))
        )
    }
    // Step 6: apply the completed mask target.
    // destinationIn performs the per-position multiplication:
    // pattern premultiplied RGBA × mask alpha.
}
// Step 7: a separate operation. Ordinary source-over composites
// the masked-pattern intermediate image over the navy parent.

11 · EXERCISES
Answer before opening each result

  
Exercise 1 · What is processed at an outside position?
The full-size mask image contains a transparent pixel with alpha 0. destinationIn uses that alpha at the same position. The masked pattern output becomes transparent there. The API-level model does not treat the position as absent.

  
Exercise 2 · Straight and premultiplied output

    straight sRGB RGBA(0.8400, 0.3600, 0.1800, 1.0000)This is the opaque orange content input used throughout Lesson 4.8.
    masked by 0.60 becomes
    straight sRGB RGBA(0.8400, 0.3600, 0.1800, 0.6000)This straight output keeps the orange RGB and stores the masked alpha 0.60..
    Its premultiplied representation is
    premultiplied sRGB RGBA(0.5040, 0.2160, 0.1080, 0.6000)The chip shows the represented orange. The premultiplied numeric RGB fields are contributions, not straight channel values..
  

  
Exercise 3 · Why does the current code not need drawingGroup?
The first explicit context.drawLayer { patternLayer in ... } creates a pattern-only destination. The mask modifies that target, not the navy parent. drawingGroup() would be an alternative pattern-isolation method, not an additional requirement.

  
Exercise 4 · Diagnostic: what survives in destinationIn?
The destination color survives. The source alpha controls how much survives. In the current order, the pattern is destination and the mask image is source.

13 · SOURCES AND EVIDENCE
What the iOS contracts support

  
    
    
  • SwiftUI drawingGroup() rasterizes a view into an offscreen texture and is useful when blend modes must affect only that view’s contents.
    • 
    
  • SwiftUI GraphicsContext.drawLayer draws a transparency layer, then composites the result onto the context using the current blend mode.
    • 
    
  • GraphicsContext.BlendMode.destinationIn and .sourceIn are the Porter-Duff pair used in this lesson.
    • 
  

  
Implementation limit: the per-position formulas define the required output. A GPU may skip, tile, merge, or reuse internal work while preserving that output. This lesson does not claim one physical shader invocation per source-code-visible pixel.
