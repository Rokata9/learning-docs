Lesson 4.6 — Cubic Bézier curves

Lesson 4.5 built a Path from straight addLine(to:) segments. A straight segment cannot make the side of a glass control bow smoothly. This lesson replaces one straight segment with one curved segment.

Practical question

How can one path segment start at a known point, end at another known point, and bend through the space between them without adding many hand-written straight segments?

One new graphics idea

A cubic Bézier curve is one curved path segment defined by a start point, two control points, meaning guide positions that bend the segment, and an end point.

The general curve equation is deliberately deferred. This lesson calculates one exact point at halfway by repeatedly taking midpoints, using the center arithmetic already learned in Chapter 2.

Lesson 4.6 stays complete as Chapter 4 geometry. No dedicated cubic explorer is added.

New Lesson 4.6 object

The same Path stores one curved segment instead of one straight segment. Two new guide positions bend the segment while the start and end remain explicit.

The next two sections define those guide positions before the new Path command appears.

1 · WHAT YOU WILL SEE

Four movable points produce one curve

The start and end positions stay on the curve. Two movable guide positions influence the bend between them. The next section names those guide positions control points and defines their exact role.

Visible comparison: the optional dashed straight line connects the same start and end. It shows exactly what the completed Lesson 4.5 addLine(to: end) would draw.
2 · TERMS

Define every point before the command

Start point

The current point already stored by the path. The curved segment begins here.

First control point

A guide position that influences the beginning of the curve. It does not become the path's current point.

Second control point

A guide position that influences the ending part of the curve. It also does not become the current point.

End point

The position where the segment finishes. After addCurve(to:control1:control2:), this becomes the new current point.

Control guide

A dashed teaching line from an endpoint to its nearby control point. It makes the inputs visible. The guide is not stored as part of the path.

Cubic Bézier

The curve variant used here: one start endpoint, two control points, and one end endpoint. The word cubic names this curve family. Polynomial-degree mathematics is not required in this lesson.

addCurve(to:control1:control2:)

The Path command that appends one cubic Bézier segment. It receives the end, control 1, and control 2. The already-stored current point supplies the start.

4 · TRACE ONE VALUE

Find the curve point exactly halfway

No general Bézier formula is needed for this one fixed position.

A midpoint is halfway between two positions. Its X coordinate is the average of the two X values. Its Y coordinate is the average of the two Y values.

midpoint X = (first X + second X) ÷ 2 midpoint Y = (first Y + second Y) ÷ 2

The default course points are:

start = (120, 300) control 1 = (280, 100) control 2 = (540, 100) end = (700, 300)

Default output: the exact curve point at halfway is (410, 150). The straight start-to-end comparison is at Y = 300, so the curve's halfway point is 150 units higher in SwiftUI coordinates because smaller Y values are nearer the top.
Deliberate deferral: a general position along the curve is usually described by a progress value from 0 through 1. Progress and linear interpolation are taught in Chapter 5. This lesson uses only the already-known halfway case.

8 · EXPLAIN THE RESULT

The controls guide the segment; only endpoints anchor it

Guaranteed on the curve

The start and end points are the two endpoints of the stored segment. The curve begins and finishes at those exact coordinates.

Usually not on the curve

The two control points are inputs that bend the segment. The visible curve is not required to pass through either control point.

Path continuation

After addCurve, the end point becomes current. A following addLine(to:) or another addCurve starts there.

Why this matters for Liquid Glass: later morphing and custom silhouettes need smooth boundaries whose endpoints remain predictable while intermediate curvature changes. This lesson supplies the geometric vocabulary only; animation is still deferred.

10 · EXERCISES

Answer before opening the solutions

Exercise 1 · Identify the three supplied points

In addCurve(to: CGPoint(x: 700, y: 300), control1: CGPoint(x: 280, y: 100), control2: CGPoint(x: 540, y: 100)), which point is control 1, control 2, and the end?

Show answer

Control 1 is (280, 100). Control 2 is (540, 100). End is (700, 300). The start is not supplied because it is already the current point.

Exercise 2 · First midpoint round

Using the default course points, calculate the midpoint between start (120, 300) and control 1 (280, 100).

Show answer
X = (120 + 280) ÷ 2 = 200 Y = (300 + 100) ÷ 2 = 200 midpoint = (200, 200)
Exercise 3 · Diagnostic: must the curve pass through its controls?

Does a cubic Bézier curve always pass through control 1 and control 2?

Show answer

No. The curve is guaranteed to pass through the start and end endpoints. The control points guide its shape and usually remain outside the visible curve.

Exercise 4 · Continue the path

After the curve ends at (700, 300), the next command is addLine(to: CGPoint(x: 760, y: 340)). Where does that straight segment begin?

Show answer

It begins at (700, 300) because the cubic end became the current point.

12 · SOURCES AND EVIDENCE

What the SwiftUI API contract supports

  • SwiftUI Path exposes move(to:), addLine(to:), addCurve(to:control1:control2:), and other path operations.
  • The SwiftUI path contract describes a cubic segment as beginning at the current point, approaching two control points, and ending at the supplied to: point.
  • GraphicsContext.stroke and GraphicsContext.fill draw the geometry stored in a Path.

SwiftUI Path · Path.addCurve(to:control1:control2:) · SwiftUI Canvas

Evidence boundary: the browser uses SVG's cubic-path command with the same four points. The iOS mapping uses SwiftUI Path.addCurve(to:control1:control2:). There is no dedicated cubic explorer. The repeated-midpoint construction proves one mathematical point at halfway. This lesson does not claim how the iOS renderer internally divides the curve into GPU work, nor how antialiasing assigns partial pixel coverage.
