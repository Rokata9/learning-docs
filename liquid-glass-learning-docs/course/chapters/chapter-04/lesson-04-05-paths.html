Chapter 4 · Shapes, corners, paths, and masks

Lesson 4.5 — Paths

Lessons 4.1 through 4.4 used built-in rectangle, circle, and rounded-rectangle operations. Each operation accepts a fixed set of inputs and can produce only the matching kind of shape. This lesson solves a new problem: describe one custom boundary whose five straight sides do not match any one built-in shape call.

Practical question

How can Android receive ordered commands containing local positions and turn those commands into one custom shape?

One new idea

A path is an ordered list of geometric instructions. The instructions can move to a starting position, append connected segments, and explicitly return to the start when the boundary must be stored as closed.

This lesson uses only straight segments. Curved path segments begin in Lesson 4.6.

1 · WHERE THIS LESSON FITS

Keep the known coordinate system; change how the boundary is described

No new coordinate system is introduced.

What remains known

The diagram uses local X and Y coordinates. X increases to the right. Y increases downward. Every named point is one exact local position.

What changes

Instead of passing rectangle bounds or a corner radius to one built-in shape operation, the code supplies an ordered sequence of path commands.

2 · WHAT YOU WILL SEE

A right-pointing tag appears one command at a time

The tag is only a teaching shape. Its coordinates are exact.

The browser begins with an empty path. The step buttons then apply one command at a time. The first command stores A as the position where the next line will begin, without drawing. Each later line command adds one straight segment from the current point to a new point. The final command adds the missing segment from E back to A.

Visible result first: an unfinished stroked path has a visible gap between E and A. A closed path explicitly stores the complete five-sided boundary, so its stroke includes E → A. Compose can still fill an open connected run by treating it as closed during filling; that drawing rule does not add close() to the stored Path.
3 · TERMS

Name the objects before using the API

Path

An object that stores an ordered list of geometric drawing instructions.

Current point

The local position where the next connected segment will begin.

Segment

One connected part of a path. This lesson uses only straight line segments between two endpoints.

Closed boundary

A boundary whose final segment returns to its starting point, so no gap remains.

moveTo(x, y)

Set the current point to one local position. Do not append a visible segment.

lineTo(x, y)

Append a straight segment from the current point to the supplied position. Then make the supplied position the new current point.

close()

Explicitly close the current connected run by joining its final point to its starting point.

6 · ANDROID CONNECTION

Build one Compose Path, then draw it

Complete source stays in Android Studio and the incremental Android ZIP.

1 · Local point values

Five dp coordinate pairs describe A, B, C, D, and E inside a fixed drawing surface.

2 · Convert dp to px

The Compose Path consumes Canvas-local px coordinates, so the code converts each dp value with the current density.

3 · Build commands

moveTo, four lineTo calls, and close create the complete command list.

4 · Teaching fill

The explorer reveals its fill only after close() so the stored open-versus-closed state remains visible. Compose can also fill an open connected run by treating it as closed during filling.

5 · Inspection stroke

A second drawPath call with Stroke follows the stored segments, so E → A appears only after close().

Short path-building excerpt

// PathsExplorer.kt · buildTagPath
Path().apply {
    moveTo(a.x, a.y)
    lineTo(b.x, b.y)
    lineTo(c.x, c.y)
    lineTo(d.x, d.y)
    lineTo(e.x, e.y)
    close()
}

When the Path is rebuilt: the visible command list is rebuilt when the selected sequence step, adjustable tip position, or display density changes. An unrelated redraw reuses the existing Path object and its command list.

9 · EXPLAIN THE RESULT

The endpoint of one command becomes the start of the next segment

Connected sequence

moveTo(A) lineTo(B) → segment A → B; current = B lineTo(C) → segment B → C; current = C lineTo(D) → segment C → D; current = D lineTo(E) → segment D → E; current = E close() → segment E → A

Why point C affects two segments

C is the endpoint of B → C and the starting point of C → D. Moving C therefore changes both connected segments while A, B, D, and E remain fixed.

C moves right B → C changes C → D changes A → B, D → E, E → A do not change
Path versus pixels: the Path stores geometric instructions. drawPath is the later drawing operation that turns those instructions into visible output inside the Canvas. A fill-style draw implicitly closes an open connected run for filling; a stroke-style draw follows the stored segments and therefore exposes the E → A gap until close() is present.

11 · EXERCISES

Answer before opening each hidden solution

Exercise 1 · Current point

The path executes moveTo(A), lineTo(B), and lineTo(C). What is the current point?

Show answer

C. Each lineTo makes its supplied endpoint the new current point.

Exercise 2 · Diagnostic: does moveTo draw?

Does moveTo(120, 90) create a visible segment from the Canvas origin to A?

Show answer

No. It sets the path's current point to A without appending a visible segment.

Exercise 3 · Missing segment

The path contains A → B → C → D → E but has not executed close(). Which exact segment is missing from the explicit boundary?

Show answer

E → A.

Exercise 4 · Shared endpoint

Only point C moves. Which segments change, and why?

Show answer

B → C and C → D change. C is the endpoint of the first segment and the starting point of the second segment. The other three segments do not use C.

13 · SOURCES AND EVIDENCE

What the Android documentation supports

  • Compose describes a path as a series of mathematical instructions and demonstrates building one with moveTo, lineTo, and close.
  • DrawScope.drawPath draws a Compose Path. When the draw style is Fill, Compose documents that open connected runs are implicitly closed for filling.
  • The Compose drawing coordinate origin is at the top-left of the drawing area; X grows rightward and Y grows downward.

Android Developers · Graphics in Compose · AndroidX Compose Path reference
