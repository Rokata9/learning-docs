Why does multiplying by 7 give every remainder exactly once?

We will not begin with abstract number theory. We will first follow real columns, watch the totals change, see what a duplicate would require, and only then give the compact rule.

The formula we are investigating
raw = ((column + 3) × 7+(row + 5) × 13) remainder 16

The claim concerns 16 consecutive integer columns while row stays fixed.

Four misunderstandings to avoid

“The raw totals must be 0 to 15.”No. The totals can be large. Only their remainders are restricted to 0 through 15.
“The outputs must appear in numerical order.”No. They appear in a shuffled order such as 12, 3, 10, 1, …, but every value still appears once.
“The row may change while the column changes.”Not in this claim. The row contribution must be the same shared constant for all 16 columns.
“One example is the proof.”An example helps us see the mechanism. The no-collision gap argument is what proves it for every starting column and fixed row.

Picture B · pattern, not a random roll

The remainder formula is a 16×16 tile, not a dice roll

The offset in Lesson 7.10 comes from a frozen arithmetic recipe on column and row. Remainder 16 means: divide by 16 and keep the leftover 0 through 15. That leftover is a remainder slot, not an 8-bit rounding bin. The same (column, row) always returns the same slot. Column 200, row 80 is always slot 14. Column 216, row 80 is also slot 14, because 216 is 16 columns later. That repeat is the tile. It is not a new value each frame.

raw = ((column + 3) × 7 + (row + 5) × 13) remainder 16 unit = raw / 15 ← never negative signed = 2 × unit − 1 ← this number carries the sign offset = signed × amount

The iOS call, with salt 0

Production luminance noise uses salt 0. That makes salt × 11 zero, so raw is the formula above. A fixed salt on one channel is another shared constant, like the frozen row. It chooses which leftover appears first. It does not change the +7 step.

private func unitNoise(column: Int, row: Int, salt: Int) -> Float { let raw = floorMod((column + 3) * 7 + (row + 5) * 13 + salt * 11, 16) return Float(raw) / 15 }

Why a darker navy stripe sits next to a lighter navy stripe

Amount is the number on the Lesson 7.10 slider. Here it is 0.02, the production value. Lesson 7.12’s dark destination is one navy after tint and saturation. If we add nothing, every interior pixel stores RGB (98, 109, 121).

There are 16 leftovers, so there are 16 stored navy triples. They only span stored red 93 through 103. That is a small change. On the glass, the next column does not use the next leftover. It jumps 7 leftovers. A high leftover (lighter navy) therefore sits next to a low leftover (darker navy). That pair repeats.
