Four misunderstandings to avoid

“The raw totals must be 0 to 15.”No. The totals can be large. Only their remainders are restricted to 0 through 15.
“The outputs must appear in numerical order.”No. They appear in a shuffled order such as 12, 3, 10, 1, …, but every value still appears once.
“The row may change while the column changes.”Not in this claim. The row contribution must be the same shared constant for all 16 columns.
“One example is the proof.”An example helps us see the mechanism. The no-collision gap argument is what proves it for every starting column and fixed row.

Picture B · pattern, not a random roll

The remainder formula is a 16×16 tile, not a dice roll

The offset in Lesson 7.10 comes from a frozen arithmetic recipe on column and row. Remainder 16 means: divide by 16 and keep the leftover 0 through 15. That leftover is a remainder slot, not an 8-bit rounding bin. The same (column, row) always returns the same slot. Column 200, row 80 is always slot 14. Column 216, row 80 is also slot 14, because 216 is 16 columns later. That repeat is the tile. It is not a new value each frame.

raw = ((column + 3) × 7 + (row + 5) × 13) remainder 16 unit = raw / 15 ← never negative signed = 2 × unit − 1 ← this number carries the sign offset = signed × amount
