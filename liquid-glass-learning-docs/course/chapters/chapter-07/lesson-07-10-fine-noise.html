Chapter 7 · Break stripes without dirty specks

Fine noise or dither

Question: Lesson 7.6’s navy half looks like one navy. The orange half looks like one orange. After blur, only the place those two fields meet is a short mix of slightly different pixels. When each channel is stored as an integer 0..255, that mix can turn into visible stripes. How do we break those stripes without covering the glass with colored specks?

Store means write each channel as an 8-bit integer 0..255 into the bitmap. The true 0..1 value is not what the screen keeps. Banding is a visible stripe of neighbors that all stored the same integer. Fine noise is a small signed offset added before that write. Dither is using that offset so neighbors can round to different integers and the eye averages the field.

1 · THE NEW OBJECTS

A stripe is a store collision. Noise is an offset.

Teaching ramp

Each column of this lesson’s panel has a normalized RGB that changes slowly from left to right, from (0.32, 0.40, 0.52) to (0.36, 0.44, 0.56). That card is a stand-in so the 8-bit staircase is wide enough to count. It is not the 7.6 navy/orange artwork redrawn, and it is not a new blur.

8-bit store

Store is the write: channel8 = round(normalized × 255) is placed in the bitmap. Lesson 3.1 taught that rounding. Many neighboring true values round to the same integer. That run is a stripe. The formula that picks the offset lives in the companion.

Signed offset

A number in −1 .. +1 taken from the pixel’s column and row with a fixed recipe. offset = signed × amount is added to the true channel, then the sum is stored. Amount 0 is no noise.

offset = signed × amount stored8 = round(clamp(true channel + offset) × 255)
Luminance noise, in this lesson, means the same signed offset is added to red, green, and blue. The speck only gets lighter or darker. Chroma noise, in this lesson, means a different signed offset is added to each channel. The speck changes color family. Production uses luminance noise at a small amount. The remainder recipe that produces signed is in the companion, not required to use the production rule.

4 · THE PRODUCTION RULE

After you have seen stripes and dirt

add one signed offset to red, green, and blue
then store each channel as an 8-bit integer
keep the amount small
do not give each channel its own offset

Inputs

Amount — the slider. Normalized channel units. Teaching default: 0.02. Android default: the same 0.02.

Column and row — integer pixel coordinates in the bitmap. They are not dp.

True channel — the teaching ramp at that column, still normalized 0..1.

Outputs, and who consumes them

Signed is consumed by the offset multiply.

Offset is consumed by the add, then by Lesson 3.1 rounding.

Stored 8-bit RGB is consumed by the panel bitmap. Rim, band, shadow, and label do not read it.

6 · NOT A PHOTOGRAPH

The recipe is arithmetic, not a grain scan

What “dirty” means

A large luminance amount makes strong light and dark specks. Those specks stay in the same color family because red, green, and blue still received one shared offset. That is gray grain on a navy field, not red and green dots.

Chroma noise at the same amount splits the three channels, so the specks change color family. That is the colored dirt.

What this noise is not

It is not a photograph of sand, a GPU program, or Apple’s private grain. The numbers 7, 13, 3, and 5 only feed the remainder table in the companion. They are not camera constants. The label is drawn later, so it is not stored through this write.

7 · ANDROID ROUTE

Write the stored integers into a bitmap, then draw it

val t = x / (width - 1).toFloat()
var red = lerp(leftRed, rightRed, t)
var green = lerp(leftGreen, rightGreen, t)
var blue = lerp(leftBlue, rightBlue, t)

val signed = unitNoise(x, y, salt = 0) * 2f - 1f
val offset = signed * amount
red += offset
green += offset
blue += offset

pixels[y * width + x] = android.graphics.Color.rgb(
    store8(red),
    store8(green),
    store8(blue),
)

What each part changes

unitNoise is the remainder recipe. Salt 0 is luminance noise. Chroma noise would pass a different salt per channel. Production does not.

store8 is Lesson 3.1 rounding. The bitmap then holds those integers. Canvas.drawImage shows the bitmap. Rim and label are later siblings, still sharp.

10 · EXERCISES

Answer before opening each hidden solution

What does store mean in this lesson?

Write each channel as an 8-bit integer from 0 through 255 into the bitmap: channel8 = round(clamp(normalized) × 255). The true 0..1 value is not kept as the displayed value.

Do the 7.6 navy and orange interiors change from pixel to pixel?

No. Deep inside navy, neighbors are navy, so the stored color stays navy. Deep inside orange, it stays orange. After blur, only the seam where the two fields meet is a short mix of slightly different pixels. This lesson’s card is a teaching ramp that stretches that slow-change idea so the 8-bit stripes are countable.

Why add the offset before store8, not after?

The store is what creates the stripe. Adding an offset to an already-stored integer cannot split a run of identical stored values into different integers unless you also re-store. The lesson adds, then rounds, so two neighbors can land on different integers.

Is the remainder formula random, and does it draw the stripes?

It is a frozen 16-by-16 tile. The same column and row always return the same slot. Amount 0 with no recipe still bands. The stripes come from 8-bit rounding bins on the teaching ramp. The companion draws both patterns side by side.

Established

Not claimed
