Chapter 7 · First real blur mechanism

Blur as neighborhood averaging

A sharp copy reads one source position. A blur output reads several nearby source positions and combines their colors.

This lesson advances the mechanism. It does not reteach source ownership, crop mapping, feedback prevention, or command-versus-buffer distinctions.

New causal route

one output position ← several nearby source positions ← one contribution from each → one mixed output color

The 3 × 3 arithmetic below is a deliberately transparent model. SwiftUI's real .blur() uses renderer-owned details that its public API does not expose.

2 · Exact objects

Name the five things before the arithmetic

No new formula is useful until its inputs and output are concrete.

Source image

The input grid of RGB color values. Each cell is one source pixel position in this teaching model.

Output position

The one destination pixel currently being calculated. It has integer grid coordinate (2, 2).

Neighborhood

The 3 × 3 block centered on the selected output position. It contains nine source positions.

Contribution

The amount one source color adds to the output. The teaching model gives every neighbor equal contribution 1 ÷ 9.

Output color

The one RGB value produced after the nine red, green, and blue channel contributions are combined.

Read the route literally

drawHardEdgeArtwork supplies the input drawing commands for this test image.

The Canvas view owns those commands.

.blur(radius:opaque:) asks SwiftUI to soften that view before it is composited. lessonBlur skips the modifier when the radius is 0.

.blur(radius:) takes one radius in points. SwiftUI blur is symmetric: there is no separate horizontal and vertical radius. blurRadiusPx is 12 × displayScale, a device-pixel readout. It is not the .blur() argument. On iPhone 16 Pro, displayScale is typically 3, so 12 pt covers 36 device pixels of screen size.

Fixed edge input: opaque: false lets the blur mix with transparent pixels at the view edge. SwiftUI .blur() does not expose a separate edge-treatment mode. Lesson 7.3 studies that question. This lesson keeps one 12 pt radius.
6 · Production meaning versus teaching model

Do not confuse the 3 × 3 box average with SwiftUI's private blur kernel

The public API exposes .blur(radius:opaque:) — one point radius and an opaque flag — not a nine-cell formula.

What the model proves

A blurred output position can depend on colors at neighboring source positions. A hard color edge therefore creates mixed output colors around that edge.

What the model does not prove

It does not expose SwiftUI's exact number of samples, sample coordinates, weights, passes, internal precision, color space, or GPU implementation. It also does not claim the same weights as any other blur implementation.

Official reference: View.blur(radius:opaque:). This lesson does not use system materials as the glass path.

9 · Explain it back

Check the causal idea

Open each answer only after speaking or writing your own explanation.

Why is the edge-preset output not equal to its amber center source cell?

The center source cell contributes only one of nine equal shares. Four blue cells and four additional amber cells also contribute. The final output is therefore RGB(133, 109, 65), not the center's RGB(225, 153, 45).

Why does a completely flat source region remain the same color in the teaching model?

Every source cell contains the same RGB value. Adding nine identical values and dividing by nine returns that same value for red, green, and blue.

What is lost when a small bright speck is averaged with eight dark neighbors?

The speck's color contributes only one share. The eight dark contributions pull the output toward the dark color, so the speck becomes dimmer and less locally distinct.

Why can we not claim SwiftUI literally executes the displayed nine-value arithmetic?

The public API does not specify SwiftUI's sample count, sample coordinates, weights, internal color representation, or rounding. The 3 × 3 average is a causal bridge, not a reverse-engineered implementation claim.
