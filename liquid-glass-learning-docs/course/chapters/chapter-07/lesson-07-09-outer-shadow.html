Chapter 7 · Separation that lives behind the card

Outer shadow

Question: The frosted card now has a quieted fill, a thin rim, and a soft inner band. Busy content can still touch that clipped edge. How do we put a darker, blurred copy of the panel shape behind the card so the card looks separate, without putting that copy inside the clip?

An outer shadow is a darker copy of the panel’s rounded rectangle, blurred, drawn earlier than the glass so the glass covers it. The shadow’s drawing target must be larger than the panel by at least the shadow blur radius. Otherwise the blur has no empty pixels in which to spread.
Lessons 7.7 and 7.8 placed the rim and the inner band. This lesson keeps their production objects as fixed siblings. It does not rebuild inset-stroke math or clip-after-blur. Lesson 3.4 already taught draw order. Lesson 7.1 already taught blur. The new operation is the extra empty margin around the dark shape, in a layer that sits behind the clipped card.

1 · THE NEW OBJECT

A shadow is a behind-layer, not a darker rim

Dark copy

A filled rounded rectangle the same size as the panel, painted black at a translucent alpha. It is not the glass fill. It does not sample the backdrop. Teaching alpha: 0.60. The iPhone 16 Pro explorer uses 0.45 so the halo does not crush the orange interior on a phone screen.

Room

Room means empty transparent pixels around that dark copy, on the same layer that will be blurred. Required room equals the shadow blur radius. If the layer is only as large as the panel, those empty pixels do not exist.

Behind

Lesson 3.4: earlier draws are covered by later draws. The shadow is drawn first. The clipped glass is drawn second. If the shadow is inside the panel clip, the surround can never show a halo.

required room = shadow blur radius shadow layer = panel rectangle plus room on every side draw the blurred dark copy first then draw the clipped glass on top

Browser versus iOS. This canvas uses CSS pixels. Teaching default blur is 16 CSS px. The iPhone 16 Pro explorer default is .blur(radius: 12) in points. This lesson draws the dark copy explicitly so the room requirement is visible. It does not claim to reproduce .shadow()’s private kernel or offset table. The CSS blur and .blur(radius:) are not the same kernel.
3 · CROSS-SECTION

Same-size layer versus extra room

One edge, looking from above. The yellow line is the panel path. Dark gray is shadow paint. The glass covers everything to the left of that line.

Case A · layer = panel sizeno outside pixels
Case B · layer has roomhalo on the surround

Blur can only write pixels that exist on its layer. A panel-sized layer has no pixel positions in the surround, so the halo cannot appear there.

Adding room creates those pixel positions before the blur runs. The glass, drawn later, covers the dark copy under the panel and leaves the surround halo visible.

4 · THE PRODUCTION RULE

After you have seen the missing halo

required room = shadow blur radius
shadow layer includes that room on every side
draw the blurred dark copy first
then draw the clipped glass

Inputs

Shadow blur — the slider. Teaching unit: CSS pixels. iOS unit: points passed to .blur(radius:). displayScale is not a blur input.

Offset down — fixed. Teaching: 8 CSS px. iOS: 4 pt. This is a convention that more of the halo sits below the card. It is not a simulated sun.

Stage pad — fixed, and chosen to be at least maximum blur plus offset so the halo is never clipped by the teaching stage.

Outputs, and who consumes them

Required room becomes the empty margin around the dark rounded rectangle on the shadow layer.

The blurred shadow image is consumed by the later glass draw, which covers the portion under the panel.

The surround keeps the leftover halo. That leftover is the visible separation.

5 · OFFSET IS A TRANSLATION

Why y adds the offset and height stays the glass height

The shadow rounded rectangle is the same size as the glass. It is moved down. It is not made shorter.

Stage number lineteaching canvas 320 CSS px tall

The current teaching numbers

stage height = 320 stage pad = 32 offset down = 8 glass top = 32 glass height = 320 − 2 × 32 = 256 glass bottom = 32 + 256 = 288 shadow top = 32 + 8 = 40 shadow height = 256 ← same as glass height shadow bottom = 40 + 256 = 296 room below the unblurred shadow = 320 − 296 = 24

On this teaching canvas, shadow top = stage pad + offset. That moves the whole shape down by 8 CSS px. The iPhone 16 Pro explorer uses y = stagePad + offsetY with offsetY = 4 pt.

height = size.height − 2 × stagePad keeps that shape as tall as the glass. If height were also reduced by the offset, the bottom would stay at 288 and there would be no extra halo below the card.

Room below the unblurred shadow is 24 CSS px, which is why stage pad is 32: it is at least max blur 24 plus offset 8.

6 · THE FOUR CORNER SQUARES

Those squares sit outside the rounded path

The shadow copies the panel’s rounded rectangle, not the panel’s sharp bounding box. The four leftover squares at the box corners were never filled with dark paint.

Bounding box versus rounded pathamber = outside the path

Call each amber square a corner pocket: the leftover of the sharp bounding box that the rounded corner cut away. Those pixels are surround, not glass.

The dark copy is rounded too. Dark paint starts on the arc, not in the pocket. Along a flat side the dark fill reaches the box edge, so a leaked blur can stain that side. The pockets stay the original navy or orange because no dark fill was there to blur.

A same-size layer has no extra pixels beyond that bounding box. SwiftUI .blur can still draw a fake side band outside the view. This lesson clips that teaching card with clipShape so the leak cannot pretend to be a halo. Production still uses a larger unclipped layer so blur can wrap the curve on purpose.

Those four squares are not a bug in the rounded path. They are the proof that the shadow is a rounded copy, not a dark rectangle.

9 · iOS ROUTE

Larger layer first, clipped glass second

let room = shadowBlur
ZStack {
    Canvas { context, size in
        let glassHeight = size.height - 2 * room
        context.fill(
            roundedRectPath(
                rect: CGRect(
                    x: room,
                    y: room + offsetY,
                    width: size.width - 2 * room,
                    height: glassHeight
                ),
                cornerRadius: artworkCorner
            ),
            with: .color(shadowColor)
        )
    }
    .compositingGroup()
    .blur(radius: shadowBlur, opaque: false)

    ZStack {
        glassGroup
        innerBand
        rim
        Text("Sharp label")
    }
    .padding(room)
    .clipShape(RoundedRectangle(cornerRadius: artworkCorner, style: .circular))
}

What each part changes

room is set equal to the shadow blur in points. That is the empty margin. The outer ZStack is larger than the glass by that margin on every side.

The shadow Canvas fills the larger stack. The dark rounded rectangle is inset by room, then shifted down by offsetY. Height stays the glass height, so the bottom moves down by the same offset. .blur(radius:opaque: false) then spreads into the empty margin, including around the rounded corners.

The glass stack uses padding(room) so it sits on top of the dark copy, then clipShape so frost, band, and rim stay inside the panel path.

SwiftUI .blur has no tile-mode argument. Edge treatment stays the Lesson 7.3 topic. displayScale is not a blur input. The new fact is the extra room, not a new wrap.

The explorer’s three cards share one 20 pt stage pad so the layout stays still while the slider moves. That pad is the maximum room: 16 pt blur plus the 4 pt offset. Required room for the current slider value is still the blur radius. 18 and 12 are points.

12 · EXERCISES

Answer before opening each hidden solution

What is an outer shadow in this lesson?

A darker copy of the panel’s rounded rectangle, blurred, drawn behind the clipped glass, on a layer that is larger than the panel by at least the shadow blur radius.

Why does a same-size layer fail to separate the card from busy content?

Blur can only write pixels that exist on its layer. A panel-sized layer has no pixel positions in the surround. The glass then covers that layer. The surround never receives a halo.

Why does the shadow’s y add offsetY while height stays size.height − 2 × stagePad?

That pair is a translation of the whole rounded rect down by the offset. Height matches the glass. Reducing height by the offset would keep the bottom aligned with the glass and would not put extra halo below the card.

Why are the four corner squares of the bounding box not filled with shadow paint?

They sit outside the rounded path. The dark copy is rounded too, so those leftover squares never started dark. A leaked blur along a flat side is not a production halo and does not fill those pockets. Production uses extra room so blur can wrap the curve.
