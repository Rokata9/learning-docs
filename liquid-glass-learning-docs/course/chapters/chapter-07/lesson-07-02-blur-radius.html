Chapter 7 · Blur

Blur radius

Change how far source colors can influence each output position. A small radius softens locally. A larger radius spreads information farther, widens transitions, and reduces small detail.

One new control

larger radius → farther source influence → broader color transition → less local detail

Radius is a distance parameter. It is not opacity, tint strength, or a promise about Android's private sample count.

5 · What radius changes

Three visible consequences come from the same cause

Radius changes spatial reach, not opacity.

Broader transition

More output positions around a hard edge can receive colors from both sides. The mixed-color band therefore becomes wider.

Smaller details spread

A small dot or thin line contributes to more surrounding output positions. Its color occupies a broader area but its local peak becomes less distinct.

Far regions can remain unchanged

If every source color inside the radius is identical, averaging still returns that same color. A nonzero radius does not guarantee a visible change at every position.

Important example: at teaching radius 1, the selected output still sees three amber cells, so it remains exactly amber. At radius 2, the window reaches one blue cell and the output finally changes.
6 · Android route

Expose dp, convert to pixels, feed both axes

TileMode.Clamp stays fixed so only radius changes.

// BlurRadiusExplorer.kt var blurRadiusDp by rememberSaveable { mutableFloatStateOf(12f) } val density = LocalDensity.current val blurRadiusPx = with(density) { blurRadiusDp.dp.toPx() } val blurEffect = remember(blurRadiusPx) { if (blurRadiusPx == 0f) { null } else { BlurEffect( renderEffect = null, radiusX = blurRadiusPx, radiusY = blurRadiusPx, edgeTreatment = TileMode.Clamp, ) } } Canvas( modifier = Modifier.graphicsLayer { renderEffect = blurEffect }, ) { drawTestArtwork() }

Exact data route

Slider value in dp → Density converts dp to px → radiusX receives px → radiusY receives the same px → BlurEffect processes the artwork layer

radiusX is the horizontal blur radius. radiusY is the vertical blur radius. The lesson gives both the same value so the blur does not favor one axis.

The Compose API documents the two axis radii and the edge-treatment parameter. It does not document the internal sample positions or weights.

9 · Explain it back

Check the causal idea

Answer before opening each explanation.

Why can radius 1 leave the selected output exactly amber?

The radius-1 model window contains indexes 4, 5, and 6. All three source cells are amber. Averaging identical colors returns the same amber color.

Why does radius 2 change that same output?

The window expands to indexes 3 through 7. Index 3 is blue, so the output now combines one blue cell with four amber cells. The result becomes RGB(184, 133, 54).

Why is blur radius not equivalent to opacity?

Opacity scales how strongly a completed color is composited. Blur radius changes which nearby source positions may influence an output. The operations consume different inputs and produce different spatial behavior.

Why does the Android code convert dp to px?

The lesson exposes a Compose logical size in dp, but BlurEffect accepts raw pixel radii. Density supplies the pixels-per-dp conversion used to produce radiusX and radiusY.

Why can we not say a 24 px Android radius reads exactly 49 samples?

The public API names a radius along each axis but does not specify a whole-pixel box window, a 2r + 1 sample count, sample coordinates, or weights. That formula belongs only to the transparent teaching model.
