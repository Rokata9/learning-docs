Ramp, stripe, rounding bin, and the remainder tile

Lesson 7.6’s glass is a navy field beside an orange field. Each field looks like one color. This page names the few pixels that do change after blur, then names the teaching ramp, the stored stripe, the rounding bin, and the remainder tile.

1 · THE 7.6 CARD IS TWO FLATS PLUS A SEAM

The navy half does not change from pixel to pixel. The orange half does not either.

Lesson 7.1 taught blur as neighborhood averaging. Deep inside navy, the neighbors are navy, so the stored color stays navy. Deep inside orange, the stored color stays orange. The slow change lives only where different colors sit next to each other: the vertical seam in the middle.

4 · WHAT A ROUNDING BIN IS FOR

A bin is the bucket of true values that all round to one integer.

Store means write each channel as an 8-bit integer 0..255 into the bitmap: stored8 = round(clamp(true channel) × 255). The bitmap does not keep the true fraction.

A rounding bin is the interval of true values that all produce one stored integer. For stored red 85, every true red whose true × 255 is closer to 85 than to 84 or 86 sits in that bin. The bin exists to explain the stripe: 63 neighboring columns in this ramp are not equal, but they all fall in the same bucket, so they all store 85.

stored k catches every true value in [(k − 0.5) / 255 , (k + 0.5) / 255) column 200 true red = 0.3325 0.3325 × 255 = 84.79 → round → 85 so column 200 sits in the 85 bucket with columns 182 through 244

Click a bucket. The columns that live in it light up on the ramp bar.

What the bin is

A range on the true-red number line. One stored integer owns that range.

What the bin is for

It is why a slow ramp becomes regular stripes. Neighbors collide on one integer.

What the bin is not

It is not the remainder recipe. Amount 0 with no recipe still fills these buckets.

5 · THE REMAINDER FORMULA IS A FROZEN TILE

It is a repeating pattern, not a random roll, and not the stripe generator.

The offset in Lesson 7.10 comes from a small arithmetic recipe on column and row. Remainder 16 means: divide by 16 and keep the leftover. The leftover is an integer 0 through 15. That leftover is the slot. Dividing the slot by 15 maps it to a unit in 0..1. Then signed = 2 × unit − 1 folds that unit onto −1..+1.

raw = ((column + 3) × 7 + (row + 5) × 13) remainder 16 unit = raw / 15 signed = 2 × unit − 1 offset = signed × amount

+3 and +5

They only shift the origin so column 0, row 0 is not forced into slot 0.

× 7 and × 13

A step right adds 7 to the slot, then wraps at 16. A step down adds 13. Neighbors jump to a distant slot, so the tile does not look like vertical bars.

7, 13, 3, 5

Mixing constants chosen so this 16-slot table is easy to compute by hand. They are not camera or film numbers.

The same (column, row) always returns the same slot. The map repeats every 16 columns and every 16 rows. That is a pattern. It is not a new random number each time the card is drawn.

16 consecutive columns hit 16 different remainder slots

That claim is true for this recipe. It is not true of every step. These remainder slots are leftovers 0..15. They are not the 8-bit rounding bins from section 4, and the grays in the walk below are not stored reds of the glass.

Proof that +7 wrapping at 16 cannot repeat before 16 steps

Wanted. The 16 leftovers at columns c, c+1, …, c+15 are 16 different numbers.

Setup. On one row, one step right adds 7, then wraps at 16. After k steps the leftover has moved by k × 7, wrapped at 16.

No collision in between. Suppose two of those 16 columns had the same leftover. Their separation k is an integer from 1 through 15. Then k × 7 wrapped to leftover 0, so k × 7 is a multiple of 16:

k × 7 = 16 × m for some integer m

Prime factors. 16 is 2 × 2 × 2 × 2. The left side is k × 7. 7 is not a 2, so those four 2s cannot come from the 7. They must all come from k. So k is a multiple of 16.

That k cannot exist. No integer from 1 through 15 is a multiple of 16. Contradiction. Therefore no two of the 16 columns share a leftover.

Count. 16 columns, 16 possible leftovers, none repeated, so each leftover appears once.

First return. At k = 16, 16 × 7 = 112 and 112 = 7 × 16 with leftover 0. The 17th column matches the first. That is the tile width.

Why +8 fails by the same test. k × 8 = 16 × m already holds at k = 2, because 2 × 8 = 16. Columns two apart collide. Only two leftovers appear.

Each column below is one separation k. Leftover 0 means “same slot as the start.” The first yes is the return.

This row encodes signed as gray from dark to light. It is not stored red. Gold is the selected column. Pink marks a negative signed value.

Those 16 grays are not 16 rounding bins

A rounding bin is a bucket of true channel values that all store one 8-bit integer. Column 200’s true red sits in bin 85. At amount 0, every neighbor in that stripe still stores 85.

If the offset were only about half a bin, 0.5 / 255 ≈ 0.002, then one true red that stores 84 could be pushed only to 83, 84, or 85. That is the tiny-nudge picture. Production amount is 0.02. The largest offset is 0.02, which is 0.02 × 255 ≈ 5.1 eight-bit steps, so stored red can move by about five integers either way, not only by one.

The black-to-white grays above are a display of signed in −1..+1. They are not those stored reds. The row below uses the same 16 columns, the same slots, and writes the actual stored red of this teaching ramp after the offset.

Same 16 columns. Each cell is stored 8-bit RGB of the teaching ramp plus signed × amount. The number is stored red.

Negative signed stays negative

unit = slot / 15 is never negative. It lives in 0..1. signed = 2 × unit − 1 folds that onto −1..+1. Slot 2 gives unit 2/15 and signed −11/15 = −0.733. The minus is real. The gray tile cannot store a negative byte, so it encodes signed as brightness: negative signed is darker, positive signed is lighter. That encoding is not abs(signed). The add still uses the minus: offset = −0.733 × amount lowers red, green, and blue.

Stripe pattern

Eleven vertical color bands on the amount-0 ramp. Cause: 8-bit rounding bins. Visible with no remainder recipe at all.

Grain pattern

A 16×16 gray tile from the remainder recipe. Cause: slot jumps of 7 and 13. Same pixel, same slot, every frame.

True random

A new independent roll at every pixel, every click. This lesson does not use that. Random grain would crawl from frame to frame.

Column 200, row 80 is always slot 14. Column 216, row 80 is also slot 14, because 216 is 16 columns later. That repeat is the proof that the formula is a tile, not a dice roll.
6 · ONE PIXEL AFTER THE OFFSET

Luminance noise versus chroma noise

Luminance noise, in this lesson: one signed offset is added to red, green, and blue. The speck only gets lighter or darker.

Chroma noise, in this lesson: a different signed offset is added to each channel. The speck changes color family.

0.12
A large luminance amount looks dirty as strong gray specks, still in the navy family. Chroma at the same amount looks dirty as colored specks. Production uses luminance noise at 0.02. Look at the three stored integers, not only the scaled card.
7.6 interiors are flat. The seam is the slow change. The 7.10 card is a teaching ramp, not that glass. The slope is the ramp. Each stored step is a stripe. A rounding bin is the bucket that makes a stripe. The remainder formula is a repeating 16×16 tile, not a random roll and not the stripe generator.
