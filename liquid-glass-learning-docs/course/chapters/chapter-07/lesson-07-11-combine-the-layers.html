Chapter 7 · One tree, not six separate demos

Combine the layers

Question: Lessons 7.7 through 7.10 each added one object: a thin rim, a soft inner band, a behind shadow, and a signed noise offset. Those objects still live in separate explorers. How do we put them in one tree so a later draw cannot undo an earlier one, and so the clip cannot throw away the shadow’s surround pixels?

A slot is the three-part assignment of one ingredient: whether it is a child of the panel clip, which layer owns its blur or color filter, and whether it is drawn before or after its siblings. Wrong clip membership discards pixels. Wrong sibling order covers pixels. Those two failures are independent.
This lesson does not rebuild blur, tint, saturation, inset-stroke math, band blur, shadow room, or the noise store formula. Lesson 3.4 already taught later-covers-earlier. Lesson 4.7 already taught clipping. Lesson 6.11 already kept the label outside the fill filter. The new operation is the slot assignment of every ingredient at once.

The clip is not a draw-order setting. Sibling order is not a clip. Each ingredient needs both answers, plus an owner for its own blur or filter.

1 · THE NEW OBJECT

A slot is three answers, not a new paint

Clip membership

Clip membership means: is this draw a child of clipShape on the panel’s rounded rectangle? Inside: pixels outside that path are discarded. Outside: surround pixels can survive. Lesson 4.7 taught the discard. This lesson asks it of every ingredient.

Effect owner

An effect owner is the view that carries this ingredient’s .blur(radius:) or colorEffect. The fill owns the 18 CSS px glass blur and the saturation filter. The band owns a separate 8 CSS px blur. The shadow owns a separate 16 CSS px blur. Rim, grain overlay, and label own none.

Sibling order

Sibling order is Lesson 3.4 among children of one parent: a later sibling covers an earlier sibling at the same pixel. Fill before grain before band before rim before label, all inside the clipped box. Shadow is a sibling of that whole clipped box, drawn first.

slot(ingredient) = (clip membership, effect owner, sibling order) wrong clip membership → pixels outside the path are discarded wrong sibling order → the later sibling covers the earlier sibling
The six ingredients are already known. This lesson does not invent a seventh paint. It assigns each known ingredient one slot.

Wrong clip · shadow insidemembership fault

The clip discards every shadow pixel outside the path. The surround stays busy. That is a missing halo, not a recolored halo.

Wrong order · rim before fillsibling-order fault

The rim is drawn, then the opaque fill covers it. The surround halo remains, because clip membership was still correct. The two faults do not look the same.

Browser versus iOS. This canvas uses CSS pixels. Glass blur is 18 CSS px, band blur is 8 CSS px, shadow blur is 16 CSS px, rim width is 4 CSS px. The iPhone 16 Pro explorer keeps the 7.6–7.10 point constants: glass .blur(radius: 18), band .blur(radius: 6), shadow .blur(radius: 12), rim width 3 pt. Those numbers are not interchangeable. displayScale × pt is a pixel readout. It is not a blur input. The grain overlay here applies Lesson 7.10’s signed offset to the fill pixels before store. The explorer occupies the same slot with a later low-alpha gray bitmap because the live blurred fill is not a CPU bitmap. Chapter 8 will put the exact per-pixel add on the GPU. Do not use ultraThinMaterial or glassEffect.

4 · TWO PIXELS

One surround pixel and one edge pixel

Surround pixel · 8 CSS px right of the path

This pixel is outside the panel path, on the orange surround. Only a draw whose clip membership is outside can paint it. The shadow is that draw. The fill cannot reach it.

Edge pixel · 2 CSS px inside the right path

This pixel is inside the clip, 2 CSS px inside the right path, on the rim band. Fill, band, and rim can all write it. Sibling order decides the survivor. Production lets the unblurred rim win. Rim-before-fill lets the opaque fill win.

7 · iOS ROUTE

Unclipped stage, then a clipped inner stack

ZStack { // stage, no clip
    ShadowLayer() // padded, own .blur(radius: 12), drawn first
    ZStack {
        FillGroup()      // .blur(radius: 18), tint 0.25, saturation 0.40
        GrainOverlay()   // occupies the slot after fill
        InnerBand()      // own .blur(radius: 6), then parent clip
        StaticRim()      // unblurred inset stroke
        Text("Sharp label") // outside FillGroup's colorEffect
    }
    .clipShape(panelShape)
}

What each part changes

The outer ZStack has no clip, so the shadow’s extra room can exist.

clipShape(panelShape) is attached to the inner stack only. That is clip membership for fill, grain, band, rim, and label.

Text("Sharp label") is a later sibling of FillGroup, not a child of the fill’s colorEffect. Letters stay sharp.

18, 12, and 6 are points. displayScale is not a blur input. SwiftUI .blur has no tile-mode argument. Edge treatment stays the Lesson 7.3 topic.

10 · EXERCISES

Answer before opening each hidden solution

What three facts make up a slot?

Clip membership (inside or outside the panel path), effect owner (which view carries this ingredient’s .blur(radius:) or colorEffect, or none), and sibling order (whether this draw is before or after its siblings under the same parent).

Diagnostic: the surround has no halo, but the thin rim is still visible. Which axis failed?

Clip membership of the shadow. The rim is a later sibling inside the clip, so sibling order for the edge is still correct. A missing halo with a surviving rim is the shadow-inside-clip fault, not the rim-before-fill fault.

Why is the label allowed inside the clip but not inside the fill’s colorEffect?

The clip only discards pixels outside the rounded rectangle, which keeps letters inside the card. The fill’s colorEffect carries blur and saturation. A child of that group would be blurred and desaturated. Those are two different owners.

How is this different from Lesson 7.12?

This lesson only assigns slots. The fill recipe and the destination artwork stay fixed. Lesson 7.12 freezes this tree and changes the kind of pixels behind the glass, then measures label contrast.

12 · EVIDENCE BOUNDARY

What this lesson establishes

Established

Each glass ingredient occupies one slot: clip membership, effect owner, and sibling order. Putting the shadow inside the clip discards the halo. Drawing the rim before the fill covers the rim. Those two faults are independent.

Not claimed

This tree is not a lighting model, a signed-distance glow, a custom shader, or Apple’s private material. The explorer’s gray bitmap occupies the noise slot. It is not a second derivation of Lesson 7.10’s store formula. Lesson 7.12 will change only the destination class behind this frozen tree.
