Lesson 9.10 · Build a displacement field

Why does navy reach above this square?

The checkerboard from Lesson 9.9 gives us an input image with square orange and navy cells.

We will follow the navy input cell just above and to the right of the picture’s center. After the shader runs, navy also appears above that cell’s original top edge. The edge curves. The whole pattern can look like a raised surface.

Start with your position: x is 0.65. I chose y = 0.20 for “slightly above.” The two pictures show this fixed example with dispLen = 0.10.

The output pixel stays at W. It reads the input color at R, a short distance toward the center, and copies that color. R is inside the navy cell. That is why W becomes navy.

1 · Follow the actual calculation

Build the read coordinate, one operation at a time.

Both images use the same UV coordinates from Lesson 8.6: x is a fraction of the image width; y is a fraction of its height. Zero is at the top-left. x increases rightward. y increases downward. The picture is square, so the same fraction has the same physical length in both directions.

The exact input cell

0.50 ≤ x < 0.75
0.25 ≤ y < 0.50

This is also written [0.50, 0.75) and [0.25, 0.50). Include the first endpoint; exclude the second. The cell is one quarter of the image wide and tall.

The current output position

This position is named W. Its UV pair is uv in the shader. We keep W fixed while calculating which input color to store there.

The chosen read distance

dispLen is the straight-line distance from W to the input read position. The default is one tenth of the full square’s width. It is chosen by the slider, not calculated from the cell.

The picture center is C, at (0.50, 0.50). First find the direction from C to W. Then give that direction the chosen length. Finally subtract the resulting pair from W to read toward C. The walkthrough explains the signs and each arithmetic operation before using them.

All live diagrams below share the chosen position and distance. Displayed calculated decimals are rounded; calculations keep full precision.

2 · What does dispLen change?

A longer read can reach across the cell boundary.

At the fixed example W = (0.65, 0.20), the input is orange at W. The navy cell starts at y = 0.25, below W. A small read distance stops before that edge. A large enough read reaches the navy cell. The read also moves left because the center is left of W.

The pixel’s original input color and its new output color are two different questions. The shader uses the color at R, even when the input at W is another color.

Exactly when does your default position first become navy?

The vertical part of the length-one direction has magnitude 0.894427…, calculated in step 3. A magnitude is the size without the direction’s minus sign. The read needs to go down 0.05, from y = 0.20 to y = 0.25. Divide that required downward distance by the downward part produced by one unit of read distance:

first-entry distance = required downward change / downward part per unit = (0.25 − 0.20) / 0.894427… ≈ 0.055902

At that distance, read x is 0.625, still inside the cell’s horizontal bounds. So this really is entry through the top edge. At the default 0.10, the read is already farther inside the cell. This threshold belongs to this exact W; another output position has another direction and another threshold.

3 · The apparent extra triangle

See every added position, then inspect one vertical slice.

The green region below has one precise meaning: output positions outside the original navy square whose read is inside that navy input cell. We calculate the read for every position before coloring the region. That is the same membership test used for W.

Your “extra triangle” is a useful first impression of the narrow added part near an edge. The exact added patch has curved boundaries. It also extends above and to the right of the old square. A single straight triangle cannot describe all those positions.

Each output position runs its own read. There is no code that draws an extra triangle or fills a gap after moving a square. Several neighboring output positions can read different positions inside the same navy cell. All of them receive navy.

4 · Where the curved edge comes from

One side contains many points. Their horizontal and vertical changes differ.

Now follow an input boundary point to an output position that reads it. Start at C. Draw a straight line through the input point and continue it: this is a ray. Move outward by the chosen distance along that ray. From that new position, the shader’s inward read returns to the original input point.

This construction describes output positions farther from C than dispLen. There the inward read stops before C. Section 6 shows what happens when a read passes C. Boundary dots here describe the geometric dividing line; the checker’s include/exclude rule decides the color exactly on that line.

Why the diagonal change is about 0.07071

At the top-right input corner, the horizontal and upward distances from C are both 0.25. The ray is diagonal. Its outward change therefore has equal horizontal and vertical parts.

At the default length 0.10, each part is about 0.07071. These parts are the two short sides of a right triangle. The 0.10 walk is its long side. From Lesson 9.1: 0.07071² + 0.07071² ≈ 0.10². Here ² means multiply a number by itself. Giving each short side 0.05 would produce a long side of only about 0.07071.

Which sides stay straight?

The original cell’s left boundary is x = 0.50, the vertical line through C. Moving a point along that line keeps x = 0.50. The bottom boundary is y = 0.50; its outward points keep that y.

The top and right boundaries miss C. Their points have different directions, so their horizontal or vertical changes differ. The actual outline includes curves. Rotating a square would keep four straight sides and the same side lengths.

5 · Size and the impression of depth

0.10 is a distance. It is not “make this cell 10% bigger.”

On a teaching picture 400 pixels wide, the default walk is 40 pixels long. An original cell is 100 pixels wide. So the walk is 10% of the image width and 40% of an original cell width. Neither percentage says how much the cell’s width or area increases.

The cell gets a larger visible footprint because output positions beyond its old top and right edges now read inside it. The lab’s Your example and To the right of the cell presets show one position on each side. The top and right boundaries do not all move by the same x or y change.

For any chosen direction, doubling dispLen doubles both parts of the read displacement. The cell boundary changes accordingly. At zero, the read coordinate equals the output coordinate, so the original checker returns.

A fixed extra distance differs from scale

Consider two input points on one ray. Their distances from C are 0.25 and 0.40. With the default outward construction, their output distances are 0.35 and 0.50.

first output distance = input distance + dispLen = 0.25 + 0.10 = 0.35 second output distance = 0.40 + 0.10 = 0.50 separation before = 0.40 − 0.25 = 0.15 separation after = 0.50 − 0.35 = 0.15

Along this ray, that separation stays the same. A scale of 2 from Lesson 9.9 would double it. Growth here comes from the different directions of neighboring rays, which the curved-edge picture shows.

What creates the “3D” appearance?

Visible observation: the straight checker boundaries become curves around C. The center-side cells occupy more of the picture. This pattern can resemble a checkerboard seen through a raised drop of glass.

What the code establishes: the shader calculates a new two-number read coordinate for each output position. It then copies orange or navy. The drawing surface remains flat. There is no height value, raised geometry, or lighting calculation in this shader.

The visual impression comes from the arrangement of the colored output pixels. Lesson 9.11 will use displaced reads for refraction, where a transparent material changes the apparent location of the background.

6 · The small region around C

If the read distance exceeds the distance to C, the read passes C.

This matters because our navy cell touches the center. At the default distance, some output positions near C read the opposite navy cell. Equal color does not prove that two positions read the same input cell.

The white circle marks output positions exactly dispLen from C. Outside it, the read stops on the same side of C. Inside it, the read passes C, except for the tiny guard described below.

At C, the distance is zero. Dividing by zero cannot produce a direction. The shader keeps displacement at zero whenever d ≤ 0.0001. This is a tiny circular neighborhood in UV units. At a 400-pixel width its radius is 0.04 pixels. Those positions read themselves.

7 · The code uses the same objects

The shader builds a displacement field.

A displacement is a coordinate-change pair: one horizontal change and one vertical change. A displacement field supplies such a pair at every output position. Here the direction depends on the position, while the pair’s length is the chosen dispLen outside the center guard.

This is the current DisplaceAgsl from DisplacementFieldExplorer.kt. The walkthrough calls the intermediate result p / d by the name dir. The actual shader writes it directly inside the multiplication.

uniform shader background;
uniform float2 resolution;
uniform float dispLen;

half4 main(float2 fragCoord) {
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float d = length(p);
    float2 disp = float2(0.0, 0.0);
    if (d > 0.0001) {
        disp = (p / d) * dispLen;
    }
    float2 readUv = uv - disp;
    return background.eval(readUv * resolution);
}

From a draw to one output color

Kotlin supplies the checker as background, the square’s pixel dimensions as resolution, and the slider value as dispLen. A draw of the rectangle runs the shader at its output positions.

fragCoord identifies the current position in the rectangle’s local pixel coordinates. Dividing by resolution produces its UV pair. At the end, multiplying the read UV by resolution converts the read back to the pixel coordinates that the input shader receives.

background.eval(...) evaluates the checker at that exact read coordinate. It returns a color. return makes that the color at the original output position.

The checker is a formula, not a stored bitmap being filtered. It returns one of two opaque colors; neighboring output positions can return the same color.

Refresher: why the input shader returns navy at the read

There are four columns and four rows across the displayed square. Multiplying a UV coordinate by 4 expresses it in cell widths. floor takes the integer at or below that number. This gives a column or row index, counted from zero.

float col = floor(uv.x * 4.0);
float row = floor(uv.y * 4.0);
if (fract((col + row) * 0.5) < 0.5) {
    return orange;
}
return navy;
Worked example read ≈ (0.60528, 0.28944) col = floor(read.x × 4) = floor(2.42111…) = 2 row = floor(read.y × 4) = floor(1.15777…) = 1 half the index sum = (col + row) × 0.5 = 1.5 fract(1.5) = 1.5 − floor(1.5) = 0.5 0.5 < 0.5 is false → return navy

fract, from Lesson 8.10, keeps the amount after subtracting floor. The multiplication by 0.5 divides the index sum by 2. Even sums produce zero after fract; odd sums produce 0.5. This alternates the two colors.

Navy is half4(0.10, 0.25, 0.40, 1.0). Orange is half4(0.88, 0.48, 0.18, 1.0). These RGBA fields are red, green, blue, and alpha. Alpha is 1 for both colors, so straight and premultiplied RGB agree. The browser shows their rounded 8-bit sRGB chips.

Browser and Android

The browser runs this arithmetic in JavaScript and draws the results on a canvas. It does not compile AGSL. You may inspect any mathematical UV position without snapping the read to an integer pixel.

The browser paints its image at pixel-center coordinates. The sliders also allow the exact geometric edges, 0 and 1; those endpoints are not the centers of the first and last pixels. Android evaluates the shader at its actual draw positions, using its shader precision and display color handling. A 400-pixel square is a teaching size. The Android explorer uses 360 dp, converted to actual pixels by the device density.

AGSL uses the drawing’s local coordinates and follows Canvas’s downward y direction. Android’s coordinate documentation describes that contract. The AGSL reference documents the arithmetic functions.

Small coding challenge: preserve the chosen length and read inward.

Fill in the two operators. Assume the existing d > 0.0001 guard has passed.

float2 dir = pd;disp = dir * dispLen;readUv = uvdisp;
The first operation gives the direction a length of one. The second makes the read go toward C.
Why replacing the formula with p changes the effect

p is the whole center-to-output vector. If disp = p, then readUv = uv − (uv − C) = C. Every output position reads the center.

If instead disp = p × dispLen, then readUv = C + p × (1 − dispLen). At 0.10, read distances are 90% of output distances. This is uniform scaling, so straight sides remain straight. It does not produce the same curved boundary.

Multiplying by distance again, p × d × dispLen, varies the displacement differently still. It is neither the chosen-length field nor a uniform scale.

Final exercises

1. At W = (0.65, 0.20), why is “the position is above the navy square” insufficient to predict its output color?

The output is chosen at the read coordinate. With distance 0.10, readUv = uv − disp ≈ (0.65, 0.20) − (0.04472, −0.08944) ≈ (0.60528, 0.28944). The read satisfies both bounds of the navy cell. W therefore receives navy even though the input at W is orange.

2. Does dispLen = 0.10 add 0.10 to both the cell’s width and height, or enlarge each by 10%?

Neither description states what the shader does. It chooses a read distance of 0.10 in image-width units. Different directions split that length into different horizontal and vertical parts. At the default top-left boundary point, the outward vertical change is −0.10. At the top-right corner it is about −0.07071. The edges therefore change unevenly.

3. Why is joining only the transformed top corners with a straight line insufficient?

The boundary includes every point between the corners. For the top midpoint (0.625, 0.25), the actual output is approximately (0.66972, 0.16056) at distance 0.10. A straight join between the transformed corners misses that point. The complete top edge curves. Use the comparison button in section 4 to see the difference.

4. At W = (0.54, 0.46) and distance 0.10, must the read stay above and right of C?

No. d = length(0.04, −0.04) ≈ 0.05657, smaller than the chosen 0.10. The read passes C and reaches approximately (0.46929, 0.53071), inside the navy input cell below and left of C. That cell has the same color as our chosen cell, but different bounds.
