Chapter 9 · A two-number arrow at each pixel

Build a displacement field

Question: Lesson 9.7’s eval copies the input color at a read coordinate. Lesson 8.8’s p points from the visual center C to this pixel. Lesson 9.1’s length(p) is how far that is. How do you build a two-number arrow at this pixel that says which neighbor to read, with the same arrow length at every pixel except C?

A displacement is a float2 named disp: how far to move the read in UV. A unit pair is p divided by its length, so the straight-line length becomes 1. Then disp = dir × dispLen. Subtract that arrow from UV before eval. dispLen is a UV length, not Lesson 7.10’s grain slider.

Canonical wording: displacement, unit pair, eval.

1 · THE NEW QUESTION

Each pixel owns its own two-number arrow.

Leftovers

eval still wants pixels. p = uv − 0.5 still numbers this pixel from C. length(p) is Lesson 9.1’s straight-line length. The input is a 4 × 4 orange/navy checker so both members of the arrow are visible. Column index = floor(uv.x × 4). Orange when that column index plus the row index is even. It is a teaching stand-in for Lesson 9.7’s stripes, not a claim that the stripe program changed.

Unit pair dir

dir = p / length(p) points the same way as p, and its straight-line length is 1. At T that pair is (0.60, −0.80) because the legs 0.30 and 0.40 scaled by 2 are 0.60 and 0.80, and 0.60² + 0.80² = 1. You cannot divide at C, where the length is 0. There is no direction away from C. disp stays (0, 0) there.

disp and dispLen

dispLen is how long the arrow is, in the same 0..1 family as UV. Default 0.10. disp = dir × dispLen. Then readUv = uv − disp. Subtracting an outward arrow reads toward C, so the picture appears pushed outward. That is the same opposite-direction rule as Lesson 9.8’s subtract, now with a different arrow at every pixel.

d = length(p) dir = p / d disp = dir × dispLen readUv = uv − disp sampled = background.eval(readUv × resolution)
Teaching write T p = (0.30, −0.40) d = length(p) = 0.50 dir = p / d = (0.30, −0.40) / 0.50 = (0.60, −0.80) disp = dir × dispLen = (0.60, −0.80) × 0.10 = (0.06, −0.08) uv = (0.80, 0.10) readUv = uv − disp = (0.80, 0.10) − (0.06, −0.08) = (0.74, 0.18) T’s input cell is navy. 2 · EQUAL LENGTH IS THE NEW PICTURE

Far pixels do not get a longer arrow.

One shared scale would make the implied offset grow with distance from C: a pixel twice as far would read from twice as far away. This field does not do that. Every pixel except C reads a neighbor exactly dispLen away, along the ray from C through this pixel. The lab’s arrows from the write pixel to the read pixel are all the same length. That is how you see it is not a zoom.

Pixels closer than dispLen

If length(p) is smaller than dispLen, subtracting the arrow walks past C to the opposite side. The lab draws a circle of radius dispLen around C so that disk is visible. Teaching T has length 0.50, which is larger than 0.10, so T does not sit in that disk.

What Lesson 9.11 will consume

The unit pair is the direction a later glass boundary will reuse. This lesson does not use signed distance, a radius, or a stronger push near an edge. Those are Lesson 9.11. Edge reads past the rectangle are Lesson 9.12.

5 · ANDROID ROUTE
One new uniform: dispLen. Skip the divide at C.

    

      
private const val DefaultDispLen = 0.10f
private const val TeachU = 0.80f
private const val TeachV = 0.10f

uniform shader background;
uniform float2 resolution;
uniform float dispLen;

half4 main(float2 fragCoord) {
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float d = length(p);
    float2 disp = float2(0.0, 0.0);
    if (d > 0.0001) {
        // 0.0001 UV is 0.04 px on a 400 px square, so only C skips.
        disp = (p / d) * dispLen;
    }
    float2 readUv = uv - disp;
    return background.eval(readUv * resolution);
}

      

        
What each part changes

        
dispLen is a UV length, so a 360 dp panel and a 400 px HTML square push by the same fraction of the width.

        
p / d is the unit pair. AGSL also names that normalize(p). This file writes the divide so the teaching formula stays visible.

        
The if (d > 0.0001) skips the divide at C. 0.0001 is one ten-thousandth of the width. On 400 px that is 0.04 px, so only the visual-center pixel hits the skip.

        
The slider writes dispLen. Default 0.10 so T stores orange on first draw.

8 · EXERCISES
Answer before opening each hidden solution

    

      At dispLen = 0, what is disp at T, and what color does T store?
      
disp = dir × 0 = (0, 0). readUv = uv. Identity. T’s input cell is navy, so T stores navy. C also copies itself, same as every other pixel.

    

    

      Diagnostic: someone uses Lesson 9.9’s readUv = p / scale + 0.5 with scale = 2 and says that is a displacement field. What did they get wrong?
      
Scale is one shared number. The implied offset is p − p / scale, which grows as you leave C. A displacement field is a float2 at each pixel. This lesson’s teaching field has the same length 0.10 at T and at a neighbor closer to C. The picture of equal-length arrows is the proof. Scale’s arrows would get longer farther out.

      
    

    

      At C, why is dir not (0.60, −0.80), and what is stored?
      
p = (0, 0) and d = length(p) = 0. There is no direction away from C. The program keeps disp = (0, 0) and does not divide. readUv = uv, so C still copies C. The pair (0.60, −0.80) belongs to T, where the 3-4-5 legs exist.

      
    

    

      If you add disp instead of subtracting, with dispLen = 0.10 at T, what is readUv, and which way does the picture appear to move?
      
readUv = uv + disp = (0.80, 0.10) + (0.06, −0.08) = (0.86, 0.02). Adding an outward arrow reads farther from C. The color from farther out is painted here, so the picture appears pushed inward, opposite the usual subtract. T’s store color then depends on the cell at (0.86, 0.02), not on (0.74, 0.18).
