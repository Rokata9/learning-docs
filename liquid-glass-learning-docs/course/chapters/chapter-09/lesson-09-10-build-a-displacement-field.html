Chapter 9 · A chosen walk toward C, at every pixel

Build a displacement field

1 · THE WRITE PIXEL DOES NOT MOVE

W still stores here. The bump is a copied neighbor.

Lesson 9.8 already split two jobs. The write location is this pixel: it stores the returned half4. The read coordinate is the pair passed to eval: the input color we copy. Those can be different pixels. The write pixel does not slide onto the read pixel. The input picture does not move. The draw rectangle stays a flat square.

The “3D” you see is only this: a pixel far from C stores the color of a pixel closer to C. Inner colors now appear farther out. A brain reads that radial expansion as a drop of water or a bump. There is no height map in this shader. Lesson 10.1 is the first height-map idea. Lesson 9.11 is the first glass-boundary push.

Lesson 9.8 leftover

One shared offset at every pixel. The whole picture slides, including C. Straight stripes stay straight.

Lesson 9.9 leftover

Every walk from C is shortened by the same factor. The middle looks uniformly larger. That is zoom, not a bump.

This lesson

Every pixel except C walks the same UV length toward C, along its own ray. Rings expand by adding that length. Straight grid lines bow. That is the bump.

2 · ONE RAY, NO DIAGONAL YET

A pixel due right of C only has to read left.

Do not start with a diagonal pixel. Start on the horizontal line through C, at UV y = 0.50. A write H at uv.x = 0.80 sits 0.30 right of C. The direction toward C is simply left. We choose a walk of one tenth of the square: dispLen = 0.10.

H is due right of C, so the ask is purely horizontal uv.x = 0.80 readUv.x = 0.80 − 0.10 = 0.70 readUv.y stays 0.50

H’s input cell is navy (column 3 starts at 0.75). R at 0.70 sits in column 2, orange. H stores orange. The orange that lived at 0.70 now sits at 0.80, farther from C. That is the bulge on one ray.

Why 0.10, not a random length. It is one tenth of the square, so the walk is visible. H sits 0.05 into the last column (that column starts at 0.75). A left walk of 0.10 is enough to leave that navy cell, so the copy is a different color you can see. dispLen is a UV length, not Lesson 7.10’s grain slider.

Move the walk length. The strip is the horizontal line through C. Green ticks are the reads. Amber is H. The lower band is the store along that same line.

Live ray through C
Lesson 9.8’s subtract, now on a ray. Subtracting a rightward walk reads left. The picture appears to move right, opposite the read. Here “right” is “away from C.” So the picture appears pushed out. Adding instead of subtracting would read farther out and pinch the picture in. That counterexample is an exercise.
3 · WHY THE DIVIDE EXISTS

Most pixels are not due right of C. We still want a walk of 0.10.

The horizontal pixel was easy because “toward C” was just left. A pixel off that line has a diagonal leftover walk p. Lesson 9.1 already measured one: teaching write T at uv = (0.80, 0.10) has p = (0.30, −0.40) and length 0.50. That 0.50 is how far T sits from C. It is not the walk we want for the read.

We still want a walk of length 0.10, same direction as p. Using p itself as the arrow would walk 0.50, five times too far, and a farther pixel would walk even more. That growing walk is Lesson 9.9’s zoom. This lesson’s walk must stay 0.10 at a near pixel and at a far pixel.

Recipe: first make a same-direction stick of length 1, then take 0.10 of it. T’s leftover stick is 0.50 long. A stick of 0.50 becomes a stick of 1.00 when you double it. Doubling is divide by 0.50. That is why AGSL writes p / length(p).

dir = p / length(p) = (0.30, −0.40) / 0.50 = (0.60, −0.80) same direction as p, length 1 divide by 0.50 is the doubling
same arithmetic, fraction of the leftover walk disp = p × (dispLen / d) = (0.30, −0.40) × (0.10 / 0.50) = (0.30, −0.40) × 0.20 = (0.06, −0.08)

AGSL writes the first spelling, (p / d) × dispLen, because Lesson 9.11 will reuse the length-1 direction at a glass boundary. Both spellings are the same multiply. You cannot divide at C, where the length is 0. There is no direction away from C. The program keeps disp = (0, 0) there, so C still copies C.

Wrong: use p as the arrow

A pixel twice as far from C would read from twice as far away. That is scale’s implied offset. Far arrows would be longer. The picture would zoom, not bulge.

Right: same length, own direction

Near pixel and far pixel both walk 0.10 toward C. The divide stripped the leftover length so the × 0.10 could put a length we chose back on.

4 · WHY SUBTRACT, THEN EVAL

Outward leftover, inward ask. eval still wants pixels.

p points from C to this write pixel: outward. disp points the same way. Subtracting that outward pair from UV walks toward C. That is the horizontal-ray fact from section 2, now on the leftover diagonal.

T stays at uv = (0.80, 0.10) disp = (0.06, −0.08) readUv = uv − disp = (0.80 − 0.06, 0.10 − (−0.08)) = (0.74, 0.18)

0.74 is left of 0.80. 0.18 is below 0.10. Both members moved toward C at (0.50, 0.50). T’s navy cell starts at x = 0.75, so 0.74 has already crossed into the next cell, orange. T stores orange. T did not change seats.

5 · WHY THE FLAT SQUARE LOOKS 3D

Rings expand by adding. Scale multiplies. Straight lines bow.

Take a ring of input pixels at some distance from C, say 0.25. Every pixel on that ring walks 0.10 toward C to read, so the color of that ring is stored on the ring at 0.25 + 0.10 = 0.35. A ring expands by adding dispLen. Lesson 9.9’s scale 2 would store that same ring at 0.25 × 2 = 0.50. Scale multiplies radius. That is why zoom and a bump are different pictures.

Center looks thick

A pixel closer to C than dispLen walks past C to the opposite side. The lab’s dashed circle is that disk. Strong warp in the middle is why the bump looks thicker there.

Straight lines bow

A vertical grid line is many pixels, each with a different leftover p. Each ask has a different second member. The copied colors come from a curve, so the stored edge looks bent. That bend is the “lens” look. No glass yet.

What 9.11 will change

This field uses the same walk length everywhere. A later glass will reuse the length-1 direction and make the walk stronger near the boundary, so background lines bend there instead of across the whole square.

7 · ANDROID ROUTE
Each AGSL line is one picture from this lesson.

    

      
private const val DefaultDispLen = 0.10f
private const val TeachU = 0.80f
private const val TeachV = 0.10f

uniform shader background;
uniform float2 resolution;
uniform float dispLen;

half4 main(float2 fragCoord) {
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float d = length(p);
    float2 disp = float2(0.0, 0.0);
    if (d > 0.0001) {
        // 0.0001 UV is 0.04 px on a 400 px square, so only C skips.
        disp = (p / d) * dispLen;
    }
    float2 readUv = uv - disp;
    return background.eval(readUv * resolution);
}

10 · EXERCISES
Answer before opening each hidden solution

    

      H sits at uv = (0.80, 0.50) with dispLen = 0.10. What is readUv, and why does the picture look pushed out rather than slid the way Lesson 9.8 slid?
      
readUv = (0.70, 0.50). H stores the orange that lived at 0.70, so that orange now sits farther from C. Lesson 9.8 used the same subtract at every pixel, including C, so the whole picture translated. Here the walk is along each pixel’s own ray toward C, and C copies C. The picture bulges instead of sliding.

    

    

      T’s leftover p has length 0.50. Why does the shader divide by that 0.50 instead of using p as the arrow?
      
p is how far T is from C, not the walk we want. Using p would walk 0.50, and a farther pixel would walk more than that — Lesson 9.9’s growing offset. Divide by 0.50 doubles the leftover 3-4-5 into a length-1 stick (0.60, −0.80). Times 0.10 then puts the chosen walk on it. Near and far pixels both walk 0.10.

      
    

    

      Why does this look like a bump instead of Lesson 9.9’s zoom?
      
This field adds a constant UV length along each ray: an input ring at 0.25 is stored at 0.35 when dispLen is 0.10. Scale 2 multiplies radius: that same ring would be stored at 0.50. Equal-length arrows versus growing arrows are the picture of that difference. Near C, 0.10 can be larger than the leftover walk, so those pixels read past C. That middle fold is part of the drop look. The square is still flat.

    

    

      If you add disp instead of subtracting, at H = (0.80, 0.50) with dispLen = 0.10, what is readUv, and which way does the picture appear to move?
      
readUv = (0.90, 0.50). Adding an outward walk reads farther from C. The color from farther out is painted here, so the picture appears pinched inward, opposite the usual subtract. H then stores whatever cell lives at 0.90, not the orange at 0.70.
