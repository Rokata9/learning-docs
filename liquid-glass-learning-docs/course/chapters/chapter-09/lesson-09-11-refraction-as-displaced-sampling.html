Lesson 9.11 · Refraction as displaced sampling

Why does this wallpaper line stay straight until it meets the glass?

Lesson 9.10’s checkerboard is still the wallpaper. Every output pixel stays put and copies a color from a neighbor toward the picture center C.

Lesson 9.10 is generated and is not complete. This lesson uses its extra walk anyway, and adds one new multiply. Lesson 9.10 walks every pixel the same length. The whole wallpaper bows. A glass panel should leave wallpaper straight except where the glass sits.

The glass is Lesson 9.2’s circle, default radius 0.25. The pink line is the straight wallpaper join x = 0.65. We will follow the pixel where that line meets the circle.

The new number is falloff. It is Lesson 9.3’s inside-amount, now used as a length scale on the 9.10 walk. It is not a color mix, and it does not punch a hole in the wallpaper.

The new multiply

The 9.10 walk, times one inside-amount.

sd = length(p) − radius falloff = 1.0 − smoothstep(−band, band, sd) dir = p / length(p) disp = dir × dispLen × falloff readUv = uv − disp sampled = checkerBackground(readUv × resolution, resolution)

sd is Lesson 9.2’s signed distance: minus inside the circle, zero on the boundary, plus outside. falloff is the same 0 through 1 number Lesson 9.3 called a soft mask. Here it does a different job. It shortens the extra walk. Deep inside, falloff = 1, so the walk is Lesson 9.10. Far outside, falloff = 0, so the walk is zero and the wallpaper is copied from itself. Across the band the walk changes a little whenever sd does.

1 · Follow the actual calculation

Build the shortened walk, one operation at a time.

UV is still Lesson 8.6: x is a fraction of the image width; y is a fraction of its height. Zero is top-left. y increases downward. The picture is square. Teaching W is (0.65, 0.30). That seat is on the pink wallpaper line and on the circle.

The glass circle

Center C = (0.50, 0.50). Radius 0.25. The boundary is every pixel whose straight-line distance from C equals 0.25.

The wallpaper line

The vertical join x = 0.65. It crosses the circle at y = 0.30 and y = 0.70. Those two seats are 3-4-5 leftovers: p = (±0.15, ±0.20).

The chosen extra length

Default dispLen = 0.10, the same slider as Lesson 9.10. Falloff will scale it. On the boundary the extra walk is half of that, 0.05.

Displayed decimals are rounded. Calculations keep full precision.

2 · What does the glass change?

Turn falloff off and the 9.10 picture returns.

Keep the teaching seat at W unless you click a new output position. The Falloff on · this lesson button removes the new multiply when you turn it off: every pixel walks dispLen again. The miss line at x = 0.90 is the diagnostic. With falloff on, that line never moves. With falloff off, it bows like everything else.

3 · Why the edge of the glass looks bent

Same wallpaper line. Extra walk that grows as you enter the circle.

Lesson 9.10 already showed why a constant extra walk bows a grid line. Do not redo that proof. The new picture is a walk whose length is not constant. Far from the circle the extra walk is the zero stick. Deep inside it is the full dispLen stick. Across the band it changes a little whenever distance to C does.

What x does. What y does.

At teaching W the extra walk is one stick of length dispLen × falloff = 0.05. That stick is a 3-4-5: 0.03 right and 0.04 up (minus y is up). Drag along the wallpaper line. Outside the band both legs are zero.

The landings are not a straight join and not a tent

Along x = 0.65, every point has the same p.x = 0.15. Only p.y changes. Signed distance is Lesson 9.1’s long side minus the radius:

d = length(p) = sqrt(0.15² + (y − 0.50)²) sd = d − 0.25 extra walk length at a write = dispLen × falloff(sd) The apparent line is the set of writes whose reads sit on x = 0.65.

A single straight join from the far-outside landing to the equator landing would have the form x = a + b × y. The boundary landing sits off that join. Two straight halves that meet at the equator (a tent) would still put the in-between landing on one of those halves. It does not. d changes a little with every slide of y, so falloff changes a little every time, so the slope turns continuously. There is no ridge at the rim.

In one sentence. Extra walk length depends on y only through d = sqrt(0.15² + (y − 0.50)²), which is not a linear function of y on either half of C, so the apparent line is a curve, not one straight line and not two straight halves glued at the equator.

Neighboring lines share the same rule

The next wallpaper join to the right is x = 0.75. It uses the same formula with p.x = 0.25. It is tangent to the default circle, so it only peels in a short band. The join x = 0.90 never enters the band, so it stays the original straight line. The join through C, x = 0.50, stays straight for a different reason: its extra walk is vertical, so points slide along the same line. The picture frame is not the end of the formula. We simply do not paint outside [0, 1] × [0, 1].

4 · The same 0..1 number, a different job

Falloff does not hide wallpaper and does not mix orange with navy.

A Lesson 4.8 mask would multiply visibility and could punch a hole. This shader never does that. return sampled always stores the checker color at the read. The glass is visible only because reads inside the circle ask a neighbor.

5 · The code uses the same objects

One extra multiply on the 9.10 field.

This is the current refractSample stitchable from RefractionSampling.metal. The walkthrough names dir. The shader writes p / d inside the multiplication.

[[ stitchable ]] half4 refractSample(
    float2 position,
    half4 color,
    float2 resolution,
    float dispLen,
    float radius,
    float band,
    float scale
) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float d = length(p);
    float2 disp = float2(0.0, 0.0);
    if (d > 0.0001) {
        float sd = d - radius;
        float falloff = 1.0 - smoothstep(-band, band, sd);
        disp = (p / d) * dispLen * falloff;
    }
    float2 readUv = uv - disp;
    return checkerBackground(readUv * resolution, resolution);
}

From a draw to one output color

Swift supplies the checker as the Metal function checkerBackground in this same file, the square’s pixel size as resolution, the three sliders, and displayScale as scale.

position is the current location in the rectangle’s local point coordinates. Multiplying by scale produces pixel fragCoord.

The new lines are sd, falloff, and the extra × falloff. Delete that multiply and Lesson 9.10 returns.

smoothstep needs band > 0. The lab slider starts at 0.02 so the two edges stay ordered.

Browser and iOS

The browser runs this arithmetic in JavaScript. It does not compile Metal. You may inspect any UV position.

iOS evaluates the stitchable at its actual draw positions. A 400-pixel square is a teaching size. The iOS explorer uses a 360 pt square; resolution is that size in pixels via displayScale.

This is not a physical light-path simulation. It does not use an index of refraction. It is the Lesson 1.1 visible test: a straight line bends where it crosses the glass. colorEffect documents the draw.

Final exercises

Try each question from the pictures first. Open the answer only after you have a guess.

1. At W = (0.65, 0.20), why is “9.10 copied navy here” insufficient?

This W has d ≈ 0.33541, so sd ≈ 0.08541, which is still in the outer band but near its far edge. Falloff is about 0.015. The extra walk is about 0.0015 UV, not 0.10. The read stays in the original orange cell.

sd = length(p) − radius ≈ 0.33541 − 0.25 = 0.08541 falloff = 1.0 − smoothstep(−0.10, 0.10, 0.08541) ≈ 0.01519 disp ≈ dir × 0.10 × 0.01519 readUv ≈ (0.64932, 0.20136)
2. Why does the wallpaper join x = 0.90 stay straight?

Minimum d on this line is 0.40, so minimum sd is 0.40 − 0.25 = 0.15. The band only reaches sd = +0.10. Falloff is 0 at every y. Lesson 9.10 would still bow this line, because 9.10 does not read sd.

3. At teaching W, falloff is 0.50. Is the stored color a 50/50 mix of orange and navy?

The 0.50 scales the stick. The store is still one checker color. Named walk at W:

disp = dir × dispLen × falloff = (0.60, −0.80) × 0.10 × 0.50 = (0.03, −0.04) readUv = (0.65, 0.30) − (0.03, −0.04) = (0.62, 0.34)
4. If you delete × falloff, why does the miss line suddenly bow?

The multiply is the only thing that can be 0 outside the glass. Remove it and disp = dir × dispLen everywhere except the center skip. That is Lesson 9.10. The miss line then gets the same extra walk as the teaching line, so it peels too. The circle overlay would still be drawn by the explorer; the shader would ignore it.
