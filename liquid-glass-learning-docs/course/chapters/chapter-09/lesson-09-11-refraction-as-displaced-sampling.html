Lesson 9.11 · Refraction as displaced sampling

Why does the pink line bend only inside the circle?

This is still the Lesson 9.10 checkerboard wallpaper. In that lesson, every output pixel took a walk: a short step toward the picture middle C, to copy the color it found at the end of the walk. Every walk had the same length. So the whole picture bowed.

Real glass does not bow the whole wallpaper. It bends only the part behind the glass. This lesson adds one new multiply that does exactly that. Lesson 9.10 is generated and not confirmed complete. This lesson uses its walk anyway, and adds the multiply.

The glass is Lesson 9.2’s circle, default radius 0.25. The pink line is the straight wallpaper join x = 0.65: the border between two checker columns. We follow the pixel where that line meets the circle.

The new number is called falloff. It is a 0-to-1 number that says how deep inside the glass a pixel is. 1 means deep inside. 0 means outside. We use it to shrink the walk. It never mixes colors. It never erases wallpaper.

The new multiply

The 9.10 walk, times one new number.

sd = length(p) − radius falloff = 1.0 − smoothstep(−band, band, sd) dir = p / length(p) disp = dir × dispLen × falloff readUv = uv − disp sampled = checkerBackground(readUv × resolution, resolution)

Read the six lines as a story. sd asks: where is this pixel relative to the glass edge? Minus is inside. Zero is on the edge. Plus is outside. That is Lesson 9.2. falloff turns sd into a 0-to-1 number. That is Lesson 9.3’s smooth slide. dir is a length-1 arrow that points from C to the pixel. The walk is dir × dispLen × falloff: the 9.10 walk, shrunk by falloff. Then the pixel reads the wallpaper at the end of that walk and stores the color it finds.

Deep inside, falloff is 1, so the walk is the full 9.10 walk. Far outside, falloff is 0, so the walk is zero: the pixel copies its own color and the wallpaper stays put. Between the two, in a thin ring called the band, the walk grows smoothly from 0 to full length.

1 · The whole idea in one picture

One pink line. Three seats. Three different walks.

Follow the pink join x = 0.65 from top to bottom. The walk length depends on one thing only: how close the seat is to the glass. Build the picture one seat at a time.

Six small operations at W.

UV names a spot with two fractions: x goes right, y goes down, both from 0 to 1. The picture is square, so 0.10 of x and 0.10 of y are the same length. Our teaching pixel W is (0.65, 0.30). It sits on the pink line and exactly on the glass edge.

Displayed decimals are rounded. Calculations keep full precision.

4 · Why the rim looks bent

Same line. A walk that grows as you enter the glass.

Lesson 9.10 already showed why equal walks bow a grid line. Do not redo that. The new picture here is a walk whose length changes along the line: zero far away, half on the rim, full deep inside. These five pictures build the bend one step at a time. A landing is where a point of the original line appears in the output picture.

The walk has a sideways part and an up/down part.

At W the walk is one arrow of length dispLen × falloff = 0.05. It is made of 0.03 sideways (cyan, owned by p.x) and 0.04 upward (violet, owned by p.y). Minus y is up. Slide y along the pink line. Outside the glass both parts are zero.

Is the bend secretly straight? No. Not one line. Not a roof.

Look at the pink bend. Could it secretly be one straight slanted line? Try it. Draw the cyan straight join from the far landing to the equator landing. The rim landing Q sits off that join. So it is not one straight line.

Could it be two straight pieces that meet in a point, like the two sides of a roof? The violet piece tries that. A landing between the ends still sits off the piece. So it is not a roof either.

Why? Along x = 0.65, every seat has the same p.x = 0.15. Only p.y changes. The walk length depends on y only through Lesson 9.1’s long side:

d = length(p) = sqrt(0.15² + (y − 0.50)²) sd = length(p) − radius = d − 0.25 walk length = dispLen × falloff(sd) The pink bend is every output pixel whose read lands on x = 0.65.

A straight line grows at one steady rate. A long side never does: d changes a little with every slide of y, so falloff changes a little every time, so the bend’s steepness changes at every seat. There is no single steepness and no sharp corner. It is a smooth curve.

In one sentence. The walk length depends on y only through d = sqrt(0.15² + (y − 0.50)²), which is Lesson 9.1’s long side and not a straight-line rule, so the bend is a smooth curve — not one straight join, and not two straight pieces meeting in a point.

Other lines follow the same rule.

The next join to the right is x = 0.75. It touches the circle at exactly one spot, so it bends only a little. The join x = 0.90 never meets the glass, so it stays perfectly straight. The join through C, x = 0.50, stays straight for a special reason: its walks point straight up and down along the line itself, so points slide along the line and it still looks like the same line. The formula also runs outside the picture frame. We simply do not paint outside [0, 1] × [0, 1].

5 · Same number, different job

Falloff never mixes colors and never erases wallpaper.

A Lesson 4.8 mask could hide wallpaper completely. This shader cannot. It always copies a checker color from somewhere. You see the glass only because pixels behind it copy neighbors.

6 · The code tells the same story

One new multiply: × falloff.

This is the current refractSample stitchable from RefractionSampling.metal. The walkthrough calls the direction dir. The code writes p / d. Those are the same thing.

[[ stitchable ]] half4 refractSample(
    float2 position,
    half4 color,
    float2 resolution,
    float dispLen,
    float radius,
    float band,
    float scale
) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float d = length(p);
    float2 disp = float2(0.0, 0.0);
    if (d > 0.0001) {
        float sd = d - radius;
        float falloff = 1.0 - smoothstep(-band, band, sd);
        disp = (p / d) * dispLen * falloff;
    }
    float2 readUv = uv - disp;
    return checkerBackground(readUv * resolution, resolution);
}

From a draw to one output color

SwiftUI supplies the checker as the Metal function checkerBackground in this same file, the square’s pixel size as resolution, the three sliders, and displayScale as scale.

position is the pixel’s seat in points. Multiplying by scale turns it into pixels.

uv is the seat as 0-to-1 fractions. p is the seat measured from the middle.

The guard d > 0.0001 skips the exact middle, where a direction would not exist. That is Lesson 9.10.

The new work is two lines: sd, then falloff, and the walk gets × falloff. Delete that one multiply and Lesson 9.10 returns.

Browser and iOS

This page runs the same arithmetic in JavaScript. It does not compile Metal. That is why you can click any spot here.

Final exercises

Try each question from the pictures first. Open the answer only after you have a guess.

1. At W = (0.65, 0.20), why is “Lesson 9.10 stored navy here” not enough any more?

This seat’s distance from C is d ≈ 0.33541, so sd ≈ 0.08541. That is inside the band, but close to its outer edge +0.10. Falloff is about 0.015: almost zero. The walk is about 0.0015, not 0.10. The read moves a hair and stays in the original orange cell.

sd = length(p) − radius ≈ 0.33541 − 0.25 = 0.08541 falloff = 1.0 − smoothstep(−0.10, 0.10, 0.08541) ≈ 0.01519 disp = dir × dispLen × falloff ≈ dir × 0.10 × 0.01519 readUv = uv − disp ≈ (0.64932, 0.20136)
2. Why does the wallpaper join x = 0.90 stay perfectly straight?

The smallest d on this line is 0.40, so the smallest sd is sd = length(p) − radius = 0.40 − 0.25 = 0.15. The band ends at sd = +0.10. So falloff is 0 at every y, and every walk is zero. Lesson 9.10 bowed this line because it never asks sd.

3. At teaching W, falloff is 0.50. Is the stored color half orange, half navy?

The 0.50 scales the walk. The store is still one checker color. The named walk at W:

disp = dir × dispLen × falloff = (0.60, −0.80) × 0.10 × 0.50 = (0.03, −0.04) readUv = uv − disp = (0.65, 0.30) − (0.03, −0.04) = (0.62, 0.34)
4. If you delete × falloff, why does the far line suddenly bow?

The multiply is the only factor that can be 0 outside the glass. Remove it and disp = dir × dispLen everywhere except the tiny center guard. That is Lesson 9.10. The far line then gets the same walk as the pink line, so it bends too. The explorer would still draw the circle overlay; the shader would ignore it.
