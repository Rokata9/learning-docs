Chapter 9 · Keep C still. Ask a nearer neighbor.

Scale around the center

Question: Lesson 9.7’s eval copies the input color at this pixel, so the picture sits still. Lesson 8.8’s pair p numbers the same pixel from the visual center C. How do you paint this pixel with a color that lived closer to C, so the checker looks larger, while the pixel at C still copies itself?

Keep C as a thumbtack. Divide p by scale, then add 0.5 to get the read UV. scale = 2 walks only half as far on the input, so the middle of the input fills the rectangle. That stored picture is magnification: the checker cells look larger. scale below 1 walks farther on the input. That stored picture is minification: the cells look smaller.

Canonical wording: scale around the center, magnification, minification, eval.

Read UV

2 · THE INNER HALF FILLS THE SQUARE

scale = 2 asks only uv 0.25..0.75 and stretches it.

The input picture does not move. The draw rectangle does not move. Only the pair passed to eval changes. A write pixel at the right edge has uv.x = 1, so readUv.x = 0.50 + 0.50 / 2.00 = 0.75. A write pixel at the left edge reads 0.25. The stored picture is the input’s inner half, enlarged until it fills the square. That is magnification. The outer input ring is not asked. Minification is the other direction: scale = 0.50 walks twice as far, so edge pixels read outside the rectangle. Those outside reads are Lesson 9.12. The lab paints them gray.

Thumbtack, not a Canvas slide

C is the pixel whose p is (0, 0). Dividing zero still gives zero. C still reads C. Lesson 8.8 already said the rectangle stays put. This divide does not call Canvas.scale.

Why add 0.5, and why not × 2

Subtract 0.5 is required so the origin of p is C. Add 0.5 is required to get back to UV for the pixel conversion. × 2 from Lesson 8.8 is not used. After × 2, 1 would mean one half-width. Here 0.30 already means 0.30 of the full width from C toward the right.

scale > 1 → walk a shorter input distance → cells look larger (magnification) scale = 1 → readUv = uv → identity scale < 1 → walk a longer input distance → cells look smaller (minification)

5 · ANDROID ROUTE
One new uniform: scale. eval still receives pixels.

    

      
private const val DefaultScale = 2.00f
private const val TeachU = 0.80f
private const val TeachV = 0.70f

uniform shader background;
uniform float2 resolution;
uniform float scale;

half4 main(float2 fragCoord) {
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float2 readUv = p / scale + 0.5;
    return background.eval(readUv * resolution);
}

      

        
What each part changes

        
scale is one number, so a 360 dp panel and a 400 px HTML square magnify the same inner half.

        
readUv * resolution converts the read UV back to pixels because eval still wants the Lesson 8.4 unit.

        
The slider writes scale. Default 2.00 so T stores orange on first draw.

        
The checker input is four cells across. Column index floor(uv.x × 4.0). Orange when that column index plus the row index is even: fract((col + row) × 0.5) < 0.5. floor and fract are Lesson 8.10 leftovers.

        
Geometry masks are unused. Lesson 9.8’s constant subtract is a different remap: the same pixel count at every write location. This divide is 0 at C and larger farther out.

8 · EXERCISES
Answer before opening each hidden solution

    

      At scale = 1, what is readUv at T, and what color does T store?
      
readP = p / 1 = p, so readUv = uv. Identity, same as Lesson 9.7 without the split. T’s input cell is navy, so T stores navy.

      
    

    

      Diagnostic: someone writes readUv = uv / scale with scale = 2. T still stores orange. What did they get wrong?
      
The named formula they dropped is p = uv − 0.5, then readUv = p / scale + 0.5. Dividing UV from the top-left thumbtacks (0, 0), not C. At C, uv / 2 = (0.25, 0.25), so the visual center copies a top-left cell and the picture slides toward the top-left. T can still land on orange by accident. The field is the proof: C no longer copies C.

      
    

    

      At scale = 0.50, T has uv = (0.80, 0.70). What is readUv, and why can the store be gray?
      
readP = p / scale = (0.30, 0.20) / 0.50 = (0.60, 0.40). readUv = readP + 0.5 = (1.10, 0.90). The 1.10 is past the right edge of the input rectangle. This HTML stand-in stores gray for any read UV outside 0..1. Android’s eval of an out-of-range pair is Lesson 9.12. Minification is still “walk farther on the input.” The gray is the edge, not a third checker color.

      
    

    

      Does this lesson move the Canvas, and does it use p?
      
The draw rectangle stays put. fragCoord still numbers this pixel from the top-left. p is used: it is the pair that gets divided. Lesson 9.8’s constant subtract did not use p. Lesson 9.10 will build a different pair at each pixel, a displacement, instead of this one shared scale.
