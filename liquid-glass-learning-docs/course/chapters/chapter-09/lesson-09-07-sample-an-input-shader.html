Chapter 9 · Ask another shader for a color

Sample an input shader

Question: Lessons 8.3 through 9.6 compute the stored half4 with arithmetic: a fixed orange, an if on fragCoord, a mix, a signed distance. Glass also needs colors that already exist in another picture. How does this pixel’s function ask that other picture for the color at one coordinate?

Call background(fragCoord, resolution). The returned half4 is the sampled color: a copy of the input color function’s color at that read coordinate. Production stores that copy on the left half, and teaching orange on the right half, so you can see the ask working.

Canonical wording: input color function, eval, sampled color, read coordinate.

This page does not use a distance field. Default teaching rectangle is 400×400. Teaching pixel uv.x = 0.15 sits in a navy stripe. HTML is a JavaScript stand-in. The iPhone 16 Pro explorer calls background in the same .metal file. That call is not a texture sample.
1 · THE NEW QUESTION

The stored color can be a copy, not a newly computed orange.

8.3 leftover

A shader’s return is the store: the half4 written at this pixel. Teaching orange is half4(0.88, 0.48, 0.18, 1.0). Teaching navy is half4(0.10, 0.25, 0.40, 1.0).

Input color function

An input color function is a Metal function in the same .metal file. This lesson names it background. It returns a half4 for a pixel pair. It is not a float, and it is not a texture sample.

eval

eval is this course’s name for the ask: background(fragCoord, resolution). Given a read coordinate in pixels, return the input color function’s half4 at that pair. The returned value is the sampled color. It is a copy. The input picture is not rewritten. The second argument is the panel size, because the color function divides the pair by that size.

Stripe input (another main) uv = fragCoord / resolution cell = fract(uv.x × 5.0) if (cell < 0.5) orange else navy 5.0 means five orange-navy pairs across the width. One stripe is 0.10 of the width. On 400 px that is 40 px.
Teaching pixel T uv.x = 0.15 ← x = 0.15 × 400 = 60 px from the left 5.0 × 0.15 = 0.75 fract(0.75) = 0.75 0.75 is not < 0.5, so the input stores navy background(fragCoord, resolution) returns that navy
2 · EVAL COPIES. THE SPLIT PROVES THE ASK RAN.

Read coordinate and write location are the same pair in this lesson.

The write location is this pixel: fragCoord, pixels from the top-left of the draw rectangle. The read coordinate is the pair passed to background. Identity sampling uses background(fragCoord, resolution), so those two pairs match. Lesson 9.8 will subtract before the ask.

Left half stores the sampled color

Lesson 8.5’s split: fragCoord.x < resolution.x / 2.0. On that half, production returns the sampled color unchanged. At T, x = 60 and half of 400 is 200, so T is on the left and stores navy.

Right half stores teaching orange

The right half ignores the call. It returns the 8.3 orange. If the whole rectangle looked like stripes, you could not tell this function from the input color function. The orange half is the proof that this function ran.

sampled = background(fragCoord, resolution) if (fragCoord.x < resolution.x / 2.0) return sampled return orange

5 · iOS ROUTE
One color function. One call. One half cut.

    

      
private let stripeCount: Double = 5
private let teachU: Double = 0.15
private let panelSizePt: CGFloat = 360

half4 background(float2 fragCoord, float2 resolution) {
    float2 uv = fragCoord / resolution;
    float cell = fract(uv.x * 5.0);
    half4 navy = half4(0.10, 0.25, 0.40, 1.0);
    half4 orange = half4(0.88, 0.48, 0.18, 1.0);
    if (cell < 0.5) {
        return orange;
    }
    return navy;
}

[[ stitchable ]] half4 sampleInputSplit(
    float2 position,
    half4 color,
    float2 resolution,
    float scale
) {
    float2 fragCoord = position * scale;
    half4 sampled = background(fragCoord, resolution);
    if (fragCoord.x < resolution.x / 2.0) {
        return sampled;
    }
    half4 orange = half4(0.88, 0.48, 0.18, 1.0);
    return orange;
}

ShaderRect(
    shader: ShaderLibrary.sampleInputSplit(
        .float2(pixelWidth, pixelHeight),
        .float(Float(displayScale))
    )
)
.frame(width: panelSizePt, height: panelSizePt)

      

        
What each part changes

        
background paints vertical orange and navy bands with fract(uv.x × 5.0). 5.0 is stripeCount: five pairs across the width. It lives in the same .metal file as the stitchable function.

        
sampled = background(fragCoord, resolution) is the ask. The first argument is pixels, the same units as fragCoord. resolution is the panel size in pixels, because the color function divides by it. A float argument cannot hold a picture.

        
position is points, so fragCoord = position * scale. scale is displayScale. pixelWidth and pixelHeight are 360 × displayScale. The half cut uses that same pixel resolution.

        
Chapter 6 recorded a panel-sized picture with ImageRenderer. This lesson’s ask is a function call. It is not a texture sample. A clamped sample would change a coordinate that this call passes through.

        
Input-only selects sampleInputOnly, which returns background(fragCoord, resolution) at every pixel. The buttons do not rewrite the .metal file. Pass every argument. Leaving one out still compiles the Swift file, and SwiftUI refuses that draw.

8 · EXERCISES
Answer before opening each hidden solution

    
At uv.x = 0.05, what is cell, what does eval return, and what does the left half store?
5 × 0.05 = 0.25. fract(0.25) = 0.25, which is less than 0.5, so the input is orange. x = 20, which is less than 200, so production stores that orange. The sampled color and the stored color match.

    
Diagnostic: someone writes return background(uv, resolution). Why is the teaching navy stripe in the wrong place?
The call’s first argument is in pixels, the same units as fragCoord. uv.x at T is 0.15. The color function then treats 0.15 as 0.15 pixels from the left, which sits in the first orange stripe. The navy band that should be at 40–80 px is read from the far left of the input. Pass fragCoord, not uv.

    
A pixel at x = 300 is on the right half. The input stripe there is navy. What does production store?
background would return navy, but the hard if takes the else branch because 300 is not less than 200. The store is teaching orange. The sampled color is computed and then unused on the right half.

    
Does the call change the input color function’s stored pixels?
No. The sampled color is a copy returned to this pixel. The input function still returns the same stripe color at that coordinate the next time it is asked.
