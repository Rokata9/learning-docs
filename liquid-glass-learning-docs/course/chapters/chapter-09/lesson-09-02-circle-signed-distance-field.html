Chapter 9 · Subtract the radius so a minus means inside

Circle signed distance field

Question: Lesson 9.1’s length(p) is never negative. It answers “how far is this pixel from the visual center?” Lesson 4.1 already defined a circle as a center plus a radius: every boundary pixel is one radius from the center. How do you turn that unsigned length into one number that is negative inside the circle, zero on the boundary, and positive outside?

Subtract the radius from Lesson 9.1’s length: sd = length(p) − radius. That result is a signed distance: a length that also carries a plus or a minus. This course’s convention: minus means inside, zero means on the boundary, plus means outside. A signed distance field is that number computed at every pixel. Production then stores orange when sd < 0 and navy otherwise.

1 · THE NEW QUESTION

Unsigned length cannot say inside or outside by itself.

9.1 leftover

The teaching pixel has p = (0.30, −0.40) and d = 0.50. That 0.50 is how far the pixel is from the visual center. It is the long side of the right triangle. It has no minus.

4.1 leftover

A circle’s boundary is every pixel whose straight-line length from the center equals the radius. Inside, that length is smaller than the radius. Outside, it is larger. Lesson 4.1 used a horizontal radius handle. This lesson uses 9.1’s length in every direction.

New subtract

Default radius is 0.25. That is half of the teaching 0.50, so the teaching pixel sits one radius beyond the boundary. sd = 0.50 − 0.25 = +0.25. The plus is the new information: outside.

Not a soft edge

Production uses a hard if (sd < 0.0), the Lesson 8.4-style cut, now on this new number. Lesson 9.3 will feed sd into smoothstep. This lesson keeps the cut so you can see the sign without a blend.

d = length(p) ← Lesson 9.1, never negative sd = d − radius ← this lesson ← radius = 0.25 unless the slider moves it ← teaching pixel: 0.50 − 0.25 = +0.25 (outside) ← center: 0.00 − 0.25 = −0.25 (inside) ← boundary: 0.25 − 0.25 = 0.00
This course’s sign convention: sd < 0 inside the circle sd = 0 on the boundary sd > 0 outside the circle The opposite convention would also work if every later lesson used it. This course keeps minus = inside.

4 · WHY SUBTRACT, NOT COMPARE ONLY
The sign answers inside or outside. The size still has a later job.

    

      

        
A yes/no test would discard the size

        
if (d < radius) already paints a filled circle. That test is enough for a hard silhouette. This lesson still writes sd = d − radius first, then tests sd < 0, which is the same cut. The extra number is the reason for writing the subtract: at the teaching pixel you keep +0.25, not only the word “outside.”

        
Lesson 9.3 will need that size. A soft band around a boundary is a few pixels on both sides of sd = 0. A yes/no value cannot say “0.02 past the boundary.”

      

      

        
If radius increases, sd decreases

        
Keep the teaching pixel fixed. Its d stays 0.50. If radius moves from 0.25 to 0.60, then sd moves from +0.25 to −0.10. The number decreased. It crossed zero. The pixel became inside. That is the directional proof: larger radius, smaller sd, same pixel.

radius 0.50 → sd =  0.00  (boundary)
radius 0.60 → sd = −0.10  (inside, orange)

      

    

    
Walk-around diamond. If you subtract radius from abs(p.x) + abs(p.y) instead of from length(p), equal-zero pixels form a diamond, not a circle. That is Lesson 9.1’s walk-around leftover applied to this subtract. Production uses length. The diamond button exists only so you can see the wrong shape.

7 · ANDROID ROUTE
One radius uniform, one subtract, one if

    

      
private const val PanelSizeDp = 360
private const val DefaultRadius = 0.25f
private const val TeachPx = 0.30f
private const val TeachPy = -0.40f

private const val CircleAgsl = """
uniform float2 resolution;
uniform float radius;

half4 main(float2 fragCoord) {
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float d = length(p);
    float sd = d - radius;
    half4 navy = half4(0.10, 0.25, 0.40, 1.0);
    half4 orange = half4(0.88, 0.48, 0.18, 1.0);
    if (sd < 0.0) {
        return orange;
    }
    return navy;
}
"""

val shader = remember { RuntimeShader(CircleAgsl) }

Canvas(...) {
    shader.setFloatUniform("resolution", size.width, size.height)
    shader.setFloatUniform("radius", radius)
    drawRect(brush = brush)
}

10 · EXERCISES
Answer before opening each hidden solution

    
At the visual center, radius = 0.25, what is sd, and which color does production store?
d = 0, so sd = 0 − 0.25 = −0.25. The minus means inside, so the hard if stores orange. Zero in p is still the center. Zero in sd is not the center; it is the boundary.

    
Diagnostic: someone writes float sd = abs(p.x) + abs(p.y) − radius. What shape is sd = 0, and why is that not this lesson’s circle?
sd = 0 when abs(p.x) + abs(p.y) = radius. That is Lesson 9.1’s walk-around number, whose equal-value shape is a diamond. A circle needs the long-side length, so production subtracts radius from length(p).

    
Keep the teaching pixel fixed at d = 0.50. Radius moves from 0.25 to 0.60. What happens to sd, and when does the stored color flip?
sd decreases: +0.25 → −0.10. It crosses zero when radius = 0.50. For radius above 0.50 the teaching pixel is inside and stores orange. Larger radius, smaller sd, same pixel.

    
Why keep sd = +0.25 instead of only the Boolean “outside”?
The Boolean is enough to pick navy versus orange in this lesson’s hard if. The size +0.25 is how far past the boundary. Lesson 9.3 needs that size to build a soft band around sd = 0. Throwing the size away now would force you to recompute it later.
