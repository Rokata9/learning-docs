Chapter 9 · Feed signed distance into Lesson 8.11’s band

Turn distance into a soft mask

Question: Lesson 9.2’s hard if (sd < 0.0) stores teaching orange or teaching navy. One pixel of the circle edge is fully orange. The next is fully navy. Lesson 8.11 already blended those two colors across a UV band with smoothstep. How do you turn the signed distance sd into a 0 through 1 inside-amount so the same mix can run around the circle boundary?

A soft mask is a 0 through 1 inside-amount that may also sit between 0 and 1. Production: mask = 1.0 − smoothstep(−band, band, sd), then mix(navy, orange, mask). The 1 minus is required because smoothstep grows as you leave the circle.
Complete. This page is a JavaScript stand-in. The iPhone 16 Pro explorer’s stitchable function computes the soft mask and the mix. Lesson 9.1’s far pixel stays navy. Lesson 9.4 builds a rounded-rectangle signed distance that this mask can wrap later.

1 · THE NEW QUESTION

The hard if cannot store an in-between color on the circle edge.

9.2 leftover

Default radius is still 0.25. The far pixel p = (0.30, −0.40) still has d = 0.50 and sd = +0.25. The hard if stores navy there. The center stores orange. Nothing in between those two stores is written.

8.11 leftover

smoothstep(edge0, edge1, x) already built a 0..1 blend fraction and bent it. Lesson 8.11’s x was uv.x. This lesson’s x is sd. The function is the same. The input object is new.

New mask

The new number is a soft mask: how much inside color to store, 0 through 1. Teaching band pixel p = (0.18, −0.24) has d = 0.30 and sd = +0.05. Its mask is 0.15625, not 0 and not 1.

Not those earlier fractions

Lesson 4.8’s binary mask was only 0 or 1. Lesson 4.9’s coverage was a visibility fraction from geometry crossing a pixel square. Lesson 7.1’s blur averaged neighboring stored colors. This mask comes from how far sd sits from 0.

sd = length(p) − radius ← Lesson 9.2 leftover band = 0.10 ← this lesson’s half-width, in p units edge0 = −band = −0.10 edge1 = +band = +0.10 ← edge1 must be greater than edge0 linearFraction = clamp((sd − (−band)) / (band − (−band)), 0, 1) = clamp((sd + band) / (2 × band), 0, 1) curvedFraction = linearFraction × linearFraction × (3 − 2 × linearFraction) mask = 1 − curvedFraction store = mix(navy, orange, mask)
Teaching band pixel p = (0.18, −0.24) d = 0.30 ← 0.18×0.18 + 0.24×0.24 = 0.0900 = 0.30×0.30 sd = 0.30 − 0.25 = +0.05 linearFraction = (0.05 + 0.10) / 0.20 = 0.75 curvedFraction = 0.75 × 0.75 × (3 − 1.50) = 0.5625 × 1.50 = 0.84375 mask = 1 − 0.84375 = 0.15625 stored red = 0.10 + (0.88 − 0.10) × 0.15625 = 0.221875
2 · WHY 1 MINUS

smoothstep grows as you leave the circle. The mask must grow as you enter it.

Lesson 8.11’s smoothstep is 0 when its input is at or below edge0, and 1 when its input is at or above edge1. Here the input is sd, edge0 = −band, edge1 = +band. So the raw smoothstep is 0 deep inside and 1 far outside. That is the opposite of an inside-amount.

Do not reverse the edges. Metal leaves smoothstep undefined when edge0 is greater than or equal to edge1. Writing smoothstep(band, −band, sd) is not a legal shortcut for the 1 minus. Keep −band first, then subtract from 1.

6 · iOS ROUTE
Two arguments, one 1 minus, one mix

    

      
[[ stitchable ]] half4 softMask(
    float2 position,
    half4 color,
    float2 resolution,
    float scale,
    float radius,
    float band
) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    float sd = length(p) - radius;
    float mask = 1.0 - smoothstep(-band, band, sd);
    half4 navy = half4(0.10, 0.25, 0.40, 1.0);
    half4 orange = half4(0.88, 0.48, 0.18, 1.0);
    return mix(navy, orange, mask);
}

private let panelSizePt: CGFloat = 360
private let teachPx: Float = 0.18
private let teachPy: Float = -0.24

ShaderRect(
    shader: ShaderLibrary.softMask(
        .float2(pixelWidth, pixelHeight),
        .float(Float(displayScale)),
        .float(radius),
        .float(band)
    )
)
.frame(width: panelSizePt, height: panelSizePt)
// SwiftUI Canvas overlay: center cross, radius ± band, teaching mark

      

        
What each part changes

        
panelSizePt = 360 is a square teaching size in points so UV x and UV y use the same pixel length. It is not glass geometry. Default band 0.10 makes the band pixel’s linearFraction exactly 0.75.

        
Xcode compiles softMask in the .metal file. ShaderLibrary looks it up. position is points, so fragCoord = position * scale and resolution are both in pixels. scale is displayScale. radius and band are in p units. There is no runtime string compiler. Moving either slider passes a new .float. That is Lesson 8.9’s argument write. Pass every argument. Leaving one out still compiles the Swift file, and SwiftUI refuses that draw.

        
At the band pixel, Swift prints sd = +0.05 and mask = 0.15625 using the same arithmetic as the HTML table. The green overlay circle is SwiftUI Canvas drawing at the current radius. The amber overlays are radius ± band.

9 · EXERCISES
Answer before opening each hidden solution

    
At the visual center, radius = 0.25, band = 0.10, what is the mask, and which color does production store?
sd = −0.25, which is below −band. linearFraction clamps to 0. curvedFraction is 0. mask = 1 − 0 = 1. mix stores orange. The pixel is deep inside the band, not on the boundary.

    
Diagnostic: someone writes float mask = smoothstep(-band, band, sd) and mixes with that mask. What color is the center, and why is that backwards?
Raw smoothstep is 0 at the center, so mix(navy, orange, 0) stores navy at the center. The inside would look like the outside. The 1 minus is what turns “how far outside” into “how much inside color.”

    
Someone writes smoothstep(band, -band, sd) to skip the 1 minus. Why is that not this lesson’s production?
Metal leaves smoothstep undefined when edge0 is greater than or equal to edge1. band is greater than −band. The legal spelling keeps −band first and subtracts the result from 1.

    
Keep the far pixel at sd = +0.25. Band is 0.10. Why is its stored color still navy, and what later consumer needs the mask even there?
sd = +0.25 is above +band, so linearFraction clamps to 1, mask is 0, mix stores navy. The mask is still computed. A later lesson that samples a background can multiply or mix with that 0 to hide the outside. Throwing the mask away on navy pixels would force a second test.
