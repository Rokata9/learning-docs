Chapter 3 · Color, opacity, and compositing

Lesson 3.9 — Saturation

You already know this final opaque color from Lesson 3.8: straight sRGB RGBA(0.65, 0.35, 0.70, 1.00). This lesson answers one new question: how can the program reduce or enlarge the differences among its red, green, and blue channel values without drawing a second tint color over it?

Saturation in this lesson: one numeric factor used by the lab helper ColorMatrix.setToSaturation. The helper copies a 4×5 matrix with weights 0.213, 0.715, and 0.072. Do not use Core Image's default saturation. The helper first calculates a gray reference, meaning one channel value that becomes the red, green, and blue value of the gray reference color. The factor then reduces, preserves, or enlarges each channel's difference from that value. A factor below 1 moves the channels closer to the gray reference. A factor above 1 moves them farther from it. Other tools may use the word saturation for a different operation.
By the end

You will be able to calculate the gray reference, transform red, green, and blue separately, prove what factors below and above 1 do, distinguish the gray reference from relative luminance, and explain where the lab helper stores the same calculation inside a color matrix.

1 · Start with one known color

No new layer is added

The input is already the final opaque output of Lesson 3.8.

Known input object

Input straight sRGB RGBA = (0.65, 0.35, 0.70, 1.00)

Alpha is 1.00. The color is already opaque. The main saturation calculation therefore does not need a destination or source-over compositing.

New operation

one input Color + one numeric factor ↓ channel transformation one output Color

The operation changes the input red, green, and blue fields. It leaves alpha unchanged. Section 7 later shows how the lab helper stores this same transformation in a ColorMatrix, which is a table of multipliers.

Important boundary, explained fully in Section 10: the saturation matrix can transform the red, green, and blue fields of a translucent source while copying its alpha unchanged. That produces a transformed source color, not the final color visible on the screen. The actual destination still contributes during source-over compositing.

3 · Calculate one shared gray reference

Calculate the value shared by gray red, green, and blue

The gray reference is an intermediate number created by the saturation transform.

A gray RGB color has equal red, green, and blue channel values. The lab saturation helper calculates one number from the input channels. The lesson calls that number the gray reference. It is an intermediate value, meaning a temporary result that a later calculation consumes. Each of the three output-channel equations consumes the gray reference. Setting all three output channels to that value produces a gray color.

The numbers 0.213, 0.715, and 0.072 are fixed multipliers used by this lab helper. A multiplier scales one input before the three results are added. The current color does not generate these constants.

Pure red input

RGB(1, 0, 0) → gray reference 0.213

Pure green input

RGB(0, 1, 0) → gray reference 0.715

Pure blue input

RGB(0, 0, 1) → gray reference 0.072
Why this demonstration matters: the helper does not give red, green, and blue one-third each. It maps the three pure primary inputs to different gray values. The lab matrix copies these exact multipliers. Section 6 explains why this calculation must still not be called relative luminance.
gray reference = 0.213 × input red + 0.715 × input green + 0.072 × input blue
Why the fixed multipliers add to 1: 0.213 + 0.715 + 0.072 = 1.000. If the input is already gray, such as RGB(0.40, 0.40, 0.40), the result remains 0.40 because 1.000 × 0.40 = 0.40.
4 · Transform one channel at a time

Scale its signed distance from gray

The same operation runs independently for red, green, and blue.

A signed distance is the input channel minus the gray reference. A positive result means the input channel is above gray on the 0-to-1 number line. A negative result means it is below gray.

signed distance = input channel − gray reference scaled distance = saturation factor × signed distance unclamped matrix output = gray reference + scaled distance

What “raw” meant in the earlier wording

Some graphics material calls the direct matrix-row result a raw output. Here, raw meant only: the arithmetic result before the allowed channel range is enforced.

matrix row products ↓ add them unclamped matrix output ↓ clamp to 0..1 displayed channel value

The revised lesson uses unclamped matrix output because it names the exact stage.

Clamping is not geometric clipping

Clamping restricts one number to an allowed range. If the arithmetic produces 1.01308, the displayed normalized channel becomes 1.00000. The word clipping is avoided here because later graphics lessons use clipping for cutting drawing geometry to a boundary.

unclamped value 1.01308 allowed range 0..1 ↓ clamp displayed value 1.00000
Exact meaning of closer to gray and farther from gray: a factor below 1 reduces the absolute distance between every channel and the gray reference. A factor above 1 increases that distance. The lesson proves the claim with the live signed distances above; it does not rely on the words alone.
5 · Read the factor by region

Zero, below one, one, and above one do different things

Range-limit check: a factor above 1 can create an unclamped matrix output below 0 or above 1. Clamping restricts that number to the nearest allowed boundary. The browser and Swift show both the unclamped arithmetic result and the displayed clamped value.
6 · Separate the gray reference from relative luminance

Similar coefficients do not make the operations identical

This is the most likely misconception in this lesson.

Saturation gray reference

The input is the stored straight sRGB channels. The operation combines those stored numbers directly. The output is one reference value used by all three output-channel equations in this saturation transform.

≠

Relative luminance from Lesson 3.6

The input sRGB channels are decoded into linear-light values first. The output is one unitless measurement used by contrast calculations.

Why this matters: do not call the gray reference “luminance,” and do not use input.luminance() as the gray reference for this lab matrix. The two calculations answer different questions.
7 · Inspect the lab ColorMatrix

Four rows calculate four output channels

The saturation helper stores its operation in a 4-by-5 table.

The matrix receives one source color written as five inputs:

[ input R, input G, input B, input A, constant 1 ]

The first four inputs are the source color's red, green, blue, and alpha fields. The final input is always the number 1. It exists so the fifth value in each row can be added as a constant offset.

output channel = row[0] × input R + row[1] × input G + row[2] × input B + row[3] × input A + row[4] × 1

What changes per source pixel?

The input R, G, B, and A can be different for every affected source pixel. A photograph therefore supplies many different input tuples.

This lesson chooses one known input color so that every multiplication, row sum, unclamped output, and clamp can be inspected.

What changes with the factor slider?

The fixed gray weights remain 0.213, 0.715, and 0.072. The actual coefficients written into the first three rows change when setToSaturation(factor) receives a different factor.

For one fixed factor, the same completed matrix is applied to every affected source pixel.

What does “+ offset” mean?

The fifth value in a row is added after the four component products. It is not inherited from a previous lesson and it is not controlled by a slider.

For setToSaturation, all four offsets are 0. The offsets therefore add nothing in this lesson.

Illustrative row in one channel scale: products total = 0.40 offset = +0.10 unclamped row output = 0.40 + 0.10 = 0.50

This small arithmetic example only explains the role of the fifth column. A custom matrix chooses an offset in the channel scale expected by its API. The saturation helper uses zero.

The RGB row coefficients are rebuilt from the current factor and the fixed matrix weights. The alpha row and all offsets remain unchanged for setToSaturation.
Output× input R× input G× input B× input A+ offset
The matrix values come from the current factor. The input values come from the current RGB sliders and input alpha. The results are calculated here.

Apply the rows to the current input

The row sum is the unclamped matrix output. The displayed color is constructed only after each normalized channel is clamped to 0..1.

Why the alpha row is [0, 0, 0, 1, 0]

A′ = 0 × R + 0 × G + 0 × B + 1 × A + 0 = input A

The first three zeros prevent input RGB from changing output alpha. The 1 copies input alpha. The final zero adds no constant alpha.

Is every ColorMatrix alpha row identical?

No. A general 4-by-5 color matrix can change alpha. This exact row belongs to the identity matrix and remains in setToSaturation because that helper changes saturation only.

A different custom matrix may scale alpha or add an alpha offset. Its contract must say so explicitly.

Each input receives its own gray reference

9 · Recalculate luminance and contrast from the output RGB

A saturation transform creates a new measurement input

Wrong after RGB changes

The old values still describe the input RGB. They become stale when attached to a different output RGB.

Correct

Calculate relative luminance from the transformed output. Then calculate black and white contrast from that new luminance.

No promise of luminance preservation: this lab saturation matrix operates directly on channel values. It does not promise that the WCAG relative-luminance number remains unchanged.

If the transformed result does not provide enough foreground contrast

The saturation factor is not an accessibility control. It changes RGB, but it does not guarantee that contrast will move in a useful direction. Use this order:

1 · Finish the visible color

Apply the saturation transform at its intended stage. If alpha remains below 1, composite through the real lower layers until an opaque displayed RGB is known.

2 · Measure

Calculate relative luminance and foreground contrast from that final displayed RGB. Do not measure the pre-transform or still-translucent source as though it were final.

3 · Try foreground candidates

Compare black, white, or another permitted foreground color. Choose a candidate that meets the target for the content.

4 · Change the material if needed

If no allowed foreground passes, strengthen the glass tint or opacity, add a local dimming/backing layer, or use the reduced-transparency/high-contrast variant. Then measure again.

Needed for Liquid Glass: yes. Later adaptive-material lessons will use the final backdrop and material output to choose foreground color or strengthen the material. Lesson 3.9 only establishes the order of operations; it does not yet build the complete adaptive policy.
10 · Saturation with translucent colors

The matrix transforms a source; compositing determines the visible result

These are two separate operations with two separate outputs.

Yes, saturation can be applied to a translucent color. The matrix changes its red, green, and blue fields. For setToSaturation, the alpha row copies the source alpha unchanged.

Translucent input source straight sRGB RGBA(R, G, B, A) ↓ saturation matrix transformed translucent source straight sRGB RGBA(R′, G′, B′, A) ↓ source-over with actual destination final displayed output RGBA
The RGB and factor use the current controls. The example alpha is fixed at 0.50 only to expose the destination's contribution.

Step 1 · Transform a 50% source

The transformed source remains 50% opaque. Its tuple says what color the source contributes when it is later drawn. It does not yet say what the screen finally shows.

Step 2 · Composite over real destinations

The same transformed source produces different final colors over white and navy. Alpha is therefore relevant before luminance, even though alpha is not a fourth term inside the luminance formula.

Where the saturation filter is attached changes the operation

A · Transform the translucent source first

This models a color filter attached to the source content. The destination itself is not saturated.

≠

B · Composite first, then transform the combined color

This transforms the already combined source-and-destination result. The destination contribution is transformed too.

Liquid Glass consequence: “saturate the backdrop,” “saturate the translucent glass layer,” and “saturate the final composite” are different instructions. Later lessons must name the exact input buffer and the exact position of the transform in the rendering pipeline.

private let matrixRedWeight: CGFloat = 0.213
private let matrixGreenWeight: CGFloat = 0.715
private let matrixBlueWeight: CGFloat = 0.072
private let contrastOffset: CGFloat = 0.05

private struct SaturationResult {
    let matrix: LabColorMatrix
    let grayReference: CGFloat
    let unclampedRed: CGFloat
    let unclampedGreen: CGFloat
    let unclampedBlue: CGFloat
    let unclampedAlpha: CGFloat
    let outputColor: Color

    var redWasClamped: Bool { unclampedRed < 0 || unclampedRed > 1 }
    var greenWasClamped: Bool { unclampedGreen < 0 || unclampedGreen > 1 }
    var blueWasClamped: Bool { unclampedBlue < 0 || unclampedBlue > 1 }
    var anyChannelWasClamped: Bool {
        redWasClamped || greenWasClamped || blueWasClamped
    }
}

/// 4×5 color matrix copied from the course saturation contract.
/// Weights stay 0.213 / 0.715 / 0.072. Do not use Core Image saturation.
private struct LabColorMatrix {
    private var values: [CGFloat]

    init() {
        values = Array(repeating: 0, count: 20)
        self[0, 0] = 1
        self[1, 1] = 1
        self[2, 2] = 1
        self[3, 3] = 1
    }

    subscript(row: Int, column: Int) -> CGFloat {
        get { values[row * 5 + column] }
        set { values[row * 5 + column] = newValue }
    }

    mutating func setToSaturation(_ sat: CGFloat) {
        self = LabColorMatrix()
        let invSat = 1 - sat
        let red = matrixRedWeight * invSat
        let green = matrixGreenWeight * invSat
        let blue = matrixBlueWeight * invSat
        self[0, 0] = red + sat
        self[0, 1] = green
        self[0, 2] = blue
        self[1, 0] = red
        self[1, 1] = green + sat
        self[1, 2] = blue
        self[2, 0] = red
        self[2, 1] = green
        self[2, 2] = blue + sat
    }
}

private struct StraightRgba {
    let red: CGFloat
    let green: CGFloat
    let blue: CGFloat
    let alpha: CGFloat
}

private func applySaturationMatrix(
    input: Color,
    saturation: CGFloat
) -> SaturationResult {
    var matrix = LabColorMatrix()
    matrix.setToSaturation(saturation)
    let rgba = input.toStraightRgba()

    func evaluateRowBeforeClamp(_ row: Int) -> CGFloat {
        matrix[row, 0] * rgba.red
            + matrix[row, 1] * rgba.green
            + matrix[row, 2] * rgba.blue
            + matrix[row, 3] * rgba.alpha
            + matrix[row, 4]
    }

    let unclampedRed = evaluateRowBeforeClamp(0)
    let unclampedGreen = evaluateRowBeforeClamp(1)
    let unclampedBlue = evaluateRowBeforeClamp(2)
    let unclampedAlpha = evaluateRowBeforeClamp(3)
    let grayReference = matrixRedWeight * rgba.red
        + matrixGreenWeight * rgba.green
        + matrixBlueWeight * rgba.blue

    return SaturationResult(
        matrix: matrix,
        grayReference: grayReference,
        unclampedRed: unclampedRed,
        unclampedGreen: unclampedGreen,
        unclampedBlue: unclampedBlue,
        unclampedAlpha: unclampedAlpha,
        outputColor: Color(
            red: min(max(unclampedRed, 0), 1),
            green: min(max(unclampedGreen, 0), 1),
            blue: min(max(unclampedBlue, 0), 1),
            opacity: min(max(unclampedAlpha, 0), 1)
        )
    )
}

private func sourceOverOpaque(_ source: Color, _ destination: Color) -> Color {
    let sourceRgba = source.toStraightRgba()
    let destRgba = destination.toStraightRgba()
    let sourceAlpha = sourceRgba.alpha
    return Color(
        red: sourceRgba.red * sourceAlpha + destRgba.red * (1 - sourceAlpha),
        green: sourceRgba.green * sourceAlpha + destRgba.green * (1 - sourceAlpha),
        blue: sourceRgba.blue * sourceAlpha + destRgba.blue * (1 - sourceAlpha),
        opacity: 1
    )
}

private func contrastRatio(_ foreground: Color, _ background: Color) -> CGFloat {
    let foregroundLuminance = foreground.luminance()
    let backgroundLuminance = background.luminance()
    let lighter = max(foregroundLuminance, backgroundLuminance)
    let darker = min(foregroundLuminance, backgroundLuminance)
    return (lighter + contrastOffset) / (darker + contrastOffset)
}

private func readableLabelColor(_ background: Color) -> Color {
    contrastRatio(Color.black, background) >= contrastRatio(Color.white, background)
        ? Color.black
        : Color.white
}

private func decodeSrgbChannel(_ encoded: CGFloat) -> CGFloat {
    let safeEncoded = min(max(encoded, 0), 1)
    if safeEncoded <= 0.04045 {
        return safeEncoded / 12.92
    }
    return CGFloat(pow(Double((safeEncoded + 0.055) / 1.055), 2.4))
}

private func calculateRelativeLuminance(red: CGFloat, green: CGFloat, blue: CGFloat) -> CGFloat {
    0.2126 * decodeSrgbChannel(red)
        + 0.7152 * decodeSrgbChannel(green)
        + 0.0722 * decodeSrgbChannel(blue)
}

private func zeroDecimals(_ value: CGFloat) -> String {
    String(format: "%.0f", Double(value))
}

private func oneDecimal(_ value: CGFloat) -> String {
    String(format: "%.1f", Double(value))
}

private func twoDecimals(_ value: CGFloat) -> String {
    String(format: "%.2f", Double(value))
}

private func fourDecimals(_ value: CGFloat) -> String {
    String(format: "%.4f", Double(value))
}

private func sixDecimals(_ value: CGFloat) -> String {
    String(format: "%.6f", Double(value))
}

private func signed4(_ value: CGFloat) -> String {
    let normalized = abs(value) < 0.00005 ? 0 : value
    return String(format: "%+.4f", Double(normalized))
}

private extension Color {
    init(hex: UInt32) {
        self.init(
            red: Double((hex >> 16) & 0xFF) / 255,
            green: Double((hex >> 8) & 0xFF) / 255,
            blue: Double(hex & 0xFF) / 255
        )
    }

    func toStraightRgba() -> StraightRgba {
        var red: CGFloat = 0
        var green: CGFloat = 0
        var blue: CGFloat = 0
        var alpha: CGFloat = 0
        guard UIColor(self).getRed(&red, green: &green, blue: &blue, alpha: &alpha) else {
            return StraightRgba(red: 0, green: 0, blue: 0, alpha: 0)
        }
        return StraightRgba(red: red, green: green, blue: blue, alpha: alpha)
    }

    func rgbText() -> String {
        let rgba = toStraightRgba()
        return "RGB(\(fourDecimals(rgba.red)), \(fourDecimals(rgba.green)), \(fourDecimals(rgba.blue)))"
    }

    func rgbaText() -> String {
        let rgba = toStraightRgba()
        return "RGBA(\(fourDecimals(rgba.red)), \(fourDecimals(rgba.green)), " +
            "\(fourDecimals(rgba.blue)), \(fourDecimals(rgba.alpha)))"
    }

    func hasSameRgb(_ other: Color) -> Bool {
        let tolerance: CGFloat = 0.00005
        let lhs = toStraightRgba()
        let rhs = other.toStraightRgba()
        return abs(lhs.red - rhs.red) <= tolerance
            && abs(lhs.green - rhs.green) <= tolerance
            && abs(lhs.blue - rhs.blue) <= tolerance
    }

    func luminance() -> CGFloat {
        let rgba = toStraightRgba()
        return calculateRelativeLuminance(red: rgba.red, green: rgba.green, blue: rgba.blue)
    }
}

Exercise 1 · Calculate the default gray reference
For straight sRGB RGB(0.65, 0.35, 0.70):

Exercise 2 · Diagnostic: is 0.43910 the relative luminance?
No. It is the gray reference used by this saturation matrix. It combines stored sRGB channel values directly. Relative luminance first decodes sRGB into linear-light values. The input color's relative luminance is approximately 0.185009.

17 · Sources and evidence limits
What the lab matrix and SwiftUI Color establish
  • The lab helper ColorMatrix.setToSaturation copies a 4×5 matrix with weights 0.213, 0.715, and 0.072, an unchanged alpha row, and zero offsets. Do not use Core Image's default saturation.
  • Apple Developer · SwiftUI Color documents Color(red:green:blue:opacity:) as 0...1 components stored separately from opacity.
  • The lab helper luminance() copies the sRGB Rec.709 path taught in Lesson 3.6. SwiftUI Color has no luminance API of its own.
Evidence limit: this lesson reproduces the copied 4×5 matrix values and applies them to normalized straight sRGB inputs in Swift. It does not claim that this transform is the only valid definition of saturation, that it preserves WCAG relative luminance, or that it reveals every color-management step owned by the iOS renderer.
