Chapter 3 · Color, opacity, and compositing

From one visible color to one relative-luminance number

You already know this object: Color(red: 0.80, green: 0.25, blue: 0.60, opacity: 1.00). It draws one opaque color. This lesson answers one question: how can the program turn that final visible color into one number that a later lesson can use when comparing text or icon colors with their background?

Relative luminance is that number. This lesson uses sRGB, which means standard Red Green Blue. sRGB is a standard that gives red, green, and blue channel numbers precise meanings. The calculation uses two fixed reference endpoints: sRGB black is 0 and sRGB white is 1. The result is a mathematical value calculated from the color. It is not the iPhone 16 Pro brightness control. It is not a physical display-luminance measurement in nits, which are units used to report physical luminance.

Learning promise: the conversion formula will not appear until the input number, the output number, and the reason for the conversion have all been defined.
One complete path
  1. Start with the three channel numbers in one opaque Color.
  2. Follow one channel through the standard conversion used before calculations that add or scale modeled light contributions.
  3. Repeat the same conversion for the other two channels.
  4. Multiply the three converted values by three fixed multipliers.
  5. Add the three results to obtain one relative-luminance number.

Section 5 names each fixed multiplier a coefficient and explains why the three multipliers are different.

1 · Start with a known object

The input is one final opaque SwiftUI Color

No photograph, shader, texture, or sampled screen area is involved.

Visible opaque region

What is already known?

  • The tuple has red, green, blue, and alpha fields.
  • Alpha is fixed at 1.00. The color completely covers the destination at this position.
  • The final visible RGB therefore equals the RGB in this Color object.

What does sRGB mean here?

A color space is a rule set that gives numeric color channels a precise meaning. This lesson uses sRGB, meaning standard Red Green Blue, as its color space. We need only one part of that standard now: the rule that maps each sRGB channel number to a second number used for light arithmetic. Section 2 names and defines that second number.

Why do we want one number?

Later, a glass control may need to compare a background color with a text or icon color. Comparing three channels separately is awkward. Relative luminance reduces one final opaque color to one standardized number that later contrast formulas can consume.

Not a display measurement: this lesson reads numbers from a Color object. It does not use a light sensor and it does not measure the iPhone display's physical output.
2 · One channel before three

The number held by Color is not yet a direct light fraction

Choose one channel and follow only that value.

Input: sRGB code value

The phrase sRGB code value means the number supplied to the selected channel in the Color object. “Code value” does not mean program source code. It means a standardized numeric representation.

The word encoded means that the number follows the sRGB transfer curve. A transfer curve is a rule that maps one input number to one output number. The value is not encrypted. It is not compressed. It is simply not proportional to modeled light.

Output: linear-light channel value

A linear-light value is a number used by software to represent how much the selected red, green, or blue channel contributes in a light-based calculation. It is a mathematical model, not a reading from a light sensor. In this representation, doubling the number means doubling that modeled channel contribution.

The output is still one channel. It is not a complete RGB color and it is not relative luminance yet.

Why keep sRGB code values?

A digital channel can store only a finite number of distinct codes. For example, an 8-bit channel has 256 integer codes from 0 through 255. sRGB uses more of those available codes in darker parts of the range than a linear encoding would. This helps reduce banding, which means visible steps inside a transition that should look smooth. More importantly for this lesson, the Color input is declared to use sRGB, so its stored numbers must be interpreted using the sRGB rule.

Why convert to linear light?

Calculations that add or scale modeled light contributions require proportional numbers. The program therefore reads the sRGB numbers using the meaning promised by the Color object, then converts them when a light-based calculation begins. The documentation for the object or function decides which representation its numbers use; the program must not guess.

Five exact mappings

sRGB code valuelinear-light valueMeaning

Why the conversion is necessary

Relative luminance adds light contributions. The addition is meaningful only after the channel values are proportional to modeled light.

sRGB 0.50 ≠ half of modeled light linear 0.50 = half of modeled light

The sRGB code value 0.50 decodes to approximately 0.214. Using 0.50 directly would overstate that channel's modeled light contribution.

3 · Reveal the decoding rule

One input chooses exactly one of two cases

The need for the conversion is now established. We can inspect the standardized formula.

Piecewise formula: a piecewise formula contains more than one case. The input selects one case. The program does not run both cases and average them. The sRGB rule has a short straight case for very small channel values close to black and a curved case for the rest of the range. The value 0.04045 is the fixed point where the rule changes cases.
if sRGB code value ≤ 0.04045: linear light = sRGB code value ÷ 12.92 otherwise: linear light = ((sRGB code value + 0.055) ÷ 1.055) raised to 2.4

0.04045

The fixed sRGB boundary that selects the case. A current channel value at or below this number uses the short straight case. A larger value uses the curved case. The boundary is not calculated from the current color.

12.92

The divisor in the short straight case. Dividing a very small sRGB code value by 12.92 produces its smaller linear-light value.

0.055

The fixed amount added to a channel value in the curved case. This shifts the input before the next scaling operation.

1.055

The fixed divisor used after adding 0.055. It rescales the shifted value before the power operation.

2.4

The fixed exponent in the curved case. “Raised to 2.4” is a calculator power operation that bends the relationship between input and output. It does not mean “multiply by 2.4.” For the course example, 0.526066 ^ 2.4 ≈ 0.214041; multiplying instead would produce about 1.2626, which is a different operation.

Where did these constants come from? They are part of the sRGB standard. Our app did not derive them, and the iPhone 16 Pro did not report them. Their complete derivation from color-measurement standards is outside this beginner lesson. What matters now is the contract: when a channel is sRGB, this rule converts its code value to linear light.

5 · Turn three light contributions into one number
Now define relative luminance completely
The formula appears only after its inputs are available.

    

      

        
What the output means

        
Relative means the number is compared with two reference endpoints: sRGB black is 0 and sRGB white is 1.

        
Luminance here means a standardized light-related quantity calculated from the color's three linear-light channels.

        
The output is a scalar, which means one number rather than an RGB tuple.

      

      

        
What the output does not mean

        
  • It is not a new color.
  • It is not alpha.
  • It is not the iPhone brightness control.
  • It is not a direct measurement of physical display luminance in nits.
  • It does not claim that a person experiences exactly the same percentage of apparent brightness.

      

    

    
Coefficient: a coefficient is a fixed multiplier attached to one changing input. Here, each coefficient tells the formula how much one linear-light primary contributes to the final luminance number: 0.2126 multiplies linear red, 0.7152 multiplies linear green, and 0.0722 multiplies linear blue. These are fixed properties of the standardized sRGB-to-XYZ color calculation; they are not chosen from the current color and they are not UI tuning values. Deriving them requires later matrix and color-measurement mathematics, so this lesson explains their role but does not pretend to derive them.

    
relative luminance
= 0.2126 × linear red
+ 0.7152 × linear green
+ 0.0722 × linear blue

    
Why are the coefficients unequal? The standardized calculation defines red, green, and blue as three different light primaries. An equal numeric amount of each primary does not produce the same luminance contribution in that model. Fully on linear red by itself produces 0.2126; fully on linear green produces 0.7152; fully on linear blue produces 0.0722. The three coefficients add to 1.0000, so linear white (1, 1, 1) produces relative luminance 1.

  

    
Why do the pure-primary checks contain zeros?
(1, 0, 0), (0, 1, 0), and (0, 0, 1) are isolation tests. An isolation test deliberately turns off the other inputs so one coefficient can be checked by itself. For (1, 0, 0), green and blue are zero, so only 0.2126 × 1 remains. The zeros are not the normal input pattern and they are not required by the luminance formula.

    
The main calculation uses mixed values
The course color begins as sRGB (0.80, 0.25, 0.60). After decoding, all three linear-light channels are non-zero, so all three contribution terms take part. Use Mixed check for a second reproducible example: sRGB (0.37, 0.58, 0.21). Fixed non-round values are better than true randomness here because you can repeat and verify the same arithmetic.

6 · Two diagnostic checks
These checks expose the two most common wrong mental models
Use the presets in Section 1 to change the current color.

Pure green
channel average = 0.3333
relative luminance = 0.7152

      
Pure blue
channel average = 0.3333
relative luminance = 0.0722

    

    

      
Wrong model 1: average the stored channels
Pure red, green, and blue all have the same average, but the standardized luminance values are different. The average therefore cannot be the relative-luminance calculation.

      
Wrong model 2: treat sRGB 0.50 as linear 0.50
For 50% sRGB gray, all three code values are 0.50. Each decodes to approximately 0.214. Because the coefficients sum to 1, the relative luminance is also approximately 0.214, not 0.50.

    

  


  

    
7 · Connect the lesson to alpha and source-over
Alpha changes which RGB reaches the luminance formula
Alpha acts during compositing. It is not a fourth relative-luminance term.

    

      
Direct answer
Relative luminance is calculated from three decoded color channels:
L = 0.2126 × linear red
  + 0.7152 × linear green
  + 0.0722 × linear blue
There is no + coefficient × alpha term. Alpha still matters when it is below 1, but it matters earlier: alpha controls how much source color and destination color enter the source-over output RGB.

      
The required order
source straight sRGB RGBA
+ destination straight sRGB RGBA
        ↓ source-over
output straight sRGB RGBA
        ↓ if output alpha is still below 1, composite over the next lower layer
final opaque straight sRGB RGB
        ↓ decode red, green, and blue
final linear-light RGB
        ↓ apply the three coefficients
relative luminance

    

    
What does “final opaque” mean? The output alpha must be 1, so no unknown lower layer can still change the displayed color. When the first destination is translucent, source-over may produce another translucent output. That output must be composited over the next lower layer. Continue until an opaque backing is reached. Without that backing, the tuple does not determine one final visible luminance.

output alpha

These are the familiar Lesson 3.3 operations. Alpha is applied here. It is not applied again as a separate luminance input.

      
This lesson uses opaque destinations
Because destination alpha is 1, output alpha becomes 1. The source-over output RGB is therefore the final visible RGB. Only then does the lesson decode that RGB and calculate relative luminance.

    

    

      
Do not add ambiguous “precomputed RGB” values
Name the numbers before using them. They might be straight sRGB code values, premultiplied sRGB contributions, decoded linear-light values, or output straight RGB. This lesson follows the actual lab-helper call order:
let visibleOutput = source.compositeOver(destination)
let visibleLuminance = visibleOutput.luminance()
compositeOver() produces the output color first. The lab helper luminance() then reads that output color's RGB channels. It does not read opacity. SwiftUI Color has no luminance API of its own; the helper copies the sRGB Rec.709 path taught in this lesson.

      
Do we add source and destination luminance values?
Not in this lesson. Do not calculate one luminance number for the source and another for the destination and then add those two numbers. First calculate the actual source-over output color channel by channel. Then calculate one luminance number from that output RGB. A later color-space lesson must separately explain when linear-light algebra allows shortcuts and whether a renderer composites in encoded or linear space.

    

    
Evidence limit: the browser model and iOS example establish the order used by this lesson. They do not claim that every renderer performs compositing in the same color space. The current goal is narrower: never feed a translucent source's RGB directly into the luminance formula as though the destination did not exist.

private func decodeSrgbChannel(_ encoded: CGFloat) -> DecodedChannel {
    let safeEncoded = min(max(encoded, 0), 1)
    if safeEncoded <= 0.04045 {
        return DecodedChannel(
            encoded: safeEncoded,
            linear: safeEncoded / 12.92,
            branch: .nearBlack
        )
    }
    return DecodedChannel(
        encoded: safeEncoded,
        linear: CGFloat(pow(Double((safeEncoded + 0.055) / 1.055), 2.4)),
        branch: .mainCurve
    )
}

let relativeLuminance =
    0.2126 * linearRed +
    0.7152 * linearGreen +
    0.0722 * linearBlue

private struct StraightRgba {
    let red: CGFloat
    let green: CGFloat
    let blue: CGFloat
    let alpha: CGFloat
}

private func calculateRelativeLuminance(
    red: CGFloat,
    green: CGFloat,
    blue: CGFloat
) -> LuminanceBreakdown {
    let redDecoded = decodeSrgbChannel(red)
    let greenDecoded = decodeSrgbChannel(green)
    let blueDecoded = decodeSrgbChannel(blue)

    let redContribution = 0.2126 * redDecoded.linear
    let greenContribution = 0.7152 * greenDecoded.linear
    let blueContribution = 0.0722 * blueDecoded.linear

    return LuminanceBreakdown(
        red: redDecoded,
        green: greenDecoded,
        blue: blueDecoded,
        redContribution: redContribution,
        greenContribution: greenContribution,
        blueContribution: blueContribution,
        relativeLuminance: redContribution + greenContribution + blueContribution
    )
}

private func decodeSrgbChannel(_ encoded: CGFloat) -> DecodedChannel {
    let safeEncoded = min(max(encoded, 0), 1)
    if safeEncoded <= 0.04045 {
        return DecodedChannel(
            encoded: safeEncoded,
            linear: safeEncoded / 12.92,
            branch: .nearBlack
        )
    }
    return DecodedChannel(
        encoded: safeEncoded,
        linear: CGFloat(pow(Double((safeEncoded + 0.055) / 1.055), 2.4)),
        branch: .mainCurve
    )
}

private func threeDecimals(_ value: CGFloat) -> String {
    String(format: "%.3f", Double(value))
}

private func fourDecimals(_ value: CGFloat) -> String {
    String(format: "%.4f", Double(value))
}

private func sixDecimals(_ value: CGFloat) -> String {
    String(format: "%.6f", Double(value))
}

private extension Color {
    init(hex: UInt32) {
        self.init(
            red: Double((hex >> 16) & 0xFF) / 255,
            green: Double((hex >> 8) & 0xFF) / 255,
            blue: Double(hex & 0xFF) / 255
        )
    }

    func toStraightRgba() -> StraightRgba {
        var red: CGFloat = 0
        var green: CGFloat = 0
        var blue: CGFloat = 0
        var alpha: CGFloat = 0
        guard UIColor(self).getRed(&red, green: &green, blue: &blue, alpha: &alpha) else {
            return StraightRgba(red: 0, green: 0, blue: 0, alpha: 0)
        }
        return StraightRgba(red: red, green: green, blue: blue, alpha: alpha)
    }

    func compositeOver(_ destination: Color) -> Color {
        let source = toStraightRgba()
        let dest = destination.toStraightRgba()
        let destinationOpening = 1 - source.alpha
        let outputAlpha = source.alpha + dest.alpha * destinationOpening
        let outputPremultipliedRed =
            source.red * source.alpha + dest.red * dest.alpha * destinationOpening
        let outputPremultipliedGreen =
            source.green * source.alpha + dest.green * dest.alpha * destinationOpening
        let outputPremultipliedBlue =
            source.blue * source.alpha + dest.blue * dest.alpha * destinationOpening
        if outputAlpha <= 0 {
            return Color(red: 0, green: 0, blue: 0, opacity: 0)
        }
        return Color(
            red: min(max(outputPremultipliedRed / outputAlpha, 0), 1),
            green: min(max(outputPremultipliedGreen / outputAlpha, 0), 1),
            blue: min(max(outputPremultipliedBlue / outputAlpha, 0), 1),
            opacity: min(max(outputAlpha, 0), 1)
        )
    }

    func luminance() -> CGFloat {
        let rgba = toStraightRgba()
        return calculateRelativeLuminance(
            red: rgba.red,
            green: rgba.green,
            blue: rgba.blue
        ).relativeLuminance
    }
}

12 · Exercises
Answer without opening the hidden solutions
At least one question deliberately targets the likely misconception.

    
Exercise 1 · What do the two numbers mean?
Question: For a gray sRGB channel, explain the difference between sRGB code value 0.50 and linear-light value approximately 0.214.
Answer: 0.50 is the channel number held by the sRGB Color. It is not proportional to light. The sRGB decoding rule maps it to approximately 0.214, which is the modeled linear-light channel contribution used by light-based calculations.

    
Exercise 2 · Select the branch
Question: Which branch decodes sRGB code value 0.02, and what is the approximate result?
Answer: 0.02 ≤ 0.04045, so use the near-black branch: 0.02 ÷ 12.92 ≈ 0.001548.

    
Exercise 3 · Diagnostic: where does alpha enter?
Question: A source is Straight RGBA(0.80, 0.25, 0.60, 0.50). Does relative luminance add a fourth term for alpha? What must happen first?
Answer: No. Relative luminance still has only red, green, and blue terms. Alpha acts earlier in source-over compositing. Composite the source over the actual destination. If the result remains translucent, continue through lower layers until the displayed output is opaque. Then decode that final output RGB and calculate relative luminance.

    
Exercise 4 · Why do the coefficients add to one?
Question: What result does linear-light white (1, 1, 1) produce?
Answer: 0.2126 × 1 + 0.7152 × 1 + 0.0722 × 1 = 1.0000. This is why the reference white maps to relative luminance 1.

Sources and evidence limits
What the standards and lab helper establish

    
    
      
  • W3C CSS Color 4 · sRGB and sRGB-linear defines the sRGB transfer rule and distinguishes gamma-encoded components from linear-light components.
    • 
      
  • WCAG 2.2 · relative luminance defines the normalized 0-to-1 quantity, the sRGB decoding rule, and the coefficients 0.2126, 0.7152, and 0.0722.
    • 
      
  • Apple Developer · SwiftUI Color documents Color(red:green:blue:opacity:) as 0...1 components stored separately from opacity. The lab helpers compositeOver() and luminance() copy the straight-RGBA source-over formula and the sRGB Rec.709 luminance path taught in this lesson. luminance() decodes and weights red, green, and blue; it does not read opacity.
