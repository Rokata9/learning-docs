Chapter 3 · Color, opacity, and compositing

Draw order matters

Draw the same two translucent colors in opposite orders. The overlap changes because the layer drawn second becomes the current source.

One main graphics idea: later drawing operations are placed over earlier drawing operations at positions where they overlap.

Lesson goal

  • Name the source and destination from the actual draw-call order.
  • Predict which pixels can change when two shapes overlap.
  • Explain why both orders have alpha 0.80 but different RGB values.
  • Repair a reversed pair of Canvas draw calls.

1 · Vocabulary

Four exact terms

Each term names a concrete part of the drawing operation.

Draw order

Draw order is the sequence in which drawing operations write into the same drawing target. The first call runs before the second call.

Overlap

An overlap is an image position covered by both shapes. Only overlap positions receive both colored draw operations.

Source and destination

The source is the color being drawn now. The destination is the value already present at that same position.

Commutative

A commutative operation gives the same result after its inputs exchange places. Source-over compositing is not commutative.

magenta over green ≠ green over magenta
The color names do not permanently own the words source and destination. A color becomes the source when its draw call is executing. Reversing the calls reverses those roles at the overlap.

Why alpha matches

In the first order, alpha is 0.50 + 0.60 × 0.50 = 0.80.

In the reversed order, alpha is 0.60 + 0.50 × 0.40 = 0.80.

The two calculations leave the same total covered share.

Why RGB differs

The current source receives its full alpha weight. The lower color receives only its own alpha multiplied by the opening left by the source.

Changing the source changes the weight applied to each color channel.

Per-position rule: Draw order changes a position only when both reordered operations affect that position. A magenta-only position and a green-only position each receive only one colored call, so swapping the two colored calls does not change those positions.

@Composable
private fun DrawOrderCanvas(
    topLayer: TopLayer,
    shapesOverlap: Boolean,
    markerColor: Color,
) {
    Surface(
        modifier = Modifier.fillMaxWidth(),
        shape = PreviewShape,
        color = MaterialTheme.colorScheme.surfaceVariant,
        border = BorderStroke(
            width = 1.dp,
            color = MaterialTheme.colorScheme.outlineVariant,
        ),
    ) {
        Canvas(
            modifier = Modifier
                .fillMaxWidth()
                .height(230.dp),
        ) {
            drawCheckerboard()

            val geometry = orderGeometry(
                drawingSize = size,
                shapesOverlap = shapesOverlap,
            )

            if (topLayer == TopLayer.A) {
                drawLayerB(geometry)
                drawLayerA(geometry)
            } else {
                drawLayerA(geometry)
                drawLayerB(geometry)
            }

            if (shapesOverlap) {
                drawCircle(
                    color = markerColor,
                    radius = 11.dp.toPx(),
                    center = geometry.overlapCenter,
                    style = Stroke(width = 3.dp.toPx()),
                )
                drawCircle(
                    color = OverlapMarker,
                    radius = 4.dp.toPx(),
                    center = geometry.overlapCenter,
                )
            }
        }
    }
}

private data class OrderGeometry(
    val layerSize: Size,
    val layerATopLeft: Offset,
    val layerBTopLeft: Offset,
    val overlapCenter: Offset,
    val cornerRadius: CornerRadius,
)

private fun DrawScope.orderGeometry(
    drawingSize: Size,
    shapesOverlap: Boolean,
): OrderGeometry {
    val layerSize = Size(
        width = drawingSize.width * 0.44f,
        height = drawingSize.height * 0.56f,
    )
    val layerATopLeft = Offset(
        x = drawingSize.width * 0.06f,
        y = drawingSize.height * 0.12f,
    )
    val layerBTopLeft = Offset(
        x = drawingSize.width * if (shapesOverlap) 0.34f else 0.55f,
        y = drawingSize.height * 0.31f,
    )
    val overlapLeft = maxOf(
        layerATopLeft.x,
        layerBTopLeft.x,
    )
    val overlapTop = maxOf(
        layerATopLeft.y,
        layerBTopLeft.y,
    )
    val overlapRight = minOf(
        layerATopLeft.x + layerSize.width,
        layerBTopLeft.x + layerSize.width,
    )
    val overlapBottom = minOf(
        layerATopLeft.y + layerSize.height,
        layerBTopLeft.y + layerSize.height,
    )
    val overlapCenter = Offset(
        x = (overlapLeft + overlapRight) / 2f,
        y = (overlapTop + overlapBottom) / 2f,
    )

    return OrderGeometry(
        layerSize = layerSize,
        layerATopLeft = layerATopLeft,
        layerBTopLeft = layerBTopLeft,
        overlapCenter = overlapCenter,
        cornerRadius = CornerRadius(22.dp.toPx()),
    )
}

private fun DrawScope.drawLayerA(
    geometry: OrderGeometry,
) {
    drawRoundRect(
        color = LayerA.toColor(),
        topLeft = geometry.layerATopLeft,
        size = geometry.layerSize,
        cornerRadius = geometry.cornerRadius,
        blendMode = BlendMode.SrcOver,
    )
}

private fun DrawScope.drawLayerB(
    geometry: OrderGeometry,
) {
    drawRoundRect(
        color = LayerB.toColor(),
        topLeft = geometry.layerBTopLeft,
        size = geometry.layerSize,
        cornerRadius = geometry.cornerRadius,
        blendMode = BlendMode.SrcOver,
    )
}

private fun DrawScope.drawCheckerboard() {
    val cellSize = 22.dp.toPx()
    val columns = ceil(size.width / cellSize).toInt()
    val rows = ceil(size.height / cellSize).toInt()

    for (row in 0 until rows) {
        for (column in 0 until columns) {
            drawRect(
                color = if ((row + column) % 2 == 0) {
                    CheckerLight
                } else {
                    CheckerDark
                },
                topLeft = Offset(
                    x = column * cellSize,
                    y = row * cellSize,
                ),
                size = Size(
                    width = cellSize,
                    height = cellSize,
                ),
            )
        }
    }
}

private data class OrderRgba(
    val red: Float,
    val green: Float,
    val blue: Float,
    val alpha: Float,
) {
    fun toColor(): Color = Color(
        red = red,
        green = green,
        blue = blue,
        alpha = alpha,
    )

    fun asTuple(): String =
        "RGBA(${red.twoDecimals()}, ${green.twoDecimals()}, " +
            "${blue.twoDecimals()}, ${alpha.twoDecimals()})"
}

private data class OrderComposite(
    val sourceWeight: Float,
    val destinationWeight: Float,
    val output: OrderRgba,
)

private fun calculateOver(
    source: OrderRgba,
    destination: OrderRgba,
): OrderComposite {
    val sourceWeight = source.alpha
    val destinationWeight = destination.alpha * (1f - source.alpha)
    val outputAlpha = sourceWeight + destinationWeight

    val weightedRed =
        source.red * sourceWeight + destination.red * destinationWeight
    val weightedGreen =
        source.green * sourceWeight + destination.green * destinationWeight
    val weightedBlue =
        source.blue * sourceWeight + destination.blue * destinationWeight

    val output = if (outputAlpha <= 0f) {
        OrderRgba(
            red = 0f,
            green = 0f,
            blue = 0f,
            alpha = 0f,
        )
    } else {
        OrderRgba(
            red = weightedRed / outputAlpha,
            green = weightedGreen / outputAlpha,
            blue = weightedBlue / outputAlpha,
            alpha = outputAlpha,
        )
    }

    return OrderComposite(
        sourceWeight = sourceWeight,
        destinationWeight = destinationWeight,
        output = output,
    )
}

private fun Float.twoDecimals(): String =
    String.format(Locale.US, "%.2f", this)

9 · Exercises
Answer before opening the solutions
Exercise 3 deliberately targets the most likely misconception.
Exercise 1 · Identify the source
The code executes drawGreen() and then drawMagenta(). Which color is the source at an overlap position during the second call?
Show answer
Magenta is the source. The source is the value being drawn by the current call. Green is already present and therefore supplies the destination input for the two-color composition.
Exercise 2 · Reverse the result
Green is drawn over magenta. Use the lesson values. What output straight RGBA tuple should the overlap have?
Show answer
RGBA(0.30, 0.70, 0.50, 0.80). Green has source weight 0.60. Magenta has surviving destination weight 0.50 × (1 − 0.60) = 0.20.
Exercise 3 · Diagnostic
Both draw orders produce output alpha 0.80. Does that prove that the two final overlap colors are identical?
Show answer
No. Output alpha describes total coverage, not the RGB mixture. The two RGB outputs are (0.60, 0.40, 0.65) and (0.30, 0.70, 0.50).
Exercise 4 · Per-position reasoning
A position lies inside the magenta rectangle but outside the green rectangle. Does swapping the two colored draw calls change that position?
Show answer
No. Only magenta covers that position, so only the magenta colored call affects it. Draw order matters there only if another reordered operation also covers that same position.
