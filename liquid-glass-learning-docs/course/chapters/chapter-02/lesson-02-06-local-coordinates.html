Chapter 2 · Coordinate spaces

Local coordinates

A child element starts its own coordinate system. Its top-left corner is local (0, 0). A point inside that child is measured from that local origin.

One graphics idea: the same visible point can have different coordinates in different coordinate systems. One math idea: subtract the child origin to convert a parent-local point into a child-local point.

By the end

  • Define a local coordinate system.
  • Identify the local origin of a child.
  • Calculate local = parent point − child origin.
  • Explain why moving a child does not change a point stored in the child's local coordinates.
  • Use the tap CGPoint returned to the child without adding the child's placement again.
1 · Name the coordinate system

A coordinate is incomplete without its owner

The owner is the element whose origin and axes give the numbers their meaning.

Parent-local

Parent scene

The parent scene has its own origin at its top-left corner. Positions inside that scene can be measured from that origin.

Child-local

Child panel

The child panel starts another coordinate system. The child's top-left corner is child-local (0, 0), even when the child is not at the parent's top-left.

Unit: pt

Local drawing values

Inside the SwiftUI Canvas and tap-gesture code used here, X and Y are point-coordinate values. Lesson 2.5 explained the pt-to-px conversion.

Do not say only “the point is X = 48.” Say “the point is child-local X = 48 pt” or “parent-local X = 48 pt.” The coordinate-system name prevents two different positions from being confused.

3 · Same number, different position

Each origin gives the number a different starting point

Both marks below use X = 48 SVG-local teaching units. They do not occupy the same visible position.

parent-local X = 48 starts at the parent origin
child-local X = 48 starts at the child origin

The number is the same. The origin is different. Therefore the visible positions are different.

Likely mistake: comparing two coordinate numbers without first checking whether they belong to the same coordinate system.

private enum ChildPlacement: String, CaseIterable {
    case left
    case right

    var buttonLabel: String {
        switch self {
        case .left: return "Placement A"
        case .right: return "Placement B"
        }
    }

    var xPt: CGFloat {
        switch self {
        case .left: return 16
        case .right: return 96
        }
    }

    var yPt: CGFloat { 70 }
}

struct LocalCoordinatesExplorer: View {
    @State private var placement = ChildPlacement.left

    private var childPanel: some View {
        ZStack(alignment: .topLeading) {
            Canvas { context, size in
                let verticalStep = size.width / 4
                let horizontalStep = size.height / 4

                for index in 1..<4 {
                    var vertical = Path()

                    var horizontal = Path()

                        horizontal,
                        with: .color(Color(hex: 0x94A3B8).opacity(0.45)),
                        lineWidth: 1
                    )
                }

                topAxis.move(to: .zero)

                        x: selectedPoint.x - innerRadius,
                        y: selectedPoint.y - innerRadius,
                        width: innerRadius * 2,
                        height: innerRadius * 2

                    with: .color(.white)

        }

            childSizePt = newSize

            }
        }
        .onTapGesture(coordinateSpace: .local) { location in
            selectedLocalPt = location
        }
        .accessibilityLabel(
            "Child panel. Tap to choose a position in the child's local coordinate system. " +
            "Current local position is \(formatNumber(selectedPoint.x)) by " +
            "\(formatNumber(selectedPoint.y)) points."
        )
    }
}

private struct ChildSizeKey: PreferenceKey {
    static var defaultValue = CGSize.zero

    static func reduce(value: inout CGSize, nextValue: () -> CGSize) {
        value = nextValue()
    }
}

private extension CGSize {
    func centerPoint() -> CGPoint {
        CGPoint(x: width / 2, y: height / 2)
    }
}

private func formatNumber(_ value: CGFloat) -> String {
    String(format: "%.1f", Double(value))
}

private extension Color {
    init(hex: UInt32) {
        self.init(
            red: Double((hex >> 16) & 0xFF) / 255,
            green: Double((hex >> 8) & 0xFF) / 255,
            blue: Double(hex & 0xFF) / 255
        )
    }
}

9 · Exercises
Answer before opening the details
The first and fourth questions target the most common coordinate-space mistake.


Exercise 1 · Diagnostic subtraction
A child origin is parent-local (120, 70). A point is parent-local (270, 190). What is the child-local point?
Answer: (270 − 120, 190 − 70) = (150, 120). Subtract matching coordinates.


Exercise 2 · Move the child
A point is stored as child-local (64, 48). The child moves 80 pt to the right inside its parent. What happens to the stored child-local point?
Answer: it remains (64, 48). The corresponding parent-local X increases by 80 pt because the entire child moved.


Exercise 3 · Read the callback
The child view receives location = CGPoint(x: 144, y: 96) from onTapGesture. What do the two numbers describe?
Answer: 144 pt to the right and 96 pt down from the containing child view's local top-left origin.


Exercise 4 · Diagnose the wrong marker
The marker is drawn inside the child Canvas, but code first adds the child's parent-local origin to location. Why does the marker move too far?
Answer: the addition converts the value toward parent-local coordinates, then the result is incorrectly consumed by a child-local drawing operation. The code mixes two coordinate spaces.
