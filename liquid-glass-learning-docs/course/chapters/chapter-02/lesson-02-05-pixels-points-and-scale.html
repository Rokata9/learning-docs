Chapter 2 · iOS measurement units

Pixels, points, and scale

SwiftUI layout code expresses intended size in points (pt). A SwiftUI Canvas also draws in points. Pixels (px) are the raster unit used by shader pixel math. Scale (displayScale) is the runtime conversion between those two units.

One graphics idea: layout points and raster pixels can describe the same distance using different units. One math idea: converting pt to px is multiplication by scale.

By the end

  • Define px, pt, and scale.
  • Calculate px = pt × scale.
  • Convert px back with pt = px ÷ scale.
  • Explain why SwiftUI Canvas size.width is not a px value.
  • Read the real runtime displayScale on the iPhone 16 Pro.
1 · Three separate terms

Name the unit before using the number

The number 96 is incomplete until its unit is known.

pt

Point

A point is the SwiftUI layout unit. iOS changes the number of px used for one point according to the current displayScale.

Concrete object: .frame(width: 96, height: 96) requests a layout size in points.

px

Pixel coordinate unit

In this lesson, px is one coordinate unit in the app's raster drawing surface. Shader pixel position and resolution use px. SwiftUI layout and SwiftUI Canvas use points, not px.

Concrete object: shader resolution is points × displayScale in px. A Canvas size.width is a point value until you multiply by scale.

scale

Conversion scale

displayScale tells SwiftUI how many px correspond to one pt on the current screen. On the iPhone 16 Pro it is usually 3.

Example: scale 2.75 means 1 pt → 2.75 px before integer layout rounding. The browser uses 2.75 as a teaching value. The phone reports its own scale.

Shader pixel numbers stay pixels: Lesson 8.4’s 80.0 remains 80 pixels, not 80 points. On the iPhone 16 Pro at scale 3, 80 pixels is a smaller slice of the view than 80 density-independent pixels were on a density-2.625 display. Do not rescale that teaching number.
Not covered yet: physical OLED subpixels, display-compositor scaling, and Dynamic Type text scaling. Those topics do not change today's pt-to-px conversion rule.

3 · Why points exist

Keep layout intent, not a fixed px count

The diagram uses a fixed teaching scale of three SVG units for one pt. SVG units here are only diagram coordinates.

Same layout intent

At scale 1, 96 pt uses 96 px. At scale 3, the same 96 pt uses 288 px. The point width remains the same in the SwiftUI layout model.

96 pt × 1 = 96 px · 96 pt × 3 = 288 px

Common mistake

Using 96 as a shader pixel distance fixes the value at 96 px. On a scale-3 display, that distance represents only 96 ÷ 3 = 32 pt. SwiftUI Canvas can use 96 directly because Canvas is already in points.

private let canvasInsetPt: CGFloat = 16

struct DensityExplorer: View {
    @Environment(\.displayScale) private var displayScale
    @State private var selectedPt = initialSamplePt
    @State private var measuredSquarePt = CGSize.zero
    @State private var measuredCanvasPt = CGSize.zero

    private var requestedSize: CGFloat { CGFloat(selectedPt) }
    private var calculatedSizePx: CGFloat { requestedSize * displayScale }
    private var roundedSizePx: Int { Int(calculatedSizePx.rounded()) }
    private var onePtPx: CGFloat { displayScale }
    private var canvasInsetPx: CGFloat { canvasInsetPt * displayScale }
    private var onePixelPt: CGFloat { 1 / displayScale }
    private var measuredSquarePx: (width: Int, height: Int) {
        pixelSize(from: measuredSquarePt)
    }
    private var measuredCanvasPx: (width: Int, height: Int) {
        pixelSize(from: measuredCanvasPt)
    }

    var body: some View {
        VStack(spacing: 14) {
            Text("Runtime scale = \(formatNumber(displayScale, places: 2)) px per pt")
                .font(.system(size: 22, weight: .black))
                .foregroundStyle(Color(hex: 0x1E40AF))
            Text(
                "\(selectedPt) pt × \(formatNumber(displayScale, places: 2)) = " +
                "\(formatNumber(calculatedSizePx, places: 2)) px"
            )
            .font(LabType.titleMedium)
            .fontWeight(.bold)
            Text(
                "Layout rasterizes to whole pixels, so this request rounds to \(roundedSizePx) px."
            )
            .font(LabType.bodyLarge)

            ZStack {
                RoundedRectangle(cornerRadius: 16, style: .continuous)
                    .fill(Color(hex: 0xDBEAFE))
                RoundedRectangle(cornerRadius: 16, style: .continuous)
                    .strokeBorder(Color(hex: 0x1E40AF), lineWidth: 2)

                    .font(LabType.titleMedium)
                    .fontWeight(.black)
                    .foregroundStyle(Color(hex: 0x1E3A8A))

            .measuredSize($measuredSquarePt, key: SquareSizeKey.self)
            .accessibilityLabel(
                "Square requested as \(selectedPt) points, " +
                "measured as \(measuredSquarePx.width) by \(measuredSquarePx.height) pixels"
            )

            Text(
                "Measured square = \(measuredSquarePx.width) × \(measuredSquarePx.height) px"
            )
            .font(LabType.bodyLarge)
            .fontWeight(.bold)
            .foregroundStyle(Color(hex: 0x059669))

            HStack(spacing: 8) {
                ForEach(sampleSizesPt, id: \.self) { sizePt in
                    let selected = selectedPt == sizePt
                    if selected {
                        Button {
                            selectedPt = sizePt
                        } label: {

    private func pixelSize(from points: CGSize) -> (width: Int, height: Int) {
        (
            width: Int((points.width * displayScale).rounded()),
            height: Int((points.height * displayScale).rounded())
        )
    }
}

private struct SquareSizeKey: PreferenceKey {
    static var defaultValue = CGSize.zero

    static func reduce(value: inout CGSize, nextValue: () -> CGSize) {
        value = nextValue()
    }
}

private struct CanvasSizeKey: PreferenceKey {
    static var defaultValue = CGSize.zero

    static func reduce(value: inout CGSize, nextValue: () -> CGSize) {
        value = nextValue()
    }
}

private extension View {
    func measuredSize<Key: PreferenceKey>(
        _ size: Binding<CGSize>,
        key: Key.Type
    ) -> some View where Key.Value == CGSize {
        background {
            GeometryReader { proxy in
                Color.clear.preference(key: key, value: proxy.size)
            }
        }
        .onPreferenceChange(key) { size.wrappedValue = $0 }
    }
}

private func formatNumber(_ value: CGFloat, places: Int) -> String {
    String(format: "%.\(places)f", Double(value))
}

private extension Color {
    init(hex: UInt32) {
        self.init(
            red: Double((hex >> 16) & 0xFF) / 255,
            green: Double((hex >> 8) & 0xFF) / 255,
            blue: Double(hex & 0xFF) / 255
        )
    }

9 · Exercises
Predict before opening the answers
At least one question targets the most common unit mistake.

    
Exercise 1 · A component is 96 pt wide and scale is 2.75 px per pt. What is its converted width?
Answer: 96 × 2.75 = 264 px.

    
Exercise 2 · A measured shader pixel distance is 220 px and scale is 2.75. What is the equivalent point distance?
Answer: 220 ÷ 2.75 = 80 pt.

    
Exercise 3 · Diagnostic: inside a SwiftUI Canvas, size.width is 600. Is that 600 px?
Answer: no. Inside the Canvas draw block, size.width is 600 pt. Multiply by the current displayScale when you specifically need a pixel value for a shader. Convert the other way only when you need an equivalent point value from a pixel count.

    
Exercise 4 · A design radius is 24 pt. Scale is 3. Why is radius = 24 wrong in a shader that uses pixel coordinates?
Answer: 24 supplies 24 px if you pass it as a pixel uniform, which is only 24 ÷ 3 = 8 pt at scale 3. The intended pixel radius is 24 * displayScale = 72 px. SwiftUI Canvas can use 24 directly because Canvas is in points.
