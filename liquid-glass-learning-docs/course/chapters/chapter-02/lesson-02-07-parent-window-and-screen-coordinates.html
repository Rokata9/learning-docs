Chapter 2 · The screen is a grid

Parent, window, and screen coordinates

One control has one visible top-left corner. The numbers used to describe that corner depend on the origin from which we measure it.

One graphics idea: a control can be located relative to its parent, the application window, or the device screen. One math idea: convert toward a larger coordinate system by adding each origin offset once.

By the end

  • Define parent-local, window-relative, and screen-relative positions.
  • Explain what object owns each origin.
  • Calculate a control position by adding nested offsets.
  • Use GeometryReader in a named parent space, convert(_:to: nil) for the window, and convert(_:to: screen.coordinateSpace) for the screen.
  • Explain why equal window and screen numbers do not make the two coordinate systems identical.
1 · Name every origin

The same corner can have several correct coordinate pairs

This lesson measures the top-left corner of one green control.

Control-local

The control itself

The control's top-left corner is local (0, 0). This pair describes the origin inside the control.

Parent-local

The immediate SwiftUI parent

proxy.frame(in: .named("parentScene")).origin measures the control's top-left corner from the top-left of its parent scene.

Window-relative

The application window

The window is the rectangular iOS surface that contains the application UI. view.convert(.zero, to: nil) measures from that window's origin.

Screen-relative

The device screen

view.convert(.zero, to: screen.coordinateSpace) measures from the device screen's origin. The conversion returns nil when the view has no window.

Top-left position, not the whole rectangle

Every API above returns a CGPoint. A CGPoint contains an X value and a Y value for one position. The control's width and height are separate values.

Do not say “the control is at (120, 80)” without naming the coordinate system. Say “the control's top-left is parent-local (120, 80) pt” or “screen-relative (420, 310) pt.”

private enum ControlPlacement: String, CaseIterable {
    case upperLeft
    case lowerRight

    var buttonLabel: String {
        switch self {
        case .upperLeft: return "Placement A"
        case .lowerRight: return "Placement B"
        }
    }

    var xPt: CGFloat {
        switch self {
        case .upperLeft: return 28
        case .lowerRight: return 168
        }
    }

    var yPt: CGFloat {
        switch self {
        case .upperLeft: return 92
        case .lowerRight: return 188
        }
    }
}

    var positionInWindowPt: CGPoint?
    var positionOnScreenPt: CGPoint?

private struct WindowScreenProbe: UIViewRepresentable {
    var onChange: (CGPoint?, CGPoint?) -> Void

    func makeCoordinator() -> Coordinator {
        Coordinator(onChange: onChange)
    }

    func makeUIView(context: Context) -> ProbeView {
        let view = ProbeView()
        view.isUserInteractionEnabled = false
        view.backgroundColor = .clear
        view.onLayout = { [weak view] in
            guard let view else { return }
            context.coordinator.report(from: view)
        }
        return view
    }

    func updateUIView(_ uiView: ProbeView, context: Context) {
        context.coordinator.onChange = onChange
        uiView.onLayout = { [weak uiView] in
            guard let uiView else { return }
            context.coordinator.report(from: uiView)
        }
        DispatchQueue.main.async {
            context.coordinator.report(from: uiView)
        }
    }

    final class Coordinator {
        var onChange: (CGPoint?, CGPoint?) -> Void
        private var lastWindow: CGPoint?
        private var lastScreen: CGPoint?

        init(onChange: @escaping (CGPoint?, CGPoint?) -> Void) {
            self.onChange = onChange
        }

        func report(from view: UIView) {
            let inWindow: CGPoint?
            let onScreen: CGPoint?
            if let window = view.window {
                inWindow = view.convert(.zero, to: nil)
                if let screen = window.windowScene?.screen {
                    onScreen = view.convert(.zero, to: screen.coordinateSpace)
                } else {
                    onScreen = nil
                }
            } else {
                inWindow = nil
                onScreen = nil
            }

            guard inWindow != lastWindow || onScreen != lastScreen else { return }
            lastWindow = inWindow
            lastScreen = onScreen
            onChange(inWindow, onScreen)
        }
    }

    final class ProbeView: UIView {
        var onLayout: (() -> Void)?

        override func layoutSubviews() {
            super.layoutSubviews()
            onLayout?()
        }

        override func didMoveToWindow() {
            super.didMoveToWindow()
            onLayout?()
        }
    }
}

private func addOrNil(_ first: CGPoint?, _ second: CGPoint?) -> CGPoint? {
    guard let first, let second else { return nil }
    return CGPoint(x: first.x + second.x, y: first.y + second.y)
}

private func subtractOrNil(_ first: CGPoint?, _ second: CGPoint?) -> CGPoint? {
    guard let first, let second else { return nil }
    return CGPoint(x: first.x - second.x, y: first.y - second.y)
}

private func coordinateCheckText(expected: CGPoint?, measured: CGPoint?) -> String {
    guard let expected, let measured else {
        return "waiting for coordinates"
    }

    let agrees = abs(expected.x - measured.x) < 0.75 && abs(expected.y - measured.y) < 0.75
    if agrees {
        return "calculated \(formatOffset(expected)); measured \(formatOffset(measured))"
    }
    return "calculated \(formatOffset(expected)); measured \(formatOffset(measured)); " +
        "the current layout contains an additional transform or offset"
}

private func formatOffset(_ offset: CGPoint?) -> String {
    guard let offset else { return "not available" }
    return "(\(formatCoordinate(offset.x)), \(formatCoordinate(offset.y))) pt"
}

private func formatOffsetForSpeech(_ offset: CGPoint?) -> String {
    guard let offset else { return "not yet available" }
    return "\(formatCoordinate(offset.x)) by \(formatCoordinate(offset.y))"
}

private func formatCoordinate(_ value: CGFloat) -> String {
    String(format: "%.1f", Double(value))
}

9 · Exercises
Answer before opening the details
Questions 2 and 4 target the most common mistakes.


1. Parent-to-window calculation
A parent starts at window-relative (240, 180) pt. A control starts at parent-local (90, 70) pt. What is the control's window-relative top-left?
Answer: (330, 250) pt. Add matching components: (240 + 90, 180 + 70).


2. Diagnostic: equal numbers
The app window begins at screen (0, 0). A control is window-relative (330, 250) pt. Its screen-relative reading is also (330, 250) pt. Does this prove that window and screen coordinates are the same coordinate system?
Answer: No. The origins happen to coincide in this configuration. The two systems still name different owners: the app window and the device screen. Moving the window would separate the readings.


3. Move only the window
The control and parent keep the same layout positions, but iOS moves the whole app window 50 pt right and 30 pt down. Which readings change?
Answer: The control-local, parent-local, and window-relative readings stay unchanged. The screen-relative reading increases by (50, 30).


4. Diagnostic: unavailable screen conversion
The screen conversion returns nil. Is it safe to store CGPoint.zero instead and continue as if the control were at the screen origin?
Answer: No. CGPoint.zero is a valid position. It means the real screen origin. An unavailable conversion means the position is not known. Use a nullable state or another explicit unavailable state.
