Chapter 6 · How SwiftUI draws the scene

Lesson 6.6 — Record the background

Lesson 6.5 ended with one concrete missing object: something that can receive BackdropSibling's bands, line, and circle and let later drawing use that same work again. In this lesson, that object is the Image named recordedBackdrop, produced by snapshotting a dedicated background view.

Practical goal: snapshot only BackdropArtwork into recordedBackdrop, then replay it—draw that Image into the visible scene—and replay the same snapshot into a second inspector without recording GlassPanel.
Scope boundary: this is the recording route, not the panel-sized crop. Lesson 6.7 maps panel bounds into backdrop coordinates and selects the matching region.

The route you will build

snapshot means “render this dedicated background view into an Image while it is not the visible scene child.” replay means “draw that Image into the view that should display it now.”

BackdropArtwork draw commands → ImageRenderer(content: dedicatedBackdropView) → recordedBackdrop → Image(recordedBackdrop) → current draw target

New term: recordedBackdrop is an Image produced by snapshotting a dedicated background view. ImageRenderer is the SwiftUI API that performs that snapshot. BackdropRecorder is the lab helper that calls ImageRenderer so later lessons reuse one capture path.

Not implied: replaying the Image does not mean this lesson walks a CPU-readable red-green-blue-alpha pixel array (the central processing unit is where ordinary application code runs). Reading individual stored colors from the bitmap is a separate operation.

1 · OBJECT LEDGER

Name every owner, command set, snapshot, and target first

The names remain stable through every diagram and both implementations.

BackdropSibling

The scene owner already known from Lesson 6.5. It owns the sharp background content.

Produces: BackdropArtwork draw commands.

BackdropArtwork

The commands for six repeating color bands, one horizontal line, and one red circle.

Normal consumer: the current visible draw target.

recordedBackdrop

An Image produced by ImageRenderer from a dedicated BackdropArtwork view. That dedicated view is not the visible scene child.

New consumer: the snapshot operation receives the backdrop commands.

ParentScene

The visible target. It eventually receives one replay of recordedBackdrop, then the separate panel.

Output: the visible scene.

LayerInspector

A second teaching target. It receives another replay of the same full snapshot.

Purpose: prove reusability without pretending this is the panel crop.

4 · ONE COMMAND TRACE

Trace the sharp horizontal line without changing coordinate space

This lesson replays the full snapshot at the same origin and size. Mapping starts in Lesson 6.7.

Why the formula exists

The line needs one owner-local vertical coordinate. The controlled fraction places it at 68% of the backdrop height.

Symbolic: y_line = H × f_y Current values: y_line = 260 pt × 0.68 = 176.8 pt

Complete command: start (20.0 pt, 176.8 pt), end (320.0 pt, 176.8 pt), stroke 4.0 pt, straight sRGB color #0F172A.

Actual trace: BackdropArtwork creates the line command → ImageRenderer places that artwork in recordedBackdrop → the first Image draw turns it into pixels in ParentScene → the second Image draw turns it into pixels in LayerInspector. The owner-local coordinate remains 176.8 pt in this same-size replay. iOS converts it to pixels with ypx = 176.8 pt × d px/pt.
Browser versus iOS: the SVG draws a teaching copy of this route. The iOS explorer uses real ImageRenderer snapshot and Image replay calls and displays the current runtime displayScale.
5 · iOS ROUTE

Read the exact scopes before reading the code as a whole

Dedicated background view

This view is a BackdropArtwork constructed only as ImageRenderer content. It is not the visible scene child in the recording routes.

Normal target in the direct route: the visible scene.

Snapshot scope

While ImageRenderer runs, its offscreen image receives the dedicated view. BackdropRecorder.snapshot is the lab helper that performs that call with an explicit size and displayScale.

Temporary target: the offscreen recordedBackdrop image.

let recordedBackdrop = BackdropRecorder.snapshot(
    size: CGSize(width: 340, height: 260),
    scale: displayScale
) {
    BackdropArtwork()
}

ZStack(alignment: .topLeading) {
    if let recordedBackdrop {
        recordedBackdrop.image
    }
    GlassPanel()
        .offset(x: 64, y: 70)
}

// GlassPanel is a separate later sibling

Operation order

  1. BackdropRecorder.snapshot calls ImageRenderer on the dedicated backdrop view.
  2. The snapshot Image is the intermediate object named recordedBackdrop.
  3. Drawing recordedBackdrop.image replays it into the current visible target.
  4. GlassPanel draws later, outside the snapshot content.
Recording is not video: the snapshot runs when this explorer records the current backdrop. This lesson proves the route for the current draw. Exactly when to snapshot again and how to keep the sample current is Lesson 6.8.

7 · CODING CHALLENGE

Finish the explicit record-and-replay route

The snapshot exists, but nothing draws recordedBackdrop.image into the current target, and GlassPanel is not shown as a later sibling.

Required contract

let recordedBackdrop = BackdropRecorder.snapshot(…) { BackdropArtwork() } if let recordedBackdrop { recordedBackdrop.image } GlassPanel()

The first operation creates the intermediate snapshot. The second operation consumes that snapshot and makes it visible in the current target. GlassPanel stays outside the snapshot content.

8 · EXERCISES

Answer before opening the explanations

1 · Why does the backdrop disappear in the record-only state?

ImageRenderer redirects the dedicated backdrop view into recordedBackdrop. No later Image draw sends that snapshot to ParentScene. Recording and displaying are separate operations.

2 · Why is GlassPanel absent from LayerInspector?

The snapshot content is only BackdropArtwork. GlassPanel is a later sibling outside that content, so its commands never enter recordedBackdrop.

3 · Does the second replay already prove the correct backdrop crop?

No. It replays the entire recorded snapshot at the same origin and size. Lesson 6.7 maps the panel bounds into backdrop coordinates and selects the matching region.

4 · Is recordedBackdrop automatically a CPU-readable array of red-green-blue-alpha pixels that this lesson walks?

No. This lesson uses it as a recorded rendering source that an Image draw can consume. Converting the snapshot to a bitmap—a rectangular pixel image—and reading individual colors is a separate explicit operation and is not required for this replay route.

10 · SOURCES AND EVIDENCE

Keep the proof boundary explicit

What this lesson proves

A dedicated background view can be snapshotted with ImageRenderer so that only the backdrop owner's draw work enters recordedBackdrop. The same recorded Image can then be replayed deliberately into the visible scene and another draw target while the later panel remains excluded.

What remains outside this lesson

No panel-coordinate mapping, panel-sized selection, blur, freshness policy, feedback prevention, CPU readback, or performance conclusion is proved here. Lessons 6.7 through 6.10 handle those boundaries.

  • ImageRenderer — snapshots a dedicated SwiftUI view into an image. This lesson uses that snapshot as a replayable rendering source.
  • Image — draws the recorded snapshot into a later target. Drawing the image is not the same operation as walking a CPU pixel array.
Evidence boundary: the browser SVG is a teaching copy of the route. The iOS explorer executes real ImageRenderer snapshot and Image replay. It does not inspect the renderer's command stream, GPU allocations, or claim that a CPU pixel walk ran. Do not use ultraThinMaterial or glassEffect as the glass path.
