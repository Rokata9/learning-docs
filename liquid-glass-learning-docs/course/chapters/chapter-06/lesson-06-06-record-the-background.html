Chapter 6 · One graphics idea

Lesson 6.6 — Record the background

Lesson 6.5 ended with one concrete missing object: something that can receive BackdropSibling's bands, line, and circle and let later drawing use that same work again. In this lesson, that object is the controlled GraphicsLayer named backgroundLayer.

Practical goal: redirect only BackdropArtwork into backgroundLayer, then replay it—draw its recorded work into the visible scene—and replay the same layer into a second inspector without recording GlassPanel.
Scope boundary: this is the recording route, not the panel-sized crop. Lesson 6.7 maps panel bounds into backdrop coordinates and selects the matching region.

The route you will build

record means “run this drawing while the layer is the active target.” drawLayer means “draw the recorded layer into the target that is active now.”

BackdropArtwork draw commands → backgroundLayer.record { … } → backgroundLayer → drawLayer(backgroundLayer) → current draw target

New term: a GraphicsLayer is a controlled rendering object that can receive recorded draw work and later be drawn into another target.

Not implied: recording does not automatically create a pixel array readable by the CPU (central processing unit, where ordinary application code runs). Pixel readback is a separate operation.

1 · OBJECT LEDGER

Name every owner, command set, layer, and target first

The names remain stable through every diagram and both implementations.

BackdropSibling

The scene owner already known from Lesson 6.5. It owns the sharp background content.

Produces: BackdropArtwork draw commands.

BackdropArtwork

The commands for six repeating color bands, one horizontal line, and one red circle.

Normal consumer: the current visible draw target.

backgroundLayer

A controlled GraphicsLayer returned by rememberGraphicsLayer(). “Remembered” means Compose keeps the same layer object available across recompositions.

New consumer: its record operation receives the backdrop commands.

ParentScene

The visible target. It eventually receives one replay of backgroundLayer, then the separate panel.

Output: the visible scene.

LayerInspector

A second teaching target. It receives another replay of the same full layer.

Purpose: prove reusability without pretending this is the panel crop.

Trace the sharp horizontal line without changing coordinate space

This lesson replays the full layer at the same origin and size. Mapping starts in Lesson 6.7.

Why the formula exists

The line needs one owner-local vertical coordinate. The controlled fraction places it at 68% of the backdrop height.

Symbolic: y_line = H × f_y Current values: y_line = 260 dp × 0.68 = 176.8 dp

Complete command: start (20.0 dp, 176.8 dp), end (320.0 dp, 176.8 dp), stroke 4.0 dp, straight sRGB color #0F172A.

Actual trace: BackdropArtwork creates the line command → record places that command in backgroundLayer → the first drawLayer turns it into pixels in ParentScene → the second drawLayer turns it into pixels in LayerInspector. The owner-local coordinate remains 176.8 dp in this same-size replay. Android converts it to pixels with ypx = 176.8 dp × d px/dp.
Browser versus Android: the SVG draws a teaching copy of this route. The Android explorer uses the real Compose GraphicsLayer recording and replay calls and displays the current runtime density.
5 · ANDROID ROUTE

Read the exact scopes before reading the code as a whole

Outer drawWithContent scope

This scope can call drawContent(). That operation asks the wrapped BackdropArtwork child to emit its draw commands now.

Normal target: the visible canvas.

Inner record scope

While this block runs, backgroundLayer receives the emitted draw work. The label this@drawWithContent explicitly selects the outer scope so its wrapped content can be invoked.

Temporary target: backgroundLayer.

val backgroundLayer = rememberGraphicsLayer()

Box(
    Modifier.drawWithContent {
        backgroundLayer.record {
            this@drawWithContent.drawContent()
        }
        drawLayer(backgroundLayer)
    },
) {
    BackdropArtwork()
}

GlassPanel() // separate later sibling

Operation order

  1. rememberGraphicsLayer() supplies the stable layer handle.
  2. record redirects the wrapped backdrop drawing into that layer.
  3. drawLayer replays the layer into the current visible target.
  4. GlassPanel draws later, outside the recording owner.
Recording is not video: the draw callback executes when Compose redraws this content. This lesson proves the route for the current draw. Exactly when to rerecord and how to keep the sample current is Lesson 6.8.

7 · CODING CHALLENGE

Finish the explicit record-and-replay route

Two things are missing or ambiguous: select the outer content scope explicitly, then replay the recorded layer into the current target.

Required contract

record { this@drawWithContent.drawContent() } drawLayer(backgroundLayer)

The first operation creates the intermediate layer content. The second operation consumes that content and makes it visible in the current target.

8 · EXERCISES

Answer before opening the explanations

1 · Why does the backdrop disappear in the record-only state?

record redirects the wrapped backdrop commands into backgroundLayer. No later drawLayer call sends that layer to ParentScene. Recording and displaying are separate operations.

2 · Why is GlassPanel absent from LayerInspector?

The recording modifier wraps only BackdropArtwork. GlassPanel is a later sibling outside that owner, so its commands never enter backgroundLayer.

3 · Does the second replay already prove the correct backdrop crop?

No. It replays the entire recorded layer at the same origin and size. Lesson 6.7 maps the panel bounds into backdrop coordinates and selects the matching region.

4 · Is backgroundLayer automatically a CPU-readable array of RGBA pixels?

No. This lesson uses it as a recorded rendering source that drawLayer can consume. Converting a layer to a bitmap—a rectangular pixel image—is a separate explicit operation and is not required for this replay route.

10 · SOURCES AND EVIDENCE

Keep the proof boundary explicit

What this lesson proves

A controlled GraphicsLayer can receive only the backdrop owner's draw work. The same recorded layer can then be replayed deliberately into the visible scene and another draw target while the later panel remains excluded.

What remains outside this lesson

No panel-coordinate mapping, panel-sized selection, blur, freshness policy, feedback prevention, CPU readback, or performance conclusion is proved here. Lessons 6.7 through 6.10 handle those boundaries.
