Chapter 6 · One graphics idea

Lesson 6.7 — Crop the correct region

Lesson 6.6 created a reusable backgroundLayer, but every replay still started at the layer's own top-left corner. A glass panel needs the part of that layer that occupies the same place as the panel in the parent scene.

Practical goal: measure the panel bounds in backgroundLayer's local coordinate space, keep a panel-sized target clip fixed at local (0, 0), and shift the full recorded layer so the matching backdrop region lands inside that target.
Scope boundary: the selected region remains sharp. This lesson proves current coordinate mapping and draw-time selection. Lesson 6.8 keeps the sample current while content moves; later lessons handle feedback, cost, and blur.

The complete mapping route

panel LayoutCoordinates → backgroundCoordinates.localBoundingBoxOf(panel) → crop bounds in background-local pixels → clip the panel-local target → translate by (−crop.left, −crop.top) → drawLayer(backgroundLayer)

New term: a coordinate space is a named origin plus axis directions and units. The same visible point has different numeric coordinates when measured from different origins.

Exact meaning of crop here: do not copy pixels into a new CPU image. Limit the current draw target to the panel rectangle, then replay a translated part of the full layer through that rectangle.

1 · THE VISUAL PROBLEM

A full-layer replay has the right image but the wrong starting point

The layer exists. The remaining question is which part of it reaches the panel-local target.

No translation

The panel target clips a 210 × 130 dp rectangle, but the replay starts from backgroundLayer (0, 0). The panel therefore shows the backdrop's top-left region, not the pixels physically behind the panel.

Parent coordinates used directly

The panel's parent position is treated as though it were already background-local. This silently ignores the recorded backdrop owner's own parent offset and shifts the selected pattern.

Correct mapping

Convert the panel bounds into the background owner's local space. The source rectangle then refers to the same physical area as the panel, even though the two objects use different origins.

Two distinct rectangles: the source crop is a rectangle inside backgroundLayer. The panel-local target is a rectangle whose top-left is (0, 0) inside GlassPanel. Translation makes the source rectangle land on the target rectangle.
2 · OBJECTS AND SPACES

Name every origin before subtracting coordinates

ParentScene

The layout that places both the recorded backdrop owner and GlassPanel.

Local size: 340 × 260 dp.

Origin: its own top-left.

BackdropHost

The owner whose artwork is recorded into backgroundLayer.

Parent-local origin: (12, 10) dp.

Local size: 316 × 240 dp.

GlassPanel

The later sibling that needs the matching backdrop region.

Default parent-local origin: (64, 70) dp.

Layout size: 210 × 130 dp.

cropBounds

The panel's axis-aligned layout rectangle expressed in BackdropHost-local pixels.

Default dp model: left/top (52, 60), right/bottom (262, 190).

PanelLocalTarget

The draw scope inside the panel. Its local top-left is always (0, 0).

Clip: 0…210 dp horizontally and 0…130 dp vertically.

5 · ONE COMPLETE BOUNDS AND POINT TRACE

Convert the default panel rectangle, then map one line point

Why each formula exists

1 · Find the source top-left. Both input origins are in ParentScene-local dp, so subtraction is valid.

C_b = P_p − B_p = (64, 70) dp − (12, 10) dp = (52, 60) dp

2 · Find the source bottom-right.

C_b,max = C_b + S_p = (52, 60) dp + (210, 130) dp = (262, 190) dp

3 · Make the source origin land at target origin.

T = −C_b = (−52, −60) dp

Tracked point proof

Q_panel = Q_b + T = (172, 163.2) dp + (−52, −60) dp = (120, 103.2) dp

The tracked backdrop point lands inside the panel because 0 ≤ 120 ≤ 210 and 0 ≤ 103.2 ≤ 130. The selected region therefore places that same physical point at panel-local (120, 103.2).

Why the parent-coordinate defect is visibly wrong

T_wrong = (−64, −70) dp Q_wrong = (172, 163.2) + T_wrong = (108, 93.2) dp error = Q_wrong − Q_panel = (−12, −10) dp

The error exactly equals the ignored backdrop-owner offset, with a negative sign in the output. The pattern shifts left by 12 dp and up by 10 dp.

Runtime units: LayoutCoordinates.localBoundingBoxOf returns pixels. DrawScope.translate also consumes pixels. Android therefore does not convert the returned crop rectangle back to dp before replaying the layer.
6 · ANDROID ROUTE

Measure in the background's space, then replay inside the panel's draw scope

onGloballyPositioned

Runs after layout coordinates are available. The lesson stores the current LayoutCoordinates for BackdropHost and GlassPanel.

Output: two coordinate-conversion objects from the same Compose hierarchy.

localBoundingBoxOf

Called on the background coordinates with the panel coordinates as the source. It converts the panel's axis-aligned layout bounds into background-local pixels.

Output: Rect(left, top, right, bottom).

clipRect + translate + drawLayer

The clip stays in panel-local coordinates. The negative crop translation moves the full layer behind that fixed target. drawLayer then supplies the recorded artwork.

Output: only the matching panel-sized region is visible.

var backgroundCoordinates by remember {
    mutableStateOf<LayoutCoordinates?>(null)
}
var panelCoordinates by remember {
    mutableStateOf<LayoutCoordinates?>(null)
}
var cropBoundsPx by remember {
    mutableStateOf<Rect?>(null)
}

fun updateCropBounds() {
    val background = backgroundCoordinates
    val panel = panelCoordinates

    cropBoundsPx = if (
        background != null &&
        panel != null &&
        background.isAttached &&
        panel.isAttached
    ) {
        background.localBoundingBoxOf(
            sourceCoordinates = panel,
            clipBounds = false,
        )
    } else {
        null
    }
}
Modifier.drawWithContent {
    val crop = cropBoundsPx

    if (crop != null) {
        clipRect {
            translate(
                left = -crop.left,
                top = -crop.top,
            ) {
                drawLayer(backgroundLayer)
            }
        }
    }

    drawContent() // later panel material and details
}
Why clipBounds = false here: the requested mapping is the panel's layout rectangle in background-local coordinates, even if an intermediate ancestor clips visible drawing. This lesson still keeps the panel fully inside the recorded backdrop. A panel partly outside the recorded layer needs an explicit edge policy later.
Rectangle versus shape: localBoundingBoxOf gives the rectangular layout bounds. The panel's rounded shape is a later target clip applied after the rectangular source region has been identified. Do not rename the rounded outline as the source bounds.

Fill the API that converts panel bounds into background-local coordinates, then use the negative crop origin as the replay translation.

Required contract

background.localBoundingBoxOf(panel) → crop Rect in background-local px clip panel-local target → translate(−crop.left, −crop.top) → drawLayer(backgroundLayer)

9 · EXERCISES

Answer before opening the explanations

1 · Why is Pp − Bp valid, but subtracting a screen coordinate from a parent coordinate is not?

Pp and Bp use the same ParentScene origin, axis directions, and dp unit. Their difference is therefore a displacement in that shared space. A screen coordinate and a parent coordinate use different origins; subtracting them without first converting one space into the other produces an undefined mixture.

2 · Why is the translation negative?

The desired source crop begins at positive background-local position Cb. The target begins at panel-local (0, 0). Moving the layer by −Cb sends the source point Cb to Cb + (−Cb) = (0, 0).

3 · Does clipRect create a new cropped bitmap?

No. It limits drawing in the current panel-local target. The full recorded backgroundLayer is still the replay source. Translation and clipping together make only the desired region visible in this draw.

4 · Why is a rounded panel clip not the same object as cropBounds?

cropBounds is the rectangular panel layout extent expressed in background-local coordinates. The rounded clip is a target-shape operation inside the panel after mapping. It removes corner output but does not redefine which rectangular part of the backdrop corresponds to the panel's layout slot.

5 · Does this lesson guarantee correct sampling while a scroll container moves?

No. It proves the mapping for the current measured layout state. Lesson 6.8 examines when the recorded scene and mapped bounds must be refreshed as content scrolls or animates.

11 · SOURCES AND EVIDENCE

Keep the proof boundary explicit

What this lesson proves

Two attached Compose layout nodes can be related through LayoutCoordinates. The panel's current axis-aligned layout bounds can be expressed in background-local pixels. A panel-local clip plus the negative crop translation replays the matching part of backgroundLayer.

What remains outside this lesson

No blur is applied. No guarantee is made about scroll or animation freshness, self-capture feedback, panels outside the recorded layer, rotated sampling geometry, CPU readback, render-target memory, or GPU cost. Lessons 6.8 through 6.10 handle the next boundaries.
