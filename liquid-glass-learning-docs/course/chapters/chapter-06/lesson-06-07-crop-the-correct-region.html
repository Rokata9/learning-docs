Lesson 6.7 — Crop the correct region

Lesson 6.6 created recordedBackdrop, an Image of the full backdrop. Every replay still started at that image's own top-left corner. A glass panel needs the part of that image that occupies the same place as the panel in the parent scene.

Practical goal: measure the panel bounds in recordedBackdrop's local coordinate space, keep a panel-sized target clip fixed at local (0, 0), and offset the full recorded image so the matching backdrop region lands inside that target.
Scope boundary: the selected region remains sharp. This lesson proves current coordinate mapping and draw-time selection. Lesson 6.8 keeps the sample current while content moves; later lessons handle feedback, cost, and blur.

The complete mapping route

panel frame in ParentScene → panel origin − backdrop origin → crop bounds in backdrop-local points → clip the panel-local target → offset by (−cropOrigin.x, −cropOrigin.y) → draw recordedBackdrop.image

New term: a coordinate space is a named origin plus axis directions and units. The same visible point has different numeric coordinates when measured from different origins.

Exact meaning of crop here: do not copy pixels into a new CPU image, and do not treat the sized ImageRenderer snapshot as the crop. That snapshot is the full backdrop. Clip the panel-local target, then offset the full recorded image so the matching region lands inside that clip.

1 · THE VISUAL PROBLEM

A full-image replay has the right picture but the wrong starting point

The snapshot exists. The remaining question is which part of it reaches the panel-local target.

No translation

The panel target clips a 210 × 130 pt rectangle, but the replay starts from recordedBackdrop (0, 0). The panel therefore shows the backdrop's top-left region, not the pixels physically behind the panel.

Parent coordinates used directly

The panel's parent position is treated as though it were already background-local. This silently ignores the recorded backdrop owner's own parent offset and shifts the selected pattern.

Correct mapping

Convert the panel bounds into the background owner's local space. The source rectangle then refers to the same physical area as the panel, even though the two objects use different origins.

Two distinct rectangles: the source crop is a rectangle inside recordedBackdrop. The panel-local target is a rectangle whose top-left is (0, 0) inside GlassPanel. Translation makes the source rectangle land on the target rectangle.
2 · OBJECTS AND SPACES

Name every origin before subtracting coordinates

ParentScene

The layout that places both the recorded backdrop owner and GlassPanel.

Local size: 340 × 260 pt.

Origin: its own top-left.

BackdropHost

The owner whose artwork is recorded into recordedBackdrop.

Parent-local origin: (12, 10) pt.

Local size: 316 × 240 pt.

GlassPanel

The later sibling that needs the matching backdrop region.

Default parent-local origin: (64, 70) pt.

Layout size: 210 × 130 pt.

cropBounds

The panel's axis-aligned layout rectangle expressed in BackdropHost-local points.

Default point model: left/top (52, 60), right/bottom (262, 190).

PanelLocalTarget

The draw scope inside the panel. Its local top-left is always (0, 0).

Clip: 0…210 pt horizontally and 0…130 pt vertically.

5 · ONE COMPLETE BOUNDS AND POINT TRACE

Convert the default panel rectangle, then map one line point

All values below use the controlled point teaching model. SwiftUI layout frames are in points. The snapshot bitmap is those points times displayScale. The image offset stays in points.

Variable ledger before the formulas

VariableMeaning and sourceCoordinate space and unitsNext consumer
Bp BackdropHost top-left inside ParentScene: (12, 10)ParentScene-local ptOrigin subtraction
Pp GlassPanel top-left inside ParentScene: default (64, 70)ParentScene-local ptOrigin subtraction

Why each formula exists

1 · Find the source top-left. Both input origins are in ParentScene-local pt, so subtraction is valid.

C_b = P_p − B_p = (64, 70) pt − (12, 10) pt = (52, 60) pt

2 · Find the source bottom-right.

C_b,max = C_b + S_p = (52, 60) pt + (210, 130) pt = (262, 190) pt

3 · Make the source origin land at target origin.

T = −C_b = (−52, −60) pt

Tracked point proof

Q_panel = Q_b + T = (172, 163.2) pt + (−52, −60) pt = (120, 103.2) pt

The tracked backdrop point lands inside the panel because 0 ≤ 120 ≤ 210 and 0 ≤ 103.2 ≤ 130. The selected region therefore places that same physical point at panel-local (120, 103.2).

Why the parent-coordinate defect is visibly wrong

T_wrong = (−64, −70) pt Q_wrong = (172, 163.2) + T_wrong = (108, 93.2) pt error = Q_wrong − Q_panel = (−12, −10) pt

The error exactly equals the ignored backdrop-owner offset, with a negative sign in the output. The pattern shifts left by 12 pt and up by 10 pt.

Runtime units: GeometryReader frame(in:) returns points. .offset also consumes points. The explorer shows the same crop origin in pixels only as points × displayScale. Do not pass that pixel pair to .offset. ImageRenderer already stored the full backdrop; it does not perform this crop.
6 · iOS ROUTE

Measure both frames in ParentScene, then replay inside the panel clip

frame(in:)

GeometryReader reads each owner's rectangle in the named ParentScene coordinate space. In this controlled scene those readings match the placement state that also positions the views.

Output: two rectangles in the same point space.

Origin subtraction

Subtract BackdropHost's ParentScene origin from GlassPanel's ParentScene origin. The difference is the panel's top-left in backdrop-local points.

Output: cropOrigin.

.clipped() + .offset + Image

The clip stays in panel-local coordinates. The negative crop offset moves the full recorded image behind that fixed target. Drawing recordedBackdrop.image supplies the snapshot.

Output: only the matching panel-sized region is visible.

let backdropFrame = backdropProxy.frame(in: .named("ParentScene"))
let panelFrame = panelProxy.frame(in: .named("ParentScene"))
let cropOrigin = CGPoint(
    x: panelFrame.minX - backdropFrame.minX,
    y: panelFrame.minY - backdropFrame.minY
)
recordedBackdrop.image
    .frame(width: 316, height: 240, alignment: .topLeading)
    .offset(x: -cropOrigin.x, y: -cropOrigin.y)
    .frame(width: 210, height: 130, alignment: .topLeading)
    .clipped()
What frame(in:) returns: the view's layout rectangle in ParentScene points. It is not a drawing clip. This lesson keeps the panel fully inside the recorded backdrop. A panel partly outside the snapshot needs an explicit edge policy later.
Rectangle versus shape: frame(in:) gives the rectangular layout bounds. The panel's rounded shape is a later target clip applied after the rectangular source region has been identified. Do not rename the rounded outline as the source bounds. ImageRenderer recorded the full backdrop; the clip and the offset select the region.

8 · CODING CHALLENGE

Complete the coordinate conversion and replay translation

Subtract the backdrop frame origin from the panel frame origin, then use the negative crop origin as the image offset.

Required contract

panelFrame.min − backdropFrame.min → cropOrigin in backdrop-local points clip the panel-local target → offset(−cropOrigin.x, −cropOrigin.y) → recordedBackdrop.image

The clip defines where output may appear. The offset defines which source position lands at panel-local (0, 0). ImageRenderer does not choose this rectangle.

9 · EXERCISES

Answer before opening the explanations

1 · Why is Pp − Bp valid, but subtracting a screen coordinate from a parent coordinate is not?

Pp and Bp use the same ParentScene origin, axis directions, and pt unit. Their difference is therefore a displacement in that shared space. A screen coordinate and a parent coordinate use different origins; subtracting them without first converting one space into the other produces an undefined mixture.

2 · Why is the translation negative?

The desired source crop begins at positive background-local position Cb. The target begins at panel-local (0, 0). Offsetting the image by −Cb sends the source point Cb to Cb + (−Cb) = (0, 0).

3 · Does .clipped() create a new cropped bitmap?

No. It limits drawing in the current panel-local target. ImageRenderer already stored the full backdrop in recordedBackdrop. The offset and the clip together make only the desired region visible in this draw. The sized snapshot is not the crop.

4 · Why is a rounded panel clip not the same object as cropBounds?

cropBounds is the rectangular panel layout extent expressed in background-local coordinates. The rounded clip is a target-shape operation inside the panel after mapping. It removes corner output but does not redefine which rectangular part of the backdrop corresponds to the panel's layout slot.

5 · Does this lesson guarantee correct sampling while a scroll container moves?

No. It proves the mapping for the current measured layout state. Lesson 6.8 examines when the recorded scene and mapped bounds must be refreshed as content scrolls or animates.

11 · SOURCES AND EVIDENCE

Keep the proof boundary explicit

What this lesson proves

Two SwiftUI frames in the same ParentScene coordinate space can be subtracted. That difference is the panel rectangle in backdrop-local points. A panel-local clip plus the negative offset replays the matching part of recordedBackdrop.

What remains outside this lesson

No blur is applied. No guarantee is made about scroll or animation freshness, self-capture feedback, panels outside the recorded image, rotated sampling geometry, CPU readback, render-target memory, or GPU cost. Lessons 6.8 through 6.10 handle the next boundaries.

  • GeometryProxy.frame(in:) — reads a view's rectangle in a named coordinate space. This lesson uses ParentScene points.
  • ImageRenderer — snapshots the dedicated backdrop view. The snapshot is the full backdrop, not the panel crop.
  • offset(x:y:) — moves the recorded image in points so the crop origin lands at the panel-local origin.
Evidence boundary: the browser SVG is a teaching copy of the route. The iOS explorer executes a real ImageRenderer snapshot, GeometryReader frame reading, and Image replay. It does not walk a CPU pixel array. Do not use ultraThinMaterial or glassEffect as the glass path.
