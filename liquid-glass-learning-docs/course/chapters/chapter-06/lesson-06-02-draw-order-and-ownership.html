Lesson 6.2 — Draw order and ownership

Lesson 6.1 ended with placed nodes ready to draw. This lesson asks two different questions: which draw command runs later, and which UI node owns each command?

Practical problem: a translucent panel, a background pattern, and a foreground label overlap. If the result is wrong, you need to know whether the problem is sibling order, a zIndex override, or drawing inside one node in the wrong internal order.

One distinction to keep

draw order = when a draw command is applied relative to other draws ownership = which node's code issued that draw command

The last visible color at one position can include several owners when translucent draws are involved. Ownership does not transfer merely because another node later covers or mixes with the result.

0 · TERMS BEFORE THE SCENE

Name the objects before changing their order

These terms are separate even when the final screenshot looks simple.

Parent

The layout node whose content block contains the three overlapping children. In this lesson, it is one Box.

Sibling

One child that shares the same immediate parent with another child. The background, panel, and label are siblings.

Draw owner

The node whose code issues a draw command. The background owner draws stripes; the panel owner draws its fill and rim.

Draw order

The sequence in which draws reach the current target. A later opaque draw can cover earlier draws at the same position.

Contributor

One draw whose value participates at the selected position. A translucent panel can leave the background as an earlier contributor.

Ownership is not “whatever is visible on top.” If a panel draws translucent white over a blue stripe, the panel owns the white draw and the background owns the stripe draw. The final pixel can contain both contributions.

4 · SOURCE ORDER VERSUS Z-INDEX

Default sibling order can be overridden

zIndex changes drawing order among children of the same layout parent.

CaseSource child orderzIndex valuesEffective draw orderVisible consequence
Correct defaultBackdrop, Panel, Labelall 0Backdrop, Panel, LabelPanel is over the background; label is over the panel.
Background last defectPanel, Label, Backdropall 0Panel, Label, BackdropOpaque backdrop covers the panel and label.

Do not use zIndex as a substitute for understandable structure. Use ordinary child order when it expresses the intended stack clearly. Use zIndex when overlapping siblings genuinely need an order independent of source order.
5 · A DIFFERENT ORDER: INSIDE ONE NODE

Sibling order is not modifier-internal draw order

This diagnostic stays inside one composable node.

1 · drawBehind

owner = one panel node operation = draw material behind its content output = fill exists before content

drawBehind is a convenience drawing modifier whose commands run behind the composable's content.

2 · drawContent()

operation = draw the node's normal content output = icon or text appears over the fill

Inside drawWithContent, calling drawContent() is what renders the composable's actual content.

3 · Overlay draw

operation = issue another draw after drawContent() output = highlight or diagnostic overlay covers content

The owner is still the same node. Only its internal command order changed.

Modifier
    .drawBehind {
        // Same node: material behind its content.
        drawRoundRect(panelFill)
    }
    .drawWithContent {
        drawContent() // Draw this node's normal content.
        drawRoundRect(
            color = highlight,
            style = Stroke(...),
        ) // Same node: overlay after content.
    }
Two separate axes: first Compose orders sibling nodes relative to one another. Then each node executes its own internal drawing modifiers and content in the order defined by that node.

4 · Owner-local commands

5 · Final frame

Compose combines the effective sibling order with each node's internal drawing order.

Default structure

Box {
    BackdropOwner()
    GlassPanelOwner()
    ForegroundLabelOwner()
}

zIndex rescue

Box {
    BackdropOwner()
    ForegroundLabelOwner(
        Modifier.zIndex(2f),
    )
    GlassPanelOwner()
}

The label and panel remain siblings of the same Box. The larger label zIndex makes it draw later.

9 · EXERCISES

Answer before opening the details

Exercise 1 · Who owns the stripe visible through the translucent panel?

Answer: BackdropScene owns the stripe draw. The panel owns its translucent fill. The final visible position contains contributions from both owners.

Exercise 2 · Why does moving the label call after the panel fix the label?

Answer: with equal zIndex values, the later sibling draw is applied after the panel draw. The label therefore appears above the panel.

Exercise 3 · What does drawContent() do inside drawWithContent?

Answer: it renders the normal content of that same composable node. Draw commands before it appear behind that content; commands after it appear above that content.

Exercise 4 · Does a panel automatically own the background sibling because the background is visible through it?

Answer: no. Visibility through translucency does not transfer ownership. The background sibling still owns its own draws.

11 · SOURCES AND EVIDENCE

What the official APIs support

  • Compose Box is the standard layout for stacking elements on top of one another.
  • Modifier.zIndex controls drawing order for children of the same layout parent.
  • drawBehind draws behind the composable's content.
  • drawWithContent lets a node decide whether custom draws happen before or after drawContent().
