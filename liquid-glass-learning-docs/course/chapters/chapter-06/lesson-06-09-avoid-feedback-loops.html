Chapter 6 · How SwiftUI draws the scene

Avoid feedback loops

The panel needs backdrop pixels, but its own finished output must never become part of the source it samples. The fix is an ownership boundary, not another comparison mode.

One production rule: snapshot only BackdropArtwork. Keep GlassPanel as a later sibling that consumes recordedBackdrop.

The entire route

BackdropArtwork → BackdropHost recording → recordedBackdrop → GlassPanel replay → panel tint and label → ParentScene output

There is no return arrow. GlassPanel output does not re-enter recordedBackdrop.

Compact warning only: snapshotting the whole parent would make the source include the consumer. That creates a circular dependency and is deliberately not implemented as a second mode.
1 · PRACTICAL PROBLEM

A sampled result must not become its own future input

This lesson keeps the correct route central and uses one small counterexample only to name the danger.

Safe, one-way dependency

backdrop commands → recordedBackdrop → panel sample → final panel output

The data moves forward. The panel consumes an already defined source.

Feedback cycle to avoid

whole scene recording → panel sample → panel output → whole scene recording → …

The source now depends on the result that depends on that source. The exact artifact can vary by architecture, but the dependency is already invalid for this lesson’s intended backdrop route.

Definition: a feedback loop exists when an operation’s output is routed back into an input that helps produce the next output. Here, the forbidden return route would be GlassPanel output → recordedBackdrop input.
2 · NAME THE OBJECTS

Five stable names, one ownership boundary

ParentScene

The common parent that places the backdrop and panel as siblings. It is not the recording owner.

BackdropHost

The recorded producer. Its subtree contains only BackdropArtwork.

recordedBackdrop

The replayable Image produced by ImageRenderer from BackdropArtwork. Its coordinate system is BackdropHost-local.

GlassPanel

A later sibling. It consumes recordedBackdrop, then adds panel-owned material and content.

PanelLocalTarget

The panel-sized active draw target that receives the selected backdrop region before tint and label.

6 · iOS ROUTE

Read the implementation as three short blocks

Complete source: AvoidFeedbackLoopsExplorer.swift. The lesson HTML shows only the route-defining excerpts.

1 · Sibling ownership is visible in the layout

ZStack(alignment: .topLeading) {
    BackdropHost(recorded: recordedBackdrop)
    GlassPanel(recorded: recordedBackdrop, panelLeft: panelLeft)
        .offset(x: panelLeft, y: 72)
}

The recording boundary is attached to the smaller producer, not to the common parent. GlassPanel is a later sibling.

2 · Snapshot and visibly replay only the backdrop

recordedBackdrop = BackdropRecorder.snapshot(
    size: CGSize(width: 340, height: 240),
    scale: displayScale
) {
    BackdropArtwork()
}

recordedBackdrop.image

BackdropRecorder calls ImageRenderer on a dedicated BackdropArtwork view. That view is not ParentScene, and GlassPanel is not inside it. Drawing recordedBackdrop.image puts the snapshot back into the visible BackdropHost. The snapshot is an Image, not a CPU pixel walk.

3 · One position value drives placement and crop

recordedBackdrop.image
    .frame(width: 340, height: 240, alignment: .topLeading)
    .offset(x: -panelLeft, y: -72)
    .frame(width: 196, height: 116, alignment: .topLeading)
    .clipped()

// then GlassPanel draws its tint, border, and label

In this controlled scene, ParentScene and BackdropHost share origin (0, 0). The same panelLeft and fixed top value therefore drive both placement and the negative source offset, without a separately stored crop rectangle. .offset uses points. Snapshot pixels are pt × displayScale and are not passed to .offset. Panel-owned commands still happen afterward and outside the source owner.

Source constants are named

feedbackSceneWidth, feedbackPanelWidth, and every preset are declared once. Comments state why the scene fits the direct 412 × 915 preview and why each allowed panel position remains in bounds.

Backdrop artwork math is local and explained

The equal band width is size.width / 4, and the four band fills are the band count. The guide line and marker centers use named scene-local point coordinates instead of unexplained fractions. Comments distinguish geometry values from purely visual alpha choices.

No diagnostic branches or trailing crop state

The file contains no “safe/unsafe” enum, no captured comparison snapshot, and no separately stored crop rectangle. One panel position value drives both placement and replay offset. The unsafe cycle exists only as the small conceptual warning in Section 1.

Official reference: ImageRenderer snapshots the dedicated backdrop view. offset(x:y:) moves that image in points.

8 · CODING CHALLENGE

Complete the one-way source route

There are only three blanks. No alternate mode is required.

Fill the record body, the visible replay, and the later sibling consumer.

Required behavior

  1. Snapshot BackdropArtwork() with BackdropRecorder.snapshot.
  2. Replay recordedBackdrop.image so the backdrop remains visible.
  3. Place GlassPanel(recorded: recordedBackdrop) after BackdropHost as a sibling.

Do not move the snapshot to the common parent. Do not use ultraThinMaterial or glassEffect as the glass path.

9 · EXPLAIN IT BACK

Five checks for ownership reasoning

1 · Why is sibling order not enough by itself?

Order tells us which sibling draws first. The recording boundary tells us which owner’s content enters recordedBackdrop. The panel must be both later in draw order and outside the recorded owner’s subtree.

2 · Why can the panel replay recordedBackdrop without joining it?

Drawing recordedBackdrop.image does not move the consumer into the producer’s ownership subtree. GlassPanel remains a separate sibling whose draw target receives the replayed backdrop image.

3 · Why is recording ParentScene too broad?

ParentScene owns both siblings. Recording its complete content would admit backdrop commands and panel commands into the same source boundary, so the intended one-way backdrop dependency would be lost.

4 · Does moving the panel alter which commands belong to recordedBackdrop?

No. Motion changes the crop rectangle consumed by the panel. Ownership remains unchanged: BackdropArtwork still supplies the recorded commands and GlassPanel still remains outside that subtree.

5 · Why does this lesson not need a runnable unsafe mode?

The main concept is the correct ownership boundary. A second route would add state, branches, and duplicate explanation without improving the production implementation. The static cycle diagram is enough to identify what must not be connected.
