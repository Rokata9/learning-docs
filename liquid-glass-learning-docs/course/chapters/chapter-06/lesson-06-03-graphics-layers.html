Chapter 6 · How SwiftUI draws the scene

Lesson 6.3 — Graphics layers

Lesson 6.2 gave one owner several draw commands. This lesson groups those commands so offset, rotation, scale, opacity, and later effects can be applied to the complete owner as one unit.

Practical problem: the panel base, stripe, status dot, and label must move and fade together. Updating every draw command separately would duplicate transformation logic and make later effects harder to attach consistently.

The boundary to keep

owner transform group = one view whose drawing instructions receive one set of offset, rotation, scale, and opacity not automatically = one stored pixel image not automatically = a readable copy of sibling backdrop pixels
0 · PREREQUISITE LEDGER

Name every object before the first layer property

Only the draw-layer terms are new.

Owner view

LayerArtwork is one SwiftUI view that owns the panel base, stripe, dot, and label.

Drawing instructions

Commands such as “draw rounded rectangle” and “draw dot.” They describe what the owner paints.

Owner transform group

The owner view plus the modifiers that apply offset, rotation, scale, and opacity to every owned draw as one unit. Later owner properties affect the complete group.

Offscreen image

Rasterize means execute drawing instructions and store their result as pixels. An offscreen image is that temporary pixel image before it is drawn into the final scene. drawingGroup() is the explicit SwiftUI modifier that creates one. An owner transform group does not always require one.

4 · DRAW LAYER VERSUS OFFSCREEN PIXELS

Do not use “layer” and “bitmap” as synonyms

Owner group exists

LayerArtwork commands → grouped by owner modifiers → offset, rotation, scale, and opacity can transform the group

This is the core owner-transform contract.

Offscreen is explicit

opacity < 1 → complete owner fades as one group drawingGroup() → explicit offscreen image, not implied

Opacity below 1 does not prove that SwiftUI allocated an offscreen image. drawingGroup() is the named extra step that does.

No sibling capture

Backdrop sibling ≠ automatic input image for LayerArtwork

The owner group contains its own content. It does not create a readable copy of unrelated siblings behind it.

Deferred: Lesson 6.4 applies .blur() to the owner's own content. Lessons 6.6–6.8 create the explicit backdrop recording, coordinate mapping, and replay route.

6 · iOS VALUE PATH

Apply one set of owner modifiers to the view that contains every draw

1 · Layout

LayerArtwork receives one measured slot.

2 · Internal drawing

Canvas commands and label content belong to that owner.

3 · Owner modifiers

The owner content becomes one transform group.

4 · Layer properties

Offset, rotation, scale, opacity, and origin apply to the group.

5 · Parent drawing

The transformed owner is composited into the scene.

LayerArtworkContent()
    .frame(width: 210, height: 120)
    .scaleEffect(uniformScale, anchor: selectedOrigin)
    .rotationEffect(.degrees(rotationDegrees), anchor: selectedOrigin)
    .offset(x: translationXPt, y: translationYPt)
    .compositingGroup()
    .opacity(layerAlpha)
Why this modifier order: Lesson 4.10 already applied scale, then rotation, around one UnitPoint. Offset then moves that result along the parent axes. compositingGroup() plus one .opacity fades the flattened owner. Changing those properties does not change the measured slot or rewrite each internal command.
iOS opacity contract: every base, stripe, dot, detail line, and label color is opaque in the controlled iOS scene. layerAlpha is applied once as .opacity to the complete owner. The faded original-position ghost is a separate evidence copy with its own outer opacity; it is not implemented by multiplying opacity into every child. The detached blue translation line was removed because it was not anchored or labelled clearly enough to function as evidence.
Preview-fit boundary: the iOS teaching card uses a compact 210 × 120 point measured slot and conservative default transform values so the complete transformed result remains inspectable in a 412-point Xcode #Preview. The browser uses larger teaching units because it has a much wider desktop diagram.

9 · EXERCISES

Answer before opening each explanation

Exercise 1 · Layout slot

A 360 × 200 view scales to 1.2× using scaleEffect. Does layout reserve a 432 × 240 slot?

Show answer

No. The measured slot remains 360 × 200. Only the draw result is scaled.

Exercise 2 · Whole-group opacity

Where should .opacity(0.5) be applied if the base, dot, and label must fade together?

Show answer

Apply the opacity on the owner that contains the complete group, not independently to only one child.

Exercise 3 · Offscreen boundary

Does applying offset, rotationEffect, and scaleEffect prove that SwiftUI allocated an offscreen image?

Show answer

No. Those modifiers group drawing instructions. drawingGroup() is the explicit extra step that composites the view into an offscreen image. Opacity below 1 does not prove that step ran.

Exercise 4 · Backdrop

Does placing the glass panel in an owner transform group automatically give it a readable image of the backdrop sibling?

Show answer

No. An explicit record, mapping, crop, and replay/read route is still required.

11 · SOURCES AND EVIDENCE

Primary iOS contracts used by the lesson

  • View.offset(x:y:) — moves drawing without changing the measured layout slot.
  • View.rotationEffect(_:anchor:) and View.scaleEffect(_:anchor:) — rotate and scale around a UnitPoint without changing layout size.
  • View.opacity(_:) and View.compositingGroup() — one opacity on a flattened owner group.
  • View.drawingGroup(opaque:colorMode:) — explicit offscreen image. This lesson does not call it.
Evidence boundary: the browser reproduces the layer-property geometry. The iOS explorer executes real offset, rotationEffect, scaleEffect, compositingGroup, and opacity. It does not inspect the renderer's internal command stream or GPU allocations, and it does not prove that opacity below 1 allocated an offscreen image.
