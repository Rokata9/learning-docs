Chapter 6 · How SwiftUI draws the scene

Build a two-layer scene architecture

Use two controlled products for the backdrop source and the panel sample. Draw tint, border, and sharp foreground content in explicit later stages.

Main rule: the future blur view must own the backdrop crop, and it must not own the label or icon that should remain sharp.

Two layers does not mean two offscreen images

Layer 1 is recordedBackdrop, the ImageRenderer image of the full backdrop. That product is pixels: backdrop points times displayScale.

Layer 2 is panelSample, a clip and offset of that same image. This lesson does not call drawingGroup() and does not snapshot the panel, so the sample is not a second offscreen image allocated here.

ForegroundContent is an ordinary later child, not a third recorded product.

1 · Practical problem

Keep the future blur away from labels

Architecture decides which views can become blur input.

One overloaded panel owner

If the sampled backdrop, tint, border, icon, and label all enter one future blur view, the sharp foreground becomes blur input too.

One explicit owner split

Let ArchitectureGlassMaterial own the sampled backdrop and the later tint and border. Let ArchitectureForegroundContent draw afterward as an ordinary child.

Lessons 6.6–6.10 established the ImageRenderer snapshot, the clip and offset crop, freshness, one-way ownership, one shared panel position, and the difference between that snapshot and a drawingGroup() target. This lesson assembles those pieces into one route and leaves drawingGroup() off.

6 · iOS route

The complete source stays readable

Open TwoLayerSceneArchitectureExplorer.swift for the full implementation.

A · Snapshot the backdrop once

recordedBackdrop = BackdropRecorder.snapshot(
    size: CGSize(width: 340, height: 240),
    scale: displayScale
) {
    ArchitectureBackdropArtwork()
}

B · Keep producer and consumer as siblings

ZStack(alignment: .topLeading) {
    ArchitectureBackdropHost(recorded: recordedBackdrop)

    ArchitectureGlassPanel(
        recorded: recordedBackdrop,
        panelLeft: panelLeftPt
    )
    .offset(x: panelLeftPt, y: 72)
}

C · Split material from foreground

ZStack {
    ArchitectureGlassMaterial(
        recorded: recordedBackdrop,
        panelLeft: panelLeftPt
    )

    ArchitectureForegroundContent()
}

Read the child order literally

ArchitectureGlassMaterial is the first child. ArchitectureForegroundContent is the later child, so its dot and text draw over the complete material.

D · Replay only the crop, then add material outside that view

recorded.image
    .resizable()
    .interpolation(.none)
    .frame(width: 340, height: 240, alignment: .topLeading)
    .offset(x: -panelLeft, y: -72)
    .frame(width: 196, height: 116, alignment: .topLeading)
    .clipped()

// Tint and border are later siblings of this view.
// This lesson does not call drawingGroup().
No drawingGroup() here: the sharp Chapter 6 route does not need a second offscreen image. Lesson 6.10 called drawingGroup(opaque: false) only so one panel-sized target existed for the size estimate. Chapter 7 will add a blur that needs the sample as pixel input. Do not use ultraThinMaterial or glassEffect as the glass path.
Official reference: ImageRenderer snapshots ArchitectureBackdropArtwork. offset(x:y:) moves the replay in points. clipped(antialiased:) keeps the replay inside the panel frame.

Restore the role boundaries

The material must receive the existing snapshot and the current panel position. The foreground call must remain a later sibling rather than moving inside the sample view.

9 · Explain back

Four checks for the architecture

Open an answer only after stating your own version.

Why is ForegroundContent not a third layer?

The architecture needs two controlled products: the full backdrop image and the panel crop replay. The foreground is an ordinary later child. A third snapshot would not improve the ownership rule being taught.

Why will the label stay outside a future blur on panelSample?

The label is created after ArchitectureGlassMaterial. It is not a child of the clipped replay, so it is not part of that view’s input.

Why can the panel not capture itself?

ArchitectureBackdropHost and ArchitectureGlassPanel are siblings. BackdropRecorder snapshots only ArchitectureBackdropArtwork. The consumer panel belongs to a later sibling.

Why does one panel position also define the crop in this sample?

BackdropHost fills ParentScene, and both begin at local origin (0, 0). Therefore the panel’s parent-local origin equals its backdrop-local crop origin. .offset uses those points. Arbitrary nested layouts still require a real coordinate mapping.

Established

One ImageRenderer image and one panel replay view coexist with a third ordinary foreground role. The snapshot excludes the consumer.
