Lesson 6.5 — The backdrop problem

Lesson 6.4 proved that .blur() reads pixels rasterized from its selected owner. This lesson shows why that is not enough for a glass panel that should blur unrelated content behind it.

Practical problem: the foreground panel is visually above a sharp sibling backdrop. The panel can be translucent over that backdrop, but its code still has no readable image containing the backdrop's neighboring pixels.

The missing object

what the panel currently owns = its fill, stripe, dot, lines, and label what backdrop blur additionally needs = an image-like object containing the matching backdrop region

Lesson 6.6 creates the explicit recording route. Lesson 6.5 stops after proving why that route is necessary.

0 · OBJECT LEDGER

Name every image and owner before the first calculation

Visual overlap and readable image input are different relationships.

BackdropSibling

The separately owned bands, line, and circle drawn first into the parent scene.

GlassPanel

The foreground owner. It draws its own tint, stripe, dot, detail lines, and label.

Panel effect input

The pixels rasterized from GlassPanel when .blur() is attached to that owner.

Required backdrop region

The backdrop image region whose coordinates match the current panel bounds.

Readable image input

An image-like object that code can sample — meaning read one stored color value at a named coordinate. It is absent from the current panel path.

1 · ALL FORMULAS

Separate same-position compositing from neighborhood sampling

The first formula can run with the current drawing target. The second needs a readable backdrop image.

p

The selected output coordinate inside the panel, measured in parent coordinates.

B(q)

The backdrop's teaching blue-channel value at one readable backdrop coordinate q.

Panel(p)

The panel owner's source value at the selected coordinate.

C(p)

The ordinary source-over result at the selected coordinate.

N(p)

The neighborhood: a small set of nearby backdrop coordinates around p.

B̄(p)

The teaching blurred-backdrop value calculated from the readable values in N(p).

Ordinary source-over at one position

C(p) = Panel(p) over Backdrop(p)

p is one output position. Source-over combines the panel source with the destination already present at that same position. It does not ask for neighboring backdrop values.

Teaching blur of the backdrop

B̄(p) = [B(p-left) + B(p) + B(p-right)] ÷ 3

This controlled one-channel average is a teaching bridge. A real blur uses a two-dimensional neighborhood and implementation-specific weights.

Desired glass output

GlassOutput(p) = PanelMaterial(p) over B̄(p)

The blurred backdrop must be calculated first. The panel material then composites over that result.

Data requirement

to calculate B̄(p), code needs: B(p-left) B(p) B(p-right)

The panel-owned effect input contains none of those backdrop values unless an explicit recording or image input is supplied.

7 · EXERCISES

Answer before opening the explanations

1 · Why can a translucent panel show a sharp stripe without owning that stripe?

The stripe was already drawn into the parent destination. Source-over combines the panel source with that destination at the same position. The panel does not need a readable stripe image merely to composite over it.

2 · Why is a panel-owned .blur() insufficient for backdrop blur?

Its input contains the panel owner's rasterized pixels. A backdrop blur needs neighboring colors from the separately owned backdrop image.

3 · What changes when the panel moves?

The panel's own artwork may remain unchanged, but the matching backdrop region under the panel changes. A real implementation must remap or recrop that region.

4 · Is the desired browser reference a production backdrop capture?

No. The browser deliberately duplicates the teaching background inside the panel. It proves the required appearance and data dependency, but not the iOS recording architecture.

9 · SOURCES AND EVIDENCE

Keep the proof boundary explicit

What this lesson proves

A .blur() modifier attached to the panel processes panel-owned pixels. A real backdrop blur additionally needs an explicit readable backdrop image and the region matching the panel.

What remains outside this lesson

Lesson 6.5 does not yet record the backdrop, map panel coordinates, crop the region, keep it current, or prevent feedback. Those are Lessons 6.6 through 6.9.

  • View.blur(radius:opaque:) — blurs the selected view's own pixels. This lesson does not use system materials as the glass path.
  • ImageRenderer — snapshots a dedicated SwiftUI view. Lesson 6.6 uses an explicit recording route; this lesson only names the missing input.
Evidence boundary: the browser duplicates backdrop artwork inside the panel as a teaching reference. The iOS explorer executes real .blur() on GlassPanel and draws a labelled reference crop from the same teaching function. It does not capture the sibling, inspect the renderer's command stream, or claim identical kernel weights. Do not use ultraThinMaterial or glassEffect as the glass path.
