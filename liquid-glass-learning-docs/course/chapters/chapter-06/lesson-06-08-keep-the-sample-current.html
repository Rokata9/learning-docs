Lesson 6.8 — Keep the sample current

Lesson 6.7 selected the correct sharp backdrop region for one settled scene state. A moving scene adds a second requirement: the selected recorded image and the mapped source rectangle must still describe what is current now.

Practical goal: refresh the backdrop snapshot when backdrop drawing changes, refresh the crop bounds when panel geometry changes, and replay only after both data products correspond to their current inputs.
Scope boundary: the sample remains sharp. This lesson does not add blur, permit the panel to enter its own recording, measure render-target cost, or prove an atomic same-frame production architecture.

A sample is a pair

current recorded image (replayed as backdrop pixels) + current panel bounds in backdrop space → current sharp panel sample

Refreshing only one side is not enough. The selected recording may represent old backdrop draw work while the rectangle is current, or the recording may be current while the rectangle still points to an old panel position.

1 · THE VISUAL PROBLEM

“Correct once” is not the same as “correct after motion”

Two different inputs can change, so two different stored products can become stale.

Stale recorded image

The panel uses the current crop rectangle, but the selected recorded image still represents older backdrop draw work. When the panel draws that image, the resulting panel pixels show the moving red marker at its former position.

Stale crop bounds

The selected recorded image represents the current backdrop, but the replay still uses the rectangle measured before GlassPanel moved. The panel shows current backdrop content from the wrong physical region.

Current sample pair

The selected recorded image matches the current backdrop state, and cropBounds matches the current panel geometry. Only then does replay produce panel pixels representing the backdrop behind the panel now.

Definition used here: current means “derived from the latest input state that this lesson is displaying.” It does not mean “looks plausible,” and it does not claim that two independent callbacks form an atomic production snapshot.
2 · OBJECTS AND FRESHNESS CHANNELS

Name the two producers before discussing updates

LiveBackdropState

A controlled content step from 0 through 8. It changes color-band offset and the tracked red marker inside BackdropArtwork.

currentRecorded

A recorded Image from ImageRenderer. Its snapshot contains the latest backdrop draw work. Its local coordinate system is still BackdropHost-local.

capturedRecorded

A deliberately frozen comparison snapshot. It changes only when Capture current state is pressed. It exists to expose stale-image behavior.

CurrentPanelFrames

The latest GeometryReader frames in ParentScene for the moving panel and backdrop owner.

CapturedCropBounds

A deliberately frozen comparison rectangle, captured beside the frozen snapshot. It exposes stale-bounds behavior.

PanelLocalTarget

The fixed 210 × 130 pt destination. It consumes one selected image and one selected crop rectangle.

Causal interpretation

The marker can move inside the recorded image, and the crop rectangle can move inside that image. The panel-local result subtracts the selected crop origin from the selected marker position. Therefore an old marker position and an old crop origin contribute separate coordinate errors.

Important: all subtractions above compare coordinates in BackdropHost-local space before producing one GlassPanel-local coordinate.

6 · iOS ROUTE

Refresh the live snapshot from drawing and refresh bounds from layout

Correct image-content channel

let currentRecorded = BackdropRecorder.snapshot(
    size: CGSize(width: 316, height: 240),
    scale: displayScale
) {
    BackdropArtwork(step: backdropStep)
}

// Diagnostic direct draw keeps the visible backdrop live.
BackdropArtwork(step: backdropStep)

When backdrop drawing changes, ImageRenderer snapshots the current BackdropArtwork and replaces currentRecorded. The explorer also draws the current artwork directly so a frozen comparison snapshot can be visibly wrong. Drawing an older image does not refresh it.

Correct bounds channel

let backdropFrame = backdropProxy.frame(in: .named("ParentScene"))
let panelFrame = panelProxy.frame(in: .named("ParentScene"))
let currentCrop = CGPoint(
    x: panelFrame.minX - backdropFrame.minX,
    y: panelFrame.minY - backdropFrame.minY
)

currentRecorded.image
    .frame(width: 316, height: 240, alignment: .topLeading)
    .offset(x: -currentCrop.x, y: -currentCrop.y)
    .frame(width: 210, height: 130, alignment: .topLeading)
    .clipped()

The panel clip still determines the output coordinate space. Read the frames again after layout so the selected rectangle follows the panel instead of retaining a former placement. .offset uses points. Do not pass snapshot pixels to .offset.

SwiftUI update connection: state read while rendering the backdrop can invalidate rendering when it changes; panel placement changes require layout before new frames exist. The two update causes are different even though both products meet later at the panel replay.
Diagnostic-only comparison objects: the iOS explorer keeps a second frozen snapshot and a captured rectangle so stale states can be selected on demand. That extra comparison storage is teaching evidence, not a production recommendation. Lesson 6.10 examines offscreen cost. Do not use ultraThinMaterial or glassEffect as the glass path.

9 · EXPLAIN IT BACK

Five checks for causal understanding

1 · Why can the crop bounds remain valid while backdrop drawing changes?

If the backdrop artwork scrolls or animates inside a fixed BackdropHost and the panel does not move, the two layout nodes keep the same geometric relationship. The crop rectangle can remain unchanged even though the recorded image must be snapshotted again.

2 · Why can the recorded image remain valid while the crop bounds change?

If the backdrop artwork itself is unchanged but GlassPanel moves, the recorded image still represents the same backdrop. The source rectangle must move inside that image so the panel selects the new physical region.

3 · Does drawing an old recorded image make that snapshot current?

No. Drawing the Image consumes the snapshot it already holds and produces output pixels from it. Replaying an older snapshot again therefore produces the older backdrop result again.

4 · Why is “sample current” a two-part condition?

The panel output depends on both the image and the rectangle used to select from that image. Either one can refer to an older input. The pair is current only when both selected products correspond to their latest producers.

5 · What does this lesson not prove about timing?

It does not prove that independent render and layout updates create one atomic same-frame snapshot in every architecture. It proves the data dependencies and visible failure modes. A later architecture lesson can coordinate ownership and timing more tightly.

11 · SOURCES AND EVIDENCE

Keep the proof boundary explicit

What this lesson proves

A dynamic panel sample has two freshness dependencies: the selected recorded image must reflect current backdrop draw inputs, and the crop rectangle must reflect current panel geometry. Freezing either dependency produces a distinct, traceable panel-local error.

What remains outside this lesson

No blur is applied. The panel remains excluded from the backdrop owner. The lesson does not prove atomic same-frame capture, production synchronization, rotated sampling geometry, CPU readback, render-target memory, or GPU cost. Lesson 6.9 handles feedback loops.

  • ImageRenderer — snapshots the dedicated backdrop view again when backdrop drawing changes. The snapshot is the full backdrop, not the panel crop.
  • GeometryProxy.frame(in:) — reads the current panel and backdrop rectangles in ParentScene points. A new placement is visible here only after layout.
  • offset(x:y:) — moves the recorded image in points so the selected crop origin lands at the panel-local origin.
Evidence boundary: the browser SVG is a teaching copy of the route. The iOS explorer executes a real ImageRenderer snapshot, GeometryReader frame reading, and Image replay. It does not walk a CPU pixel array. Do not use ultraThinMaterial or glassEffect as the glass path.
