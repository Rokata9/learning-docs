Chapter 5 · Motion without mystery

Lesson 5.12 — Slow-motion controller

The animation can already reverse and preserve its in-flight state. Now we need a debugging controller that can slow the animation, pause it without losing its current value, and advance it by one fixed simulation step.

Practical problem: full-speed motion can hide a one-frame defect. A local debug clock makes each intermediate state inspectable without changing the animation’s endpoint formulas.
By the end

You will be able to separate real frame time from debug-controlled simulation time, calculate a scaled time delta, pause automatic advancement, step one fixed increment, reverse direction, and connect the model to TimelineView(.animation) and a custom play-time clock.

1 · ALL FORMULAS

Keep the complete debug-clock contract visible

Each card states the inputs, output, and next consumer.

Real frame delta

Δtᵣ = t𝚌 − tₚ

Input: two frame timestamps. Output: real elapsed time between callbacks.

Speed-scaled delta

Δtₛ = Δtᵣ × s

At s = 0.25, simulation time receives one quarter of the real delta.

Accumulate play time

p_next = clamp( p + dir × Δtₛ, 0, duration )

Direction decides whether play time moves toward expansion or collapse.

Normalize progress

u = p ÷ duration

The existing interpolation formulas consume u.

Paused automatic update

isPlaying = false → automatic Δtₛ = 0

Paused does not reset p or u.

One debug step

p_next = clamp( p + dir × h, 0, duration )

h = 16 ms is a chosen debugging increment, not a promise about the device refresh rate.

Current width

width = 64 + (320 − 64) × u

The same u drives height, radius, and content alpha.

Current radius

radius = 32 + (28 − 32) × u

Slow motion changes when u advances, not the endpoint values.

4 · PAUSE AND FRAME STEP

Pause the accumulator, not the animation state

Paused automatic playback

isPlaying = false p stays unchanged u stays unchanged width stays unchanged

The next frame callback may still exist elsewhere in the UI, but this controller does not add its real delta to play time.

One manual debug step

h = 16 ms p = 320 ms dir = +1 p_next = 320 + 1 × 16 = 336 ms u_next = 336 ÷ 800 = 0.4200

The step is deterministic because it does not depend on how long the browser or device waited before the click.

Terminology boundary: “Step 16 ms” means one chosen simulation-time increment. It does not mean that the iPhone 16 Pro is currently rendering at exactly 62.5 frames per second, nor that every physical display frame lasts 16 ms.

6 · iOS VALUE PATH

Use TimelineView as a timestamp source

1 · Frame timestamps

TimelineView(.animation) supplies dates converted to nanoseconds.

2 · Real delta

Subtract the previous frame timestamp from the current one.

3 · Debug speed

Multiply the real delta by the local speed control.

4 · Play time

Add or subtract the scaled delta and clamp it to the animation duration.

5 · Play-time clock

progress = playTime / duration calculates the value for that play time.

6 · UI

The current value drives the capsule-to-panel geometry and readouts.

Local controller versus system setting: UIKit can apply a global animation-duration scale, and Reduce Motion can change system animations. This lesson builds a local per-component debug controller so one experiment can be slowed or stepped without changing every animation on the device.

8 · CODING CHALLENGE

Do not scale the accumulated play time repeatedly

The defect multiplies the entire accumulated time on every frame.

The speed multiplier must apply to the new frame delta, not repeatedly to all past play time.

Correct contract

scaledDelta = realDelta × speed nextPlayTime = playTime + scaledDelta

Past accumulated simulation time remains unchanged. Only the newly arrived real-time interval is scaled.

9 · EXERCISES

Answer before opening the details

Exercise 1 · Quarter speed

A real frame delta is 20 ms and speed is 0.25×. What simulation delta is added?

Show answer
Δtₛ = 20 × 0.25 = 5 ms
Exercise 2 · Paused state

Play time is 500 ms and playback is paused for two real seconds. What is the new play time before any manual step?

Show answer

Still 500 ms. Paused automatic playback adds no real-frame delta to the simulation accumulator.

Exercise 3 · Reverse step

Play time is 320 ms, direction is −1, and step size is 16 ms. What is the next play time?

Show answer
320 + (−1 × 16) = 304 ms
Exercise 4 · Why not call 16 ms one physical frame?

Explain why that claim would be inaccurate.

Show answer

The actual display and frame scheduler can produce different frame intervals. Here, 16 ms is only the debugger’s chosen deterministic simulation increment.

11 · SOURCES AND EVIDENCE BOUNDARY

Primary iOS contracts used by the lesson

  • Apple Developer, SwiftUI TimelineView — publishes dates that can be converted to nanoseconds and subtracted to obtain a real frame delta.
  • A custom play-time clock is a stateless calculation: this lesson uses progress = playTime / duration at the supplied play time.
  • System-wide animation settings are a different, device-wide control; this controller affects only this lesson.
Evidence boundary: the browser and iOS lesson implement a local debug clock. They do not claim to replace SwiftUI’s internal animation clock globally, and a 16 ms debug step is not a measurement of the current display refresh interval.
