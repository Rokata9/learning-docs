Chapter 5 · Motion without mystery

Lesson 5.11 — Reversal and interruption

The capsule-to-menu animation already has a current progress value and a current velocity. Now the user taps again before the first request finishes. This lesson explains which values change immediately, which values must stay continuous, and why the drawing can continue briefly in its old direction after the target reverses.

Prerequisite boundary: this lesson uses completed Lessons 5.4–5.10, including the press-deformation lesson.
By the end

You will be able to explain an interruption snapshot, reverse a spring without snapping value or resetting velocity, trace the first three updates after a target change, distinguish a new request from the current animation state, and connect the model to a custom spring clock that keeps the current value and velocity.

0 · OBJECTS BEFORE FORMULAS

Name the animation values at the interruption moment

A request changes the target. It does not rewrite the current state.

Current progress q

The value currently used by interpolation. 0 means collapsed. 1 means expanded.

Current velocity v

The signed change carried from the previous spring update. Positive means progress is moving upward; negative means downward.

Requested target T

The endpoint currently requested by the latest user action: 1 for expand or 0 for collapse.

Interruption

A new target request that arrives while the previous animation is still moving.

Reversal is the special interruption in which the new target is on the opposite side of the current movement. The latest target changes immediately. Current q and current v do not jump.

2 · ALL FORMULAS

Keep the complete interruption contract visible

The formulas are grouped by operation, not by implementation file.

At the request instant

T_after = newly requested target q_after request = q_before request v_after request = v_before request

The request changes the target only. Value and velocity continuity are preserved.

One spring update

d = T − q S = k × d D = −c × v N = S + D Δv = N ÷ m v_next = v + Δv q_next = q + v_next

Visible values

width = 64 + (320 − 64) × q height = 64 + (232 − 64) × q radius = 32 + (28 − 32) × q

The current q, not the requested target, drives the current drawing.

Two discontinuity defects

velocity reset: v_after request = 0 value snap: q_after request = T_new v_after request = 0

Resetting velocity creates a motion cusp. Snapping value creates a visible position jump.

Interpretation

The target changes immediately. The current progress and velocity remain the actual current state. If velocity still points toward collapse, the drawing may continue collapsing briefly even though expansion has just been requested.

This is not a delayed input bug. It is velocity continuity.

10 · CODING CHALLENGE

Do not erase velocity during a normal target reversal

Remove the unnecessary velocity override, then check the repair.

Why this matters

The spring clock already carries current velocity into the next tick. Assigning velocity = 0 creates a visible velocity discontinuity during an ordinary reversal.

11 · EXERCISES

Answer before opening the details

Exercise 1 · What changes at the interruption instant?

The target changes immediately. Current progress and current velocity remain unchanged at that instant.

Exercise 2 · Why can q still increase after collapse is requested?

The preserved positive velocity can remain positive after the first negative velocity change. As long as v_next is positive, q_next = q + v_next still increases.

Exercise 3 · What is wrong with snapping to the new target?

It replaces the current value with the endpoint, causing a visible position discontinuity and discarding the in-flight state.

Exercise 4 · What does the latest request own?

It owns the current target. It does not own or rewrite the current value and velocity.
