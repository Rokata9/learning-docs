Chapter 5 · Motion without mystery

Lesson 5.1 — State before animation

Chapter 4 already gave you static shapes with exact bounds and radii. Before any of those values can move, the program must know the complete resting result and the complete expanded result.

Practical question

What exact data must exist before an animation can move a three-dot button into an expanded menu?

Deliberate lesson limit

This lesson switches instantly between two endpoint snapshots. It contains no clock, duration, progress, interpolation, easing, velocity, spring, or automatic playback.

If the visual jumps, that is correct. Motion begins only after later lessons define the missing operations.

Keep the shapes; add named endpoint data

The new idea is state, not animation.

Completed object

New object

A state snapshot is one complete group of values that describes one of those UI results at one instant.

2 · TERMS

Define each object before the walkthrough

Property

One named piece of UI data, such as width, height, corner radius, or content alpha.

State

The data that describes the UI at one instant.

Snapshot

One complete set of property values recorded together for one named state.

Endpoint

One named state at an end of a future animation. This lesson uses a resting endpoint and an expanded endpoint.

Current state

The endpoint currently selected by the state owner.

State owner

The code object that stores the current state and receives events that change it.

Renderer

The code that reads the current snapshot and produces the visible UI.

Instant switch

Replace one snapshot with another without calculating any intermediate frames.

6 · INVALID MIXED COMBINATIONS

One enum protects the endpoint contract

The free-play mixed state deliberately breaks the contract.

Independent properties can disagree

width = 320 pt height = 64 pt three-dot alpha = 1.00 menu alpha = 1.00

This is neither the resting button nor the expanded menu. Both content families compete inside a shape whose height still belongs to the button.

One named endpoint selects one valid snapshot

currentEndpoint ↓ visualStateFor(endpoint) complete width + height + radius + content values ↓ renderer one valid endpoint image

Later animation lessons will calculate valid intermediate values deliberately. They will not rely on accidental independent combinations.

7 · iOS CONNECTION

State owner → visual snapshot → Canvas output

The complete files remain in Xcode and LiquidGlassLab-iOS.

1 · Event

The learner presses Resting button or Expanded menu.

2 · State owner

selectedEndpointName stores the current endpoint name with @SceneStorage.

3 · Endpoint object

MenuEndpoint(rawValue:) reconstructs the enum value.

4 · Snapshot mapping

visualStateFor(endpoint) returns one complete MenuVisualState.

5 · Renderer

The Canvas reads the snapshot values and draws exactly one endpoint. No animation API participates.

// StateBeforeAnimationExplorer.swift — endpoint selection
@SceneStorage("lab.ch5.selectedEndpoint")
private var selectedEndpointName = MenuEndpoint.restingButton.rawValue

var selectedEndpoint: MenuEndpoint {
    MenuEndpoint(rawValue: selectedEndpointName) ?? .restingButton
}

var visualState: MenuVisualState {
    visualStateFor(selectedEndpoint)
}
Why @SceneStorage: the selected endpoint is a small piece of UI state. SwiftUI can save this string and restore it after common scene recreation. The heavy visual snapshot is derived again from that small endpoint name.

12 · EXERCISES

Answer before opening the details

Exercise 1 · Read the current snapshot

If currentEndpoint = RestingButton, what width and menu-content alpha must the renderer receive?

Show answer

Width 64 pt. Menu-content alpha 0.00.

Exercise 2 · Diagnostic mixed state

Is width 320 pt, height 64 pt, dots alpha 1, and menu alpha 1 one of the two defined endpoint snapshots?

Show answer

No. It mixes properties from both endpoints and violates the endpoint contract.

Exercise 3 · Why no animation yet?

Why does knowing width 64 pt → 320 pt not yet define an animation?

Show answer

The two endpoint values exist, but no time, progress, interpolation rule, or intermediate values exist.

Exercise 4 · State owner versus renderer

Which object stores the current endpoint, and which code consumes the resulting visual snapshot?

Show answer

The state owner stores the current endpoint. The renderer or view consumes the derived snapshot and draws the UI.

14 · SOURCES AND EVIDENCE

Primary iOS contracts used by the lesson

  • Apple Developer, SwiftUI State — explains that observable state changes trigger view updates of code that reads that state.
  • Apple Developer, SceneStorage — retains saveable UI state across scene recreation.
  • Apple Developer, SwiftUI Animation — describes animation as interpolating from current values toward a target. Lesson 5.1 deliberately stops before those APIs.
Evidence boundary: the browser is a teaching model. The iOS app is the source of truth for SwiftUI state restoration and Canvas rendering behavior. This lesson does not claim anything about animation timing because no animation API runs.
