Lesson 5.7 — Velocity

Lesson 5.6 showed where the menu width is at a selected time. This lesson answers the next practical question: during one measured time interval, how quickly is that width changing, and is it increasing or decreasing?

One new result

Calculate the average velocity of one UI property over one named interval. The result is a signed number measured in dp per second.

Course boundary

This lesson measures velocity between two observations. It does not yet calculate an exact instantaneous velocity at one infinitely small moment.

Springs, flings, interruption, and gesture tracking use velocity later. Here, the calculation stays manual and inspectable.

Velocity

This lesson compares two current widths over one time interval.

Practical question: if the menu is 80 dp wide at 175 ms and 128 dp wide at 350 ms, how many dp per second did its width gain during that interval?
1 · TERMS BEFORE FORMULA

Name the two observations and the two changes

The formula appears only after its objects are defined.

Observation A

One property value recorded at one time.

time A = 175 ms width A = 80 dp

Observation B

The same property recorded at a later time.

time B = 350 ms width B = 128 dp

Value change

The ending width minus the starting width.

Delta width = width B − width A

Time change

The ending time minus the starting time.

Delta time = time B − time A
Velocity is signed. Positive means the property is increasing in the chosen positive direction. Negative means it is decreasing. The sign is part of the result.

3 · EXACT DEFAULT TRACE

Calculate one average velocity from start to finish

Observation A

time A = 175 ms raw progress = 175 ÷ 700 = 0.2500 eased progress = 0.2500² = 0.0625 width A = 64 + 256 × 0.0625 = 80 dp

Observation B

time B = 350 ms raw progress = 350 ÷ 700 = 0.5000 eased progress = 0.5000² = 0.2500 width B = 64 + 256 × 0.2500 = 128 dp

1 · Value change

Delta width = 128 − 80 = +48 dp

2 · Time change

Delta time = 350 − 175 = 175 ms = 0.175 s

3 · Divide

average velocity = +48 dp ÷ 0.175 s = +274.2857 dp/s
Meaning: during that measured interval, the width gained an average of approximately 274.29 dp for every second of elapsed time. The actual interval lasted only 0.175 s; “per second” is the comparison unit.
4 · EQUAL-TIME INTERVALS

Ease-in changes velocity even when each interval lasts 175 ms

Same time length; different width changes.

Why this matters: ease-in does not merely place the curve below the linear diagonal. Across equal time intervals, its width changes become larger. That is the visible meaning of “starts slowly, then speeds up” in this controlled example.
5 · SIGN AND DIRECTION

The sign tells whether the property grows or shrinks

Opening

width A = 80 dp width B = 128 dp Delta width = +48 dp velocity = +274.2857 dp/s

Positive: width is increasing.

↔

Closing

width A = 304 dp width B = 256 dp Delta width = −48 dp velocity = −274.2857 dp/s

Negative: width is decreasing.

Do not use absolute value when direction matters. abs(velocity) gives speed only: the magnitude without the sign. The motion engine later needs the sign to know the current direction.
6 · AVERAGE VERSUS INSTANTANEOUS

This lesson measures one interval

Average velocity taught here

Uses two observations separated by a real interval.

average velocity = value change ÷ time change

Instantaneous velocity deferred

Describes the velocity at one moment. It can be approximated using a very small interval or obtained from an animation/gesture system that tracks current velocity.

That deeper model is not required for this lesson’s checkpoint.

For the final Liquid Glass transition, velocity becomes important when a second tap interrupts an ongoing animation and when a spring must continue from the motion already in progress.
7 · ANDROID CONNECTION

Calculate the same interval from explicit Kotlin values

1 · Times

startTimeMillis and endTimeMillis.

2 · Raw progress

Divide each time by the fixed duration.

3 · Easing

Transform both raw progress values.

4 · Widths

Interpolate one width at each time.

5 · Changes

Subtract widths and times.

6 · Velocity

Divide signed dp change by seconds.

// VelocityExplorer.kt — controlled average-velocity calculation
val deltaWidthDp = endWidthDp - startWidthDp
val deltaTimeSeconds =
    (endTimeMillis - startTimeMillis) / 1_000f

val averageVelocityDpPerSecond =
    deltaWidthDp / deltaTimeSeconds
Real Android boundary: Compose provides VelocityTracker for pointer movements and animation APIs can carry current velocity into physics-based motion. This lesson does not call either API. It builds the measurement contract they later consume.

9 · CODING CHALLENGE

Preserve direction and convert milliseconds to seconds

The starting function loses direction and returns dp per millisecond.

Required contract

10 · EXERCISES

Answer before opening the solutions

Exercise 1 · Default opening interval

Calculate the average velocity from 80 dp at 175 ms to 128 dp at 350 ms.

Show answer
Delta width = 128 − 80 = 48 dp Delta time = 350 − 175 = 175 ms = 0.175 s velocity = 48 ÷ 0.175 = 274.2857 dp/s
Exercise 2 · Diagnostic: why not divide by 175 directly?

What unit would 48 ÷ 175 produce?

Show answer

It produces dp per millisecond, not dp per second. Convert 175 ms to 0.175 s before reporting dp/s.

Exercise 3 · Closing direction

A closing width changes from 304 dp to 256 dp in 0.175 s. Calculate velocity.

Show answer
Delta width = 256 − 304 = −48 dp velocity = −48 ÷ 0.175 = −274.2857 dp/s

The negative sign means the width is decreasing.

Exercise 4 · Equal intervals under ease-in

Why can equal 175 ms intervals have different velocities?

Show answer

Easing changes how much progress—and therefore how much width change—is used during each interval. Equal time does not guarantee equal value change.
