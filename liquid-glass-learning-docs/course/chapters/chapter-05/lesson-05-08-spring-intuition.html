Lesson 5.8 — Spring intuition

Lesson 5.7 measured signed velocity. A spring uses both the current position and current velocity when deciding how the value should move next. This lesson builds that causal picture one teaching tick at a time.

One new mental model

A spring repeatedly pulls toward a target, carries inertia from existing velocity, and removes motion through damping.

1 · TERMS BEFORE ARITHMETIC

Define every physical word used by the teaching model

Mass

A teaching number representing inertia: resistance to changing velocity. Larger mass makes the same net push change velocity less.

Stiffness

A teaching multiplier controlling how strongly displacement from the target creates a restoring pull.

Damping

A teaching multiplier controlling resistance against the current velocity. It removes motion rather than pulling toward the target by itself.

Contract boundary: the browser’s mass, stiffness, and damping numbers form a small discrete teaching model. They are not Android units and they are not Compose’s numerical solver. Compose’s public spring() exposes dampingRatio and stiffness; it does not expose a mass argument.

Calculate one complete update before repeating it

Known state before Tick 1

target = 1.0000 position = 0.0000 velocity = 0.0000 mass = 1.0000 stiffness = 0.1800 damping = 0.5000

Tick 1 output

displacement = 1.0000 − 0.0000 = 1.0000 spring pull = 0.1800 × 1.0000 = 0.1800 damping resistance = 0.5000 × 0.0000 = 0.0000 velocity change = (0.1800 − 0.0000) ÷ 1.0000 = 0.1800 new velocity = 0.0000 + 0.1800 = 0.1800 new position = 0.0000 + 0.1800 = 0.1800
4 · SECOND TICK

The output becomes the next input

position = 0.1800 velocity = 0.1800 displacement = 1.0000 − 0.1800 = 0.8200 spring pull = 0.1800 × 0.8200 = 0.1476 damping resistance = 0.5000 × 0.1800 = 0.0900 velocity change = (0.1476 − 0.0900) ÷ 1.0000 = 0.0576 new velocity = 0.1800 + 0.0576 = 0.2376 new position = 0.1800 + 0.2376 = 0.4176
Why this differs from interpolation: the next position depends on the velocity carried from the previous tick. The browser does not look up a predetermined easing Y value.
5 · PARAMETER EFFECTS

Change one coefficient and inspect the resulting trace

ChangeImmediate causal effect in the teaching modelVisible tendency
Increase massThe same net push is divided by a larger number.Velocity changes more slowly.
Increase stiffnessThe same displacement creates a larger spring pull.The value heads toward the target more aggressively.
Increase dampingThe same velocity creates more resistance.Motion is removed faster; crossing and oscillation are reduced.
Do not compress these into “faster” or “slower” only. Stiffness changes the target-directed pull. Damping changes resistance to existing motion. Mass changes how much a net push alters velocity.

6 · Evidence boundary

The browser coefficients are not copied into Compose.

// SpringIntuitionExplorer.kt — actual Android spring specification
val progress by animateFloatAsState(
    targetValue = if (expanded) 1f else 0f,
    animationSpec = spring(
        dampingRatio = dampingRatio,
        stiffness = stiffness,
    ),
    label = "springProgress",
)
Android’s public spring() documentation describes dampingRatio as bounciness control and stiffness as how quickly the spring moves toward the end value. It also notes that springs preserve velocity continuity when a target changes during motion.

9 · EXERCISES

Answer before opening the solutions

1 · What creates the target-directed pull?

Displacement multiplied by stiffness. Damping does not pull toward the target by itself.

2 · What happens when velocity is zero?

Damping resistance is zero for that tick because it is proportional to current velocity.

3 · Diagnostic: is browser damping equal to Compose dampingRatio?

No. The browser coefficient belongs to the discrete teaching model. Compose dampingRatio belongs to Compose’s spring contract.

4 · Why can the position pass the target?

Velocity can remain positive when the position reaches the target. The next lesson names and measures that crossing.
