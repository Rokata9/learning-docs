Chapter 1 · First mathematical model

Learn the first alpha-mixture formula

The panel from Lesson 1.5 contains white with alpha 0.25f. This lesson follows one color-channel value through the mixture. You will see exactly why the background still contributes 75% at that position.

Scope: we calculate one position well inside the panel. We do not calculate a rounded edge pixel. Edge antialiasing adds another coverage amount. Chapter 4 explains that later.

By the end

  • You can explain every symbol in R = F × A + B × (1 − A).
  • You can calculate the course example: 1.00 × 0.25 + 0.20 × 0.75 = 0.40.
  • You can explain why alpha compositing reads the background at the same image position.
  • You can explain why the Android renderer performs this work instead of one Kotlin helper call.
1 · Four values

Name each number before using the formula

The lesson uses values from 0 to 1. This keeps the arithmetic small.

Foreground channel · F

A color channel is one numeric component of a color. We inspect only one channel. The white panel has the value 1.00 in each red, green, and blue channel.

Background channel · B

This is the channel value already stored at the same image position behind the panel. The teaching example uses 0.20.

Alpha · A

Alpha is the foreground opacity amount. In this simplified mixture, it is also the foreground weight. Lesson 1.5 supplies 0.25.

Result channel · R

This is the final channel value produced for that one output position. It is calculated from the other three values.

Normalized value: a normalized value has been mapped into a standard range. Here 0 is the low end and 1 is the high end. Chapter 3 will introduce complete red, green, and blue colors. This lesson deliberately follows only one channel.
2 · Interactive formula

Two weighted contributions become one result

The canvas geometry is calculated from the live values. The default numbers are the course example.

Course calculation: foreground contribution = 1.00 × 0.25 = 0.25. Background contribution = 0.20 × 0.75 = 0.15. Final result = 0.25 + 0.15 = 0.40.

5 · Spatial boundary
Alpha reads the same position; blur and refraction do not
A sample is one read of a stored image value at a chosen image position.

    

      

      

        

        
TranslucencyFor output position x = 3, the formula reads background B[3]. It combines that value with foreground F[3].

        
Positions readforeground[3], background[3]

        
Visible consequenceThe color changes at x = 3. Nearby boundaries keep their original positions.

      

    

    
Diagnostic conclusion: the alpha formula contains no term such as B[x − 1], B[x + 1], or B[x + offset]. It cannot spread or move background detail by itself.

What official Android documentation establishes: Compose Color.copy copies a color while replacing the supplied components. Compose defines the default SrcOver blend mode as placing the source over the destination. See Compose Color and Compose BlendMode.

    
Evidence limit: the arithmetic laboratory is a one-channel teaching model with an opaque background. Exact captured Pixel values can also depend on the working color space, numeric rounding, display or screenshot conversion, and shape-edge coverage. Those details do not change the spatial conclusion: ordinary alpha compositing uses source and destination values for the same output position. It does not request neighboring background positions.

  


  

    
7 · Production boundary
Do not replace the renderer with one Kotlin calculation
The formula is necessary knowledge. A single helper call is not the correct panel implementation.

    

      
Incorrect architecture for the real panel
val oneBackgroundValue = 0.20f
val oneResult = mixChannel(
    foreground = 1.00f,
    background = oneBackgroundValue,
    alpha = 0.25f,
)

Box(Modifier.background(Color(oneResult, oneResult, oneResult)))
This creates one opaque grayscale color. It cannot preserve the many different colors and shapes behind the panel.

      
Existing Android architecture
Box(
    modifier = modifier.background(
        color = Color.White.copy(
            alpha = PanelFillAlpha,
        ),
        shape = PanelShape,
    ),
)
The panel supplies a translucent source color. The renderer applies the blend separately wherever the rounded shape covers the already drawn background.

    

    
Why this matters later: when we add real backdrop blur and refraction, we will need an explicit background image input. Ordinary alpha compositing does not expose that image as a Kotlin array. Chapter 6 builds the required Android backdrop architecture.

10 · Exercises

Exercise 1 · Calculate
Course values
Use F = 1.00, B = 0.20, and A = 0.25. Write the foreground contribution, background contribution, and final result.
Show answer
Foreground contribution: 1.00 × 0.25 = 0.25. Background share: 1 − 0.25 = 0.75. Background contribution: 0.20 × 0.75 = 0.15. Result: 0.25 + 0.15 = 0.40.

      
Exercise 2 · Endpoints
What happens at alpha 0 and alpha 1?
Keep F = 1.00 and B = 0.20. Calculate both results and explain them in words.
Show answer
At A = 0, R = 1 × 0 + 0.20 × 1 = 0.20. The foreground contributes nothing. At A = 1, R = 1 × 1 + 0.20 × 0 = 1.00. The foreground completely replaces the opaque background at that position.

      
Exercise 3 · Same alpha, two backgrounds
Compare dark and light inputs
With white foreground and alpha 0.25, calculate the result for B = 0.20 and for B = 0.80. Why are the results different?
Show answer
For B = 0.20, the result is 0.40. For B = 0.80, the result is 1 × 0.25 + 0.80 × 0.75 = 0.25 + 0.60 = 0.85. The source alpha is the same, but each output position begins with its own background value.

      
Exercise 4 · Diagnostic
Can this formula bend or soften a line?
Answer yes or no. Name the exact missing input that blur or refraction would require.
Show answer
No. The formula reads the background at the same position only. Blur would need nearby background samples such as B[x − 1] and B[x + 1]. Refraction would need a background sample from a shifted position such as B[x + offset].
