Chapter 1 · First mathematical model

Learn the first alpha-mixture formula

The panel from Lesson 1.5 contains white with alpha 0.25. The first part follows one color-channel value over an opaque background. The new full-RGBA section then combines two different partially transparent colors, with separate red, green, blue, and alpha values in both layers.

Scope: we calculate one position well inside the panel. We do not calculate a rounded edge pixel. Edge antialiasing adds another coverage amount. Chapter 4 explains that later.

By the end

  • You can explain every symbol in result = F × A + B × (1 − A).
  • You can calculate the course example: 1.00 × 0.25 + 0.20 × 0.75 = 0.40.
  • You can explain why 0.40 is one channel value, while RGBA(0.60, 0.40, 0.65, 0.80) is a complete color.
  • You can follow a source-over calculation in which both complete RGBA colors have different red, green, blue, and alpha values.
  • You can explain why alpha compositing reads the background at the same image position.
  • You can explain why the iOS renderer performs this work instead of one Swift helper call.
1 · Four values

Name each number before using the formula

The lesson uses values from 0 to 1. This keeps the arithmetic small.

Foreground channel · F

A color channel is one numeric component of a color. We inspect only one channel. The white panel has the value 1.00 in each red, green, and blue channel.

Background channel · B

This is the channel value already stored at the same image position behind the panel. The teaching example uses 0.20.

Alpha · A

Alpha is the foreground opacity amount. In this simplified mixture, it is also the foreground weight. Lesson 1.5 supplies 0.25.

Result channel · result

This is the final channel value produced for that one output position. It is calculated from the other three values.

Normalized channel value: 0.40 is not a complete color by itself. It is the value of one selected red, green, or blue channel at one image position. The value is written on a normalized 0.0..1.0 scale instead of an integer 0..255 scale. RGBA still has four components. For example, normalized RGBA (0.40, 0.65, 0.90, 1.00) is approximately integer RGBA (102, 166, 230, 255). If red, green, and blue are all 0.40 and alpha is 1.00, the complete color is an opaque gray approximately equal to #666666. The full RGBA bridge below combines two complete colors. Chapter 3 returns to color representation and color spaces in more depth.
Naming rule: in the first one-channel formula, result means the calculated output channel. In the full RGBA section, R means the red channel. The revised lesson spells out result so the two meanings cannot be confused.

3 · Full RGBA bridge

Combine two complete translucent colors

The one-channel formula above assumed that the destination behind the panel was fully opaque. We now remove that simplifying assumption.

Exact object names: the source is the upper color that we draw now. The destination is the color value already present at the same image position underneath it. “Source” does not mean a file, and “destination” does not mean a future screen location. They name the upper and lower inputs to this one compositing operation.

Ordinary RGBA tuple

RGBA(R, G, B, A) stores four normalized components. The first three numbers describe red, green, and blue. The fourth number is alpha. Ordinary, also called straight or unpremultiplied, means that the RGB values have not already been multiplied by alpha.

Alpha-weighted contribution

Before a color channel contributes to the composite, we multiply that channel by the layer alpha. This intermediate value is often called a premultiplied channel because the multiplication by alpha has already happened.

Output RGBA tuple

The result also has red, green, blue, and alpha components. When its alpha is below 1.00, the result remains partly transparent and can still reveal another layer underneath.

Why calculate output alpha first?

The source covers Aₛ of the result. The destination may contribute only through the part not already occupied by the source, which is 1 − Aₛ. The destination also has its own alpha Aᴅ. Therefore its surviving coverage is Aᴅ × (1 − Aₛ).

How the first formula fits inside this one

If the destination is opaque, then Aᴅ = 1. The output alpha becomes Aₛ + 1 × (1 − Aₛ) = 1. Division by output alpha changes nothing, and each channel reduces to Cₛ × Aₛ + Cᴅ × (1 − Aₛ). That is the earlier one-channel formula.

Layer order matters: press Swap layer order. The default result RGBA(0.60, 0.40, 0.65, 0.80) changes to RGBA(0.30, 0.70, 0.50, 0.80). The result alpha stays 0.80, but the RGB color changes because the upper layer receives priority in a source-over operation.
Evidence limit: the browser uses CSS colors to make the numbers visible. The arithmetic is a straight-RGBA teaching model of source-over compositing. It does not prove which temporary numeric representation iOS uses inside every graphics stage. The important relationship is exact for this model: both alphas affect the result when both inputs are partly transparent. Chapter 3 will add color-space details.

8 · Production boundary
Do not replace the renderer with one Swift calculation
The formula is necessary knowledge. A single helper call is not the correct panel implementation.

    

      
Incorrect architecture for the real panel
let oneBackgroundValue: CGFloat = 0.20
let oneResult = mixChannel(
    foreground: 1.00,
    background: oneBackgroundValue,
    alpha: 0.25
)

Rectangle()
    .fill(Color(red: oneResult, green: oneResult, blue: oneResult))
This creates one opaque grayscale color. It cannot preserve the many different colors and shapes behind the panel.

      
Existing iOS architecture
RoundedRectangle(cornerRadius: panelCornerRadius, style: .circular)
    .fill(Color.white.opacity(panelFillAlpha))
The panel supplies a translucent source color. The renderer applies the blend separately wherever the rounded shape covers the already drawn background.

    

    
Why this matters later: when we add real backdrop blur and refraction, we will need an explicit background image input. Ordinary alpha compositing does not expose that image as a Swift array. Chapter 6 builds the required SwiftUI backdrop architecture.

Exercise 1 · Calculate
Course values
Use F = 1.00, B = 0.20, and A = 0.25. Write the foreground contribution, background contribution, and final result.
Show answer
Foreground contribution: 1.00 × 0.25 = 0.25. Background share: 1 − 0.25 = 0.75. Background contribution: 0.20 × 0.75 = 0.15. Result: 0.25 + 0.15 = 0.40.

      
Exercise 2 · Complete RGBA
Calculate the complex default example
Use source S = RGBA(0.90, 0.10, 0.80, 0.50) and destination D = RGBA(0.10, 0.90, 0.40, 0.60). Calculate output alpha, the three alpha-weighted RGB sums, and the final ordinary RGBA tuple.
Show answer
Output alpha: 0.50 + 0.60 × (1 − 0.50) = 0.80. Source RGB contributions: (0.45, 0.05, 0.40). Destination survival factor: 0.60 × 0.50 = 0.30. Destination RGB contributions: (0.03, 0.27, 0.12). Alpha-weighted sums: (0.48, 0.32, 0.52). Divide each sum by 0.80: (0.60, 0.40, 0.65). Final ordinary tuple: RGBA(0.60, 0.40, 0.65, 0.80).

      
Exercise 3 · Same alpha, two backgrounds
Compare dark and light inputs
With white foreground and alpha 0.25, calculate the result for B = 0.20 and for B = 0.80. Why are the results different?
Show answer
For B = 0.20, the result is 0.40. For B = 0.80, the result is 1 × 0.25 + 0.80 × 0.75 = 0.25 + 0.60 = 0.85. The source alpha is the same, but each output position begins with its own background value.

      
Exercise 4 · Diagnostic
Can this formula bend or soften a line?
Answer yes or no. Name the exact missing input that blur or refraction would require.
Show answer
No. The formula reads the background at the same position only. Blur would need nearby background samples such as B[x − 1] and B[x + 1]. Refraction would need a background sample from a shifted position such as B[x + offset].
