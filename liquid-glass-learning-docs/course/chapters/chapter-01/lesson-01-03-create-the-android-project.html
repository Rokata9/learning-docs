Chapter 1 · Lesson 3 of 8

Create LiquidGlassLab and prove the Android baseline

This lesson creates the separate Android Studio project. It proves that your build tools, your Pixel 8 Pro connection, and Jetpack Compose all work before we add any glass effect.

No Liquid Glass is implemented in this lesson. That is deliberate. A known-good baseline lets us separate future graphics mistakes from project, dependency, or device-connection mistakes.

Small lesson goal

At the end, the Pixel 8 Pro shows three lines of text:

  • Liquid Glass Lab
  • Chapter 1 · Android baseline
  • No glass effect is implemented yet.

Main engineering idea: first prove the simplest complete path from source code to visible pixels.

New math: none.

1 · What the baseline proves

One visible result can prove several separate systems

A successful editor preview is useful, but it is not the same evidence as a successful run on the physical phone.

Build proof

Gradle and the Android build tools can turn the project source into an installable debug application package.

Evidence: the build completes without an error.

Connection proof

Android Debug Bridge, abbreviated ADB, can communicate with the Pixel 8 Pro. ADB is the tool that installs and launches a debug build from the computer.

Evidence: Android Studio lists the Pixel and installs the app.

Rendering proof

The Android process starts MainActivity. Jetpack Compose creates the text elements. Android draws them on the phone screen.

Evidence: the exact three lines appear on the Pixel.

Baseline means a simple result that is already known to work. We will compare later results against it. The baseline is not a graphics effect.

3 · Code-driven teaching preview and coding challenge

Three SDK numbers have three different jobs

Edit the code or click the controls on the right. Both paths update one shared state.

compileSdk

The newest Android application programming interface, abbreviated API, that the compiler lets your source code reference.

Question answered: “Which Android API names may this source code compile against?”

minSdk

The oldest Android API level on which the package is allowed to install.

Question answered: “Is this device new enough to run the app at all?”

targetSdk

The Android behavior level for which the app declares that it has been tested.

7 · Run on the Pixel 8 Pro
Verify the physical-device path

        
This section performs Run B, the course-baseline run. Run A, the untouched-template proof, must already be complete. Use USB first if you have not already paired wireless debugging because USB removes one network variable from the first device check.

      


      

        

          
Enable developer options and USB debugging
On the Pixel, open Developer options and enable USB debugging. USB debugging permits ADB commands after you authorize the computer.

          
Connect and authorize the computer
Unlock the Pixel. Connect the USB cable. Accept the RSA authorization dialog on the phone. RSA is the public-key security check that prevents an unknown computer from silently controlling ADB.

          
Select the Pixel in Android Studio
Use the device chooser near the Run button. The chosen target must be the physical Pixel 8 Pro, not an emulator.

          
Press Run 'app' for the course baseline
Android Studio builds the debug variant containing the two supplied Kotlin files, installs it through ADB, and asks Android to launch MainActivity.

          
Compare the exact screen
Confirm all three lines. A blank screen, a template greeting, or a crash is not the checkpoint result.

          
Save evidence
Take one Pixel screenshot and save it under your preferred learner-work location. Record the device Android version and API level shown by Android Studio.

        


        

          
Expected result
The app launches without a crash. The phone shows the baseline title, chapter label, and explicit statement that no glass effect exists yet.

          
Pixel does not appear in the device chooser
Open Tools → Troubleshoot Device Connections. Rescan USB devices. Restart the ADB server from the assistant if needed. On Windows, an ADB USB driver may also be required.

          
The device appears as unauthorized
Unlock the Pixel and accept the authorization dialog. If the dialog never appears, revoke USB debugging authorizations in Developer options, reconnect, and authorize again.

          
I prefer wireless debugging
First complete one USB run when possible. For Wi-Fi, place the computer and Pixel on the same network. On the Pixel, enable Wireless debugging under Developer options. In Android Studio, open Pair Devices Using Wi-Fi, then pair with the QR code or pairing code shown by the phone. Select the paired Pixel in the device chooser and run the same app configuration.
Wireless debugging changes only the computer-to-device transport. The Gradle build, APK installation, activity launch, and Compose rendering stages remain the same.

          
Android SDK Platform 37 is missing
Open Tools → SDK Manager. Install the Android 17 SDK platform. Then sync the project again.

          
Android Studio or the Android Gradle Plugin is too old for API 37
Update to a supported stable Android Studio release. Do not solve this by pasting unrelated plugin versions from old tutorials. The current course documentation was checked against Android Studio Quail 2 and Android Gradle Plugin 9.3 compatibility. Keep the template-generated tool versions together.

          
LiquidGlassLabTheme is unresolved
Open the generated ui/theme/Theme.kt file. Use the actual generated theme function name and package. This mismatch occurs when the project name or package differs from the lesson baseline.

          
The package declaration does not match my project
Replace com.example.liquidglasslab in all supplied Kotlin files with the package you selected. Move the files into matching directories. Kotlin package declarations and source folders should describe the same namespace for clarity.

        

      

      
Windows 11 and WSL2 boundary: Windows Subsystem for Linux 2, abbreviated WSL2, is the Linux environment running beside Windows. Android Studio running on Windows normally uses adb.exe from the Windows Android SDK. A separate Linux adb process inside WSL2 is a different tool process and can show a different device list unless you deliberately configure USB or network forwarding. For this baseline, use Android Studio and the Windows SDK for every device action. An ADB server is the background computer process that owns ADB device connections. This rule keeps one ADB server responsible for the Pixel connection.

    


    

      

        
8 · Exercises
Answer before opening the hidden answers

        
These questions diagnose whether the three SDK values and the evidence levels are still being merged into one idea.

      


      

        

          Exercise 1 · SDK roles
          
Which value controls the oldest device that may install the app?

          
          
Show answer
minSdk. With minSdk = 33, an API 32 device is rejected and an API 33 device is allowed.

        


        

          Exercise 2 · Diagnostic misconception
          
Does compileSdk = 37 make an API 37-only function exist on an API 33 phone?

          
          
Show answer
No. compileSdk controls which API names the compiler accepts. The runtime device still contains only the APIs delivered by its Android version. Code that calls a newer-only API needs a runtime version check or a compatible alternative.

        


        

          Exercise 3 · Evidence
          
A debug build succeeds, but the Pixel screen has never been checked. What has been proven, and what remains unproven?

          
          
Show answer
Proven: the project model resolved, the source compiled, and a debug package was produced. Unproven: ADB authorization, installation, activity launch, Compose execution on the phone, and the final visible result.

        


        

          Exercise 4 · Trace
          
Write the source-to-screen path in order.

          
          
Show answer
One acceptable path is: Kotlin source → Gradle and Android build tools → debug APK → ADB install → Android launches MainActivity → setContent starts Compose → Chapter01Screen declares the visible user interface → Compose text elements are drawn on the Pixel.
