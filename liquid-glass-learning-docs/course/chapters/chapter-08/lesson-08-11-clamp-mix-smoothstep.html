Chapter 8 · Turn a hard cut into a soft band

clamp, mix, and smoothstep

Question: Lesson 8.4 stored teaching orange or teaching navy with a pixel test. One pixel stores orange. The next stores navy. Nothing in between. How does the stitchable function store a blend of those two colors across a chosen band of pixels?

clamp keeps one number inside a closed interval. mix is MSL’s name for Lesson 5.4’s linear interpolation: it stores a blend of two values. smoothstep first builds a 0..1 blend fraction in that band, then bends it so the store stays near navy, then rises faster, then stays near orange.

1 · THE NEW QUESTION

The hard cut cannot store an in-between color.

8.4 leftover

Lesson 8.4 stored teaching orange half4(0.88, 0.48, 0.18, 1.0) or teaching navy half4(0.10, 0.25, 0.40, 1.0) with if (fragCoord.x < 80.0). That test picks one of two stores. It never writes a red between 0.10 and 0.88.

5.4 leftover

Lesson 5.4 already calculated one number between two endpoints: start + (end − start) × progress. Progress was one fraction from 0 through 1. MSL’s name for that arithmetic is mix.

New band

This lesson’s band is the UV interval from edge0 = 0.40 to edge1 = 0.60. Left of 0.40 the store stays navy. Right of 0.60 it stays orange. Between those edges the store is a blend.

Not 7.10 amount

The third input to mix is a blend fraction: how far from navy toward orange, 0 through 1. It is not Lesson 7.10’s noise amount slider.

clamp(x, lo, hi) = min(max(x, lo), hi) ← lo and hi are included ← MSL clamp is this function, not Lesson 7.3’s sampler wrap mix(a, b, t) = a + (b − a) × t ← same arithmetic as Lesson 5.4 ← t is the blend fraction, 0 stores a, 1 stores b
linearFraction = clamp((x − edge0) / (edge1 − edge0), 0.0, 1.0) curvedFraction = linearFraction × linearFraction × (3.0 − 2.0 × linearFraction) store = mix(navy, orange, curvedFraction) ← x is this pixel’s uv.x ← edge0 = 0.40, edge1 = 0.60 unless a slider moves them ← MSL writes the last two lines as mix(..., smoothstep(...))

3 · CLAMP
Keep one number inside a closed interval
clamp(x, lo, hi) returns lo when x is below lo, returns hi when x is above hi, and returns x when it is already between them. Both ends are included.

    

      

        
Three teaching inputs

        
clamp(−0.20, 0.0, 1.0) = 0.00
clamp(0.45, 0.0, 1.0) = 0.45
clamp(1.20, 0.0, 1.0) = 1.00
  ← −0.20 is below 0, so the store of the bound is 0
  ← 1.20 is above 1, so the store of the bound is 1

        
This is the MSL function. Lesson 3.9’s ColorMatrix clamp was a later range restriction on a matrix result. Lesson 7.3’s snapshot sampler wrap is an edge-read mode. Those are different objects.

      

      

        
Why mix needs this

        
If the blend fraction is 1.50, mix walks past orange: red becomes 0.10 + (0.88 − 0.10) × 1.50 = 1.27. That is no longer between navy red and orange red. Clamp of the blend fraction keeps mix between the two colors.

        
MSL also has saturate(x), which is clamp(x, 0.0, 1.0). This lesson writes the two bounds so you can see them.

      

    

    
    
    

  


  

    
4 · MIX
Blend two values with Lesson 5.4’s arithmetic
MSL’s documentation calls this a linear blend. The numbers are the Lesson 5.4 current-value formula. Trace red first. Then the same blend fraction is reused for green and blue.

    

      

        
One channel, t = 0.25

        
navy red   = 0.10
orange red = 0.88
t          = 0.25
difference = 0.88 − 0.10 = 0.78
selected   = 0.78 × 0.25 = 0.195
stored red = 0.10 + 0.195 = 0.295
  ← red increased toward orange

      

      

        
Blue moves the other way

        
navy blue   = 0.40
orange blue = 0.18
t           = 0.25
difference  = 0.18 − 0.40 = −0.22
selected    = −0.22 × 0.25 = −0.055
stored blue = 0.40 + (−0.055) = 0.345
  ← blue decreased toward orange

        
The adjective “toward orange” is those two signed changes from the same t. Channels can move in opposite directions.

5 · SMOOTHSTEP
Build a 0..1 in the band, then bend it
smoothstep(edge0, edge1, x) does two operations. First it builds linearFraction, the straight ramp that is 0 left of edge0 and 1 right of edge1. Then it bends that ramp with linearFraction × linearFraction × (3 − 2 × linearFraction). The output is still 0 through 1. It is not linear in the band.

    

      

        
Teaching pixel x=180

        
x = 180 / 400 = 0.45
edge0 = 0.40
edge1 = 0.60
span = 0.60 − 0.40 = 0.20
(x − edge0) / span = 0.05 / 0.20 = 0.25
linearFraction = clamp(0.25, 0, 1) = 0.25
curvedFraction = 0.25 × 0.25 × (3 − 2 × 0.25)
               = 0.0625 × 2.50
               = 0.15625
  ← 0.15625 is smaller than 0.25
  ← the store stays nearer navy than a straight ramp would

      

      

        
The midpoint is unchanged

        
x = 0.50 → linearFraction = 0.50
curvedFraction = 0.50 × 0.50 × (3 − 1) = 0.50
x = 0.55 → linearFraction = 0.75
curvedFraction = 0.75 × 0.75 × (3 − 1.50)
               = 0.5625 × 1.50
               = 0.84375
  ← 0.84375 is larger than 0.75
  ← after the middle, the store sits nearer orange

        
This lesson requires edge1 > edge0. Equal edges would divide by zero. The sliders keep a 0.02 gap. MSL’s documentation calls the bend Hermite interpolation. That name is only a label for this arithmetic.

8 · iOS ROUTE
Two edge arguments, one mix of smoothstep

    

      
// shader/SmoothBand.metal
[[ stitchable ]] half4 smoothBand(
    float2 position, half4 color, float scale, float2 resolution,
    float edge0, float edge1) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    half4 navy = half4(0.10, 0.25, 0.40, 1.0);
    half4 orange = half4(0.88, 0.48, 0.18, 1.0);
    float t = smoothstep(edge0, edge1, uv.x);
    return mix(navy, orange, t);
}

let pixelWidth = pointWidth * displayScale
let pixelHeight = pointHeight * displayScale
ShaderLibrary.smoothBand(
    .float(Float(displayScale)),
    .float2(Float(pixelWidth), Float(pixelHeight)),
    .float(edge0),
    .float(edge1))

      

        
What each part changes

        
Xcode compiles smoothBand when it builds the app. Moving edge0 or edge1 only passes .float arguments. That is Lesson 8.9’s argument pass, now feeding this lesson’s functions.

        
MinEdgeGap = 0.02 stops the sliders from making edge1 − edge0 zero. Division by zero is not this lesson’s experiment.

        
TeachingU = 0.45 is the UV of pixel x=180 on the 400-wide teaching rectangle. The explorer draws an indigo marker there and prints the same arithmetic as the HTML table. position is points. Pixel fragCoord is position × displayScale.

        
Hard-if and linear-mix comparisons live in the HTML lab. The iPhone 16 Pro production route is the Smooth mix only.

11 · EXERCISES
Answer before opening each hidden solution

    
What does clamp(−0.20, 0.0, 1.0) return, and which input supplied −0.20?
0.00. The first argument is the number being restricted. −0.20 is below the included lower bound 0.0, so the function returns that lower bound. It does not return −0.20, and it does not wrap the way fract wrapped −0.25 to 0.75.

    
Diagnostic: mix(navy, orange, uv.x) at x=180 stores red 0.451. Why is that not this lesson’s 0.40–0.60 band?
Because the blend fraction is the whole-width UV, 0.45. The band starts at 0.40, so a band-local fraction at this pixel is 0.25, not 0.45. You need clamp((uv.x − edge0) / (edge1 − edge0), 0.0, 1.0) or smoothstep(edge0, edge1, uv.x) before mix.

    
At x=180, edges 0.40 and 0.60, which is smaller: linearFraction or curvedFraction, and what stored red does Smooth mix write?
curvedFraction 0.15625 is smaller than linearFraction 0.25. Smooth mix stores red 0.10 + 0.78 × 0.15625 = 0.221875. That is nearer navy than linear mix’s 0.295.

    
For mix at t = 0.25, why does red increase while blue decreases?
Orange red 0.88 is larger than navy red 0.10, so the signed difference is positive and red increases. Orange blue 0.18 is smaller than navy blue 0.40, so the signed difference is negative and blue decreases. One blend fraction. Two opposite channel moves. Both are “toward orange.”

13 · EVIDENCE BOUNDARY
What this lesson establishes

    

      
Established
clamp restricts one number to a closed interval. mix is Lesson 5.4’s interpolation under an MSL name. smoothstep(edge0, edge1, x) builds a 0..1 blend fraction in that band and bends it with t × t × (3 − 2t). The production store is mix(navy, orange, smoothstep(edge0, edge1, uv.x)). At teaching pixel x=180 that store’s red is 0.221875.

      
Not claimed
No sine. No step. No distance-to-a-circle. No claim that the GPU uses a different private curve than this arithmetic. Equal edges are excluded, not explored. Lesson 8.12 reads the Xcode Metal log. Chapter 7 frost is unchanged.
