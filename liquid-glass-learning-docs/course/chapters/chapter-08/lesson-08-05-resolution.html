1 · THE NEW OBJECTS

Name resolution, the uniform slot, and splitX

Two different objects

fragCoord is this pixel’s position. Resolution is the whole rectangle’s width and height. A pixel at (40, 60) on a 400-wide rectangle has fragCoord = (40, 60) and resolution width 400. Those numbers are not interchangeable. You cannot compute “left half” from fragCoord alone.

Resolution

Resolution in this lesson is the pair (width, height) of the draw rectangle, in pixels. Kotlin reads it from the Canvas as size.width and size.height. Those values are pixels, not dp. Lesson 2.5 already separated those units. At density 1 they can match. On a Pixel 8 Pro they do not.

Uniform

A uniform in this lesson is a named slot in the compiled program. Kotlin writes a value into that slot. The GPU reads the same value for every pixel of this draw. The AGSL string is not rewritten. Lesson 8.3 rebuilt RuntimeShader to change color. This slot is only resolution. Other slots are Lesson 8.9.

splitX

splitX is a name for half the current width, in pixels. splitX = resolution.x / 2.0. For width 240, splitX is 120. For width 400, splitX is 200. It is still a pixel count compared with fragCoord.x. It is not a 0..1 fraction.

Kotlin, once per draw of this rectangle: shader.setFloatUniform("resolution", size.width, size.height) ← writes the pair into the compiled program ← does not rebuild RuntimeShader
AGSL, once per output pixel: splitX = resolution.x / 2.0 if (fragCoord.x < splitX) return orange else return navy ← every pixel sees the same resolution pair ← each pixel has its own fragCoord

Kotlin writes resolution once for this draw, on the CPU, before drawRect. Then the GPU calls main many times. Each call sees the same resolution pair and a different fragCoord. resolution.y is the height. This split does not read it. The pair still needs two numbers because float2 is two numbers.

6 · ANDROID ROUTE
Write resolution every draw

    

      
private const val HalfSplitAgsl = """
uniform float2 resolution;

half4 main(float2 fragCoord) {
    float splitX = resolution.x / 2.0;
    if (fragCoord.x < splitX) {
        return half4(0.88, 0.48, 0.18, 1.0);
    }
    return half4(0.10, 0.25, 0.40, 1.0);
}
"""

val shader = remember { RuntimeShader(HalfSplitAgsl) }
val brush = remember(shader) { ShaderBrush(shader) }

Canvas(Modifier.width(if (wide) 360.dp else 240.dp).height(140.dp)) {
    shader.setFloatUniform("resolution", size.width, size.height)
    drawRect(brush = brush)
}

      

        
What each part changes

        
remember { RuntimeShader(...) } compiles once. Switching 240.dp and 360.dp does not construct a new RuntimeShader.

        
setFloatUniform("resolution", size.width, size.height) runs on the CPU in the Canvas lambda, once per draw of this rectangle. size.width is pixels of this Canvas.

        
240.dp is a teaching width so the 8.4 leftover of 80 pixels still sits inside the narrow card in Preview at density 1. It is not glass geometry. On a Pixel 8 Pro, 240.dp is more than 240 pixels, and the 8.5 split still sits at half of those pixels.

9 · EXERCISES
Answer before opening each hidden solution

    
What is resolution in this lesson?
The draw rectangle’s width and height, in pixels. Kotlin writes that pair with setFloatUniform("resolution", size.width, size.height).

    
Diagnostic: can main compute “left half” from fragCoord alone?
No. fragCoord is this pixel’s position. Half of the rectangle needs the rectangle’s width. That width is resolution.x, not fragCoord.x.

    
You switch 240.dp to 360.dp. Does Kotlin construct a new RuntimeShader?
No. The compiled program stays. Kotlin writes a new resolution pair into the existing uniform slot. Lesson 8.3 constructed a new RuntimeShader because it rewrote the string to change color.

    
A pixel has x=150 on a 400-wide rectangle. What does 8.4 store? What does 8.5 store?
8.4 compares 150 < 80, which is false, so navy. 8.5 compares 150 < 200, which is true, so orange. That pair is the proof that the baked 80 does not follow size.
