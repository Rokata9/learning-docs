Chapter 8 · Hand the function to the GPU

Add a .metal file

Question: Lesson 8.1 wrote a pixel function named colorAt(column, row) and a CPU loop that called it once per cell of an 8×4 grid. SwiftUI drawing does not ask you to write that loop. How do you hand a pixel function to the GPU so it runs?

A .metal file holds the pixel-function text. Xcode compiles that file into a GPU program. ShaderLibrary plus ShaderRect asks SwiftUI to fill a rectangle using that program.
This lesson does not rebuild the 8×4 CPU loop. It does not explain the four numbers inside return half4(...). That is Lesson 8.3. It does not read position. That is Lesson 8.4’s pixel coordinate. The orange fill on this page is a JavaScript stand-in. The iPhone 16 Pro explorer runs the compiled function.

1 · THE NEW OBJECTS

Name the file, the compile, and the draw

.metal file

MSL means Metal Shading Language. It is the language this pixel-function text is written in. A .metal file stores that text. It is not yet a running program. The course does not compile Metal from a Swift String while the app runs.

Compile

Compile here means Xcode reads the .metal file and builds a GPU program from it when it builds the app. If the file is not valid Metal, the Xcode build fails. Lesson 8.12 teaches those errors. Compile is not a draw.

ShaderLibrary

ShaderLibrary is the compiled GPU program table. ShaderLibrary.labOrange() looks up the stitchable function. Looking it up does not draw a rectangle. colorEffect needs iOS 17. This project’s deployment target is 17.0, so the modifier is present.

ShaderRect and colorEffect

ShaderRect is Rectangle().fill(.white).colorEffect(shader). Every output pixel of that rectangle is then colored by the shader. You do not write a Swift for-loop over those pixels.

Entry function labOrange

The entry function is the function the GPU starts. [[ stitchable ]] marks it so ShaderLibrary can call it. SwiftUI requires float2 position, half4 color first. half4 is four numbers packed together; Lesson 8.3 names them. position is the current sample in points. color is the incoming pixel. This body does not read either parameter. Lesson 8.4 will name the pixel coordinate.

What stays from Lesson 8.1

A shader is still a pixel function the GPU runs. Same function body, once per output pixel. The new work is the handoff: .metal file → Xcode compile → ShaderLibrary → colorEffect. The CPU loop is no longer the runner.

.metal file → Xcode compiles the stitchable function → ShaderLibrary.labOrange() → ShaderRect colorEffect → GPU calls labOrange once per output pixel of that rectangle

You stop visiting cells yourself

    
    

      

        
A whole-view .blur() is still not this

        
Lesson 7.11 attached .blur() to the fill. The renderer owned that per-pixel body. Here you authored the body as a stitchable function in a .metal file. The GPU still runs it once per output pixel. You now own the text.

    return half4(0.88, 0.48, 0.18, 1.0);
}

What each part changes

        
The .metal function is the pixel-function text. Xcode compiles it when it builds the app. ShaderLibrary.labOrange() looks up that compiled function. ShaderRect fills the rectangle with colorEffect.

        
The height is 140 points. A short solid fill is enough to prove the program is attached. This is not glass geometry. The width is the explorer card width so the GPU program covers that rectangle.

        
The function is compiled once at build time. Looking it up on a later view update does not compile a string. This course does not compile Metal from a Swift String while the app runs.

9 · EXERCISES
Answer before opening each hidden solution

    
What does the Xcode build do to the .metal file?
It compiles the file: Xcode reads the text and builds a GPU program. The result is a stitchable function ShaderLibrary can look up. The build does not draw a rectangle.

    
Diagnostic: ShaderLibrary.labOrange() exists and you have not applied colorEffect. Is the rectangle filled?
No. The lookup is a Shader value. Pixels are stored when ShaderRect runs colorEffect. Stage 3 of the lab shows that empty target.

    
Is this page’s orange rectangle a real Metal shader?
No. This page cannot compile Metal. The orange is a JavaScript stand-in of the GPU output. The iPhone 16 Pro explorer runs ShaderLibrary.labOrange().

    
Why must position and color appear if this body does not read them?
SwiftUI requires that stitchable signature. It passes the current sample in points and the incoming pixel. This lesson leaves both unread. Lesson 8.4 teaches the pixel coordinate.
