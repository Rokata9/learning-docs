Chapter 8 · Same function, every output pixel

What a shader does

Question: Lesson 7.11 stacked the frosted card as whole layers: one blur, one tint, one grain, one band, one rim, and a sharp label. You attached those effects to the card. You did not write “for this pixel, return this color.” How do you choose one output pixel’s color yourself?

A pixel function is a small function that returns one color for one output pixel. The same function body runs once for every pixel. Only that pixel’s column and row change between calls.

1 · THE NEW OBJECTS

Name the grid, the function, and one call

Output grid

An 8-column by 4-row rectangle of pixels we will fill. Lesson 2.1 already defined a pixel as one addressable position. Column 0 is the leftmost column. Row 0 is the top row. There are 8 × 4 = 32 pixels.

Pixel function

A function named colorAt(column, row). It returns one straight RGB color with alpha 1 for that one pixel. Straight RGB means the red, green, and blue fields are stored independently from alpha, as Lesson 3.1 and Lesson 3.5 taught.

Call

One run of colorAt for one pair (column, row). Call 1 is (0, 0). Call 2 is (1, 0). After column 7 it wraps to the next row. The function text does not change.

Store

Write the returned color into that cell as 8-bit integers. Lesson 7.10 already defined store as writing round(channel × 255) with alpha 1. The empty cell color is only a “not filled yet” marker. It is not a destination photograph.

CPU loop — this lesson’s stand-in

The CPU is the phone’s main processor. This page’s JavaScript, and the Android explorer’s Kotlin, run a loop on the CPU: visit the next pixel, call colorAt, store, then visit the next pixel.

Shader — the GPU name for the same idea

The GPU is the phone’s graphics processor. A shader is a pixel function that processor will run. The GPU may fill many pixels at the same time. The function still has to make sense for one pixel by itself. Lesson 8.2 hands the function to Android. This lesson does not.

for row from 0 to 3: for column from 0 to 7: color = colorAt(column, row) store color in the cell at (column, row)

8 columns and 4 rows are a teaching size so 32 calls are countable. They are not the Pixel 8 Pro screen size. CSS pixels are not dp.

3 · ONE PIXEL

Column 3, row 1, stripe function

Follow one actual value. The stripe function is selected. The current pixel is column 3, row 1. That is call number 1 × 8 + 3 + 1 = 12.

Inputs

Operation, output, next consumer

3 remainder 2 = 1 1 is not 0, so colorAt returns navy store (26, 64, 102) in cell (3, 1) the next consumer is the visible cell in the output grid

Row is passed because every pixel has a row. Paint and stripe do not read row. The function still receives it so later lessons can use it without changing the call shape.

The neighbor on the right is column 4, row 1. 4 remainder 2 = 0, so that call returns orange. The function text is the same. Only the column the loop passed in changed. That pairing — leftover 1 then leftover 0 — is why stripe looks like navy, orange, navy, orange across a row.

6 · ANDROID ROUTE

The same colorAt in a Kotlin loop

fun colorAt(column: Int, row: Int, mode: Mode): Color {
    if (mode == Mode.Paint) return Orange
    return if (column % 2 == 0) Orange else Navy
}

for (row in 0 until 4) {
    for (column in 0 until 8) {
        val color = colorAt(column, row, mode)
        drawCell(column, row, color)
    }
}

What each part changes

colorAt is the pixel function. column % 2 is remainder 2. Orange and navy are fixed teaching colors, not the 7.6 navy-and-orange artwork.

The nested for loops are the CPU stand-in. They are not a GPU program. Do not look for RuntimeShader in this file.

9 · EXERCISES

Answer before opening each hidden solution

What is a pixel function in this lesson?

A small function that returns one color for one output pixel. This lesson’s name is colorAt(column, row). The same function body runs once per pixel.

Diagnostic: stripe is selected. Cell (3, 1) is navy and cell (4, 1) is orange. Did the function text change between those two calls?

No. Call 12 passed column 3, remainder 2 was 1, so navy. Call 13 passed column 4, remainder 2 was 0, so orange. Only the column the loop supplied changed.

Is this page’s loop a shader?

No. A shader is a pixel function the GPU will run. This loop runs on the CPU so each call is visible. Lesson 8.2 connects a function string to Android drawing. Lesson 8.3 proves that GPU path with one fixed color.

Why can Chapter 7’s BlurEffect not replace colorAt?

Blur still produces one color per output pixel, but you did not write that body, and it reads a neighborhood. Paint and stripe are bodies you can read. They use this pixel’s column. They do not read neighbor cells. Chapter 9 will need a per-pixel sample coordinate; that still uses this call model.

11 · EVIDENCE BOUNDARY

What this lesson establishes

Established

A pixel function returns one color per output pixel. The same body runs once per pixel. A CPU loop makes each call visible. Paint always stores orange. Stripe stores orange or navy from column remainder 2. A shader is this idea when the GPU runs it.

Not claimed

This loop is not a GPU program. It is not AGSL. It is not RuntimeShader. Column and row here come from the teaching loop, not from fragCoord. The GPU may run many pixels at once; this lesson does not measure that. Chapter 7 frost is unchanged.
