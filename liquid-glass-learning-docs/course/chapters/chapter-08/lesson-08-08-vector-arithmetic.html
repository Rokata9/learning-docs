Chapter 8 · Number the same pixels from the middle

Vector arithmetic

Question: Lesson 8.6’s UV answers “how far from the top-left?” Glass work needs “which way from the middle?” How do you build that extra pair, and why do later shaders then multiply it by 2 so the left and right edges sit near −1 and +1?

0.5 is the UV of the visual center, not a random number. Subtract it to get an extra pair p whose 0 is that center. That subtract is required for any later test about the middle. 2.0 is also not random: after the subtract the left edge is about −0.5; multiplying by 2 puts that edge at about −1, so 1 means one half-width, the run from the center to the left or right edge. The stripe is only the visible proof in this lesson. The draw rectangle does not move.
This page is a JavaScript stand-in. The iPhone 16 Pro explorer builds p = uv - (0.5, 0.5) in a stitchable function. Chapter 9 consumes this pair: a circle in the middle, scale around the center, and later background-sample offsets. This lesson does not draw those. Other arguments are Lesson 8.9. 1 · WHY THIS LESSON EXISTS

Two questions about the same pixels

UV, already learned

Question UV answers: how far is this pixel from the top-left, as a fraction of the rectangle?

Left edge ≈ 0. Visual center ≈ 0.5. Right edge ≈ 1. Lesson 8.6 used this for a left-half split and a red ramp. Keep UV for “fraction across the panel.”

The extra pair this lesson builds

Question p answers: which way is this pixel from the visual center, and how far as a fraction of the half-width?

A half-width is the run from the visual center to the left edge, or from the visual center to the right edge. Glass sits in the middle of the panel. Later tests are about that middle, not about the corner.

0.5 and 2.0 are chosen, not random. 0.5 is the UV of the visual center. Subtracting it is the step you cannot skip: 0 in p must be the middle. After that subtract the left edge is about −0.5. Multiplying by 2 maps −0.5 → −1 and +0.5 → +1. You can leave p in −0.5..+0.5. Many later shaders still write (uv - 0.5) * 2.0 so that |p.x| = 1 means “this pixel is at the left or right edge.”

Your observation about the span is correct. After × 2 the numbering covers about 2 instead of about 1. A test that keeps the same comparison numbers, such as −0.25 < p.x < 0.25, then covers half as much of the rectangle. The canvas did not shrink. The numbers in p got larger, so the same if accepts fewer pixels. That shrink is the 1D preview of Lesson 9.9: scale around the center. You keep a center-based threshold and change the scale to make the region smaller or larger without rewriting the threshold.

What this lesson proves now

A vertical stripe around the visual center, then a thinner stripe from the same two comparison numbers. The stripe tests only p.x because this lesson has not taught combining both members yet.

Chapter 8’s own destination

The Chapter 8 checkpoint is a size-independent radial effect: from the center outward. A radial test cannot use UV’s 0 at the top-left. It needs this extra pair first. Lesson 8.9 only adds sliders. It does not replace this numbering.

2 · THE NEW OPERATIONS

A new pair for “around the center,” then the same if after × 2

Two pairs, one pixel

The visual-center pixel still has uv = (0.5, 0.5). That pair is the fraction from the top-left. After subtract, that same pixel has p = (0, 0). That pair is the offset from the visual center. (0.5, 0.5) is not a leftover distance. Do not add it back. The stripe tests p, not uv.

Subtract a pair

p = uv - float2(0.5, 0.5) subtracts 0.5 from each member. The draw rectangle stays put. fragCoord stays put. Only the extra pair p is new. A pixel left of center gets negative p.x. A pixel above center gets negative p.y, because y still increases downward. fragCoord is position × displayScale. resolution is that same rectangle in pixels.

The same two comparison numbers

Both stripe programs use this exact test: if (p.x > -0.25 && p.x < 0.25). Those two numbers, −0.25 and 0.25, are not edited. They are not a physical window that resizes. They are the if written in the program.

Multiply by one number

p * 2.0 maps the ≈ −0.5 left edge to ≈ −1. Then |p.x| = 1 means “at the left or right edge”: one half-width. The center stays (0, 0) because 0 × 2 = 0. A pixel whose p.x was −0.25 becomes −0.50 and leaves the same if. That shrink is the 1D preview of Lesson 9.9. You do not need × 2 just to put 0 at the middle.

float2 p = uv - float2(0.5, 0.5) ← extra pair: offset from the visual center if (p.x > -0.25 && p.x < 0.25) orange ← the stripe. Those two numbers stay in the string
Center pixel uv = (0.5, 0.5) still the UV address p = (0.0, 0.0) after subtract p after × 2 = (0.0, 0.0) ← 0 × 2 is still 0. The center stays in the stripe

The origin of a pair is the pixel whose two numbers in that pair are both 0. For UV that pixel is the top-left. For p after this subtract, that pixel is the visual center. The function subtracts matching members: first minus first, second minus second. Multiplying a pair by one number multiplies each member by that number.

7 · iOS ROUTE
Subtract the center, then scale

    

      
// shader/VectorArithmetic.metal
[[ stitchable ]] half4 centeredFromMiddle(
    float2 position, half4 color, float scale, float2 resolution) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    float2 p = uv - float2(0.5, 0.5);
    if (p.x < 0.0 && p.y < 0.0) {
        return half4(0.88, 0.48, 0.18, 1.0);
    }
    if (p.y < 0.0) {
        return half4(0.10, 0.25, 0.40, 1.0);
    }
    if (p.x < 0.0) {
        return half4(0.05, 0.59, 0.41, 1.0);
    }
    return half4(0.85, 0.47, 0.02, 1.0);
}

What each part changes

        
float2(0.5, 0.5) builds a pair from two scalars. Subtracting it makes the extra pair p. The visual-center pixel’s p is (0, 0). Its uv is still (0.5, 0.5). The rectangle and fragCoord stay put. fragCoord is position × displayScale. Swift passes the pixel size with .float2.

        
The stripe function keeps if (p.x > -0.25 && p.x < 0.25). The scaled function multiplies p by 2.0, then uses that same if. The two comparison numbers are not edited. The stripe gets thinner because pixels near the old edge now fail the test. Switching programs selects another stitchable function. It does not compile a string.

10 · EXERCISES
Answer before opening each hidden solution

    
After subtract, the center pixel’s p is (0, 0). Is (0.5, 0.5) now a distance?
No. (0.5, 0.5) is still that pixel’s UV address: the fraction from the top-left. p = (0, 0) is the extra pair. Do not add 0.5 back. The stripe tests p.x, not UV.

    
Diagnostic: what stays written in the if when the stripe gets thinner?
The two comparison numbers −0.25 and 0.25. The scaled program still says if (p.x > -0.25 && p.x < 0.25). The pixel at UV 0.25 has p.x = −0.25 after subtract and p.x = −0.50 after × 2. −0.50 sits outside that range, so the pixel leaves the orange stripe. The rectangle did not shrink.

    
Why is negative p.y the top half?
y increases downward. A pixel above the center has smaller y, so uv.y - 0.5 is negative. Subtracting 0.5 does not flip the axis.

    
Is the stripe a circle?
No. The stripe is the vertical strip where p.x is between −0.25 and 0.25. A circle would use both members together. That is Lesson 9.2. The stripe exists so you can see a center-based test before that lesson.

    
Diagnostic: subtract already put 0 at the middle. Why multiply by 2?
After subtract the left edge is about −0.5 and the span is still about 1. Multiplying by 2 maps that edge to about −1, so 1 means one half-width. It is a convention, not required to center. The same multiply is also Lesson 9.9’s scale-around-the-center: a fixed numeric test then covers less of the rectangle, which is why the stripe looks smaller. 2.0 is not a random number. It is “the edge was ±0.5; make it ±1.”
