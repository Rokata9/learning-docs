1 · THE NEW OBJECTS

Name fragCoord, float2, and the 80-pixel split

fragCoord

fragCoord is this course’s name for the current output pixel’s position, in pixels. SwiftUI passes position in points. splitAtEighty multiplies by scale, which is displayScale. The GPU passes a new position every time it calls that function. Lesson 8.1’s column was a cell index in an 8-wide teaching grid. fragCoord.x is not that index. It is a pixel count from the left edge of this draw rectangle.

float2

A float2 is two numbers packed together, in order: x then y. The word float names a storage size. Lesson 8.7 explains float versus half. Here you only need “two numbers.” Read them as fragCoord.x and fragCoord.y.

Coordinate space

The space is the draw rectangle that ShaderRect fills. Origin is the top-left corner of that rectangle. x increases to the right, as Lesson 2.2 taught. y increases downward, as Lesson 2.3 taught. position is in points. pixel fragCoord is position × displayScale. The comparison uses pixels, not points.

Split at 80 pixels

80.0 is a named pixel count from the left. It is not half of the rectangle. If x is less than 80, the return is teaching orange. Otherwise the return is teaching navy. The same function body runs for every pixel. Only fragCoord changes.

fragCoord = (x pixels from left, y pixels from top) of the draw rectangle if (fragCoord.x < 80.0) return half4(0.88, 0.48, 0.18, 1.0) ← teaching orange else return half4(0.10, 0.25, 0.40, 1.0) ← teaching navy

The comparison fragCoord.x < 80.0 asks: is this pixel’s distance from the left smaller than 80 pixels? Yes stores orange. No stores navy. y is present in the pair and is unread. Lesson 8.5 will tell the shader the rectangle’s width so a split can follow size.

Y origin is the draw rectangle, not GLSL

        
SwiftUI position matches the draw rectangle: origin at the top-left, y increases downward. pixel fragCoord uses that same direction after position × displayScale. GLSL fragment coordinates start at the lower left. This course does not convert to GLSL space. Do not subtract y from height in this lesson.

6 · iOS ROUTE
One function that reads x

    

      
// shader/FragCoord.metal
[[ stitchable ]] half4 splitAtEighty(float2 position, half4 color, float scale) {
    float2 fragCoord = position * scale;
    if (fragCoord.x < 80.0) {
        return half4(0.88, 0.48, 0.18, 1.0);
    }
    return half4(0.10, 0.25, 0.40, 1.0);
}

let shader = readX
    ? ShaderLibrary.splitAtEighty(.float(Float(displayScale)))
    : ShaderLibrary.labOrange()
ShaderRect(shader: shader)
// indigo line at 80 / displayScale points when the program reads x

      

        
What each part changes

        
80.0 is a pixel count. position is points, so the function multiplies by scale before the comparison. The indigo line is drawn at 80 / displayScale points. It is a teaching mark. It is not a second shader.

        
The unread 8.3 program is labOrange. Switching to it must fill the whole rectangle orange. That is the proof that reading x is what created the split.

        
80.0 stays 80 pixels on the iPhone 16 Pro even when the rectangle is hundreds of pixels wide. At scale 3 the band is 80 ÷ 3 points. That leftover is Lesson 8.5’s problem.

9 · EXERCISES
Answer before opening each hidden solution

    
What is fragCoord in this lesson?
The current output pixel’s position in the draw rectangle. It is a float2: x pixels from the left, y pixels from the top. SwiftUI passes position in points. fragCoord = position × displayScale.

    
Diagnostic: the teaching rectangle is 400 pixels wide. Is the orange band half of the rectangle?
No. The split is 80 pixels from the left. Half of 400 would be 200. 80 is a pixel count written into the string, not half the width.

    
Two pixels have x=40. One has y=60. The other has y=160. Why are both orange?
The if reads only fragCoord.x. Both have x=40, and 40 < 80.0. y is unread, so the row does not change the store.

    
Is fragCoord.x = 40 the same object as Lesson 8.1’s column 40?
No. Lesson 8.1’s column was a cell index in an 8-wide teaching grid. Valid columns were 0 through 7. 40 is a pixel count from the left of this draw rectangle.
