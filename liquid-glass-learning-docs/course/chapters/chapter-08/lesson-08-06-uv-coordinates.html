Chapter 8 · Divide position by size

UV coordinates

Question: Lesson 8.5 split the rectangle at half of resolution.x. That half is still a pixel count: 200 when the width is 400. How do you describe this pixel as a fraction of the rectangle, so 0.5 means halfway across any width?

UV in this lesson is the pair (fragCoord.x / resolution.x, fragCoord.y / resolution.y). U is the horizontal fraction of the width. V is the vertical fraction of the height. Lesson 2.8 called this a normalized coordinate. The shader name for that pair is UV.
This page is a JavaScript stand-in. The iPhone 16 Pro explorer divides pixel fragCoord by the pixel resolution. float versus half is Lesson 8.7. Remapping the pair so 0 sits at the visual center is Lesson 8.8. Other arguments are Lesson 8.9.

1 · THE NEW OPERATION

Divide each member by its matching size

8.5 leftover

splitX = resolution.x / 2.0 is a pixel count. On a 400-wide rectangle it is 200. On a 240-wide rectangle it is 120. The number that means “halfway” keeps changing because it is still measured in pixels.

UV

UV is two fractions. u = fragCoord.x / resolution.x. v = fragCoord.y / resolution.y. At x=150 on a 400-wide rectangle, u is 150 / 400 = 0.375. That 0.375 is not 150 and not 200.

Matching members

x is divided by width. y is divided by height. Those two divisions are separate. The short form fragCoord / resolution still does those two matching divisions. It does not divide both members by width.

Next consumer

The pair is consumed by a test such as if (uv.x < 0.5), or by a store such as return half4(uv.x, 0.0, 0.0, 1.0). The red-channel store makes the fraction itself visible as a left-to-right ramp.

u = fragCoord.x / resolution.x v = fragCoord.y / resolution.y float2 uv = fragCoord / resolution ← same two matching divisions, packed
Teaching pixel (150, 80) on 400 × 160: u = 150 / 400 = 0.375 v = 80 / 160 = 0.5 ← 0.375 < 0.5, so this pixel is left of halfway ← 0.5 is halfway down the height

0 is the left edge for u and the top edge for v. 1 would be the right edge and the bottom edge. A pixel sitting just inside the right edge has u a little below 1, because fragCoord.x is this pixel’s position, not the rectangle’s width. Lesson 2.8 already separated the last pixel from the right edge. On the iPhone 16 Pro, fragCoord is position × displayScale and resolution is that same rectangle in pixels. Both sides of the divide use pixels. Dividing point position by a pixel resolution would shrink every fraction by displayScale.

3 · ONE PIXEL, TWO WIDTHS
150 pixels is not a stable fraction

    
Follow x=150 first. Then follow the fraction 0.375. Those two stories run in opposite directions.

    

      

        
Fixed pixel x=150

        
width 400:
150 / 400 = 0.375
0.375 < 0.5 → left half

width 240:
150 / 240 = 0.625
0.625 < 0.5 → right half

        
The pixel count 150 did not change. Its fraction of the width did. A baked pixel count is not a UV value.

      

      

        
Fixed fraction u=0.375

        
u × width = x

width 400:
0.375 × 400 = 150 px from the left

width 240:
0.375 × 240 = 90 px from the left

        
The same relative point survives the size change. That is why UV exists. Lesson 2.8 taught this on a SwiftUI view. This lesson computes it inside the stitchable function.

      

    

    
The half split is a poor proof by itself. uv.x < 0.5 and fragCoord.x < resolution.x / 2.0 store the same orange/navy split. They are the same test written two ways. The new object is the fraction 0.375, which the red ramp stores as the red channel.

6 · iOS ROUTE
Divide inside the function, after Swift passes resolution

    

      
// shader/UvCoordinates.metal
[[ stitchable ]] half4 uvSplitAtHalf(
    float2 position, half4 color, float scale, float2 resolution) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    if (uv.x < 0.5) {
        return half4(0.88, 0.48, 0.18, 1.0);
    }
    return half4(0.10, 0.25, 0.40, 1.0);
}

let pixelWidth = pointWidth * displayScale
let pixelHeight = pointHeight * displayScale
ShaderLibrary.uvSplitAtHalf(
    .float(Float(displayScale)),
    .float2(Float(pixelWidth), Float(pixelHeight)))
// 8.5 leftover stays ShaderLibrary.halfOfResolution(...)

      

        
What each part changes

        
Swift still passes resolution once per draw, as in Lesson 8.5. The new line is float2 uv = fragCoord / resolution inside uvSplitAtHalf.

        
That line is two matching divisions. It is not a third argument. UV is calculated on the GPU for this pixel, after the GPU already has this pixel’s fragCoord and the shared resolution pair. fragCoord is position × scale. resolution is the same rectangle in pixels.

        
Switching 240 pt and 360 pt does not compile a new function. Swift passes a new float2. Switching the teaching program (half, UV split, red ramp, four regions) selects another stitchable function Xcode already compiled. There is no runtime string compiler.

9 · EXERCISES
Answer before opening each hidden solution

    
What is UV in this lesson?
The pair (fragCoord.x / resolution.x, fragCoord.y / resolution.y). U is the horizontal fraction of the width. V is the vertical fraction of the height. Lesson 2.8 called this a normalized coordinate.

    
Diagnostic: why is uv.x < 0.5 a poor proof that UV is new?
It stores the same left/right split as Lesson 8.5’s fragCoord.x < resolution.x / 2.0. The new object is the fraction itself, for example 0.375 at x=150 on width 400. The red ramp stores that fraction as the red channel. The four-region fill reads v as well, which 8.5 never did.

    
Pixel (200, 80) on 400 × 160. What is UV if you divide both members by width?
(200/400, 80/400) = (0.5, 0.2). The pixel is visually halfway down. 0.2 is not halfway down. A later uv.y < 0.5 test would then be true for every row of this short rectangle.

    
Does the last pixel of a 400-wide rectangle have u = 1?
No. 1 would be the right edge, which is the width itself. A pixel whose x is 399.5 has 399.5 / 400 = 0.99875. Division produces the fraction. This lesson does not clamp it.

11 · EVIDENCE BOUNDARY
What this lesson establishes

    

      
Established
UV is the pair of matching divisions fragCoord / resolution. U is x over width. V is y over height. A fixed pixel count is not a stable fraction. A fixed fraction is a stable relative position. The half split matches Lesson 8.5. The red ramp and the four-region fill are the new visible consumers. The last pixel is not exactly u = 1.

      
Not claimed
This page’s fill is not a GPU compile. float versus half is Lesson 8.7. Subtracting 0.5 so the pair’s 0 is the visual center is Lesson 8.8. Color, time, and other arguments are Lesson 8.9. UV is not a texture sample. Chapter 7 frost is unchanged.
