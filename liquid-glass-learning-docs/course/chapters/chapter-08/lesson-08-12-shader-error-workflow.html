Chapter 8 · Compile the string, then shrink a failure

Shader error workflow

Question: Lesson 8.2 compiles an AGSL string when Kotlin constructs RuntimeShader(string). If that string is illegal, there is no running program. How do you read the constructor exception and shrink the string until one bad line is isolated?

A shader compile error is a failure of RuntimeShader(string). Android throws IllegalArgumentException. The message usually starts with error:, then a 1-based line number, then the complaint. A smallest failing program is the shortest string that still throws. Fix that string. Then restore the other lines.

1 · THE NEW MOMENT

Construction compiles. A later uniform write does not.

8.2 leftover

Lesson 8.2 constructed RuntimeShader(agslString). That call compiles the string. A legal string becomes a running program. This lesson is the illegal-string path of that same call.

8.9 leftover

A mismatched Kotlin uniform name is not a compile error. The program still constructs. The unread slot stays at 0. Do not hunt a compile message for that case.

Exception

An exception is an object the runtime throws instead of returning a value. IllegalArgumentException is the type Android documents for a bad RuntimeShader string. Its message field holds the compiler text.

Line number

The number after error: counts lines in the string passed to the constructor, starting at 1. A leading newline in a Kotlin """ string is line 1 if that newline is inside the string.

Kotlin: try { RuntimeShader(agslString) } catch (e: IllegalArgumentException) { // e.message is the compiler text } ← no running ShaderBrush if this catch runs ← setFloatUniform is not reached

5 · THREE FAILURES, ONE RULE
The workflow does not change with the complaint

    

      

        
Unknown name

        
gl_FragCoord is not an AGSL identifier. Typical complaint names that token. Smallest failing form is one main that uses it once.

      

      

        
Missing semicolon

        
AGSL statements end with ;. Public Android output for this class of error looks like error: 13: expected ';', but found '. Smallest failing form is return half4(1.0, 0.0, 0.0, 1.0) without the semicolon.

      

      

        
Wrong return type

        
Lesson 8.3’s contract is half4 main(...). A float main that returns 1.0 is a different signature. Smallest failing form is that signature alone.

      

    

    
Not a compile error: Lesson 8.9’s name mismatch still constructs. setFloatUniform("splitX", ...) when AGSL declared splitU is a later write failure or a silent 0, not a constructor exception. Do not shrink the AGSL string for that.

  


  

    
6 · ANDROID ROUTE
Construct inside try, keep the working string first

    

      
private fun compile(source: String): CompileResult {
    return try {
        CompileResult.Ok(RuntimeShader(source))
    } catch (e: IllegalArgumentException) {
        CompileResult.Fail(e.message ?: "IllegalArgumentException")
    }
}

val result = remember(sampleKey) { compile(source) }

when (val current = result) {
    is CompileResult.Ok -> {
        Canvas(...) {
            current.shader.setFloatUniform(
                "resolution",
                size.width,
                size.height,
            )
            current.shader.setFloatUniform("edge0", 0.40f)
            current.shader.setFloatUniform("edge1", 0.60f)
            drawRect(brush = ShaderBrush(current.shader))
        }
    }
    is CompileResult.Fail -> {
        Text(current.message)
    }
}

      

        
What each part changes

        
The production path is the working 8.11 string. Broken strings exist only because this lesson’s new operation is reading a constructor failure. They are opt-in buttons, not extra drawing modes in the main glass engine.

        
remember(sampleKey) reconstructs when the selected string changes. A successful compile still does not rebuild while uniforms change. That is 8.9. A failed compile never reaches setFloatUniform.

        
The printed message is the live IllegalArgumentException.message. This HTML page’s typical shapes can differ in punctuation from a given device.

9 · EXERCISES
Answer before opening each hidden solution

    
When does AGSL compilation run in this course’s Android path?
When Kotlin constructs RuntimeShader(string). A later setFloatUniform write is not compilation. Lesson 8.9 already wrote extra slots into a program that had constructed successfully.

    
Diagnostic: Kotlin writes setFloatUniform("splitX", 0.25f) but AGSL declared uniform float splitU. Is the next step shrinking the AGSL string?
No. That program still compiles. Lesson 8.9’s mismatch leaves splitU at 0 or throws at the write, depending on the call. It is not a constructor compile error. Do not delete mix and smoothstep to debug it.

    
You replace the body of a failing 8.11 string with return half4(0.88, 0.48, 0.18, 1.0); and construction succeeds. What did that prove?
The uniforms and the half4 main(float2 fragCoord) signature were legal. The bad line was in the body you removed. Restore body lines one at a time until construction fails again. That restored line belongs in the smallest failing program.

    
Why keep a leading newline in mind when you read error: 6:?
The line number counts lines in the exact string passed to the constructor, starting at 1. A Kotlin """ string that starts on the next source line includes that first newline. Line 6 in the exception may be line 5 of the visible AGSL if you ignored that newline.
