Chapter 8 · Compile the file, then shrink a failure

Shader error workflow

Question: Lesson 8.2 adds a .metal file and Xcode compiles it at build time. If that file is illegal, there is no running function. How do you read the Xcode Metal log and shrink the function until one bad line is isolated?

A shader compile error is a failure of the Xcode Metal compile. The log names the .metal file, a 1-based line, a column, and the complaint. There is no Swift try. A smallest failing program is the shortest function that still produces that error. Fix that function. Then restore the other lines.
This page does not compile Metal. It shows the Metal compiler text for three prepared sources. The iPhone 16 Pro explorer draws only the working 8.11 function. Broken sources are not in the built file, because that would fail the Xcode build.

3 · REDUCE
Start from 8.11 with one GLSL name left in
gl_FragCoord is GLSL’s name for the current pixel. This course’s pixel position is fragCoord = position × scale, from Lesson 8.4. The rest of the function is legal. The job is to prove that with shrinking, not by rereading the whole file.

    

    

      

        
If the tiny body compiles

        
Replace the body with return half4(0.88, 0.48, 0.18, 1.0);. If the file now compiles, the extra arguments and the stitchable signature were not the failure. SwiftUI still requires float2 position, half4 color first. The bad line is in the body you removed.

      

      

        
If the tiny body still fails

        
The failure is in the leftover lines or the signature. Shrink those next. Do not restore mix and smoothstep until the tiny function compiles.

5 · THREE FAILURES, ONE RULE
The workflow does not change with the complaint

    

      

        
Unknown name

        
gl_FragCoord is not an MSL identifier. The Metal log says use of undeclared identifier 'gl_FragCoord'. If a local fragCoord exists, the note adds did you mean 'fragCoord'?. Smallest failing form is one stitchable function that names gl_FragCoord once. It still starts with float2 position, half4 color.

      

      

        
Missing semicolon

        
MSL statements end with ;. The Metal log for this source is expected ';' after return statement, at the line of that return. Smallest failing form is that return without the semicolon, inside a stitchable half4 function.

      

      

        
Wrong return type

        
Lesson 8.3’s store is half4. Metal still compiles [[ stitchable ]] float. The Swift file compiles too, because ShaderLibrary is a name lookup. The output type is float, not four channels. That is not an Xcode Metal error. Do not shrink the file looking for a log that will not appear.

      

    

    
Not a compile error: Lesson 8.9’s missing argument still lets the Swift file compile. SwiftUI refuses that draw. It does not fill the slot with 0. Pass 0 on purpose to show the slot. Do not shrink the .metal function for that.

9 · EXERCISES
Answer before opening each hidden solution

    
When does Metal compilation run in this course’s iOS path?
When Xcode builds the app. A later .float argument pass is not compilation. Lesson 8.9 already passed extra arguments into a function that had compiled successfully.

    
Diagnostic: the Swift call omits splitU. Is the next step shrinking the .metal function?
No. The Swift file still compiles, because ShaderLibrary looks the function up by name. SwiftUI refuses that draw. It does not fill the slot with 0. Pass 0 to show the slot. It is not an Xcode Metal error. Do not delete mix and smoothstep to debug it.

    
You replace the body of a failing 8.11 function with return half4(0.88, 0.48, 0.18, 1.0); and the file compiles. What did that prove?
The extra arguments and the stitchable signature were legal. SwiftUI still requires float2 position, half4 color first. The bad line was in the body you removed. Restore body lines one at a time until the build fails again. That restored line belongs in the smallest failing program.

    
Why does the teaching log say line 13, not the line number you see in the function body?
The line number counts lines in the .metal file, starting at 1. #include <metal_stdlib>, using namespace metal;, the blank line, and the multi-line signature come before float2 uv = gl_FragCoord / resolution;. That uv line is line 13 of the prepared file.

What this lesson establishes

    

      
Established
Compilation happens when Xcode builds the .metal file. gl_FragCoord in an otherwise legal 8.11 function fails that build before any .float pass. The useful next step is to shrink to a smallest failing function, fix that line, then restore. A Lesson 8.9 missing argument is a different failure moment, and it is not a silent 0.

      
Not claimed
This HTML page does not run the Metal compiler. The log wording is the compiler text captured for these sources. A float stitchable return is not a compile error. No runtime try. No GPU timing. Chapter 9 distance fields are unused. Chapter 7 frost is unchanged.
