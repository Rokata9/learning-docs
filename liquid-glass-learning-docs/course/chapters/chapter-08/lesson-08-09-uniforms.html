Chapter 8 · Write Kotlin values that are not size

Uniforms

Question: Lesson 8.3 rebuilt RuntimeShader to change color. Lesson 8.5 wrote only the rectangle size into a uniform. How do you send a slider value and a color from Kotlin into the same compiled program?

A uniform is still a named slot. This lesson adds two slots besides resolution: splitU, one fraction from 0.0 through 1.0, and leftColor, four channels each from 0.0 through 1.0. Kotlin writes them with setFloatUniform. The AGSL string is not rewritten. The GPU reads the same slot values for every pixel of this draw.

1 · THE NEW SLOTS

Resolution stays. Two more names join it.

8.3 leftover

Changing orange to navy meant a new AGSL string and a new RuntimeShader. That path still works. It is the wrong path for a slider that moves every frame of a drag.

8.5 leftover

Resolution is already a uniform. This lesson does not re-teach size. It keeps writing resolution so UV can be computed, then writes two more slots.

splitU

uniform float splitU is one fraction from 0.0 through 1.0. Kotlin writes the current slider value. if (uv.x < splitU) uses that same number at every pixel. 0.5 is halfway. 0.25 is a quarter from the left.

leftColor

uniform half4 leftColor is four channels, each from 0.0 through 1.0. Kotlin writes them with four floats. The else branch still returns teaching navy from the string, so only the left store is a slot.

Kotlin, once per draw: setFloatUniform("resolution", size.width, size.height) setFloatUniform("splitU", splitU) setFloatUniform("leftColor", r, g, b, a) ← three writes, one compiled program
AGSL, once per pixel: float2 uv = fragCoord / resolution; if (uv.x < splitU) return leftColor; return navy ← splitU and leftColor are the same for every pixel ← uv is not

The Kotlin name string must equal the AGSL name. A mismatch is not a compile error. The unread slot then stays at its default, often 0. If splitU stays 0, uv.x < 0 is false for pixels inside the rectangle, so the orange band vanishes. Lesson 8.12 is the fuller error workflow. This lesson only needs that visible leftover.

6 · ANDROID ROUTE
Three writes, one RuntimeShader

    

      
private const val UniformAgsl = """
uniform float2 resolution;
uniform float splitU;
uniform half4 leftColor;

half4 main(float2 fragCoord) {
    float2 uv = fragCoord / resolution;
    if (uv.x < splitU) {
        return leftColor;
    }
    return half4(0.10, 0.25, 0.40, 1.0);
}
"""

val shader = remember { RuntimeShader(UniformAgsl) }

Canvas(...) {
    shader.setFloatUniform("resolution", size.width, size.height)
    shader.setFloatUniform("splitU", splitU)
    shader.setFloatUniform(
        "leftColor",
        leftR, leftG, leftB, 1.0f,
    )
    drawRect(brush = brush)
}

      

        
What each part changes

        
remember { RuntimeShader(...) } still compiles once. Slider and color changes do not enter that remember block.

        
Four-float setFloatUniform writes the half4. This lesson does not call setColorUniform, which can convert into the shader’s working color space. The teaching numbers should match Lesson 8.3’s 0..1 channels exactly.

        
The name-mismatch leftover lives on this HTML page. The Android explorer only writes matching names. Writing a name that the compiled program does not declare can throw, so that path is not an executable device toggle.

9 · EXERCISES
Answer before opening each hidden solution

    
What new slots does this lesson add?
uniform float splitU and uniform half4 leftColor. Resolution is still written, as in Lesson 8.5. Time is not a slot yet.

    
Diagnostic: you change leftColor from orange to green. Is RuntimeShader reconstructed?
No. Kotlin writes four new floats into the existing leftColor slot. Lesson 8.3 reconstructed because it rewrote the AGSL string. This path does not rewrite the string.

    
Kotlin writes "split" but AGSL declares splitU. What do you see?
The unread splitU stays at its default, often 0. uv.x < 0 is false inside the rectangle, so the fill is navy and the orange band vanishes. That is not an AGSL compile error.

    
Why not setColorUniform in this lesson?
That API can convert the color into the shader’s working color space. Four-float setFloatUniform writes the same 0..1 numbers Lesson 8.3 used. The conversion path is not measured here.
