Chapter 8 · Pass a number that changes every frame

Time uniform

Question: Lesson 8.6 stored the horizontal UV fraction as red. That ramp sits still because nothing in the compiled function changes between draws. Lesson 5.2 already measured elapsed seconds with TimelineView(.animation). How do you send that growing number into the same compiled function so the ramp moves?

A trip is one crossing of the black edge (stored red = 0) from the left of the rectangle to the right. Swift converts elapsed seconds into a trip count with trips = elapsedSeconds / 4.0. It passes that count into float time every frame. The function stores fract(uv.x - time) as red. The .metal file is not rewritten.
This page uses 8.9’s contract: extra arguments are passed with .float and the .metal file is not rewritten. Time is the new argument. This page is a JavaScript stand-in. The iPhone 16 Pro explorer passes the real frame-clock value. Xcode Preview freezes at 0.25 trips.

1 · THE NEW SLOT

The ramp already exists. Time is the number that moves it.

8.6 leftover

Lesson 8.6 stored uv.x as red. At pixel x=100 on a 400-wide rectangle, uv.x = 100 / 400 = 0.25, so that pixel stored half4(0.25, 0.0, 0.0, 1.0). The next draw stored the same red. The picture sat still.

5.2 leftover

Lesson 5.2 subtracted two TimelineView dates to get elapsed seconds. That number lives in Swift. The shader cannot see Swift variables unless they are passed as arguments.

time

float time is one number shared by every pixel of this draw. Its unit in this lesson is trips, not seconds. Swift divides elapsed seconds by 4 before the pass. 4 is SecondsPerTrip: four seconds of wall-clock time produce one trip, so 0.25 and 0.50 stay readable.

8.9 leftover

Lesson 8.9 already passed extra arguments without rewriting the .metal file. Time uses that same pass. The new part is that Swift changes the number on every frame-clock tick, even if you do not drag a slider.

Swift, once per frame: elapsedSeconds = newDate − previousDate trips = elapsedSeconds / 4.0 .float(trips) ← 4.0 is SecondsPerTrip, a teaching choice ← the .metal file is not recompiled
Metal, once per pixel: float2 fragCoord = position * scale; float2 uv = fragCoord / resolution; float stripe = fract(uv.x - time); return half4(stripe, 0.0, 0.0, 1.0); ← time is the same for every pixel ← uv.x is not

Subtracting time from uv.x is legal because both numbers are unitless trip counts: uv.x is this pixel’s fraction of one trip across the width, and time is how many trips have elapsed. Swift already turned seconds into trips. Do not subtract a raw second count from a UV fraction without that conversion.

3 · FRACT
Keep the leftover after removing whole trips
A stored red channel uses 0.0 through 1.0. uv.x - time can leave that range. fract puts it back.

    

      

        
floor

        
floor(x) is the whole number that is not larger than x. On the number line, that is x itself when x is already a whole number. Otherwise it is the first whole number to the left of x.

        
floor(0.25) = 0
floor(1.00) = 1
floor(1.25) = 1
floor(-0.25) = -1
  ← 0 is larger than -0.25, so floor walks left

      

      

        
fract

        
fract(x) is the leftover after removing complete 1.0-sized steps with floor. MSL lists floor as the nearest integer that is not larger than x. This lesson uses the same identity:

        
fract(x) = x − floor(x)
fract(0.25) = 0.25 − 0 = 0.25
fract(-0.25) = -0.25 − (-1) = 0.75
  ← leftover is always 0.0 (included) through 1.0 (not included)

      

    

    
    
    

    
Why the left edge needs this immediately. At time = 0.25, pixel x=0 has uv.x = 0, so 0 - 0.25 = -0.25. Wrap is not a later special case. It is required as soon as time is greater than that pixel’s uv.x.

Direction at this pixel

        
While time increases and this pixel has not yet wrapped, stored red decreases: 0.25 → 0.00. After the wrap at time = 0.25, the next sample at 0.50 has stored red 0.75, which is larger. Then at 1.25 it is 0.00 again. The adjective “moves” is that pair of changes: decreasing leftover, then a jump up when floor drops by 1.

      

      

        
Where the black edge sits

        
Stored red is 0 when uv.x - time is a whole number, so uv.x = leftover(time). The indigo line in the lab is drawn at that fraction of the width. As time increases, that line travels to the right. After a whole trip it starts at the left again.

6 · iOS ROUTE
Frame clock, then one float argument

    

      
// shader/TimeUniform.metal
[[ stitchable ]] half4 timeRamp(
    float2 position, half4 color, float scale, float2 resolution,
    float time) {
    float2 fragCoord = position * scale;
    float2 uv = fragCoord / resolution;
    float stripe = fract(uv.x - time);
    return half4(stripe, 0.0, 0.0, 1.0);
}

TimelineView(.animation(minimumInterval: nil, paused: !playing)) { context in
    // first date after Play only primes the clock
    // later dates: trips += elapsedSeconds / 4
}

let pixelWidth = pointWidth * displayScale
let pixelHeight = pointHeight * displayScale
ShaderLibrary.timeRamp(
    .float(Float(displayScale)),
    .float2(Float(pixelWidth), Float(pixelHeight)),
    .float(trips))

      

        
What each part changes

        
Xcode compiles timeRamp when it builds the app. Play does not compile a new function.

        
TimelineView(.animation) is the Lesson 5.2 clock. Subtracting two dates gives elapsed seconds. Dividing by SecondsPerTrip turns seconds into trips. The first date after Play only stores the start, so the first gap is not added.

        
Some samples pass iTime from an animator. This course’s explorer passes time from the frame clock. Both are argument passes. They are not claimed to produce identical timestamps.

        
Xcode Preview freezes at 0.25 trips so the ramp is visibly shifted from Lesson 8.6. Play on the iPhone 16 Pro.

9 · EXERCISES
Answer before opening each hidden solution

    
What new argument does this lesson add, and what unit does Swift pass into it?
float time. The passed number is a trip count. Swift converts with trips = elapsedSeconds / 4.0. 4.0 is SecondsPerTrip. Resolution is still passed. splitU is not this lesson’s argument.

    
Diagnostic: you pause at 0.25 trips. Does the ramp keep moving?
No. Pause stops adding to the trip count. Every later draw passes the same time value, so fract(uv.x - time) is unchanged and the picture sits. Motion is a changing argument, not a property of the compiled function.

    
At time = 0.25, pixel x=0 stores which red, and why is it not negative?
uv.x = 0, so 0 - 0.25 = -0.25. floor(-0.25) = -1. fract(-0.25) = -0.25 - (-1) = 0.75. The stored red is 0.75. Wrap is required as soon as time is greater than that pixel’s uv.x.

    
Why divide seconds by 4 before .float(trips)?
So uv.x and time are both unitless trip counts and can be subtracted. 4 is a teaching duration: one trip takes four wall-clock seconds. The .metal file does not contain that 4. Changing 4 in Swift changes speed without compiling a new function.

11 · EVIDENCE BOUNDARY
What this lesson establishes

    

      
Established
Time is a uniform. Swift converts elapsed seconds into trips and passes that count every frame. Every pixel of this draw reads the same time. fract(uv.x - time) wraps the leftover into 0..1 and is stored as red, so Lesson 8.6’s ramp travels. The .metal file is not rewritten. Pause passes a frozen number.

      
Not claimed
No mix, smoothstep, or sine. No GPU timing measurement. No claim that TimelineView dates match any other clock. No .color. Lesson 8.11 is the next consumer of wrapping into a 0..1 leftover. Chapter 7 frost is unchanged.
