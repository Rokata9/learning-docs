Lesson 11.1 — The glass picture, and the shader that reads it.

Look at “New Tab” and the soft amber stripe behind it. Both can move inside the dark menu. Build the picture they share, then follow one output pixel to see how reading farther right puts the picture farther left.

Where this is used. Lesson 11.2 uses this same read with a different source point at each pixel near the rim, so the picture bends there. Lesson 11.4 uses the glass picture in place of the flat color inside the resting menu, so the lens can bend both the page and the rows.

Section 1 · build the sourcePut the page, tint, and rows in one picture

The lab uses the resting menu’s 261 × 188 pt size from the Safari recording. Here we enlarge that region of the phone screen so you can see the changes. Each view counts in points from the top-left corner of the pictured region. x goes right and y goes down. Green marks inputs we know before a calculation.

    Draw the page again

    We choose an amber shape with a foot on its right and put a blue block on the other side. The picture looks different when it moves or flips. The sharp page in the first picture is a separate SwiftUI view. layerEffect can read only the view you apply it to. It cannot see the page already drawn behind that view.

    The app owns the page, so it draws the same SwiftUI page again in the same place. The second picture shows that copy. The app can now change the copy while the page behind the menu stays sharp.

    Soften the copy

    Look at the amber foot. Its sharp boundary becomes a soft patch. We apply a blur of 18 pt to the copied page. This is the course’s starting setting. A larger radius spreads the softening over a wider area.

    Lay dark gray over the blur

    The tint is a sheet of dark gray over the copied page. We use the shortcut lab’s dark menu gray and choose its opacity to be 0.55 so the colored marks remain visible in the demo. At opacity 0 the tint contributes nothing. At 1 the tint covers the copy. Watch the amber and blue get darker while their shapes remain visible.

    Draw the rows on top

    Draw the rows last so they stay sharp. SwiftUI’s ZStack puts the blur at the back, the tint above it, and the rows in front. Apply .compositingGroup() to keep those children together, then apply .layerEffect to the group. The shader gets one flat glass picture with the blur, the tint, and the rows already drawn together.

    Use SwiftUI views for this copy. Apple says a UIKit-backed view inside a layer effect may fail to draw into the layer. SwiftUI may show a placeholder and log a warning. For example, keep a wrapped UIKit web view outside this effect and supply a SwiftUI-rendered picture for the shader to read. Apple’s layerEffect documentation

    Section 2 · follow the readWhich point gives P its color?

    P is the output pixel we want to color. The center of P starts at (174, 58) pt, just to the left of the amber stripe’s center. The worked figures show the glass picture as a rectangle so you can follow P across it. A dot marks the center of a pixel or the exact place to read.

    SwiftUI runs the Metal function for each output pixel. SwiftUI passes the location of that pixel as position and the drawn glass picture as layer. In this lab position is in points from the top-left corner of the effect’s own view. The axes in both pictures show that local origin. The phone screen has its own top-left corner farther up and left.

    We choose 10 pt right so the shift is easy to see. This is a move of +10 along x and 0 along y. Start at P and follow the arrow to S, the source point on the glass picture. Drag P in either picture or use the arrow keys on its dot. Then try a read of 0 pt.

    Read distance

    layer.sample(S) reads the color at S. When S falls between the centers of pixels in the picture, the sampler blends nearby colors. The function returns that color for P.

    Reset P and compare the two pictures at 10 pt. The amber stripe starts at x = 184 pt, at S. It appears at x = 174 pt, at P. To find how the stripe moved, subtract its starting x from its output x.

    Stripe’s shift = 174 − 184 = −10 pt

    The minus sign means left. Each output pixel looks 10 pt to the right for its color, so every feature lands 10 pt to the left of where it started, including the menu rows. The menu’s outline is a fixed cutout around the result.

    Section 3 · Swift and MetalReturn the color that S supplies

    What the sample contains

    The sample returns four numbers in one half4. They hold red, green, blue, and alpha, in that order. Alpha is opacity. It ranges from 0 for fully transparent to 1 for fully opaque. The sample’s color is premultiplied. Its red, green, and blue already include the color’s share of opacity.

    For a small example, choose red 0.80, green 0.40, blue 0.20, and alpha 0.50. To store the color’s contribution, multiply each color number by alpha. Keep alpha itself.

    Stored red = 0.80 × 0.50 = 0.40
    Stored green = 0.40 × 0.50 = 0.20
    Stored blue = 0.20 × 0.50 = 0.10
    Premultiplied RGBA = (0.40, 0.20, 0.10, 0.50)

    For P’s actual read, the copied page is opaque behind the tint and rows, so the finished color at S has alpha 1. The shader returns the sampled numbers as they are. At a translucent source the same return would preserve the alpha and the already weighted color.

    Allow room for the read

    maxSampleOffset declares the allowed read distance from any output pixel in the layer. Its width is the farthest the shader may read left or right. Its height is the farthest it may read up or down. The value tells SwiftUI how far the shader can reach. The shader code still chooses each read point.

    We declare 24 pt on both axes. In the course’s reconstruction, 24 pt is the chosen farthest read when the menu is opening or closing. The course fitted this setting to the visible bending of the rows in the Safari opening recording. A read that far might point along either axis, so the caller allows the full distance in each. The lab’s 10 pt rightward read is within that allowance. The lab extends the drawing past the right side of the visible menu so there is page color to read near that edge.

    let readRightPt: Float = 10
let readLimit: CGFloat = 24
ZStack(alignment: .topLeading) {
    page.drawingGroup(opaque: true)
        .blur(radius: 18, opaque: true)
    darkTint.opacity(0.55)
    menuRows
}
.compositingGroup()
.layerEffect(
    ShaderLibrary.default.glassPictureShift(.float(readRightPt)),
    maxSampleOffset: CGSize(width: readLimit, height: readLimit)
)
    #include <metal_stdlib>
#include <SwiftUI/SwiftUI.h>
using namespace metal;

[[ stitchable ]] half4 glassPictureShift(
    float2 position, SwiftUI::Layer layer, float readRightPt
) {
    float2 source = position + float2(readRightPt, 0.0);
    return layer.sample(source);
}

    Section 4 · lab checkCheck the shift in Xcode

    Run LiquidGlassLab → Chapter 11. Compare the two menus in GlassPictureView.swift. Both call GlassPictureShift.metal. Each menu has the same fixed guides at x = 174 pt (mint) and x = 184 pt (yellow). The first read is 0 pt, so the amber stripe sits under the yellow guide. The second read is 10 pt right, so the stripe moves to the mint guide. Look at “New Tab” to check that the sharp text moves by the same amount.

    An iPhone 16 Pro draws 3 device pixels per point. In a screenshot from that device, the 10 pt shift covers 10 × 3 = 30 device pixels.

    Section 5 · check your understandingWhich source point supplies R?

    R is the red output pixel at (132, 58) pt. This time the shader reads 10 pt to the left. The axes are the same as in the worked example. Find the source point for R.

    Source x = 132 − 10 = 122 pt
    Source y = 58 + 0 = 58 pt

    Step through it as you did for P. Start at R. Move 10 pt left on x and stay on the same row. Read the color there and return it for R. The color at x = 122 pt appears at x = 132 pt, so this time the picture would slide right.
