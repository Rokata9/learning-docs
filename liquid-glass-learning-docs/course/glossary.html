Canonical definitions

Liquid Glass glossary

Terms are defined here once. Lessons link back when a term returns. The wording will grow as the course introduces more precise models.

Transparent

A transparent area lets the background pass through with no added visible material.

Visible test: the background looks unchanged.

Translucent

A translucent area shows the background and also adds some foreground color.

Visible test: the background remains recognizable, but its colors change.

Blur

Blur makes fine detail less sharp by combining information from nearby positions.

Visible test: a thin edge spreads into a softer band.

Diffusion

Diffusion is visible light spreading inside a material. User interfaces often imitate it with blur and other softening operations.

Visible test: detail becomes softer and less distinct.

Refraction

Refraction is a change in the apparent position or direction of background detail as light passes through a material.

Visible test: a straight line bends, shifts, or changes size.

Tint

A tint is a controlled color influence added to an existing color. Lesson 3.8 uses one explicit model: a chosen straight sRGB tint source is drawn over an opaque destination with source-over.

Visible test: the output red, green, and blue values move toward the chosen tint source values while the destination still contributes when tint alpha is below 1.00.

Tint amount

In the Lesson 3.8 source-over tint model, tint amount is the alpha of the tint source. It controls the source contribution in that draw operation.

Not final output opacity: a translucent tint source over an opaque destination still produces output alpha 1.00.

Highlight

A highlight is a bright region that suggests reflected light. A specular highlight is a concentrated bright reflection.

Visible test: one edge or spot becomes brighter than the rest.

Shadow

A shadow is a darker region outside or below a surface. It suggests separation from the content behind it.

Visible test: the surface appears raised or detached.

Morph

A morph is a continuous change from one shape into another shape.

Visible test: width, height, corners, or outline change without a sudden replacement.

Implementation hypothesis

An implementation hypothesis is a possible explanation for how software produced a visible result. It is not proven by watching the result.

Evidence needed: documentation, source code, tracing, profiling, or direct measurement.

Frame

A frame is one complete image shown by the screen at one moment.

Visible test: pause a recording. The single paused image is one frame.

Transition

A transition is the sequence of visible changes between one stable state and another stable state.

Visible test: identify the starting state, the ending state, and the changing images between them.

Stage

A stage is a human-chosen name for a useful group of nearby frames that share a visible purpose.

Important: the real animation does not need to pause at a stage boundary.

Baseline

A baseline is a result that is already known to work before a new change is added.

Lesson 1.3 test: run the untouched Compose template before replacing its source.

Project

An Android project is the top-level collection of source files, resources, build rules, and modules used to build an application.

Concrete object: the LiquidGlassLab directory.

Module

A module is a buildable unit inside a Gradle project. The course starts with one application module named app.

Concrete output: the app module produces the Android application package.

Gradle

Gradle is the build system that reads the project build rules, resolves libraries, and runs repeatable tasks such as compiling and packaging.

Not the same as Android Studio: Android Studio is the development environment. Gradle performs the configured build work.

APK

APK means Android Package. A debug APK is an installable application file used for local development runs.

Pipeline position: Gradle creates it before ADB sends it to the device.

ADB

ADB means Android Debug Bridge. It is the tool that communicates between the development computer and an authorized Android device.

Visible test: adb devices lists the Pixel with the state device.

Activity

An Activity is an Android component that owns an app window and receives lifecycle events such as creation and destruction.

Course entry: Android creates MainActivity; Compose is then installed into its content.

Composable

A composable is a Kotlin function marked with @Composable that describes part of a Compose user interface.

Course example: Chapter01Screen() describes the baseline screen.

API level

An API level is Android's integer platform version used by source APIs and compatibility checks.

Course floor: minSdk = 33.

SDK

SDK means software development kit. The Android SDK is the installed set of platform declarations, build tools, and device tools used to compile, package, and test Android applications.

Concrete object: Android Studio's SDK Manager installs Android platform 37 for this lesson.

compileSdk

compileSdk is the newest Android API level whose names the compiler lets the source code reference.

It does not change the phone: compiling against API 37 does not add API 37 functions to an API 33 device.

minSdk

minSdk is the oldest Android API level on which the package is allowed to install.

Lesson 1.3 operation: Android compares the device API with 33 before installation.

targetSdk

targetSdk is the Android behavior level for which the application declares that it has been tested.

Different job: it does not choose the oldest supported phone and it does not choose which API names compile.

Kotlin DSL

Kotlin DSL means a domain-specific language written with Kotlin syntax. Gradle Kotlin DSL build files end in .gradle.kts.

Concrete file: app/build.gradle.kts.

Android manifest

The Android manifest is the application declaration that names components and app metadata. The generated manifest declares MainActivity as the launcher activity.

Pipeline position: build tools merge the manifest before packaging the APK.

Lifecycle

A lifecycle is the sequence of states and callbacks through which Android creates, shows, pauses, and destroys a component.

Lesson 1.3 callback: Android calls MainActivity.onCreate when it creates the activity instance.

Version catalog

A Gradle version catalog is a file that gives stable aliases to plugin and library coordinates and versions.

Concrete file: current Android Studio templates commonly use gradle/libs.versions.toml.

Render

To render means to produce the pixels for a screen image.

Evidence boundary: the browser can model the idea, but the Pixel run proves the Android result.

Opaque

An opaque color or surface does not let the background show through it.

Lesson 1.4 example: every gradient and color-region color is fully opaque. Transparency begins in Lesson 1.5.

Study background

A study background is a deliberately designed image placed behind an effect so the effect is easier to inspect.

Concrete purpose: known shapes and edges provide visual evidence when blur, tint, or distortion is added later.

Visual clue

A visual clue is one recognizable part of an image whose change can be noticed and described.

Lesson 1.4 examples: a sharp line, a known circle, and readable text.

Edge

An edge is a boundary. In image analysis, it is where visible values change. In rectangle geometry, it is one of the four boundary lines named left, top, right, and bottom.

Context matters: Lesson 1 uses visible color edges to reveal blur. Lesson 2.4 uses geometric edges to describe rectangle bounds.

Gradient

A gradient is a gradual change between two or more colors across an area.

Lesson 1.4 distinction: its colors are opaque. A gradient is not automatically transparent.

Silhouette

A silhouette is the visible outer shape of an object without relying on its internal detail.

Lesson 1.4 test: a known circular silhouette makes uneven distortion visible when it becomes oval.

Brush in Compose

A Compose Brush describes how colors fill a drawing area. It can provide one solid color or a color pattern such as a gradient.

Concrete code: Brush.linearGradient(colors = StudyGradientColors).

Modifier in Compose

A Compose Modifier is an ordered description of layout, drawing, input, and other behavior applied to one composable.

Concrete chain: fillMaxSize(), then safeDrawingPadding(), then ordinary padding.

Inset

An inset is a distance measured inward from one edge of the app window because that edge area may be occupied or obscured.

Android examples: the status bar, navigation bar, and camera cutout contribute inset distances.

Safe drawing area

The safe drawing area is the part of the app window where important content is not covered by system bars or a display cutout.

Concrete code: safeDrawingPadding() adds the required edge distances to the clue-content column.

Panel

A panel is one foreground user-interface area placed over other content.

Lesson 1.5 object: an empty Box with a rounded white fill.

Bounds

Bounds are the rectangular area available to or occupied by one drawn or laid-out object. Rectangular bounds can be described by left, top, right, bottom, width, and height.

Course examples: Lesson 1.5 gives the panel a size of 328.dp × 190.dp. Lesson 2.4 names all four edge coordinates and calculates the center.

Fill

A fill is the color drawn inside a shape's boundary.

Lesson 1.5 operation: Modifier.background draws the white color inside the rounded shape.

Opacity

Opacity is how strongly a source is allowed to contribute when it is drawn over existing content.

Lesson 3.2 model: opacity 0.25 means 25% source opacity. The remaining background opening is 1 − 0.25 = 0.75.

Alpha channel

The alpha channel is the numeric channel used in Lesson 3.2 to store source opacity. It follows red, green, and blue in an RGBA tuple.

Concrete tuple: RGBA(0.80, 0.25, 0.60, 0.50) has alpha 0.50.

Transparency

Transparency describes how much background remains open through a source.

Lesson 3.2 relation: transparent share = 1 − alpha. Alpha 0.25 leaves a transparent share of 0.75.

Checkerboard transparency background

A checkerboard transparency background is a fixed alternating light-and-dark pattern used to make transparent areas easy to see. The checkerboard is not part of the source color.

Lesson 3.2: when source alpha reaches 0.00, the checkerboard should look unchanged.

Layer

A layer is one set of drawing output considered separately before it is combined with other drawing output.

Lesson 1.5 layers: the study background is one layer; the translucent panel fill is another layer drawn over it.

Foreground

The foreground is content drawn over other visible content.

Lesson 1.5 foreground: TranslucentRoundedPanel().

Foreground candidate

A foreground candidate is one possible icon or text color tested before the program chooses it.

Lesson 3.7: opaque black and opaque white are the two candidates measured against one final opaque background.

Contrast

Contrast is the numeric separation between a foreground color's relative luminance and the adjacent background color's relative luminance.

Lesson 3.7 limit: the lesson measures two uniform final opaque colors. It does not yet sample a photograph or changing backdrop.

Contrast ratio

A contrast ratio is one unitless comparison number calculated from the lighter and darker relative-luminance values.

Formula: (lighter + 0.05) ÷ (darker + 0.05). The result ranges from 1:1 for equal luminance to 21:1 for reference white against reference black.

Lighter and darker luminance

The lighter luminance is the larger of the foreground and background relative-luminance values. The darker luminance is the smaller one.

Important: the foreground is not automatically the lighter input. The roles are assigned by comparing the two numbers.

Contrast target

A contrast target is a minimum ratio required by a selected policy for a particular kind of content.

Lesson 3.7 distinction: choosing the larger of the black and white ratios is a candidate-selection step. Checking 3:1 or 4.5:1 is a separate target step.

Color channel

A color channel is one named numeric component inside a color. Red, green, blue, and alpha are common channels.

Concrete example: in RGB(0.80, 0.25, 0.60), the red channel is 0.80. One number alone is not a complete color.

Normalized value

A normalized value has been mapped into a standard numeric range. This course commonly uses 0.0..1.0.

Equivalent notation: normalized channel 0.40 is approximately integer channel 102 on a 0..255 scale because 0.40 × 255 = 102.

Weight

A weight is a multiplier that controls how much an input contributes to a result.

Course examples: alpha controls source and destination contribution in Lesson 3.3. The relative-luminance weights in Lesson 3.6 are 0.2126 for red, 0.7152 for green, and 0.0722 for blue after sRGB decoding.

Contribution

A contribution is the amount produced after an input value is multiplied by its weight.

Course example: the background contribution is 0.20 × 0.75 = 0.15.

Source

The source is the RGBA value, image, or shape being drawn by the current drawing operation.

Lesson 3.3: source RGBA(0.90, 0.10, 0.80, 0.50) is drawn second, above the destination.

Destination

The destination is the RGBA value already present at one position in the drawing target before the current source is drawn.

Lesson 3.3: destination RGBA(0.10, 0.90, 0.40, 0.60) is drawn first.

Sample

A sample is one color or RGBA value associated with one chosen image position.

Source-over compositing

Source-over compositing places the current source over the existing destination. Transparent source regions allow some destination contribution to survive.

Full output alpha: Aout = As + Ad × (1 − As). Each RGB channel uses the same source and surviving-destination factors.

Drawing target

The drawing target is the image or buffer whose stored values are changed by a drawing operation.

At one position: the old value is the destination. The operation writes the new source-over output value back into that position.

Output alpha

Output alpha is the alpha value after source and destination have been combined.

Lesson 3.3: 0.50 + 0.60 × (1 − 0.50) = 0.80.

Draw order

Draw order is the sequence in which drawing operations write into the same drawing target.

Lesson 3.4: the first colored call creates the lower colored contribution. The second colored call becomes the current source at overlap positions.

Overlap

An overlap is an image position covered by more than one shape or layer.

Per-position rule: reversing two operations can change a position only when both operations affect that position.

Commutative operation

A commutative operation gives the same result when its two inputs exchange places.

Counterexample: source-over compositing is not commutative because magenta over green and green over magenta produce different RGB values.

Straight RGBA

Straight RGBA, also called unassociated RGBA, stores red, green, and blue independently from alpha. The RGB fields describe the color components before alpha weighting.

Example: Straight RGBA(0.90, 0.10, 0.80, 0.50). Converting it to premultiplied RGBA multiplies each RGB field by 0.50.

Premultiplied RGBA

Premultiplied RGBA, also called associated RGBA, stores alpha-weighted RGB contributions. Each stored RGB field equals the matching straight RGB field multiplied by that tuple's alpha. Alpha itself is stored unchanged.

Example: Straight RGBA(0.90, 0.10, 0.80, 0.50) becomes Premultiplied RGBA(0.45, 0.05, 0.40, 0.50).

Color representation

A color representation is the data contract that states what each stored number means. Straight and premultiplied RGBA can describe the same translucent color while storing different RGB numbers.

Practical rule: read the API or buffer contract. Do not infer the representation from the word RGB.

Straight RGB

Straight RGB contains red, green, and blue components stored independently from alpha. A straight RGB tuple does not yet contain multiplication by alpha.

Lesson 3.5 source: (0.90, 0.10, 0.80) is the straight RGB portion of Straight RGBA(0.90, 0.10, 0.80, 0.50).

Premultiplied RGB

Premultiplied RGB contains alpha-weighted red, green, and blue contributions. It must be interpreted together with the alpha used to create it.

Lesson 3.5 source: (0.45, 0.05, 0.40) is the source premultiplied RGB at alpha 0.50.

Alpha-weighted RGB contribution

An alpha-weighted RGB contribution is a straight red, green, or blue value multiplied by the alpha share that allows that layer to contribute at the image position.

Source red: 0.90 × 0.50 = 0.45. Destination red after source coverage: 0.10 × 0.60 × (1 − 0.50) = 0.03.

Output premultiplied RGB

Output premultiplied RGB is the sum of the source and surviving destination color contributions produced by source-over compositing.

Lesson 3.3: (0.45, 0.05, 0.40) + (0.03, 0.27, 0.12) = (0.48, 0.32, 0.52). This precise name replaces the older label weighted total.

Output straight RGB

Output straight RGB stores the output color components independently from output alpha. When output alpha is greater than zero, divide output premultiplied RGB by output alpha to obtain it.

Lesson 3.3: (0.48, 0.32, 0.52) ÷ 0.80 = (0.60, 0.40, 0.65). This precise name replaces the older label ordinary output.

dp

dp means density-independent pixel. It is an abstract Android layout unit. The runtime density determines how many px Android uses for one dp.

Lesson 2.5 boundary: 96.dp is a layout request. It is not automatically 96 px.

px

px means pixel coordinate unit. In this course, it is one coordinate unit in an app raster drawing surface. Compose Canvas sizes, coordinates, and stroke widths use px.

Concrete object: size.width inside a Canvas draw block is a px value, not a dp value.

Density

Density is the runtime conversion scale between Android dp layout values and px drawing values. Its unit is px per dp.

Formula: px = dp × density. The reverse conversion is dp = px ÷ density.

Rounded corner shape

A rounded corner shape is a rectangle whose sharp corners are replaced by curved corners.

Lesson 1.5 code: RoundedCornerShape(32.dp). Chapter 4 explains the geometry.

Controlled experiment

A controlled experiment changes one selected input while the other relevant inputs remain unchanged.

Lesson 1.7: panel alpha changes; background, panel bounds, corner radius, source color, orientation, and window stay fixed.

Variable

A variable is a named storage location whose value can change while the program runs.

Lesson 1.7: panelAlpha stores the currently selected opacity amount.

Preset

A preset is a prepared exact value that can be selected without manually positioning a continuous control.

Lesson 1.7: the five presets are 0%, 25%, 50%, 75%, and 100%.

Observation

An observation is a statement about something directly visible or measured.

Evidence limit: “the line remains straight” is an observation. “Apple uses shader X” is not.

Claim

A claim is a statement presented as true and therefore requiring suitable evidence.

Lesson 1.8: “blur is absent” is supported by the unchanged sharp boundary.

Evidence

Evidence is a visible result, measurement, document, source line, trace, or profile that supports or rejects a claim.

Concrete evidence: matching line positions across screenshots reject a claim of visible displacement.

Diagnosis

A diagnosis is a conclusion reached from specific evidence about what an effect does or does not contain.

Good form: name the clue, name the observed change or non-change, then state the supported conclusion.

Absent operation

An operation is absent when the current implementation does not perform it.

Lesson 1.8: refraction is absent because the code performs no shifted background sampling and the visible clues do not move.

Raster image

A raster image stores image information at positions arranged in a rectangular grid of rows and columns.

Lesson 2.1 model: an 8×8 raster has 64 addressable positions.

Pixel

A pixel is one addressable position in a raster image. The value stored or read at that position is a sample.

Teaching preview: one enlarged square represents one raster position but covers many physical display pixels.

Pixel function

A pixel function is a small function that returns one color for one output pixel. Lesson 8.1’s name is colorAt(column, row). The same function body runs once for every pixel. Only that pixel’s column and row change between calls.

Call: one run of the function for one (column, row) pair. An 8×4 grid needs 32 calls.

Shader

A shader, in this course, is a pixel function that the GPU will run. The GPU is the phone’s graphics processor.

Lesson 8.1 stand-in: a CPU loop makes each call visible. That loop is not itself a GPU program. Lesson 8.2 connects an AGSL string to Android drawing. Lesson 8.3 proves that path with one fixed half4 return.

GPU

The GPU is the phone’s graphics processor. It can run a pixel function, possibly for many pixels at the same time.

CPU contrast: the CPU is the phone’s main processor. Lesson 8.1’s teaching loop runs there so you can watch one call after another.

AGSL

AGSL means Android Graphics Shading Language. It is the language this course’s GPU pixel-function text is written in.

AGSL string: that text stored in Kotlin as a String. It is not yet a running program. Lesson 8.2 compiles it with RuntimeShader.

RuntimeShader

A RuntimeShader is the compiled GPU program object built from an AGSL string. The constructor compiles the string. Construction does not draw a rectangle.

Next consumer: wrap it in ShaderBrush, then drawRect(brush). Added in Android 13 / API 33. This project’s minimum SDK is 33.

ShaderBrush

A ShaderBrush is a Compose brush that paints using a Shader such as RuntimeShader. It is a paint recipe, not stored pixels.

Draw: drawRect(brush = brush) fills a rectangle. The GPU then calls main once per output pixel of that rectangle.

half4

In Lesson 8.3, a half4 is four numbers packed together, in order: red, green, blue, alpha. Each color channel uses 0 for none of that channel and 1 for the full amount.

Return is the store: return half4(0.88, 0.48, 0.18, 1.0) stores teaching orange at every pixel of the draw rectangle when position is unread. Lesson 8.7: .r is the same slot as .x, .g as .y, .b as .z, and .a as .w. half is 16-bit storage.

fragCoord

fragCoord is the GPU’s name for the current output pixel’s position in the draw rectangle. It is a float2: x pixels from the left, y pixels from the top. Origin is the top-left of that rectangle. y increases downward, matching Android Canvas, not GLSL’s lower-left origin.

Lesson 8.4: if (fragCoord.x < 80.0) stores orange or navy. 80 is a pixel count, not half the rectangle. y is unread. This is not Lesson 8.1’s column index.

float2

A float2 is two numbers packed together, in order. For fragCoord the order is x then y. For resolution the order is width then height. For UV the order is the horizontal fraction then the vertical fraction. The word float names 32-bit storage. Lesson 8.7 names that size against half.

Read one member: fragCoord.x is the first number. resolution.x is the width. uv.x is u.

Resolution

In Lesson 8.5, resolution is the draw rectangle’s width and height, in pixels. Kotlin reads it as size.width and size.height in the Canvas lambda and writes it into the shader.

Not fragCoord: fragCoord is this pixel’s position. Resolution is the whole rectangle’s size. Half-width is resolution.x / 2.0, still a pixel count. Lesson 8.6 divides position by resolution to make UV.

Uniform

A uniform is a named slot in the compiled program. Kotlin writes a value into that slot. The GPU reads the same value for every pixel of this draw. The AGSL string is not rewritten.

Lesson 8.5: uniform float2 resolution, written with setFloatUniform("resolution", size.width, size.height) once per draw.

Lesson 8.9: extra slots besides size: uniform float splitU and uniform half4 leftColor. A mismatched Kotlin name is not a compile error; the unread AGSL slot stays at its default, often 0. This course writes color as four floats, not setColorUniform.

Lesson 8.10: uniform float time holds a trip count. Kotlin writes it every frame from the frame clock. See time uniform.

Time uniform

In Lesson 8.10, the time uniform is the named slot uniform float time. The number in that slot is a trip count: how many times the black edge (stored red = 0) has crossed the rectangle from left to right. Kotlin converts elapsed seconds with trips = elapsedSeconds / 4.0. 4.0 is SecondsPerTrip, a teaching duration so 0.25 and 0.50 stay readable.

Store: fract(uv.x - time) is returned as red. Every pixel of this draw reads the same time. RuntimeShader is not rebuilt. Pause writes a frozen number, so the picture sits.

floor

floor(x) is the whole number that is not larger than x. On the number line, that is x itself when x is already a whole number. Otherwise it is the first whole number to the left of x.

Lesson 8.10: floor(0.25) = 0. floor(-0.25) = -1 because 0 is larger than −0.25. AGSL lists floor as the nearest integer ≤ x.

fract

fract(x) is the leftover after removing complete 1.0-sized steps with floor. This lesson uses the GLSL ES 1.0 identity that AGSL inherits: fract(x) = x − floor(x). The leftover is always 0.0 (included) through 1.0 (not included).

Lesson 8.10: fract(-0.25) = 0.75. That wrap is why pixel x=0 at time 0.25 stores red 0.75 instead of a negative channel. mix is Lesson 8.11.

clamp

In Lesson 8.11, clamp(x, lo, hi) is the AGSL function that keeps one number inside a closed interval: it returns lo when x is below lo, hi when x is above hi, and x when it is already between them. Both ends are included. Arithmetic: min(max(x, lo), hi).

Not the earlier clamps: Lesson 3.9’s ColorMatrix clamp was a later range restriction on a matrix result. Lesson 7.3’s BlurEdgeTreatment.Clamp was an edge-read mode. AGSL also has saturate(x), which is clamp(x, 0.0, 1.0).

mix

In Lesson 8.11, mix(a, b, t) is AGSL’s name for Lesson 5.4’s linear interpolation: a + (b − a) × t. t is a blend fraction from 0 through 1: 0 stores a, 1 stores b. It is not Lesson 7.10’s noise amount slider. On two half4 colors, each channel uses the same t.

Teaching pixel: mix of navy red 0.10 and orange red 0.88 at t = 0.25 stores red 0.295. Blue at the same t decreases from 0.40 toward 0.18.

smoothstep

In Lesson 8.11, smoothstep(edge0, edge1, x) builds a 0..1 blend fraction in the interval from edge0 to edge1, then bends it. First: linearFraction = clamp((x − edge0) / (edge1 − edge0), 0.0, 1.0). Then: curvedFraction = linearFraction × linearFraction × (3 − 2 × linearFraction). The output is still 0 through 1. It stays nearer 0 in the first half of the band and nearer 1 in the second half. The midpoint is unchanged.

Production store: mix(navy, orange, smoothstep(edge0, edge1, uv.x)). At uv.x = 0.45 with edges 0.40 and 0.60, linearFraction is 0.25, curvedFraction is 0.15625, stored red is 0.221875. Lesson 9.3 feeds a distance into the same function. This lesson requires edge1 > edge0.

Shader compile error

A shader compile error is a failure of RuntimeShader(string). Android throws IllegalArgumentException. The message usually starts with error:, then a 1-based line number in that string, then the complaint. Uniform writes do not run. Lesson 8.9’s mismatched Kotlin name is not this failure.

Lesson 8.12: the Android explorer prints the live e.message. HTML pages do not compile AGSL.

Smallest failing program

A smallest failing program is the shortest AGSL string that still throws the same compile error. Fix that string. Then restore the other lines. The teaching example is Lesson 8.11’s program with gl_FragCoord in place of fragCoord.

Reduction test: if replacing the body with Lesson 8.3’s return half4(0.88, 0.48, 0.18, 1.0); compiles, the uniforms and main signature were not the failure.

UV

UV in Lesson 8.6 is the pair (fragCoord.x / resolution.x, fragCoord.y / resolution.y). U is the horizontal fraction of the width. V is the vertical fraction of the height. Lesson 2.8 called this a normalized coordinate. The shader name is UV.

Matching members: x is divided by width and y by height. fragCoord / resolution does those two divisions. Dividing both members by width is wrong. The last pixel is not exactly 1. UV is not a texture sample.

Vector

In Lesson 8.7, a vector is a packed group of numbers. The digit in the type name is the count: float2 is two floats, half4 is four half numbers. It is not a physics velocity and not an arrow on a graph.

Member: one named number inside the pack. uv.x is first. uv.y is second.

Member

A member is one named number inside a vector. Lesson 8.7 reads uv.x or uv.y. On a half4, .r is .x, .g is .y, .b is .z, and .a is .w.

Visible test: splitting on uv.y paints a horizontal cut with orange on the top half, because y increases downward.

float

In Lesson 8.7, float is a 32-bit number format. AGSL’s usual contract stores positions, resolution, and UV as float or float2.

Not a speed claim: storage size is a format. Frame time would need a release-like device measurement.

half

In Lesson 8.7, half is a 16-bit number format. AGSL’s usual contract returns color as half4 because 8-bit channels only need a few digits after the point, such as 0.88.

Not a speed claim: a 400-wide rectangle’s pixel counts would also fit in half. The course still follows the AGSL color-as-half4 contract.

Right triangle

A right triangle is a triangle with one square corner, meaning one corner whose two sides meet like the corner of a rectangle. The two sides that meet at that corner are the legs. The remaining side is the long side.

Lesson 9.1 teaching triangle: legs 0.30 and 0.40, long side 0.50. The countable version is 3, 4, and 5. Some texts call the long side the hypotenuse. This course says long side.

Straight-line distance

The straight-line distance between two points is the length of the long side of the right triangle whose legs are the horizontal difference and the vertical difference. For Lesson 9.1’s teaching pixel, that number is 0.50, not the walk-around 0.70.

AGSL: length(p) when p is already the subtract from the visual center. distance(a, b) is the two-point spelling of the same arithmetic.

length

In Lesson 9.1, AGSL length(p) is sqrt(p.x × p.x + p.y × p.y). It is the long side of the right triangle built from the two members of p. The result is never negative.

Teaching pixel: p = (0.30, −0.40), 0.09 + 0.16 = 0.25, length = 0.50 because 0.50 × 0.50 = 0.25. Production stores that gray as half4(d, d, d, 1.0).

Walk-around

Walk-around is abs(p.x) + abs(p.y). It is the length you travel from the visual center if you may move only horizontally and then only vertically. For Lesson 9.1’s teaching pixel that number is 0.70, not the straight-line 0.50.

Equal-value shape: pixels that share one walk-around number sit on a diamond. That diamond is a square standing on a vertex: its vertices point up, right, down, and left. A smaller walk-around number is a smaller, darker diamond. Lesson 9.1 stores this only as an HTML comparison. Production uses length(p).

Equal-value outline

An equal-value outline is the set of pixels that store the same number as gray. In Lesson 9.1 Straight-line gray, that outline is a circle of radius length(p). In Walk-around gray, that outline is a diamond of walk-around abs(p.x) + abs(p.y).

Nested outlines: a smaller stored number is a smaller outline and a darker gray. A larger stored number is a larger outline and a lighter gray. The green lab outline is one of those sets: the selected pixel’s number. It is not a cutoff after which the picture becomes white.

Square root

The square of a number is that number multiplied by itself. A square root of a number is a value whose square equals that number. This course uses the square root that is zero or greater because a length is not negative: sqrt(0.25) = 0.50, not −0.50.

Check: 0.50 × 0.50 = 0.25. AGSL’s name is sqrt. length already includes it.

Signed distance

A signed distance is a length that also carries a plus or a minus. In Lesson 9.2, sd = length(p) − radius, and length(p) is the straight-line length from the visual center C. This course’s convention: minus means inside, zero means on the boundary, plus means outside.

Lesson 9.4: the same convention, now to a rounded rectangle. In a corner, the analog of length(p) is length(q): the straight-line length from the pixel to the construction-circle center, not to C. Then sd = length(q) − cornerRadius. Teaching corner pixel p = (0.26, −0.18) has sd = 0.

Signed distance field

A signed distance field is a signed distance computed at every pixel of the draw rectangle. Lesson 9.2’s production then stores orange when sd < 0 and navy otherwise. The size of sd is kept for Lesson 9.3.

The pixels where sd = 0 are the shape boundary. Subtracting radius from length(p) makes that boundary a circle around the visual center. Subtracting radius from abs(p.x) + abs(p.y) makes a diamond. Lesson 9.4 subtracts the corner radius from inner-box distance so the boundary is a rounded rectangle.

Soft mask

A soft mask is a 0 through 1 inside-amount that may also sit between 0 and 1. 1 means store the inside color fully. 0 means store the outside color fully. 0.15625 is a legal soft-mask value. Lesson 4.8’s binary mask permitted only 0 and 1.

Lesson 9.3 production: mask = 1.0 − smoothstep(−band, band, sd), then mix(navy, orange, mask). Teaching band pixel sd = +0.05 at band = 0.10 has linearFraction 0.75, curvedFraction 0.84375, mask 0.15625, stored red 0.221875. The 1 minus is required because smoothstep grows as sd grows (toward outside).

Distance band

In Lesson 9.3, the distance band is the closed interval of signed distance from −band to +band. Inside that interval the mask blends. Outside it the mask is clamped to 1 (deep inside) or 0 (far outside). band is the band half-width: the distance from the boundary sd = 0 to one edge of the blend, in the same p units as the circle radius.

Teaching default: band = 0.10. On the 400×400 square, 0.10 in p is 40 pixels because the full p.x span is about 1.0 across 400 pixels. That width is chosen so the blend is visible. It is not a measured one-pixel antialiasing width and not Lesson 4.9 coverage.

abs

AGSL abs(x) is the non-negative version of a number: x when x is already zero or greater, and −x when x is negative. On a float2, abs(p) does that to each member separately.

Lesson 9.4: after abs(p), both members are zero or greater. A pixel in the left half is treated like its mirror in the right half. A pixel in the top half is treated like its mirror in the bottom half. The rounded rectangle looks the same in all four quarters, so one quarter’s arithmetic covers all four. This is not Lesson 9.1’s walk-around sum.

Construction-circle center

In Lesson 4.2, a construction-circle center is the center of the dashed circle used to explain one rounded corner. It sits one corner radius in from both meeting outer edges. Only one quarter of that circle is the final corner arc.

Lesson 9.4: the four construction-circle centers are the four corners of the inner box. The visual center C is a different point: the origin of p. In a corner, signed distance uses the length from the pixel to this construction-circle center, not the length from C. Teaching top-right center: (0.20, −0.10).

Inner box

In Lesson 9.4, the inner box is the sharp rectangle whose half-size is outerHalf − cornerRadius. Its four corners are Lesson 4.2’s construction-circle centers. Growing every inner-box boundary point outward by the corner radius produces the rounded rectangle: flat sides stay flat, and each corner swings through a quarter-circle.

Teaching defaults: outer half-size (0.30, 0.20) means full size 0.60 × 0.40, not 0.60 × 0.30. Corner radius 0.10, inner half-size (0.20, 0.10). Then q = abs(p) − innerHalf is how far the mirrored pixel sits past each inner edge. In a corner, length(q) is the analog of Lesson 9.2’s length(p). sd = sdBox − cornerRadius.

Edge leftover

In Lesson 9.4, an edge leftover is one member of q = abs(p) − innerHalf. A positive leftover means the mirrored pixel is already past that inner-box edge. A negative leftover means it is still inside that edge. Zero means it sits on that inner edge.

Four regions after abs: both leftovers positive → nearest inner point is the inner corner, sdBox = length(q). Only the horizontal leftover positive → sdBox is that leftover. Only the vertical leftover positive → sdBox is that leftover. Both negative or zero → inside the inner box, sdBox is the larger (nearer zero) leftover.

Inner segment

In Lesson 9.5, the inner segment is the horizontal line from (−innerHalfW, 0) to (+innerHalfW, 0), where innerHalfW = outerHalf.x − radius and radius equals the half-height. It is Lesson 9.4’s inner box after the inner height has reached 0. Growing every segment point outward by the radius produces a capsule: the middle stays a flat band, and each end is a semicircle.

Teaching defaults: outer half-size (0.40, 0.20), radius 0.20, inner segment x from −0.20 to +0.20.

Nearest on segment

The nearest point on Lesson 9.5’s inner segment is (nearestX, 0), where nearestX = clamp(p.x, −innerHalfW, innerHalfW). If p.x already sits between the ends, the nearest point is directly above or below on the segment. If p.x sits past an end, the nearest point is that end. Then sd = length(p − (nearestX, 0)) − radius.

Teaching cap-boundary: p = (0.32, −0.16), nearestX = 0.20, length 0.20, sd = 0. Center sd = −0.20.

min

AGSL min(a, b) returns the smaller of two numbers. For signed distance, smaller means more inside: more negative, or closer to zero from the plus side.

Lesson 9.6 union: sd = min(sdA, sdB). Teaching left-only pixel p = (−0.10, 0) has sdA = −0.15 and sdB = +0.05, so min is −0.15 and the combined blob stores orange.

max

AGSL max(a, b) returns the larger of two numbers. For signed distance, larger means more outside.

Lesson 9.6 intersection: sd = max(sdA, sdB). At the same teaching pixel max is +0.05, so the overlap stores navy. B minus A: sd = max(sdB, −sdA). Negating sdA flips inside and outside of A, then max keeps pixels that are inside B and outside A.

Union of two distance fields

The union is the combined blob: a pixel is inside if it is inside at least one of the two shapes. Lesson 9.6 computes it as min of the two signed distances, then the usual hard if (sd < 0).

Not mix: mix blends two colors. min picks one signed-distance number.

Intersection of two distance fields

The intersection is only the overlap: a pixel is inside if it is inside both shapes. Lesson 9.6 computes it as max of the two signed distances.

Teaching overlap: p = (0.10, 0) has both signed distances −0.15, so intersection stores orange.

Subtraction of two distance fields

B minus A is B after cutting A out of it: a pixel is inside if it is inside B and outside A. Lesson 9.6 computes it as max(sdB, −sdA).

Teaching left-only T was never in B, so B minus A stores navy there. The overlap pixel is removed. The right-only pixel stays orange.

Shader uniform

A shader uniform is an AGSL slot of type shader. It holds a runnable color source, not a float. Lesson 9.7 declares uniform shader background. Kotlin writes that slot with setInputShader("background", otherShader). The name must match.

Later path: RenderEffect.createRuntimeShaderEffect can bind a layer’s pixels to the same slot type. Lesson 9.7’s explorer uses setInputShader.

eval

eval is AGSL’s name for asking an input shader for a color. background.eval(readCoordinate) returns the input’s half4 at that pair. The pair is in pixels, the same units as fragCoord. Passing UV treats 0.15 as 0.15 pixels from the left and reads the wrong stripe. eval does not wrap, clamp, or remap the pair into the draw rectangle. A negative read x stays that negative number.

Sampled color: the returned half4 is a copy. The input picture is not rewritten. Lesson 9.7 uses eval(fragCoord) so the read coordinate equals the write location. Lesson 9.8 subtracts before the ask. A color at a negative pair comes from the input program, here fract(uv.x × 5), not from wrapping the pixel to the right edge.

Sampled color

The sampled color is the half4 that eval returns: a copy of the input shader’s color at the read coordinate. Lesson 9.7’s production stores that copy on the left half of the rectangle and teaching orange on the right half, so the ask is visible.

Teaching T: uv.x = 0.15, stripe cell 0.75, sampled navy. x = 60 is less than half of 400, so the store is that navy.

Read coordinate

The read coordinate is the pair passed to eval. It is measured in pixels from the top-left of the draw rectangle, the same system as fragCoord. The write location is this pixel, which stores the returned color.

Lesson 9.8: readCoord = fragCoord − (offsetU × resolution.x, 0). Default offsetU = 0.10 is one stripe width as a fraction of the rectangle width. Teaching write uv.x = 0.15 reads 0.05 and stores orange. The picture appears to shift opposite the read offset. A write x below the offset in pixels yields a negative read x. That pair is not wrapped to the right edge. Lesson 9.9: the read UV is p / scale + 0.5, then converted to pixels. Lesson 9.10: the read UV is uv − disp, a chosen walk toward the visual center. The write pixel stays. Inner colors sit farther out.

Scale around the center

Scale around the center means: the write pixel stays put. Subtract 0.5 names that same pixel from the visual center C. Divide that walk by scale so the ask is closer to C when scale is greater than 1. Add 0.5 to read the UV name of that neighbor, because eval wants a top-left pair. readUv = p / scale + 0.5. The original pixel does not relocate. Lesson 8.8’s × 2 is unused.

Lesson 9.9: scale = 2 means twice as large, so the walk is half as long. Right-edge proof: +0.50 / 2 = +0.25, UV 0.75. Teaching write uv = (0.80, 0.70) has p = (0.30, 0.20), reads (0.65, 0.60), and stores orange. C still copies C. Generated and not complete. Lesson 9.9 is the unresolved checkpoint.

Magnification

Magnification is the stored picture when scale is greater than 1: each write pixel stays put and reads a neighbor closer to the visual center, so the middle of the input looks larger. scale = 2 means twice as large, which is why the walk from C is half as long.

Lesson 9.9: scale = 2 asks only the input region 0.25..0.75 and stretches it to the full square.

Minification

Minification is the stored picture when scale is less than 1: each write pixel reads a neighbor farther from the visual center, so more of the input looks smaller. Edge writes can ask for UV outside 0..1. That edge case is Lesson 9.12.

Lesson 9.9: scale = 0.50 at teaching write (0.80, 0.70) reads (1.10, 0.90). The HTML stand-in stores gray outside the input rectangle.

Unit pair

A unit pair is a two-number pair that points the same way as another pair, with straight-line length 1. Lesson 9.10 needs it so a chosen walk length does not grow with distance from the visual center. dir = p / length(p). At Lesson 9.1’s teaching pixel the leftover walk is length 0.50, so the divide doubles that 3-4-5 into (0.60, −0.80). Check: 0.60² + 0.80² = 1. You cannot divide when length(p) is 0, which is the visual center.

AGSL name: normalize(p) is the same divide. Lesson 9.10 writes p / d so the doubling stays visible. Using p itself as the arrow is Lesson 9.9’s growing offset.

Displacement

A displacement is a float2 named disp at one pixel: a chosen UV walk for the read. A displacement field is that pair at every pixel. Lesson 9.10’s teaching field walks the same length dispLen along each ray from the visual center. An input point is painted farther out on its ray. A vertical side tilts because its two ends sit on two rays: the end on the horizontal through C spends the whole walk going right, the end on a diagonal splits the walk, and they no longer share an x. Four corners become a trapezoid leaning toward C. That is not a rotated square, not 3D geometry, and not Lesson 9.9’s zoom. dispLen is not Lesson 7.10’s grain slider.

Lesson 9.10: default dispLen = 0.10. Teaching side: H = (0.75, 0.50) walks to (0.85, 0.50); Q = (0.75, 0.25) walks on the 45° ray to about (0.82, 0.18). They no longer share an x. The shader’s inward ask is the inverse of that outward paint. Generated ahead of checkpoint 9.9 and not complete.

Origin of a pair

The origin of a pair is the pixel where both numbers of that pair are 0. For Lesson 8.6 UV that pixel is the top-left. Lesson 8.8 computes an extra pair p = uv - float2(0.5, 0.5) so tests can ask “which way from the middle?” 0.5 is the UV of the visual center, not a random number. That pixel’s UV stays (0.5, 0.5). Its p is (0, 0). Do not add 0.5 back. The draw rectangle stays put.

Subtract is required. × 2 is a convention. After subtract the left edge is about −0.5. Multiplying by 2 puts that edge at about −1, so 1 means one half-width (center to left or right edge). The span of p.x goes from about 1 to about 2. A fixed numeric test then covers less of the rectangle. That shrink is the 1D preview of Lesson 9.9. Chapter 9’s circle, center-scale, and sample offsets consume this pair. Negative y is the top half because y still increases downward.

Vertical

Coordinate system

A coordinate system is a set of rules that assigns numbers to positions. Its rules include the origin, axis directions, and units.

Android-style screen rule: the origin is at the top-left, X increases right, and Y increases down.

Y axis

Local coordinate system

A local coordinate system is the position-measuring system owned by one specific element. In Lesson 2.6, the element's top-left corner is local (0, 0).

Concrete result: moving the entire child inside its parent moves the child on the screen, but a point stored as child-local (48, 36) remains 48 px right and 36 px down from the child's own origin.

Parent-local coordinate

A parent-local coordinate is a position measured from the parent element's origin.

Conversion: point in parent = child origin in parent + point in child.

Child-local coordinate

A child-local coordinate is a position measured from the child element's origin.

Conversion: point in child = point in parent − child origin in parent.

Containing element

The containing element is the UI element to which a pointer-input operation is attached. A gesture callback can report the pointer position relative to this element.

Lesson 2.6: pointerInput is attached to the child Box, so localOffset is measured from that child's origin.

Application window

The application window is the rectangular area that Android gives to the app for presenting its interface. Its origin is the top-left position used by window-relative coordinates.

Lesson 2.7: a full-screen phone window can begin at screen (0, 0), but the window coordinate system and screen coordinate system are still different systems.

Window-relative coordinate

A window-relative coordinate is a position measured from the application window's origin.

Screen-relative coordinate

LayoutCoordinates

Pointer

A pointer is a physical object that can point at a screen coordinate. A finger, stylus, mouse, or trackpad-controlled cursor can act as a pointer.

Crosshair

Coordinate inspector

Normalized coordinate

A normalized coordinate describes a position as a fraction of a containing width or height. Lesson 2.8 uses values from 0 through 1.

Formula: normalizedX = localX ÷ width and normalizedY = localY ÷ height.

Clamp

To clamp a value means to limit it to a minimum and maximum. A value below the minimum becomes the minimum. A value above the maximum becomes the maximum.

Lesson 2.8: coerceIn(0f, 1f) keeps the stored normalized coordinate inside the lesson range. Division performs the normalization; clamping only enforces the range.

Width

Width is the horizontal distance from the left edge to the right edge.

Formula: width = right − left.

Height

Height is the vertical distance from the top edge to the bottom edge.

Formula: height = bottom − top.

Center

The center is the position halfway between the left and right edges and halfway between the top and bottom edges.

Origin-based rectangle: centerX = width ÷ 2 and centerY = height ÷ 2.

RGB

RGB means red, green, and blue. It names three color channels. A bare RGB(r, g, b) triplet does not, by itself, say whether the numbers are straight or premultiplied when alpha is relevant.

Lesson 3.1 limit: alpha is fixed at 1.00. At alpha 1.00, straight and premultiplied RGB are numerically equal, but the data contract still defines their meaning.

RGB tuple

An RGB tuple is an ordered group of three numbers written as (red, green, blue). The word ordered means that changing the positions changes which channel receives each number.

Mapping: (0.80, 0.25, 0.60) means red 0.80, green 0.25, and blue 0.60.

Normalized color-channel value

A normalized color-channel value uses a numeric scale from 0.00 through 1.00.

Important limit: 0.80 means 80% of this numeric range. It does not by itself prove 80% physical light output or perceived brightness.

8-bit color-channel value

An 8-bit color-channel value is an integer from 0 through 255. The phrase 8-bit means that 256 distinct integer values are available.

Lesson 3.1 conversion: round(0.80 × 255) = 204.

Visual brightness

Visual brightness is how bright a color or region appears to a person. It can change with display brightness, ambient light, surrounding colors, viewing size, and the viewer.

Lesson 3.6 distinction: visual brightness is a perception. Relative luminance is a deterministic software calculation.

Relative luminance

Relative luminance is one unitless number calculated from one final color. In the sRGB model, reference black is 0 and reference white is 1.

Lesson 3.6: first decode the final opaque color's three sRGB channel code values into linear-light values. Then multiply by the standard coefficients and add. The result is not a color, alpha, the Android brightness setting, or a direct physical measurement in nits.

sRGB

sRGB means standard Red Green Blue. It is a standard RGB color space. A color space is a rule set that gives red, green, and blue numbers a precise meaning.

Lesson 3.6 focus: sRGB defines a transfer rule that maps each channel code value held by the Color object to a linear-light channel value. The lesson does not yet derive sRGB's primary colors or color-space matrix.

sRGB channel code value

An sRGB channel code value is the red, green, or blue number supplied to an sRGB color. The word code means a standardized numeric representation. It does not mean program source code.

Important: the value is not proportional to modeled light. For example, sRGB code value 0.50 decodes to approximately linear-light value 0.214.

Linear-light channel value

A linear-light channel value is the output of the sRGB decoding rule. It is a software-model number for the selected red, green, or blue channel. Its numeric size is proportional to that channel's modeled light contribution. It is not a sensor reading.

Meaning of linear: doubling a linear-light channel value means doubling that channel's modeled contribution. This is a mathematical model, not a direct sensor measurement of the Pixel 8 Pro.

sRGB decoding

sRGB decoding is the operation that accepts one sRGB channel code value and returns one linear-light channel value.

Exact data path: one channel field in Color → choose one branch of the standardized sRGB formula → one linear-light channel value. The output is not yet a complete color or relative luminance.

Transfer function

A transfer function is a rule that maps one numeric representation to another. The sRGB decoding transfer function maps an sRGB channel code value to a linear-light channel value.

Android source: AndroidX obtains the decoding function from the color space when calculating Color.luminance(). The beginner lesson uses the plain phrase sRGB decoding rule before introducing framework abbreviations.

Decision threshold

A decision threshold is an application-chosen boundary used to classify a measured number. A value on one side receives one label; a value on the other side receives another label.

Lesson 3.6: relative luminance is the measurement. A chosen light/dark threshold is separate policy and is not part of the luminance formula.

Piecewise formula

A piecewise formula contains two or more cases. A condition chooses which one case runs for the current input.

Lesson 3.6: sRGB values at or below 0.04045 use division by 12.92. Larger values use the main curve. The two cases are not both executed and averaged.

Exponent

An exponent tells a calculator to raise a base number to a power. The notation x ^ 2.4 is a power operation. It does not mean x × 2.4.

Lesson 3.6: the main sRGB decoding branch raises a scaled value to the fixed power 2.4.

Coefficient

A coefficient is a fixed number multiplied by one changing input. The coefficient tells the formula how strongly that input contributes to the result.

Lesson 3.6: 0.2126, 0.7152, and 0.0722 multiply linear red, green, and blue. These standardized coefficients are not calculated from the current color and are not UI tuning values.

Scalar

A scalar is one number. It is not a point, vector, or RGB tuple.

Lesson 3.6: relative luminance is one scalar produced from three linear-light channels.

Lesson 8.7: an AGSL scalar is one float or one half, for example float t = uv.x. Copying t into three half4 slots paints gray.

Reference black and reference white

Reference black and reference white are the two endpoints used to interpret relative luminance in this lesson. sRGB black has relative luminance 0. sRGB white has relative luminance 1.

Limit: these are software reference endpoints. They are not a measurement of the current device's darkest and brightest physical output.

Color space

A color space is a rule set that gives color numbers precise meanings. It identifies the color components and the rules that relate their numeric values to represented colors.

Lesson 3.6: the input Color uses sRGB. The lesson focuses on sRGB's channel-decoding rule and defers the full primary-color and matrix mathematics.

Banding

Banding is the appearance of visible steps or stripes inside a color transition that should look smooth.

Lesson 3.6: at a fixed numeric precision, sRGB's nonlinear code-value distribution gives more numeric detail to darker parts of the range than a linear code would, which helps reduce visible banding.

Lesson 7.10: a stripe is a run of neighboring pixels that all stored the same 8-bit integer after rounding. The 7.6 navy and orange interiors stay flat; banding is taught on a teaching ramp that stands in for the short mixed seam after blur.

Teaching ramp

A teaching ramp is a left-to-right gradient used so a slow numeric change is wide enough to inspect. It is a stand-in, not a redraw of an earlier artwork.

Lesson 7.10: true red moves from 0.32 to 0.36 across 640 columns. That range sits in the navy family. It is not the 7.6 orange field and not a claim that the whole navy interior was a gradient.

Rounding bin

A rounding bin is the interval of true channel values that all round to one stored integer.

Lesson 7.10: stored red 85 catches every true red whose true × 255 is closer to 85 than to 84 or 86. Columns 182 through 244 of the teaching ramp sit in that bucket, so they form one stripe. The bin is not the remainder recipe.

8-bit store

An 8-bit store writes a normalized channel as an integer from 0 through 255 into a bitmap: stored8 = round(clamp(channel) × 255).

Lesson 3.1 taught the rounding. Lesson 7.10: noise is added before this write so two neighbors can round to different integers.

Remainder tile

The Lesson 7.10 remainder recipe maps column and row to one of 16 slots by keeping the leftover after division by 16. The same pair always returns the same slot, and the map repeats every 16 columns and 16 rows.

Pattern, not a random roll: it is a frozen 16-by-16 grain tile. It is not what draws the 8-bit color stripes. Amount 0 with no recipe still bands.

16 unique slots in 16 consecutive columns: if two columns distance k (1 through 15) shared a leftover, k × 7 would be a multiple of 16. 16 is four 2s and 7 is not a 2, so k would have to be a multiple of 16, which is impossible in that range. A step of 8 collides at k = 2.

Signed stays signed: unit = slot / 15 is never negative. Slot 2 has signed −0.733. Gray encodes that as a darker byte; the add still uses the minus.

Slot gray is not stored red: the black-to-white walk encodes signed. At amount 0.02, one true red that stores 85 can land on stored integers about 80 through 90, not only 84, 85, 86. Amount 0.002 is the tiny nudge that stays in two or three adjacent integers.

Two stripe families: an 8-bit color stripe is neighbors that all stored the same integer after rounding a slow true ramp (columns 182–244 store red 85 when the Lesson 7.10 slider is 0). A leftover line is every pixel that gets the same leftover, so the same add. From leftover 14 at column 200, row 80, the next leftover-14 pixel is three pixels down and one pixel left. +3 only changes which leftover number appears first. It does not make that walk.

Darker then lighter on a flat navy: Lesson 7.12’s dark interior stores RGB (98, 109, 121) if we add nothing. The 16 leftovers make 16 stored navy triples. Stored red only runs 93 through 103 at amount 0.02, so the 16 shades stay close. Consecutive columns jump 7 leftovers. Leftover 14 stores RGB (102, 114, 125), a little lighter. The right neighbor is leftover 5, which stores RGB (96, 108, 119), a little darker. That pair repeats, so the eye reads darker stripe, lighter stripe, darker stripe. Picture C’s zoomed navy draws those pixels.

Dither

Dither, in Lesson 7.10, is the use of a small signed offset before the 8-bit store so neighboring pixels can round to different integers and the eye averages the field.

Fine noise is that signed offset. Production uses one shared offset on red, green, and blue so the specks stay gray.

Structure leftover

Structure leftover is an observation by eye after the frozen glass recipe: can you still name the destination class from the frosted fill?

Not a 4.5 verdict: contrast asks whether the label separates from the interior RGB. Leftover asks whether destination content still shows through that fill.

Uniform field: every pixel starts as one color. Dark is rgb(26, 64, 102) everywhere. Light is rgb(224, 230, 237) everywhere. Leftover is the remaining color neighborhood: still a dark navy, or still a light gray. The phrase “color family” meant that neighborhood.

Not the rim: the sharp white ring and the inner band are later siblings on the path. They stay sharp because they are not in the fill blur. A blurry fill is the recipe working.

Local backing

A local backing is extra more-opaque paint placed under the label, or under the glass interior, so the destination no longer shows through as strongly.

Not the outer shadow: Lesson 7.9’s shadow is a darker copy around and below the card. It does not sit under the letters.

When to use it: after measuring white and black, only if both miss the 4.5 target. Then a stronger tint or a backing can move the interior RGB. Blur radius is not that repair.

Nit

A nit is a unit used to report physical luminance. One nit equals one candela per square metre.

Lesson 3.6: the course calculates unitless relative luminance from color data. It does not measure the Pixel 8 Pro's physical output in nits.

Saturation factor

In Lesson 3.9, the saturation factor is the one numeric input supplied to AndroidX ColorMatrix.setToSaturation. It controls the size of each channel's signed distance from the transform's gray reference.

Exact regions: 0 makes all three output channels equal the gray reference; values between 0 and 1 reduce the distances; 1 preserves the input RGB; values above 1 enlarge the distances.

Saturation gray reference

The saturation gray reference is one channel value calculated directly from the stored straight sRGB input channels with 0.213R + 0.715G + 0.072B. Assigning that same value to output red, green, and blue produces the factor-zero gray result for this AndroidX transform.

Not relative luminance: relative luminance first decodes sRGB into linear light and produces one measurement. The gray reference is an intermediate value inside a color transformation.

Signed channel distance

A signed channel distance is input channel − gray reference. A positive result places the channel above the reference on the normalized number line. A negative result places it below.

Lesson 3.9: multiplying this distance by the saturation factor proves whether the output moves toward gray, remains unchanged, or moves farther away.

Color matrix

A color matrix is a table of multipliers and offsets that calculates output red, green, blue, and alpha from input red, green, blue, and alpha.

Lesson 3.9: AndroidX stores the saturation transform as four rows with five values per row. For one fixed factor, the same matrix is applied to every affected source pixel. The RGB row coefficients change when the factor changes.

Unclamped matrix output

An unclamped matrix output is the direct sum produced by one matrix row before the allowed channel range is enforced. Some material calls this a raw output.

Lesson 3.9: an unclamped blue result of 1.01308 is outside the normalized range. Clamping produces the displayed channel value 1.00000.

Color-matrix offset

A color-matrix offset is the fifth value in one matrix row. The matrix evaluates the input vector [R, G, B, A, 1], so the fifth value is multiplied by the constant 1 and added after the component products.

Lesson 3.9: all offsets in setToSaturation are zero, so they add nothing.

Value provenance

Value provenance identifies where a displayed value came from.

Course categories: inherited initial state, learner-controlled input, fixed API or standard constant, calculated result, or renderer-produced value.

Transform placement

Transform placement identifies which color object or buffer a color transformation consumes and whether it runs before or after compositing.

Lesson 3.9: transforming a translucent source before source-over and transforming the already composited output are different operations.

Identity transform

An identity transform returns the input unchanged.

Lesson 3.9: saturation factor 1.00 is the identity setting because every output channel keeps 100% of its original signed distance from the gray reference.

Blend mode

A blend mode is the rule that combines matching source and destination color channels at a drawing position to calculate the output color.

Lesson 3.10 boundary: the source and destination are both opaque. The lesson isolates the RGB rule and defers translucent blend-mode compositing.

Normal / SrcOver blend mode

Normal is the common graphics-tool name for ordinary source-over drawing. Compose names the mode BlendMode.SrcOver.

Opaque source: at a fully covered position, the opaque source replaces the destination.

Multiply blend mode

For the opaque normalized inputs in Lesson 3.10, Multiply calculates each output channel as source × destination.

Neutral opaque source: white channel value 1, because 1 × destination = destination.

Screen blend mode

For the opaque normalized inputs in Lesson 3.10, Screen calculates the shared distance before white and subtracts it from white: 1 − (1 − source) × (1 − destination). The equivalent short form is source + destination − source × destination.

Neutral opaque source: black channel value 0.

Plus blend mode

For the opaque normalized inputs in Lesson 3.10, Plus adds matching source and destination channels and clamps the unclamped sum to the supported range 0..1.

Neutral opaque source: black channel value 0.

Neutral source

A neutral source is a source value that makes one specific blend mode return the unchanged destination value.

Mode-specific: white is neutral for Multiply. Black is neutral for Screen and Plus. An opaque Normal source has no neutral source because it replaces the destination.

Saturating addition

Saturating addition means adding values and restricting any result above the maximum supported value to that maximum.

Not color saturation: Plus may use saturating addition. This has no gray reference and is unrelated to the Lesson 3.9 saturation transform.
