Shortcut — Safari's “…” button becomes the menu

A side lesson next to the course: it does not count toward the 216 lessons. iPhone 16 Pro, iOS 26, Safari. Light theme · desktop · works from file://.

On iOS 26, a tap on Safari's “…” button turns the button into a menu: a piece of glass leaves the button, flies up, grows, and stops as the menu. While it flies, the menu text near its edge looks folded over the edge, like the edge of a sheet of paper. This lesson rebuilds that motion from Chapter 5 springs, Chapter 9 read points and the rim of Lesson 10.1 (the rounded edge of the glass), and adds two ideas: the rim folds the picture (Section 1), and one number, unsettled, that is 0 at rest and near 1 in the middle of the flight (Section 2).

What differs between the two pictures. The history row's title is painted over in the recording, for privacy; this page writes a made-up title there. This page draws simple shapes instead of Apple's icons. The centers of the two glasses are at most 6.5 pt apart (pt: the iPhone's unit of length) at the seven measured moments: Section 2, step 5, compares them with numbers.

        Section 5 · short code excerptThe iPhone code

        Two excerpts from the LiquidGlassLab app, folder shortcut/. The parameter lists are shortened, and the comments on the right were added for the lesson. The new lines are green.

        The lens: SafariMenuGlass.metal

        /// How far the lens moves the read point inward, for a pixel sd from the outline.
static float rimPushAmount(float sd, float bevel, float edgePush) {
    if (bevel <= 0.0) { return 0.0; }
    float inside = clamp(-sd, 0.0, bevel);                 // Lesson 10.1
    float leg = bevel - inside;                            // Lesson 10.1
    float h = sqrt(max(bevel * bevel - leg * leg, 0.0));   // Lesson 10.1: the height of the rim
    return edgePush * (1.0 - h / bevel);                   // new: edgePush on the outline, 0 on the flat top
}

[[ stitchable ]] half4 safariMenuGlass(float2 position, SwiftUI::Layer picture, float4 box, ... float2 lens, ...) {
    float sd = glassSd(position, box, cornerRadius, drop); // Lesson 9.4, joined to the drop at the button
    ...
    float e = 0.5;                                         // how sd changes half a point to each side
    float2 slope = float2(glassSd(position + float2(e, 0.0), ...) - glassSd(position - float2(e, 0.0), ...),
                          glassSd(position + float2(0.0, e), ...) - glassSd(position - float2(0.0, e), ...));
    float slopeLength = length(slope);
    float2 outward = slopeLength > 0.00001 ? slope / slopeLength : float2(0.0);
    float push = rimPushAmount(sd, lens.x, lens.y);         // new: lens = (bevel, edgePush)
    float2 readPoint = position - outward * push;         // new: read further inside
    half4 color = picture.sample(readPoint);               // Lesson 9.7
    ...
}
        • picture is the glass picture: Swift draws the blurred page, the glass color, the “…” glyph and the menu text into one view, and the shader reads it (SafariMenuScene.swift).
        • outward points straight out of the glass. On the straight top it is (0, −1), so position − outward × push adds push to y: the read point is push pt lower, inside the glass.
        • The app needs .compositingGroup() before .layerEffect. Without it, SwiftUI runs the shader once for each child view of the glass picture, not once for the flattened picture.

        The motion: SafariMenuMotion.swift

        let f = travel.value                                           // where the glass is: 0 button, 1 menu
let u = min(1, abs(lead.value - f) / fullGap)                  // new: unsettled
let center = CGPoint(
    x: glassMix(layout.buttonCenter.x, menu.midX, f),
    y: glassMix(layout.buttonCenter.y, menu.midY, f) - SafariMenuTuning.liftPoints * u)   // new: the jump
let roundHalf = (straightHalfWidth * straightHalfHeight).squareRoot()
let half = CGSize(width: glassMix(straightHalfWidth, roundHalf, SafariMenuTuning.rounding * u),
                  height: glassMix(straightHalfHeight, roundHalf, SafariMenuTuning.rounding * u))  // new: rounder
let rimAmount = glassSmoothstep(0.0, 0.5, u) * ...               // new: the rim follows u
let bevel = min(glassMix(14, 28, rimAmount), cornerRadius)
let edgePush = glassMix(6, 24, rimAmount)
        • travel and lead are two GlassSpring values, stepped every 1/960 s by advance(to:): the Chapter 5 spring, eight steps per 120 Hz frame.
        • ... after rimAmount is the closing factor: while the glass goes back, the rim stays thin until the glass has shrunk.
        • Every frame, a TimelineView asks the motion for a frame, and Swift passes its numbers to the shader as arguments.
        Browser and iPhone. This page runs the same lines: its motion code is a copy of SafariMenuMotion.swift that gives the same numbers (checked to 9 decimals for 436 moments), and its WebGL shader repeats SafariMenuGlass.metal. Three things differ. The page blurs with three box blurs in a row instead of Core Image's Gaussian. SwiftUI's .blur(radius:) of the menu text is drawn here with a Gaussian of half that radius: an estimate, matched by eye to the recording. And the browser draws text with its own font renderer and draws simple shapes instead of Apple's icons.

        Exercise 1 — at rest, how wide is the mirrored band?
        • A0 … A6: pixels of the column at inside 0, 0.5, 1, 1.5, 2, 3 and 4 pt
        • the pink arrows: from each pixel to its read point
        • the violet line: the outline, inside 0

        The change. The glass is at rest, so unsettled = 0 and the rim is thin: bevel = 14, edgePush = 6 (Section 2). The push line stays push = edgePush × (1 − h ÷ bevel).

        What it checks. The mirrored band is where a pixel further out reads further in (Section 1, step 6). It ends at the pixel whose read point is the highest. Read the arrows: find that pixel.

        Question: at rest, how wide is the mirrored band?

        Show the answer

        Why: with the thin rim the push falls from 6 to 0 over 14 pt, much less steeply than 24 over 28. The read points turn back after only 1.1 pt. That band shows the glass picture from 4.8 to 6 pt below the outline, and the menu's first letters start 26.5 pt below it: so the band shows only the glass color, and nothing looks folded.

        Exercise 2 — does a straight-ramp push fold the picture?
        • the navy curve: the push of this lesson, edgePush × (1 − h ÷ bevel)
        • the teal line: the straight ramp, edgePush × (1 − inside ÷ bevel)
        • E, P, Q: inside 0, 5.6 and 11.2 pt, on the teal line

        The change. The push line becomes push = edgePush * (1.0 - inside / bevel), a straight line, with the moving rim: bevel = 28, edgePush = 24.

        What it checks. The fold comes from the order of the read points (Section 1, step 5). Work out where E, P and Q read with the teal line: read inside = inside + push.

        Question: does a straight-ramp push fold the picture?

        Show the answer

        Why: for each pt the pixel moves inward, the ramp's push falls by 24 ÷ 28 = 0.857 pt, so the read point moves inward by 1 − 0.857 = 0.143 pt. That is more than 0, so the order of the read points never flips. The ramp folds only when edgePush is larger than bevel. The quarter circle folds even with edgePush smaller than bevel, because near the outline its height grows faster than 1 pt per pt.

        Exercise 3 — why does the closing glass first jump up?
        • green: travel, stiffness 144, damping 16.8
        • indigo: lead, stiffness 2304, damping 144
        • J: t = 0.047 s, the highest point of the glass

        The change. A tap outside the menu sets both targets to 0, and the springs switch to the closing numbers (Section 2, step 7). The lift line stays center.y = straight path y − 36 × unsettled.

        What it checks. Section 2's idea: the gap between the springs drives the lift. Read travel and lead at J, then compare the lift with how far the straight path has moved down.

        float rimPush(float sd, float bevel, float edgePush) {
    float inside = clamp(-sd, 0.0, bevel);
    float leg = bevel - inside;
    float h = sqrt(bevel * bevel - leg * leg);
    return edgePush * (1.0 - h / bevel);
}

float2 foldReadPoint(float2 position, float4 box, float cornerRadius, float bevel, float edgePush) {
    float sd = exerciseGlassSd(position, box, cornerRadius);
    float e = 0.5;
    float2 slope = float2(
        exerciseGlassSd(position + float2(e, 0.0), box, cornerRadius) - exerciseGlassSd(position - float2(e, 0.0), box, cornerRadius),
        exerciseGlassSd(position + float2(0.0, e), box, cornerRadius) - exerciseGlassSd(position - float2(0.0, e), box, cornerRadius));
    float slopeLength = length(slope);
    float2 outward = slopeLength > 0.0 ? slope / slopeLength : float2(0.0);
    float push = rimPush(sd, bevel, edgePush);
    return position - outward * push;
}

        Why it works: rimPush is Lesson 10.1's height and this lesson's push line in one function. foldReadPoint is Chapter 9's read point with a push that depends on sd: on a straight side the outward direction is (0, −1) or (−1, 0), and around a corner it points away from the corner circle's center (T3: the 3-4-5 direction). In the middle the push is 0, so the picture is not moved there.
