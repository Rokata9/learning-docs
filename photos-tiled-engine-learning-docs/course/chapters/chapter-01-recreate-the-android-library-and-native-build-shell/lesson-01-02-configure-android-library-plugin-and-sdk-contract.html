02 · DEFINITIONS

The terms needed for this configuration

These definitions describe the build model. They do not explain image rendering yet.

Android Gradle Plugin (AGP)

Google's Gradle plugin for Android builds. It adds Android-specific configuration and tasks to a Gradle project.

Plugin ID

A stable string that identifies a Gradle plugin. The Android library plugin ID is com.android.library.

Version catalog

The project file gradle/libs.versions.toml. It gives dependencies and plugins central names and versions.

Plugin alias

A generated Kotlin DSL accessor that refers to one plugin entry in the version catalog. Here the accessor is libs.plugins.android.library.

apply false

A root-build declaration that makes a plugin and version available without applying that plugin to the root project itself.

Android library

An Android-aware Gradle project whose packaged output is an Android Archive, abbreviated AAR, rather than an installable application package.

android extension

The Android configuration object added by AGP. The android { ... } block configures that object.

Namespace

The package used for Android-generated classes such as the module's future R class. It is not the installed app's identity.

API level

An integer that identifies one Android platform API surface. The project uses API levels 36 and 23 for different purposes.

Compile SDK

The Android API level whose declarations are available while compiling the module. It does not define the oldest supported device.

Minimum SDK

The oldest Android API level that the library declares it supports. A normal consuming app must use an equal or higher minimum.

defaultConfig

The Android configuration block for values shared by every future build variant. In this lesson it contains only minSdk.

05 · EXACT VALUE TRACES

Follow the plugin alias and keep the two SDK numbers separate

No arithmetic is needed. The important work is tracing who supplies and consumes each value.

Trace A — libs.plugins.android.library

Module inputlibs.plugins.android.library

The new module build script requests one generated catalog accessor.

Catalog lookupandroid-library

The accessor maps to the plugin entry with this catalog key.

Resolved valuecom.android.library · 9.1.1

The entry supplies the plugin ID and follows version.ref = "agp".

ConsumerProject :tiled-engine

AGP adds the android extension and Android-library tasks to this project.

Trace B — the namespace

StageExact valueMeaning
Surviving caller inputcom.example.androiduisamples.tiledengine.TiledImageViewThe app expects a class with this fully qualified name.
Base packagecom.example.androiduisamples.tiledengineRemove the class name. The remaining package is the library contract.
Module configurationnamespace = "com.example.androiduisamples.tiledengine"AGP will place future Android-generated classes, including the future R class, in this namespace.

Trace C — two independent SDK decisions

Compilation API surface 36

compileSdk = 36 tells AGP which Android API declarations the module may reference while compiling.

It does not say that the device must run API 36.

Oldest supported device API 23

minSdk = 23 states the lowest Android API level supported by the library contract.

It does not limit which API declarations the compiler can see.

Why these values are kept instead of upgraded: the goal is behavioral reconstruction of the attached project. The app currently uses compileSdk = 36 and minSdk = 23. AGP 9.1.1 can support newer compile platforms, but changing the project baseline is a separate upgrade decision.
06 · MANUAL WORK

Create one minimal module build script

You author every line. The outline below shows DSL nesting, not a finished file.

  1. Create tiled-engine/build.gradle.kts

    This is the only file created or edited by Lesson 1.2.

  2. Apply the catalog's Android library plugin alias

    Use the accessor traced in Section 5. Do not apply the Android application plugin. Do not apply the Kotlin Android plugin.

  3. Configure the namespace

    Use the base package derived from the surviving TiledImageView import and XML class name.

  4. Configure the compile SDK

    Use the same compile API level as the current app module.

  5. Configure the minimum SDK inside defaultConfig

    Use the same device floor as the app module.

Required DSL nesting — replace each comment from the contracts aboveKotlin DSL
plugins {
    alias(/* library plugin accessor */)
}

android {
    namespace = /* library base package */
    compileSdk = /* app compile API level */

    defaultConfig {
        minSdk = /* app minimum API level */
    }
}

08 · EXERCISES

Answer without opening the hidden answers

Exercise 2 targets the most likely SDK misconception.

Exercise 1 — Trace libs.plugins.android.library to the exact plugin ID and version that Gradle applies.

Answer: The generated accessor maps to the android-library entry in libs.versions.toml. That entry specifies plugin ID com.android.library and follows version.ref = "agp". The agp version is 9.1.1.

Exercise 2 — The module uses compileSdk = 36. Does that prevent it from running inside the app on an API 23 device? Explain which value decides the device floor.

Answer: No. compileSdk = 36 selects the Android API declarations visible while compiling. minSdk = 23 declares the oldest supported device API level. Using a newer API at runtime still requires version-aware code, but the compile SDK number alone does not raise the device floor.

Exercise 3 — Why is com.example.androiduisamples.tiledengine a namespace but not an applicationId in this module?

Answer: The namespace owns the module's Android-generated classes and matches the package expected by surviving callers. The library is not installed as a separate app, so it does not define the installed application's identity. The :app module owns applicationId = "com.example.photos".

Exercise 4 — The root build already contains alias(libs.plugins.android.library) apply false. Why must the module still apply the alias without apply false?

Answer: The root declaration makes the plugin version available but deliberately does not apply its behavior to the root. The module-level declaration actually applies the plugin to :tiled-engine, which adds the Android extension and Android-library tasks there.
